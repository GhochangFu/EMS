## Goal

Make a database outage survivable for the ingest host. Today a batch whose `writeSamples` throws is counted in `writeFailures` and lost (`apps/ingest/src/host/supervisor.ts:425-435`). After this item the batch is appended to an on-disk JSON-lines segment under `INGEST_BUFFER_DIR`, the supervisor stops attempting the database ("buffering"), a replay loop probes on the shared §5 backoff, and when a write succeeds live batches go first and the backlog drains oldest-first. Two host-wide bounds (1 h by receipt time, 256 MiB) erase the oldest and count every erasure. The health line gains `buffered=`, `bufferDropped=`, `replayed=`, and `buffered>0` degrades the host verdict. The host refuses to start if the directory cannot be created and written. The design is ADR 0016 Amendment 4 (`docs/adr/0016-ingest-adapter-framework.md:1085-1238`), eleven decisions and four rulings; this plan transcribes it into build order and does not re-open it.

**Out of scope, stated:** the broker-disconnect backoff (already built, `packages/shared/src/ingest.ts:162`); `prom-client` (stays `F3.16`); edge store-and-forward (`E7.2`); endpoint-set reconciliation on reload; any change to `apps/ingest/src/adapter/types.ts` or any file under `apps/ingest/src/adapters/`; any new npm dependency; the memory ring queue (`host/sample-queue.ts`, unchanged); a `bms_ingest` database role; anything under `apps/api/src/rules` or `apps/api/src/notifications` (F3.7 is building there — nothing in this item needs them, confirmed against every file below); the `docs/BACKLOG.md` status flip and the `chore(agents):` sweep (both after merge).

**Contract work (§4.8 / ADR 0030): N/A.** No API response type changes. The health body is the ingest host's plain-text line, not a NestJS response, and `packages/shared/src/contracts/` is untouched.

Tasks 6 and 7 (invariant, docs) are independent of each other, but they are ten-minute Sonnet units and a cold worktree costs more than doing them in order. F1.10 is not a ⭐ enabler, so the serial-spine rule is not what forces this; the file coupling is.

## Decisions this plan makes that the ADR leaves open

- **`at` is stamped at spill time when the sample has none.** `resolveSamples` uses `receivedAt = new Date()` at write time (`normaliser.ts:152`). A line without `at` replayed an hour later would be written at replay time, and a re-replay of the same segment would produce a *different* `(time, asset_id, point_key)` — duplicate rows, not an idempotent upsert. Decision 5's "replay is safe because `writeResolved` is `ON CONFLICT DO UPDATE`" therefore requires every line to carry a fixed `at`. The store writes `at: (validDate(sample.at) ?? now()).toISOString()`; an invalid `Date` gets `now()` too, mirroring the normaliser's substitution. Every segment line carries `at`.
- **Replay probe failures count in `writeFailures`.** Decision 9 says the counter "keeps counting the write that triggered each spill"; a probe is also a rejected `writeSamples`. `docs/ingest-host.md` calls `writeFailures` "the signal that a database outage is costing telemetry", and a probe failing every ≤60 s keeps that signal moving during the outage. About 70 increments per hour at the 60 s cap.
- **Ceilings for the two new bounds** under `positiveInt`'s per-caller rule: `INGEST_BUFFER_MAX_AGE_MS ≤ 2^31-1` (reuse `MAX_TIMER_MS`; 24.8 days — anything above is a typo), `INGEST_BUFFER_MAX_BYTES ≤ 2^40` (1 TiB; a byte cap is a fact about a disk, not about integers). No lower bound beyond `> 0`: a 1-byte cap drops everything loudly and counted, which is the honest failure.
- **`buffer` is a required `SupervisorDeps` field.** Ruling 4 says a host that cannot buffer does not start, so an optional "no buffer" branch would be a production-unreachable path that keeps the old loss route alive and is covered by nothing.
- **`buffering` is entered only after a successful append.** If the disk append itself fails there is nothing on disk to replay, so the supervisor stays on the live path (count and drop, as today). Otherwise the endpoint would sit in buffering with an empty buffer and no probe ever fired.
- **All filesystem work in the store runs through one store-wide serial queue.** Two loops per supervisor (drain and replay) plus cross-endpoint byte enforcement touch the same files; an `appendFile` racing an `unlink` on the same segment is a silent loss. One promise chain removes the race for the cost of nothing (one append per 200 ms drain cycle per endpoint).
- **A segment appended to after it was read is not unlinked at commit.** The handle records the line count it read; `commit()` unlinks only when the in-memory count still equals it, else the segment is re-read next pass and its already-written head re-upserts idempotently. That is decision 8's "at most one minute, idempotently" bound made concrete.

**Model: Fable.** This unit defines the `DiskBufferHandle` seam the supervisor, `main.ts` and later `E7.2` hang off, and its semantics (bounds, crash safety, the read-then-append race, the serial queue) are where a cheaper model produces a review-fix loop.

**Files**

- Create `apps/ingest/src/host/disk-buffer.spec.ts` (assertions) and `apps/ingest/src/host/disk-buffer.test.ts` (wrapper, same shape as `sample-queue.test.ts`).

**Public surface (exact names — the supervisor and `main.ts` compile against these)**

```ts
export type BufferedSegment = {
  /** Parseable lines, oldest first, `at` revived to a Date. */
  readonly samples: readonly SourceSample[];
  /** Unlinks the segment unless a line was appended since it was read. */
  commit(): Promise<void>;
};

export type DiskBufferHandle = {
  readonly protocol: IngestProtocol;
  readonly endpointKey: string;
  /** Samples on disk for this endpoint — a gauge. */
  readonly buffered: number;
  /** Samples erased by a bound, unparseable, or lost to a failed append — a counter. */
  readonly dropped: number;
  /** Persists one batch. Resolves `false` (logged, counted) rather than rejecting. */
  append(samples: readonly SourceSample[]): Promise<boolean>;
  /** The endpoint's oldest segment, or `null` when nothing is buffered. */
  oldest(): Promise<BufferedSegment | null>;
};

export type DiskBufferStore = {
  readonly dir: string;
  /** Same `(protocol, endpointKey)` returns the same handle. */
  handle(protocol: IngestProtocol, endpointKey: string): DiskBufferHandle;
};

/** The `node:fs/promises` slice used, injectable so a spec can make it fail. */
export type BufferFileSystem = Pick<typeof fsPromises, "mkdir" | "writeFile" | "appendFile" | "readFile" | "readdir" | "unlink">;

export type DiskBufferOptions = {
  readonly dir: string;
  readonly maxAgeMs: number;
  readonly maxBytes: number;
  readonly now: () => Date;
  readonly logger: AdapterLogger;
  readonly fs?: BufferFileSystem;
};

/** mkdir -p, one write-and-unlink probe, one scan under the bounds. Rejects with `dir` in the message. */
export function openDiskBufferStore(options: DiskBufferOptions): Promise<DiskBufferStore>;
```

**Behaviour to implement (decisions 6–8, 10)**
- Path: `join(dir, protocol, encodeURIComponent(endpointKey), \`${Math.floor(now().getTime() / 60_000)}.jsonl\`)`. `handle()` throws if the encoded key is `""`, `"."` or `".."` (path traversal guard; `encodeURIComponent("..") === ".."`).
- Line: an explicit whitelist serialiser — `{ sourceKey, value, deviceKey?, at, good? }` picked field by field, never `JSON.stringify(sample)`. `at` per the decision above. One `appendFile` of all lines joined with `\n` plus a trailing `\n` (decision 8: one append is whole lines).
- In-memory records per segment: `{ path, minute, bytes, lines, unparseableCounted }` keyed per endpoint; store total bytes; per-endpoint `dropped` counters keyed by `(protocol, endpointKey)` so a start-up scan can attribute drops before a handle exists.
- After every successful append: unlink every segment (all endpoints) whose age `now - minute*60000 > maxAgeMs` (strict, like staleness), then while total > `maxBytes` unlink the oldest segment across endpoints (tie-break on path). Each unlink adds the segment's line count to its owner's `dropped`.
- `oldest()`: `readFile` the lowest minute; split on `\n`; parse each non-empty line through a small zod schema (`zod` is already an ingest dependency) with `at: z.string().datetime().transform(s => new Date(s))`; a failing line is skipped, counted once per segment (the `unparseableCounted` flag), and logged once per segment with `{ endpointKey, segment, skipped }`. `ENOENT` on read (another endpoint's byte enforcement unlinked it) → treated as gone, record removed, `null`/next.
- `open()`: `mkdir(dir, { recursive: true })`, `writeFile(join(dir, \`.probe-${process.pid}\`), "")` then `unlink`; any rejection is rethrown as `new Error(\`INGEST_BUFFER_DIR ${dir} is not writable: ${reason}\`)`. Then scan `dir/<protocol>/<enc>/*.jsonl` (`/^\d+\.jsonl$/` only; anything else is left alone and logged once at `warn`), read each once to set `bytes` and `lines`, then apply both bounds once.
- Serial queue: every fs operation of the store runs through one `chain = chain.then(op)`.
- The store owns no timer and reads no `process.env`.

**Spec assertions (`disk-buffer.spec.ts`)** — each block uses `mkdtemp(join(os.tmpdir(), "bms-ingest-buffer-"))` and `rm(dir, { recursive: true, force: true })` in `finally`; a mutable fake clock `let now = new Date("2026-09-06T10:00:00.000Z")`; a capturing logger (pattern: `adapter-contract.spec.ts` `makeCapturingLogger`).
1. `openDiskBufferStore` creates a nested directory that does not exist; opening twice is fine.
2. With an injected `fs` whose `mkdir` rejects (and separately whose `writeFile` rejects), `open` rejects and the message contains the directory path — ruling 4.
3. After one `append` at the pinned clock: exactly one file at `<dir>/mqtt/phe.thinkiot.co.in%3A8883/<floor(now/60000)>.jsonl` (assert the literal `%3A` — the Windows-safe encoding is the point); one line; `JSON.parse` gives the same `sourceKey`/`value`/`deviceKey`; `at` equals `now.toISOString()` for a sample with no `at`; a sample carrying an extra `password: SENTINEL` property does not reach disk (`Object.keys(parsed)` ⊆ the five allowed keys and the file does not contain SENTINEL). This is the file-layer analogue of `health-server.spec.ts:416-446`.
4. Two appends in the same minute → same file, two lines (append-only); advance the clock 60 s → a second file.
5. `buffered` equals the lines on disk; `oldest()` returns the lower minute first with `at instanceof Date` and the same epoch ms; `commit()` unlinks it and `buffered` drops by its lines; `oldest()` on an empty handle returns `null`.
6. Age bound: segments at minutes m and m+1; an append at m+61 unlinks m (61 min > 60) and keeps m+1 (exactly 60 min is not older); `dropped` rose by m's line count. The boundary is strict.
7. Byte bound, cross-endpoint: `maxBytes` = 300; handle A appends at m, handle B appends at m+1 and m+2 until the total exceeds 300 → A's segment is the one unlinked, A's `dropped` rises, B's does not, and B's append is what triggered it.
8. Crash truncation: write by hand two good lines plus a third cut mid-object with no trailing newline; `oldest()` returns two samples; `dropped === 1`; the captured logger has exactly one `warn` naming the segment; a second `oldest()` without `commit()` does not count it again.
9. Start-up scan: pre-create two good segments, one older than `maxAgeMs`, a stray `notes.txt` and a stray sub-directory; after `open`, `handle().buffered` equals the two kept segments' lines, `dropped` equals the aged one's lines, the stray file still exists (the store only unlinks `.jsonl` it owns) and was logged once.
10. Read-then-append: `oldest()`, then `append()` one line to the same minute, then `commit()` → the file still exists with 3 lines; `oldest()` now returns 3; `commit()` unlinks.
11. Failed append: an injected `fs.appendFile` that rejects → `append` resolves `false`, does not throw, `dropped` rises by the batch size, one `error` log line with `{ endpointKey, samples, reason }` and the log line does not contain the sample's `value` (payload privacy, §9.6).
12. `handle("mqtt", "k")` twice is the same object; `handle("mqtt", "..")` throws.
13. A `NaN` value serialises as `null` and is skipped and counted at read (JSON cannot carry it; the live path counts the same sample as `nonFinite`).
14. Sizes are tracked from the scan: after `open` over pre-existing files, one append that pushes the total exactly one byte over `maxBytes` unlinks the oldest — no `stat` is called (assert the injected `fs` slice has no `stat` and the code compiles against `BufferFileSystem`).

**Why the no-credential claim holds here:** the handle is constructed from `(protocol, endpointKey)` only; `plan.credentials` never reaches the store, the serialiser is a field whitelist (assertion 3), log fields are enumerated (assertion 11), and `endpointKey` is `host:port` — routing, not a secret, and already on the health line. The one thing that does reach disk that is not on the health line is the sample values themselves; that is the buffer's purpose.

**Gates:** `disk-buffer.test.ts` wrapper exists (repo-invariants fails a spec without it); ingest project picks up `src/**/*.test.ts` automatically; `typecheck:tests` covers the spec via `apps/ingest/tsconfig.json`. `node:fs/promises` only — no sync fs (ADR 0016 §5 rule 6's spirit; `main.ts` stays async). File under 1000 lines (§4.5, whole-file check).

The degrade must not fire without a buffer.

**Outage:** `docker compose stop postgres` (refused connections fail fast; `pause` would cost 30 s per batch through `writeTimeoutMs`). The nine live RTUs publish every ~60 s, 21 samples each. Within ~90 s: `writeFailures≥1`, `buffered>0`, `ingest-host degraded`, `queue=` stays near 0 and `dropped=0` (the breaker, decision 3 — the memory tier is not starving). `ls /var/lib/bms-ingest/mqtt/phe.thinkiot.co.in%3A8883/` shows one `<minute>.jsonl` per minute; `head -c 300` of one shows a line with `sourceKey`, `value`, `deviceKey`, `at` and nothing else; `grep -c "<MQTT_PASSWORD value>" *.jsonl` → 0 and the same grep over `docker compose logs ingest` → 0 (the credential claim at the file and log layers, on real data). Over three minutes expect ~570 samples buffered across ~3 segments; `writeFailures` rises by about one per backoff step (1, 2, 4 … 60 s).

**Recovery:** `docker compose start postgres`, wait for `service_healthy`. Within ≤ 60 s (the backoff cap): `replayed` rises to the buffered total, `buffered` returns to 0, the directory empties, the verdict loses the buffer reason, `writeFailures` stops rising. `docker compose logs api --since 5m` shows the telemetry listener reconnected and no error burst during replay (the ADR: replayed rows are notified like any upsert).

**Restart during an outage (decision 8):** stop postgres again, wait for one segment, `docker compose restart ingest`; the fresh process's first health read shows `buffered>0` (the start-up scan) before any broker connect; start postgres; `replayed` climbs and the directory empties.
