# E7.1b — Tenant columns, policies and the write path

**Backlog item:** `E7.1b` (Wave 4, P1). **Branch:** `feat/E7.1b-tenant-columns-policies-write-path`.
**Scope gate:** ADR 0043 (Accepted, Amendments 1–4) + ADR 0045 (Accepted). No new ADR owed —
[Amendment 4](../../adr/0043-multi-tenant-architecture.md#amendment-4-2026-08-26--bmsusersorganization_id-is-nullable-for-the-global-admin-a-second-exception-beside-audit_log)
was ruled 2026-08-26 before any code. **Merge gate:** human-owned.

## Goal

Extend the ADR 0043 tenant boundary from the five F4.16 tables to the full decision-5 set:
add `organization_id` to ~14 `bms.*` tables (nullable on `audit_log`, `bms.users`,
`notification_channels` and `notification_deliveries`; `NOT NULL` on the rest), backfill it,
give each table a `tenant_isolation` policy plus junction policies that follow the parent,
and extend `FORCE ROW LEVEL SECURITY` to the whole set. Because a `NOT NULL` column with no
writer breaks every insert, the schema change is inseparable from wiring the ~65 write sites
through `withTenant`, classifying every read on a tenant table as `withTenant` (default) or
`fleetDb` (named reason at the call site), and re-pointing `AccessControlService`'s pre-tenant
scope reads. Land Amendment 4 (`bms.users.organization_id` nullable for the global fleet
actor, an `auth_bootstrap_read` policy on `bms.users`, and the retirement of `0040`'s two
policies + `0039:122-124`'s three walk grants) and decision 6's `automation_rules.organization_id`
column. Verify decision 10 against the streaming and dashboard paths.

## Rulings resolved before code (2026-08-26)

1. **`bms.users.organization_id` is nullable for the global admin** — Amendment 4. `NULL` = a
   global fleet actor (`role='admin'`, no org membership), resolves to `bms_fleet`; a NULL home
   on any tenant-scoped user aborts the backfill.
2. **`notification_channels` enforcement moves to E7.1c.** E7.1b adds
   `notification_channels.organization_id` **nullable** only; `SET NOT NULL` and the
   `(organization_id, code)` re-key land in E7.1c with decision 7. Consequence:
   `notification_deliveries.organization_id` is **also nullable** in E7.1b (it resolves via
   `channel_id`), and its `SET NOT NULL` moves to E7.1c alongside its parent.
3. **`automation_rules` org is derived, not carried in the contract.** Threshold rules derive
   org from their asset; `time_window` rules derive org from the actor's current tenant (the
   `withTenant` org). **No `packages/shared` contract change** — §4.8 work is N/A.
4. **A `time_window` rule create requires a resolvable current org.** Org-scoped actors supply it
   via `withTenant`. A global `admin` (NULL home, no single tenant context) creating an asset-less
   `time_window` rule gets a clear **4xx** ("select an organization") — never a silent NULL
   (`automation_rules.organization_id` is `NOT NULL`). The admin org-picker UI is E7.1d.
5. **`audit_log.organization_id` population is deferred to E7.1c** (ruled 2026-08-26, after the
   Task 0/Task 3 audit found the write funnel is **38** call sites, not the estimated ~17, and that
   the column has **zero behavioral effect in E7.1b** — the only reader is the global admin, whose
   audit read Task 3b routes through `fleetDb`, which sees every row regardless of org). E7.1b still
   lands the `audit_log.organization_id` column (0046 ✓), the `FORCE` + `tenant_isolation` policy
   (0047), and the `fleetDb` read-move (Task 3b). The per-site org writes — org/user-lifecycle events
   → `NULL`, tenant actions → the entity's org, compiler-enforced by a required `AuditInput` field —
   move to **E7.1c**, beside the org-scoped audit reader that first consumes them (decision 5's
   "NULL is a defect" is enforceable only where a reader can observe it). Consequence: the
   `audit_log` policy in 0047 must **accept NULL org** (every E7.1b audit row is org-less), same as
   the other nullable-org tables (`bms.users`, `notification_channels`, `notification_deliveries`).

0046, in order (`SET ROLE bms_owner;` … `RESET ROLE;` — mandatory or
`tests/adr-0045-owner-and-superuser-url.test.ts` reds; forward-only + idempotent, §4):
1. `ALTER TABLE … ADD COLUMN organization_id uuid REFERENCES bms.organizations(id)` (nullable),
   guarded `IF NOT EXISTS`.
2. **`bms.users` column-grant edit** — add `organization_id` to the `bms_tenant`/`bms_fleet`
   SELECT/UPDATE column lists (`0039:82-97`), as idempotent re-`GRANT`s. Without it the column is
   unreadable to the pool roles by construction (`0039:80-81`).
3. **Backfill, parent-before-child** (order matters — a child reads a parent's freshly-filled
   column). Sources verified against the live schema by the Task 0 audit:
   - **Tier 1 (from `locations`):** `assets`/`asset_groups`/`rtus` ← `location_id →
     locations.organization_id`.
   - **Tier 2 (from `assets`, after Tier 1):** `asset_points`/`alarms`/`work_orders`/
     `maintenance_history`/`maintenance_task_templates` ← `asset_id → assets.organization_id`;
     `automation_rules` ← nullable `asset_id → assets.organization_id` (a `time_window` rule with
     `asset_id IS NULL` stays NULL and **aborts by design** — decision 11/6; audit shows 0 such rows
     on the pilot DB); `rtu_connection_configs` ← `rtu_id → rtus.organization_id`.
   - **Tier 3 (from a Tier-2 table):** `rule_executions` ← `rule_id → automation_rules.org`;
     `alarm_enrichments` ← `alarm_id → alarms.org`; `work_order_tasks` ← `work_order_id →
     work_orders.org`; `maintenance_schedules` ← `template_id → maintenance_task_templates.org`
     (**corrected** — no `asset_id`; not `asset_templates`); `notification_deliveries` ← `alarm_id →
     alarms.org` preferred (resolves), `channel_id` fallback (**nullable-tolerant** — channels are
     empty/nullable this item).
   - **`template_points`** ← `template_id → asset_templates.organization_id` (already org-scoped;
     table empty on the pilot DB).
   - **`bms.users`** ← the user's own grants, in order: `user_organization_access`, else
     `user_location_access → locations.org`, **else `user_asset_group_access → asset_groups.location_id
     → locations.org`** (the audit-added third path — `wc-hvac-admin` resolves only here).
     `role='admin'` with no grant → NULL by design; **any other role with no resolvable home → abort
     listing ids**.
4. **Abort check** per group: `SELECT id FROM <table> WHERE organization_id IS NULL` excluding the
   by-design-NULL rows (admin users, `audit_log`, and this item's nullable
   `notification_channels`/`notification_deliveries`), `RAISE EXCEPTION` with the offending ids.

**Backfill trap (load-bearing).** `bms.locations` already carries `FORCE` + `tenant_isolation`
(0040/0041) that binds `bms_owner`, so a backfill `JOIN locations` run as constrained `bms_owner`
with no `app.current_organization` sees **zero** locations → every child stays NULL → the abort
fires on rows you believed resolvable. **Mechanism (chosen):** backfill inside a per-organization
loop that sets the GUC — `FOR org IN SELECT id FROM bms.organizations LOOP; PERFORM
set_config('app.current_organization', org.id::text, true); UPDATE … WHERE … locations.organization_id
= org.id; END LOOP` (`bms.organizations` is not policied, so the loop source is fully visible; honours
the no-superuser rule). **Rejected in a comment:** running the backfill as `bms_app` superuser above
the `SET ROLE` marker — cleaner SQL, but violates the ADR 0045 "new migrations must not require
SUPERUSER" rule. The target tables are unpolicied until 0047, so the abort checks read them globally
as `bms_owner`; only the `locations` JOIN source is policied — state this in the migration header.

> **Task 2 + Task 3b are done together, service-by-service (ruled 2026-08-26).** The write funnel and
> the read reclassification for a given service are inseparable: the same service that inserts into a
> now-policied table also *reads* it (e.g. `assets.service` reads `existing` and the RTU on `tenantDb`
> with no GUC — both fall to 0 rows once `0047` policies `assets`/`rtus`). So each domain is one
> service-complete unit — writes wrapped in `withTenant`, reads reclassified, tests — and **one commit
> per service**, not "all funnels, then all reads". Per-service shape (from the assets service):
> resolve org **first** (from the parent, on `fleetDb`, gated by the existing scope check); wrap the
> write(s) in `withTenant(org)`; keep RTU-style consistency reads **inside** that GUC (never `fleetDb`
> — a by-id read of a credential-adjacent table on BYPASSRLS is a cross-tenant existence oracle);
> guard cross-org moves explicitly (`dest.org !== current.org` → 4xx, so a post-`0047` `USING`-miss is
> not a silent zero-row no-op dressed as success); pass the open `tx` to `audit.write` (atomic, and it
> sidesteps the second-pooled-client wedge in that service's docblock).

### Task 3 — `AccessControlService` read re-point (the hidden serial spine)

The ADR one-liner hides this; it is the highest-risk change and gates the whole API. In
`apps/api/src/auth/access-control.service.ts`, scope/reach reads break twice under E7.1b:
- On `authDb`: `directOrganizationIds` (`user_organization_access`),
  `locationDerivedOrganizationIds` (`user_location_access`+`locations`), and the
  `scopeFromSource` organization/location/asset_group branches that read `locations` — these lose
  their grant when Amendment 4 removes `0039:122-124`.
- On `tenantDb` with **no `withTenant`**: the `scopeFromSource` reads of `assets` /
  `asset_groups` / `asset_group_members`, and `canManageAsset` — these return **0 rows** once those
  tables get a policy.

**Resolution:** re-point every one of these reads (walk tables and tenant-table reads) onto
`fleetDb` with a named reason at the call site — "pre-tenant scope resolution across the actor's
grants; a single `SET LOCAL` cannot express the set, and the userId/orgId `WHERE` filter is the
isolation control (ADR 0043 Amendment 2/3)." Same "bypass, then trust an already-computed grant"
shape `scopeFromSource("global")` already uses, and it narrows `bms_auth` to `bms.users` alone as
Amendment 4 requires. Keep `resolveDbUser` on `authDb`; add `organization_id` (home) to its select
if a caller needs it.

**Test first — this is the gate.** `access-control.integration.spec.ts` passes the owner
connection as all three pools and cannot detect a lost grant or a missing `SET LOCAL` — a green run
there proves nothing. Only `access-control-rls.integration.spec.ts` (real
`bms_auth`/`bms_tenant`/`bms_fleet`) catches it. Extend that file so every scope source
(organization, location, asset_group) runs under real roles with **positive** counts
(`toBeGreaterThan(0)` on `scope.assetIds`), proving the `tenantDb → fleetDb` re-point live, not
vacuously.

### Task 4 — Migration 0047 (enforcement flip)

`0047_tenant_policies_force.sql` + journal entry; `SET ROLE bms_owner` … `RESET ROLE`.
1. `SET NOT NULL` on the **12** non-exception tables (not `audit_log`, `bms.users`,
   `notification_channels`, `notification_deliveries`).
2. `CREATE POLICY tenant_isolation` on all 14 + the 3 junctions (junction policy reads the parent's
   column via subquery, exact `0040` `USING`/`WITH CHECK` shape). **The four nullable-org tables**
   (`audit_log`, `bms.users`, `notification_channels`, `notification_deliveries`) need a
   **NULL-tolerant** variant: `USING (organization_id = current_org)` (so a NULL-org row is invisible
   to any single-tenant GUC and reachable only via `fleetDb` BYPASSRLS, never leaked to every tenant)
   but `WITH CHECK (organization_id = current_org OR organization_id IS NULL)` (so a NULL-org insert —
   every E7.1b `audit_log` row, an admin `bms.users` row, an org-less channel/delivery — is not
   rejected by the policy). `bms.users` additionally keeps Amendment 4's `auth_bootstrap_read` SELECT
   policy for `bms_auth`.
3. `ALTER TABLE … FORCE ROW LEVEL SECURITY` on the full set (incl. `bms.users`, `audit_log`, and the
   two nullable notification tables).
4. **Amendment 4 auth swap:** `CREATE POLICY auth_bootstrap_read ON bms.users FOR SELECT TO bms_auth
   USING (true)` (exact 0040 shape); then `DROP POLICY auth_bootstrap_read ON bms.locations` and
   `ON bms.user_organization_access` (0040:54-60), and `REVOKE SELECT ON
   bms.user_organization_access, bms.user_location_access, bms.locations FROM bms_auth`
   (0039:122-124). Discharges Amendment 1's standing instruction; if it lands without the removal the
   least-privilege claim is false and the review must say so.
5. **Audit actor-resolution must survive the `bms.users` policy (found in the asset-points unit).**
   `MasterDataAuditService.write` resolves `actorId` by reading `bms.users` on the bare tenant pool.
   The audit-**outside**-`withTenant` services (assets, rtus, point-keys) run that read with **no**
   `current_org`, so under the NULL-tolerant `users` policy they see only NULL-org users — and a
   scoped actor's `users.organization_id` is non-NULL after the 0046 backfill, so `actorId` silently
   resolves to NULL (the audit row loses its actor; the write itself still succeeds). The
   audit-**inside**-GUC service (`AssetPointCalcOverrideService`) is unaffected: its `current_org`
   equals the actor's org, so the user is visible. Fix at 0047 time, not before: point the audit
   actor-resolution read at `bms_auth`/`bms_fleet` (a pre-tenant identity read, Amendment 4 territory),
   **or** run every audit write inside the tenant GUC. Ties into the E7.1c audit rework; until 0047
   lands there is no policy and no regression.

Test first: extend `access-control-rls.integration.spec.ts` + a new Amendment-4 spec — the global
`admin` row carries NULL `organization_id`, is invisible under `bms_tenant`, visible under
`bms_fleet`, and login still succeeds via `bms_auth`; a `wc-admin`-shaped user resolves to the
Western Cape org; a non-`admin` user with no resolvable home aborts. Plus a decision-10 spec: two
sequential requests for different orgs on the same pooled connection see different rows (extend
`tenant-context.integration.spec.ts`).

### Task 5 — Multi-org fallback test + vacuous-test hardening

- **Multi-org fallback (Amendment 3 ruling 3).** No actor holds >1 org today, so **create** a

  test prefixes, one snapshot). Assert a two-org actor on a `withTenant`-classified path resolves to

- **Harden vacuous suites.** `assertOrganizationAdminStillIsolatedUnderRealRls`
