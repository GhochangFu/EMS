# F4.264 — the OpenRouter model for the copilot's mimic builder: research (2026-10-17)

*Input to `F4.264`, raised by the owner after the `F3.87` live check: ESKOM's
key ran `z-ai/glm-5.3`, which takes no image input, so an attached drawing
answered the "could not read the attached file" reply (plan D5). Base: `main`
at `f6a9df19`. Evidence: OpenRouter's model list on 2026-10-17, public
benchmarks, and 71 live copilot turns on the local stack with ESKOM's own
OpenRouter key.*

## Summary

- **Owner decision (2026-10-17): open-weight models only, and two of them**
  ("Path B"). The copilot keeps `z-ai/glm-5.3` for its tool work; a turn that
  carries an image goes to **`nvidia/nemotron-3.5-super-vl`** on the same key.
  One setting holds one model today, so this needs row `F4.267`
  ([ADR 0090 Amendment 3](./adr/0090-onboarding-agent-tool-calling-loop.md#amendment-3--a-vision-model-for-turns-that-carry-an-image-f4267-2026-10-17)).
- **Nemotron** drew both test plants correctly in **12 of 12 image turns**
  (17–24 s on average, about $0.008 a turn) but **0 of 3 PDF turns** (its
  first reply took 44 s of the 45 s deadline), so a PDF stays on the main
  model as parsed text (Amendment 3, ruling 6). `z-ai/glm-5.3-flash` was the
  runner-up: 11 of 13 image turns (one earlier turn hit the deadline), 2 of 3
  PDF turns.
- The paid models were measured first and are kept as reference:
  `anthropic/claude-haiku-5.5` was as correct as Nemotron, faster (13 s) and
  about the same price; `anthropic/claude-sonnet-5.5` and
  `google/gemini-4-argon` were as correct at 10–20 times the cost.
- **A successful image turn is now verified live** (the gap `F3.87` step 6
  left): an attached PNG became a `mimicLayout.create` card with 5 of 5 units,
  5 of 5 symbols, 4 of 4 pipes, in the drawing's order.
- **No model succeeds unaided today.** Without a hint in the message, every
  vision model spent the turn's 8 tool calls discovering the layout shape
  (`list_*`, then `describe_change`, whose budget is 3) and stopped at the cap
  with no card. This is a copilot limit, not a model limit — follow-up
  `F4.266`.
- **Every OpenAI model fails every copilot turn** since `F3.87` PR 6b (#875):
  OpenAI refuses the tool list because `propose_mimicLibrary_create` carries
  the JSON Schema pattern `^[^\p{Cc}]*$`, which its validator does not accept
  (`invalid_function_parameters`). This also hits an organization whose
  provider is `openai` directly — follow-up `F4.265`.

## 1. What the job needs

| Need | Why | Source |
|---|---|---|
| Image input (`image_url` part) | the turn sends PNG/JPEG/WebP as native parts | `openai-provider.ts` (ADR 0099 Amendment 3 A5) |
| PDF input | a PDF goes as a `file` part; OpenRouter passes it to a model with native file input, else parses it (`mistral-ocr` by default, $2 per 1,000 pages) | [OpenRouter PDF docs](https://openrouter.ai/docs/features/multimodal/pdfs) |
| Reliable tool calls | 66 tools on a global-admin turn, at most 8 calls, 45 s per turn | `agent-loop.ts` |
| A body inside the schema | the layout body is strict (`mimic-layout-writes.ts`); a refusal costs a call | `copilot-propose-tools.ts` |
| A large prompt, cheaply | the tool definitions alone are about 22,000 prompt tokens per round; a turn runs 2–4 rounds | trace below |

## 3. Live test

**Set-up.** API built from `main` (`f6a9df19`), local `AUTH_MODE`, as
`admin@bms.local`, on ESKOM with the owner's OpenRouter key and attachments on.
The model was switched in `bms.organization_llm_settings` between turns. Each
turn sent one PNG — a five-unit line `TK-101 → P-101 → V-101 → F-101 → TK-102`
(tank, pump, valve, sand filter, tank) — and asked for a new layout card. A
preload logged each request's tool results, each reply's tool calls and
OpenRouter's `usage` (never the client options). Score: units found by tag,
core symbol per unit, pipes in the flow direction, left-to-right order.

**Round 1 — the plain request** ("Draw the attached plant diagram as a new
mimic layout … Propose the card."):

| Model | Result | Calls | Stop |
|---|---|---|---|
| Sonnet 5.5 (×2) | no card | 8 | `cap_calls` |
| Haiku 5.5 (×2) | no card | 8 | `cap_calls` |
| Gemini 3.8 Flash | no card | 8 | `cap_calls` |
| GLM-5.3 Flash | no card | 8 | `cap_calls` |
| GPT-6.1 Sol, GPT-6 Luna (3 turns) | HTTP 400 before any call | 0 | `provider_error` |

Sonnet read the drawing right on its first round (its text: five units in a
line, pipes in order) and then spent its calls on `list_asset_roles`,
`list_mimic_symbols`, `list_mimic_layouts`, `get_mimic_layout` and
`describe_change`. The fourth `describe_change` (the `symbol` union) was
refused by the budget of 3, so its proposal left the filter without a symbol,
and the 8th call was that proposal — no call was left to correct it.

**Round 2 — the same request plus a hint** that names what discovery would
find: no list tool or `describe_change`, core symbols `tank`/`pump`/`valve`/
`filter`, `symbolLibraries ["core"]`, a 160 × 40 canvas, units 20 × 25, keys
in lower case with underscores, no `roleCode`.

| Model | Card | Score | Time | Cost of the first turn (OpenRouter `usage`) |
|---|---|---|---|---|
| Haiku 5.5 (3 turns) | ✅ ✅ ✅ | 5/5 units, 5/5 symbols, 4/4 pipes, L→R | 12.0–13.8 s | $0.008 |
| Sonnet 5.5 (2 turns) | ✅ ✅ | same | 18.3–19.3 s | $0.160 |
| Gemini 4 Argon (2 turns) | ✅ ✅ | same | 21.1–28.4 s | $0.082 |
| Gemini 3.8 Flash | — | — | 45 s | `cap_time` (5,807 output tokens of reasoning) |
| GLM-5.3 Flash | — | — | 45 s | `cap_time` |
| Qwen 3.8 Omni Flash | — | — | 45 s | `cap_time`, no call |

Every model's first proposal wrote pipes as `{from, to}`; the refusal
("`pipes.0.fromKey: Required`") corrected it on the second call. The field
list in the tool definition names `pipes` but not its keys.

## 6. Decision

1. **Main model: `z-ai/glm-5.3`** — unchanged, for every turn without an image.
2. **Vision model: `nvidia/nemotron-3.5-super-vl`** — for a turn that carries
   an image (owner ruling; GLM-5.3-Flash was the recommendation, because it
   also reads a PDF). Built as `F4.267`, which also carries `F4.266`'s fix.
3. Until `F4.267` merges, ESKOM stays on `z-ai/glm-5.3`, and an image turn
   answers the D5 reply.
4. The AWS demo (`bms.demosites.co.in`) keeps its own setting; the owner
   enters the models in the AI assistant settings there.
