## 1. Goal

Implement ADR 0063 decisions 2–13: `bullmq` 5.x in `apps/api`; a typed queue registry in `apps/api/src/queue/` (`defineQueue`, `enqueue` refusing a missing `jobId` and a `tenant` payload without `organizationId`, processors registered against the same declaration and run inside `withTenant` or as `bms_fleet`, key prefix `bms`, retry defaults `3 / exponential 1 s / 1000 / 5000`); a second entrypoint `apps/api/src/worker.ts` → `dist/worker.js` whose `WorkerModule` reaches none of the six `onModuleInit` loop sites; the API booting without `REDIS_URL` with the queue reporting `unconfigured` and `enqueue` rejecting `QueueUnavailableError`, and the worker refusing to start without it; one `heartbeat` repeatable job every 60 s reported on `GET /health` of both processes (three ticks stale = degraded); `bms_queue_depth{queue,state}` and `bms_queue_jobs_total{queue,outcome}` on the existing registry; Redis with AOF, `noeviction` and a `redis-data` volume; a `worker` compose service in `core`/`pilot`/`phe` on `WORKER_PORT` 4100; `pnpm --filter api worker`; a pinned Redis service in CI with the queue integration spec as a gate.

No schema change, no migration, one new npm package. No `apps/web` change.

**Out of scope, deliberately.** Moving any of the three sweeps into the worker (`F4.128`); any queue other than `heartbeat` (`F3.11`, `F3.12`, the ADR 0041 dispatch follow-up); an in-memory queue stand-in (decision 9 forbids it); Bull Board or any queue UI; a `bms_ingest`-style dedicated role; consolidating the two Redis client libraries; the key-window boot refusal in the worker (the ADR defers it to the day the worker first decrypts); any `AGENTS.md`, `docs/AGENTS.production.md`, `docs/BACKLOG.md` or `docs/roadmap.md` edit — the separate `chore(agents):` sweep (§9.10, ADR 0063 Consequences). EMQX, Traefik, MinIO: not this ADR.

```ts

export type RedisConnectionOptions = { host: string; port: number; username?: string; password?: string; db?: number; tls?: Record<string, never> };
export class QueueConfigError extends Error { override readonly name = "QueueConfigError"; }
export function redisOptionsFromUrl(raw: string): RedisConnectionOptions;
export type QueueConfig = { readonly redis: RedisConnectionOptions | null };   // null = unconfigured
```

`readQueueConfig`: `REDIS_URL` unset or whitespace → `{ redis: null }` (the adapter's rule); else parse. `redisOptionsFromUrl`: `new URL()`; scheme must be `redis:` or `rediss:` (`rediss` → `tls: {}`); host required; port default 6379; `username`/`password` from the URL's credentials when non-empty; `db` from a `/N` path (digits only). **Any failure throws `QueueConfigError("REDIS_URL is not a valid redis:// or rediss:// URL")` with the value never in the message** — a Redis URL can carry a password (§9.6). `readWorkerConfig`: `readQueueConfig` first; `redis === null` → `QueueConfigError("REDIS_URL is required for the worker process (ADR 0063 decision 9)")`; `WORKER_PORT` parsed like the ingest's `positiveInt` — digits only, `1..65535`, unset/blank → 4100, otherwise throw naming `WORKER_PORT` and the value (a port is not a secret).

## 6. Unit 2 — the typed registry, `enqueue`, and the tenancy-bound processor (decisions 4, 5, 6, 7) — Fable

**Files.** Create `apps/api/src/queue/queue-registry.ts`, `.spec.ts`, `.test.ts`; `queue-processor.ts`, `.spec.ts`, `.test.ts`; `queue-processor.integration.spec.ts`, `.integration.test.ts`; `queues.ts` (the one registry list — Unit 3 fills it).

**Public surface — the seam. Transcribe exactly.**

```ts
export type QueueTenancy = "tenant" | "fleet";
export type TenantPayload = { readonly organizationId: string };
export type RetryPolicy = { readonly attempts: number; readonly backoffMs: number; readonly removeOnComplete: number; readonly removeOnFail: number };
export const RETRY_DEFAULTS: RetryPolicy = { attempts: 3, backoffMs: 1_000, removeOnComplete: 1_000, removeOnFail: 5_000 };
export type QueueDeclaration<Name extends string = string, Payload extends object = object, Tenancy extends QueueTenancy = QueueTenancy> = {
  readonly name: Name; readonly tenancy: Tenancy; readonly retry: RetryPolicy; readonly _payload?: Payload; // phantom
};
export function defineQueue<Name extends string, Payload extends TenantPayload>(d: { name: Name; tenancy: "tenant"; retry?: Partial<RetryPolicy> }): QueueDeclaration<Name, Payload, "tenant">;
export function defineQueue<Name extends string, Payload extends object>(d: { name: Name; tenancy: "fleet"; retry?: Partial<RetryPolicy> }): QueueDeclaration<Name, Payload, "fleet">;
export type PayloadOf<D> = D extends QueueDeclaration<string, infer P, QueueTenancy> ? P : never;

export class QueueUnavailableError extends Error { override readonly name = "QueueUnavailableError"; }
export class QueuePayloadError extends Error {
  override readonly name = "QueuePayloadError";
  constructor(readonly reason: "missing_job_id" | "missing_organization_id" | "unknown_queue", queueName: string);
}

/** The subset of a BullMQ `Queue` the registry uses — small on purpose, so a fake is five lines. */
export type QueueHandle = Pick<Queue, "add" | "upsertJobScheduler" | "getJobCounts" | "client" | "close" | "on">;
export type QueueClient =
  | { readonly kind: "unconfigured" }
  | { readonly kind: "configured"; readonly prefix: string; readonly queues: ReadonlyMap<string, QueueHandle>; close(): Promise<void> };
export function createQueueClient(
  config: QueueConfig, declarations: readonly QueueDeclaration[],
  deps: { createQueue: (name: string, opts: { connection: RedisConnectionOptions; prefix: string }) => QueueHandle; logger: Pick<Logger, "warn">; prefix?: string },
): QueueClient;
export async function enqueue<D extends QueueDeclaration>(client: QueueClient, decl: D, payload: PayloadOf<D>, opts: { jobId: string }): Promise<void>;
export async function upsertSchedule<D extends QueueDeclaration>(client: QueueClient, decl: D, schedule: { schedulerId: string; everyMs: number }, payload: PayloadOf<D>): Promise<void>;
```

`defineQueue` merges `retry` over `RETRY_DEFAULTS` so a declaration always carries a resolved policy. `createQueueClient` with `redis === null` returns `{ kind: "unconfigured" }` after one `logger.warn("REDIS_URL missing; job queue unconfigured — enqueue will reject (ADR 0063 decision 9)")`; otherwise one `createQueue(decl.name, { connection, prefix })` per declaration, **and attaches `on("error", …)` → `logger.warn` on each** (fact: an unhandled `error` event kills the process). `prefix` defaults to `QUEUE_KEY_PREFIX`; the parameter exists so the integration spec can isolate its keys from the running stack.

`enqueue`, guards **in this order** and each throws before any Redis call: `jobId` not a non-empty string → `QueuePayloadError("missing_job_id")`; `decl.tenancy === "tenant"` and `payload.organizationId` not a non-empty string → `QueuePayloadError("missing_organization_id")`; `client.kind === "unconfigured"` → `QueueUnavailableError`; queue not in the map → `QueuePayloadError("unknown_queue")`. Then `queue.add(decl.name, payload, { jobId, attempts, backoff: { type: "exponential", delay: backoffMs }, removeOnComplete: { count }, removeOnFail: { count } })`. A programming error is refused whether or not Redis exists, which is why the payload guards precede availability. `upsertSchedule` applies the same tenancy and availability guards, then `queue.upsertJobScheduler(schedulerId, { every: everyMs }, { name: decl.name, data: payload, opts: <same retry opts> })`.

`queue-processor.ts`:

```ts
export type ProcessorDbs = { readonly tenantDb: BmsDb; readonly fleetDb: BmsDb };
export type ProcessorContext<T extends QueueTenancy> = T extends "tenant" ? { readonly tx: BmsTx } : { readonly db: BmsDb };
export type ProcessorHandler<D extends QueueDeclaration> = (payload: PayloadOf<D>, ctx: ProcessorContext<D["tenancy"]>) => Promise<void>;
export type ProcessorRegistration = { readonly decl: QueueDeclaration; readonly process: (job: { readonly data: unknown }) => Promise<void> };
export function runProcessor<D extends QueueDeclaration>(decl: D, dbs: ProcessorDbs, handler: ProcessorHandler<D>, deps: { withTenant?: typeof withTenant } = {}): ProcessorRegistration;
```

`tenant`: re-check `organizationId` (a job can be added by a producer that is not this registry — `redis-cli`, a future service — and decision 6's first sentence is "never sees", so the check lives at the processor too; a refusal throws `QueuePayloadError("missing_organization_id")` and the job fails, counted under `outcome=failed`), then `withTenant(dbs.tenantDb, organizationId, (tx) => handler(data, { tx }))`. `fleet`: `handler(data, { db: dbs.fleetDb })`. The `withTenant` injection exists only so the unit spec can observe the call; the integration spec below is what proves the real GUC binds.

1. **HTTP status when `status: "degraded"`.** Recommend **200 with the body status**: `/health` is documented as a liveness probe, and `metrics.service.ts:81-84` already refuses to let a dead listener make an orchestrator restart a process that serves traffic; a dead worker is the same case. 2. **`heartbeatStale` is one field beyond the ADR's list** (`configured`, `connected`, per-queue depths, `lastHeartbeatAt`). Recommend keeping it: without it a reader must know the 180 s rule to explain `degraded`, and a status with no reason field is the "one error class, many guards" shape. Strike it and the plan drops one schema line and one `it()`.
3. **A `bms-worker` scrape target in `infra/observability/prometheus.yml`** — a plan addition. Without it `bms_queue_jobs_total` (incremented in the worker's registry) reaches no Grafana panel. Recommend keeping it.
4. **Decision 3's spec cannot be written as the ADR describes it** — no Nest module boots under vitest here (§4.6, `F4.20`). The plan substitutes a static import-closure invariant with a positive control (Unit 4) and a runtime `pg_stat_activity` measurement (§12 step 4). 5. **A fresh Redis with the worker never run:** `lastHeartbeatAt: null` while `configured && connected`. Recommend it reads `heartbeatStale: true` → `degraded` — a queue with no consumer is the condition Q4 exists to make visible.
6. **The manifest commit** stages a one-line pin note in ADR 0063's Dependencies to satisfy the pre-commit gate. The alternative is the owner committing the manifest by hand. Recommend the former.
7. **BullMQ 5.81 lists node-redis as an optional peer.** ADR 0063 Context 6 says BullMQ "accepts no other client" and accepts two client libraries on that basis. The plan does not act on this — replacing the client is a decision — but the closure note should record the fact, and a follow-up row could consolidate on `redis` if it is worth the risk. No answer needed now.
8. **The worker serves `/metrics` on `WORKER_PORT`** via `ObservabilityModule`, with `bms_api_process_*` default-metric names and `bms_api_service_info{service="api"}` inherited from `MetricsService`'s constructor. Recommend leaving the wart and naming it in the closure note; renaming touches every dashboard.
