## 1. Goal

A platform catalog, `bms.mqtt_payload_formats`, names how an MQTT message is
decoded. Each MQTT RTU names one format in its connection config
(`payloadFormat`); an RTU with none uses the built-in `thinkiot-envelope`, whose
decoder **is** `parseMqttEnvelope`, unchanged, so every PHE RTU behaves exactly
as today. One Zod schema and one pure decoder, `decodeMqttPayload`, in
`@bms/shared` serve the ingest adapter, the discovery collector, the API's test
route and the web test box. Discovery tries every catalog format, records which
one decoded each device, stores it on the draft RTU, and — closing `F4.335` —
says how many messages arrived and were not decoded instead of "No device
published". A global admin manages the catalog on a **Payload formats** page
with a test box; writes are audited; a format in use cannot be deleted; a
definition edit reaches running ingest endpoints at the next reload through the
ADR 0115 supervisor replacement. The build seeds the BCPL format
`thinkiot-register-array` (two readings: `treated_water_flow_klh` = float32 BE at
`Data[0..1]`, `outlet_flow_totalizer_kl` = float32 BE at `Data[3..4]`).

**Out of scope.** Binary or hex Modbus frames (ADR 0116 Consequences); any
expression, script or regular expression in a definition; the meaning of
`Data[6..7]`, `Data[9]` and the constants 81/113/177 (waits for ThinkIoT, §9
Q13); the BCPL commit itself and the LALMATI code correction (the owner commits,
§5 "AWS checks"); the password rotation; per-reading `eng_min`/`eng_max` (the
point's own stay); a credential change on a running endpoint (ADR 0115 R5 stays
restart-only — only the *format* fingerprint is added, §3 R8); AGENTS.md (ADR
0116: nothing moves).

## 3. Drafter refinements (ADR 0116 lines marked *(drafter)*)

- **R1 (decision 1, RLS/grants).** Follow `0085`: table under `SET ROLE
  bms_owner`; `REVOKE INSERT, UPDATE, DELETE FROM bms_tenant`; no RLS, no
  policy; proof block for `bms_tenant` SELECT-only and `bms_fleet` SELECT +
  write (the API writes on `fleetDb`). (Q1)
- **R2 (decision 2, the built-in row's `definition`).** The column is `NOT
  NULL`, so the built-in row stores `{ "kind": "builtin", "name":
  "thinkiot-envelope" }`; the definition schema is a discriminated union on
  `kind` (`builtin` | `declarative`); `POST`/`PUT` refuse `kind: "builtin"`.
  `decodeMqttPayload` dispatches `builtin` to `parseMqttEnvelope`, wrapped as
  one record. (Q2)
- **R3 (decision 3, caps and names).** Array root cap **64** records per
  message; **128** readings per format; a field path is a **list of segments**
  (string ≤ 64 chars or non-negative integer), 1–8 segments, with `__proto__`,
  `constructor` and `prototype` refused — no dotted-string parser, no regex.
  The register start is **`index`** (not `offset`), so `scale`/`offset` keep
  the affine meaning. Reading value `null` → the adapter's `empty` path; key
  omitted → `missing`: a path that is absent omits the key, a register array
  too short or a NaN/±Infinity result yields `null`. (Q3, Q14)
- **R4 (decision 4, conflict).** Skip reason **`payload-format-conflict`**
  (detail: the topic) when a second RTU on the same `(endpoint, topic)` names a
  different code; plus **`payload-format-unknown`** (the code has no catalog
  row — LEFT JOIN null) and **`payload-format-invalid`** (the row fails the
  shared schema). All three listed in `docs/ingest-host.md`. (Q7)
- **R5 (decision 5, reads).** `GET` list and `GET :code` →
  `requireMasterDataUser` (the drawer's select is used by an
  `organization_admin`); `POST`, `PUT`, `DELETE`, `POST …/test` →
  `assertAdminRole`. (Q4)
- **R6 (decision 5, DELETE 409).** Body `{ message, rtus: n, drafts: m }`,
  counts only, no codes, no organizations. `rtus` counts
  `rtu_connection_configs WHERE config->>'payloadFormat' = $1` on `fleetDb`;
  `drafts` counts `onboarding_sessions WHERE status = 'draft' AND
  jsonb_path_exists(draft, '$.rtus[*].config.payloadFormat ? (@ == $code)', …)`.
  (Q5)
- **R7 (decision 7/9, seeding).** Migration `0130` seeds **both** rows:
  `thinkiot-envelope` (`builtin = true`) and `thinkiot-register-array`
  (`builtin = false`, editable), `ON CONFLICT DO NOTHING` so a later admin edit
  is never reverted. No AWS manual step. (Q6)
- **R8 (decision 6, reload).** `EndpointPlan` gains `decoderFingerprint`
  (sha256 of the sorted `topic → code → definition JSON`); `diffEndpoints`
  takes `running: ReadonlyMap<string, { devices, fingerprint }>` and emits
  `replace` with `reason: "payload-format-changed"` when only the fingerprint
  differs. Credentials stay unfingerprinted (ADR 0115 R5 unchanged). (Q8)
- **R9 (decision 4, "admin RTU routes accept it").** No admin route writes
  connection config today, so: `adminRtuDtoSchema.payloadFormat: z.string()
  .nullable()` (read from the join both producers already have) and one new
  route `PUT /api/v1/admin/rtus/:id/payload-format` body `{ payloadFormat:
  string | null }`, same authorization as the RTU `PATCH`, audit
  `master.rtu.payload_format.update`. (Q9)
- **R10 (decision 4, validator).** `OnboardingValidateService.validate` gains
  an optional `knownPayloadFormats: ReadonlySet<string>`; the validate route and
  the commit service load the codes (one `SELECT code`) and pass them; a call
  without the set that meets a `payloadFormat` records the fixed error
  `MQTT_PAYLOAD_FORMAT_UNKNOWN_MESSAGE` (fail closed; the 89 bare constructions
  keep compiling). (Q10)
- **R11 (decision 8, contracts).** `onboardingDiscoveryDeviceSchema.payloadFormat`
  is **optional** (stored results from before keep parsing); the DTO gains
  `messages`, `skipped` and `skippedReasons` (`discoveryDtoOf` strips only
  `queuedAt`); `onboardingDiscoverySkipReasonSchema = z.enum(["oversize",
  "unusable-topic", "no-format", "unusable-device-key"])`. One pure function
  `discoveryEmptySentence(dto)` in the same contract file serves the drawer and
  the copilot tool: `"<n> messages arrived but none matched a known payload
  format."` when every skip is `no-format`, `"<n> messages arrived and were not
  decoded."` otherwise, `"No device published in the window."` when nothing
  arrived. (Q11)
- **R12 (decision 5, the page).** Plain `surface-dialog` forms, **no
  `WizardShell`** (so no copilot catalog entry is owed, the F4.310 precedent);
  the definition is edited as JSON in a textarea and checked client-side with
  the shared schema, issues listed by path. (Q12)
- **R13 (decision 3, topic as device key).** With no `deviceKey` path the topic
  is the key, so the RTU code must equal the topic string. The builder checks
  `apps/api/src/admin/catalog-code-charset.ts` admits `/`; if it does not, this
  release documents the limit in `docs/ingest-host.md` and the page's help
  text rather than widening the charset. (Q2)

**T1.2 — the decoder (pure).** Same file: `decodeMqttPayload(definition,
topic, raw): DecodeResult` where `DecodeResult = { ok: true; records:
DecodedRecord[] } | { ok: false; reason: "not-json" | "root-mismatch" |
"no-device-key" | "too-many-records" }` and `DecodedRecord = { deviceKey:
string; at?: Date; values: Record<string, unknown> }`. Registers are read as
16-bit words (`value & 0xffff`) into a `DataView`, bytes per word by
`byteOrder`, words per value by `wordOrder`; `int16`/`uint16` one word,
`int32`/`uint32`/`float32` two, `float64` four. Spec claims, in this order:
1. **BCPL golden:** the sample from §2 with the `thinkiot-register-array`
   definition → one record, `deviceKey === "BCPL_LAKWA_02"`, `at.toISOString()
   === "2026-11-07T18:59:46.000Z"`, `values.treated_water_flow_klh ===
   1.2999999523162842`, `values.outlet_flow_totalizer_kl === 46627.9453125`,
   no other key.
2. **Word order twin:** the same with `wordOrder: "little"` →
   `2.718295993743181e+23` and `2.626785157928289e-17` (the mutation that drops
   the swap reddens 1 and 2 together).
3. **Signed word:** a definition reading `Data[7]` as `int16` → `-17809`, as
   `uint16` → `47727`.
4. **PHE golden:** `{ dev_id: "PHE-1", ts: 1700000000000, values: { a: 1 },
   rssi: -70 }` with the builtin definition → one record `{ deviceKey: "PHE-1",
   values: { a: 1, rssi: -70 }, at }` — byte-equal to `parseMqttEnvelope`'s
   output (the spec calls both and `toEqual`s them).
5. Short array → `values.outlet_flow_totalizer_kl === null`; a reading whose
   path is absent → key omitted; NaN float → `null`.
6. `time` `epoch_ms` and `iso8601` paths; `"abc"` → `at` absent; a numeric
   string is accepted.
7. No `deviceKey` path → `deviceKey === topic`; empty string at the path →
   `no-device-key`.
8. `root: array` on an object → `root-mismatch`; 65 elements →
   `too-many-records`; invalid JSON → `not-json`; the decoder never throws
   (`expect(() => …).not.toThrow()` over a fuzz list of 20 malformed inputs).
9. `scale`/`offset`: `scale: 0.001, offset: 5` on `Data[0..1]` → `1.3e-3 + 5`
