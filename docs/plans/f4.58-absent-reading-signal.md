## 0. The contract decision

**This plan does not change the `IngestAdapter` contract.** No field moves on `SourceSample`, `AdapterHealth`, `AdapterContext`, `RtuBinding`, `emit`, `health()` or `IngestAdapterFactory` (`apps/ingest/src/adapter/types.ts`, `packages/shared/src/ingest.ts`). No ADR 0016 amendment is owed under Q0(a).

- **(a)** lives in the adapter. `samplesFromPayload` classifies every bound key that yields no sample, and `handleMessage` reports it through `context.logger.warn` — the channel ADR 0016 §5 rule 9 names ("Reject, or log through `context.logger` with a reason"). Rules 7 ("drop and count") and 9 ("never swallow silently") already make the bare `continue` at `mqtt.ts:224-230` a contract violation; this is the repair. **The line is a sibling of `samples discarded`, not folded into it**: `samples discarded` is built from `resolveSamples`'s `SampleCounters` at the write path (`main.ts:213-222`), which an absent reading never reaches. The adapter's logger is `logger.child({ endpointKey, protocol })` (`main.ts:205`), so both lines carry the same routing fields.
- **(b)** lives in the host. `accept()` in `supervisor.ts` sees every sample's `deviceKey` and `sourceKey`; `plan.bindings[].sourceKeys` is the bound set. Per-point last-seen is derivable there with no adapter change.

**What stays indistinguishable.** The health endpoint's `dark` line cannot say whether a dark key was *published empty* (dead meter) or *never published* (wrong mapping): the host never sees the payload. That distinction lives only in the adapter's log line (`empty=` vs `missing=`). Named in `docs/ingest-host.md` (unit 4).

**Precedent.** `1e33ca35` (F1.7, #133) added `staleDevices`, `stale=`, the `stale rtu=` lines and `INGEST_STALE_AFTER_MS` with no ADR text on the health body (documented in `docs/ingest-host.md`, `docs/env-inventory.md` only). ADR 0016 §Dependencies: "The existing plain-text health endpoint is extended with per-RTU state", no shape named.

## 1. Goal and out of scope

**Goal.** A bound `source_data_key` that yields no reading stops being invisible. The MQTT adapter logs, per message, how many bound keys were published empty (`null`, `""`, non-numeric) and how many were not published at all, naming the first of each. The host tracks last-seen per `(deviceKey, sourceKey)`, and the health endpoint prints `dark=<n>` on the header and one `dark rtu=… key=…` line per bound point silent longer than `INGEST_STALE_AFTER_MS` on an RTU that is itself not stale, capped, with the same boot grace as `stale`.

**Out of scope.** Alarms and `prom-client` (F3.16). Any change to `SampleCounters`, `droppedCount` or the `samples discarded` line. The API surface for device health (F3.16). Network exposure of the health port (F4.61). A new env var. `packages/db`, `apps/web`, `apps/api`.

**Measurements the fixtures mirror.** Salkumarhat I/II: 21 bound keys, 5 land, 16 `empty`, 0 `missing` (`docs/f1.7-fleet-probe.md:98-101`). Bhutnirghat II: 21 bound, 20 land, 1 `empty` (`s12_r01` → `kwh_total`; `s12_r02` dark but unmapped). Cadence ~60 s; at the default 300 000 ms window a dark point appears five missed cycles after boot. None of the three is in `packages/db/src/ingest-enabled-set.ts`, so the running stack shows `dark=0` today.

## 2. Units, in build order (serial, one worktree, one PR)

### Unit 1 — the adapter classifies and reports absent keys ((a)) — Opus

**Files:** `apps/ingest/src/adapters/mqtt.ts`, `mqtt.spec.ts`, `mqtt.test.ts`.

**Tests first** (`runAbsentReadingTests()`, own `it()`), one claim per block:
1. `samplesFromPayload({ devId, values: { flow: 1.5, empty: "", nul: null, text: "abc", zero: 0 } }, ["flow","empty","nul","text","zero","absent"])` → `samples` = `flow`, `zero`; `absent.empty` = `["empty","nul","text"]` in binding order; `absent.missing` = `["absent"]`.
2. `undefined` classifies as `missing`.
3. `absent.*` order follows `sourceKeys` (stable `firstEmpty`).
4. Fake broker, 21 bound keys, 16 `""`: exactly one `warn("readings absent", { rtuCode, deviceKey, empty: 16, missing: 0, firstEmpty: "s01_r01" })` (`firstMissing` omitted when 0), **and** the 5 present samples reach the sink.
5. All bound keys present → no `readings absent` line.
6. All bound keys absent → the line, nothing emitted, `health().lastSampleAt` undefined.
7. In `runTopicAttributionTests`: a payload rejected for topic binding logs no `readings absent` line.
8. The line carries ids and counts only, never a value (§9.6).

**Change:** `samplesFromPayload` returns `{ samples; absent: AbsentReadings }` with `AbsentReadings = { empty: readonly string[]; missing: readonly string[] }`; `raw === undefined` → `missing`; `null`/`""`/non-finite → `empty`. `sourceKeysByDevice` → `bindingByDevice: Map<string, { rtuCode; sourceKeys }>`. `handleMessage`: after the topic guard, log if any absent, then the existing `if (samples.length === 0) return;`.

**Blast radius:** `mqtt.ts:325`; `mqtt.spec.ts:184, 205, 225, 248`.

**Mutations:** fold `missing` into `empty` (block 1); delete the warn (block 4); log unconditionally (block 5); log above the topic guard (block 7).

### Unit 3 — the health body prints dark points ((b), surface) — Sonnet

**Files:** `apps/ingest/src/host/health-server.ts`, `health-server.spec.ts`, `health-server.test.ts`.

**Format.** Header gains `dark=<n>` after `stale=<n>`. After the `stale rtu=` lines, before `skipped`: `dark rtu=<rtuCode> endpoint=<endpointKey> key=<sourceKey> lastSample=<iso|never>[ silentFor=<n>s]` — same clock rule as `stale` (`max(lastSampleAt, startedAt)`, strictly greater than `staleAfterMs`). At most `MAX_DARK_LINES = 50`, then `dark omitted=<k>`; header `dark=` is the true total. Points on a stale RTU are neither listed nor counted. `dark>0` does not change the verdict (Q3).

**Tests first** (`runDarkPointTests()`, own `it()`): one dark of two points; `never`; boundary not dark; boot grace; stale RTU suppresses; verdict stays `ok`; cap + trailer (`dark=51`); two endpoints sum.

**Mutations:** `>` → `>=`; drop stale suppression; drop the cap; measure from `lastSampleAt` alone.
