## 0. Goal, and what is out

**Goal.** An organization admin draws a plant on `/admin/mimic-layouts` — units with a closed symbol, a panel, a label, pipes between units — and stores it as one `bms.mimic_layouts` row with its nodes and pipes. A dashboard author picks `{ source: "layout", layoutId }` as a second `mimic` config arm beside the unchanged `{ source: "preset", preset }`. The resolver (`GET /dashboards/:id/mimic-nodes`) answers a layout widget with its geometry plus every roled unit resolved exactly as a preset node. Save replaces the whole layout in one transaction with an optimistic `version` (409 when stale). `DELETE` answers 409 while a dashboard widget refers to the layout. Templates accept the preset arm only. Editor: place, move, resize, delete, name, bind a role, tint a panel, draw a pipe, undo/redo, keyboard, hand-built pointer drag.

**Out (ADR 0081 decision 10).** Network mimics, free shapes/lines, per-unit colours, KPI overlays, layouts in templates, cross-organization sharing, SMOC pages on a mimic, a data migration of the preset, any `AGENTS.md` §6 change, any seed row for a layout (the demo uses "Start from Water train").

## 11. Addendum — what the build added beyond this plan (2026-09-29)

- The editor reducer has an `update-layout` action for the layout's name, slug and canvas size; it refuses a canvas out of bounds and a shrink that leaves a node outside.
- Migration `0088` adds a second pipe index, `mimic_layout_pipes_to_idx (layout_id, to_node_id)`, for the to-end cascade on every save.
- The layout delete locks the layout row before it counts the widgets, and the dashboard widget guard takes `FOR KEY SHARE` on the layouts it names, so a delete and a widget save cannot both commit.
- A stored `layoutId` is lowercase, and the delete compares it as a `uuid`.
- The stale-version sentence lives once, in `@bms/shared`, and the web and the API both import it.
