**Goal:** Ship ADR 0139 decision 18. (1) `GET /api/v1/dashboard/locations` names each location's readable parent, and the organization level shows site cards grouped under a parent header with a roll-up, a click that filters the site map, Live/Not live sections that hold groups, site counts that count a site once, and crumbs that name the parent (`F4.240` part a, decisions 12–17). (2) The PHE seed can split a station into one site per RTU: station → `campus`, one child site per RTU, a one-statement move, never back, a tariff copy once per move, site layouts, map rows, and a boot gate that counts the new shape (`F4.388`, decisions 1–11 and 4a). The split list is committed **empty**, so nothing moves on any database in release A. The legacy PHE cleanup retires and its zero count becomes a shape check (decision 8).

**Architecture:** No migration, no route, no permission, no package. One additive contract field. The API takes `parentId` from the caller's own scope (`withVisibleParents`, the one place that decision is made), so the dashboard read decides nothing itself. The web gets one pure "site" rule and one grouped-cards component. The seed gets a leaf file for the list, pure derivations beside the catalog seed, and one new module for the four database steps; every function that reads the list takes it as a parameter that defaults to the committed constant.

**Tech stack:** Zod contract in `packages/shared/src/contracts/` (ADR 0030), NestJS + raw `pg` (`apps/api/src/dashboard/`), React + TanStack Query (`apps/web`), Drizzle/`pg` seed (`packages/db/src`), Vitest (projects `shared`, `api`, `web`, `db`, `repo`).

## 3. Plan decisions (drafter lines the ADR lets the plan refine)

- **D1 — the list.** `packages/db/src/phe-split-stations.ts` holds only `export const PHE_SPLIT_STATION_CODES: readonly string[] = [];` and its docblock. It imports nothing, reads no environment, and is the one line releases B and C change. A code that is not a catalog `StationCode` throws before any write.
- **D2 — how a test runs the split path.** An injectable parameter, not a test-only seam: `seedPheCatalog(db, pool, options?)` with `options = { catalog?, splitStationCodes?, holderReader?, log? }`; `phePilotExpectedRows`, `hierarchyExpectations`, `seedPhewbSiteLayouts` and the map-row function take `splitStationCodes` with the default `PHE_SPLIT_STATION_CODES`. `catalog` lets a test seed a synthetic station whose first run is all inserts (the cold path). **Why it cannot leak:** production has two entry points, `seed.ts` `main` and `verify-hierarchy-cli.ts`; both pass no list and no catalog, so they read the committed constant; no code path reads a list from the environment, a file or the database. Task 4 adds a `tests/` invariant that holds exactly that (comment-stripped source, so docblock prose cannot satisfy it). A non-empty list with no `holderReader` throws.
- **D3 — site identity.** `pheRtuSites(catalog)` (pure, in `phe-pilot-seed.ts`) gives one entry per RTU: `name` = `RTUDisplayName`; `slug` = `stationSlug(RTUDisplayName)`; `code` = `PHE-<StationCode>-<SUFFIX>` with `SUFFIX` = the last whitespace-separated word of `RTUDisplayName`, upper-cased, `[A-Z0-9]+` only (it throws otherwise, and on a duplicate slug or code); coordinates from the RTU's first row; `meta.phe` = the station's block plus `edgeRtuId`. A site is adopted only by the triple (slug, `meta.phe.stationCode`, `meta.phe.edgeRtuId`) with `parent_id` = its station. `active` on insert and update follows the parent (the `updatePheStationLocation` rule).
- **D4 — the move, one statement** (params `[externalRtuIds int[], siteIds uuid[], organizationId]`). The final `SELECT` reads `r`, so an RTU with no wired asset still reports as moved:

```sql
WITH r AS (
  UPDATE bms.rtus AS t SET location_id = x.site_id
    FROM unnest($1::int[], $2::uuid[]) AS x(external_rtu_id, site_id)
   WHERE t.external_rtu_id = x.external_rtu_id AND t.organization_id = $3
     AND t.location_id IS DISTINCT FROM x.site_id
  RETURNING t.id, t.location_id, t.external_rtu_id
), a AS (
  UPDATE bms.assets AS a SET location_id = r.location_id FROM r WHERE a.rtu_id = r.id RETURNING a.id
)
SELECT r.external_rtu_id, r.location_id, (SELECT count(*)::int FROM a) AS assets FROM r
```

- **D5 — the target location of an RTU, in this order:** (1) its resolved site, when its station is on the list and the site was not skipped; (2) never back: the PHEWB location it sits at now, when that is not its station (amended by ruling A, 12.1: formerly only a child of its own station with the matching triple); (3) the station. The RTU upsert and the asset write use that target, and `site_name` is the target's `bms.locations.name` in cases 1 and 2 and the catalog `StationName` in case 3 (decision 11).
- **D6 — the tariff copy** runs once per site whose RTU is in D4's result of this run, and only when the site has no mapping of its own. Per station mapping: the meters of that mapping that now sit at the site; none → no copy; billing meter = the station's when it is at the site, else the lowest asset id. Matched by asset id. One log line per copy; no audit row.
- **D7 — the station's view.** The unlink (decision 7) runs in the same transaction as the move, and only for a station with at least one RTU in D4's result: "once" is the move, not a predicate that a later re-link would match again. `seedPhewbSiteLayouts` leaves a split station out of the copy, upgrade and smoc-move steps, adds the resolved sites, and for a split station with no view row inserts `kind 'generated'` (`ON CONFLICT (location_id) DO NOTHING`), so a cold start and the demo host end in the state Q5 ruled.
- **D8 — map rows.** `seedMapLocationRows` does not change. The site rows are inserted inside PHEWB bracket 1, after `seedPheCatalog`, with the existing `seedMapLocations`, and only for the sites it resolved, so a skipped site's slug never gets a row that would join a foreign location.
- **D9 — the gate.** `PhePilotExpectedRows` loses `legacyLocationSlugs` and gains `rtuSites` (all 12; in the throw-on-empty set) and `splitSites` (the listed stations' sites; **not** in that set, because it is empty in release A). New checks: split sites present by triple and parent; each split RTU at its site; each split asset at its site; `siteLayoutPheSlugs` = the 6 stations plus the split sites. The zero count becomes "PHEWB RTU-slug locations not shaped as a site" = 0. `verifyHierarchySeed` takes the seed's skipped sites and exempts exactly those (the ladder-skip shape); the CLI passes none.
- **D10 — `parentId` on the API.** `apps/api/src/dashboard/location-parent.ts` exports `parentIdByLocation(scope: AccessibleScope): Map<string, string | null>`; the controller hands it to `locationKpis` and `locationDashboard` as `parentIdByLocation`; the service writes `parentId: opts?.parentIdByLocation?.get(row.id) ?? null`. An absent map is `null` for every item (fail closed). No SQL changes.
- **D11 — the site rule on the web.** A KPI item is a site when `assetCount > 0` or no other item names it as `parentId` (`PIN_RULE` on the readable items). A site with a readable parent is filed under that parent; the rest are loose and render as today. A header is drawn only when it has a card. A group sits in Live when any of its sites is live (decision 15). The two headings read `Live sites (n)` and `Not live (n)` with n = the organization's live and not-live **sites**, equal to the organization card's chips; a group header's "x of y sites live" explains a not-live card inside the Live section. *(a refinement of decision 15 the owner sees at the skim)*
- **D12 — the header.** Text, exact: the parent's name, then `{live} of {total} sites live · {assets} assets · {alarms} alarms`. On the organization page it is a `<button>` (`aria-pressed` when it is the map's filter); a click sets the filter and calls `scrollIntoView?.({ block: "nearest" })` on the map card (jsdom has no `scrollIntoView`, hence `?.`). The page owns the filter (`rootId`, `onRootChange` props on `OrganizationSiteMap`), and the overview is keyed by organization so the filter does not survive a move to another organization.
