# F3.71 — a neumorphic surface style beside the flat one: step-3 plan

Plan by `plan-architect` (Fable), measured at `303331b8` (ADR 0085 on
`feat/F3.71-neumorphic-ui`, base `04a23f8c`). Scope: [ADR 0085](../adr/0085-neumorphic-surface-style.md).
The owner ruled the plan gate on 2026-09-29 (§0).

## Goal

Give `apps/web` a second, user-chosen surface style. Under
`data-surface="neumorphic"` (the default) every card, tile, header, sidebar,
dialog, button and tab is a `canvas`-coloured shape raised from or pressed into
the page by a pair of soft shadows composed only of the existing 41 role
tokens; under `data-surface="flat"` the same call sites render the shapes the
app has today. Call sites stop spelling surfaces as colour utilities and use a
semantic vocabulary defined once in `apps/web/src/index.css`. A header switch
beside Light / Dark writes `localStorage["bms.surface"]`, and the boot script
in `index.html` sets the attribute before first paint.

**Out of scope** (ADR 0085 *Consequences*): the `chrome` header, the
`chrome-nav` bar and the footer; any new colour role; layout, density,
navigation; motion; the inside of self-drawn canvases (mimic scene, CRAC/SLD
SVGs, Leaflet, ECharts plot area); the F3.32e files (unit D); focus-ring
behaviour; the PDF/Excel/email documents; `AGENTS.md` §5 (a later
`chore(agents):` PR).

## §0 Rulings

## §2 The vocabulary

**Where.** `apps/web/src/index.css` only: shadow tokens in two new blocks
after the dark role block; classes in one `@layer components { … }` block
after the tokens and before `body`. No `data-[surface=…]:` variants in `.tsx`
(V2). Base rules are the **neumorphic** shape; flat rules follow under
`:where([data-surface="flat"]) .x` — `:where()` keeps specificity at (0,1,0),
so source order decides and a call-site utility still wins in both styles.
Flat rules use `@apply` with today's utility strings; neumorphic rules are
plain CSS reading `rgb(var(--role))` and `var(--shadow-*)`. No `color-mix`,
no hex.

**Tokens** (keyed `:not([data-surface="flat"])`, so a blocked boot script
still yields the default style):
