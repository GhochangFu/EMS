## 2. Facts measured

### 2.1 Repo

- **The grammar has no variables** (`packages/shared/src/calc-dsl/limits.ts`, the `CALC_CALENDAR_WINDOWS` note). The mean cannot be named once. Section 3 removes it by algebra instead of inlining it.
- **Functions and arity** (`limits.ts`, `CALC_FUNCTION_ARITY`): `abs` 1, `round` 1, `min`/`max` 2..20, `clamp` 3. Caps: formula 1000 characters, 20 distinct references.
- **Division by zero** is `non_finite` at the `/` node (`evaluate.ts`, `finiteOrFail`). Both hosts then call `refuse(...)` and write nothing (`apps/api/src/calc/calc-streaming.service.ts`, `calc-scheduler.service.ts`); the skip is counted in `bms_api_calc_skipped_total` and shown on the asset's calc status. No alert rule on that counter exists in the repo.
- **Triggers** (`CALC_TRIGGERS`): `streaming` or `scheduled`. `streaming` is `bms-calc-v1` only (`toActiveDefinition` refuses `streaming_on_v2` for `v2` and `v3`); it must carry no interval. A streaming value takes the newest input's timestamp, not the wall clock.
- **Staleness** (`apps/api/src/calc/calc-inputs.ts`, `classifyInput`): an input is stale when `now − sample.time > maxInputAgeSeconds`; one stale or missing input refuses the whole formula (`stale_input` / `missing_input`). Default 300 s (`DEFAULT_MAX_INPUT_AGE_SECONDS`), bound 1..86 400.
- **A templated asset cannot take a standalone calculated point** (ADR 0109 decision 1; `calc-point-standalone.service.ts` refuses it), and an override `PUT` for a key the template does not declare is refused. So the new template version is the only way to add the points. Per-asset tuning comes after, as an override of the five calc columns.
- **The template flow exists end to end** (`apps/api/src/admin/asset-templates/asset-templates.controller.ts`, web pages `asset-template-detail-page.tsx`, `asset-template-versions-page.tsx`): `POST :id/draft` ("Edit this published version", copies points and `content`) → `PATCH :id` → `POST :id/publish` → `POST :id/migration-preview` → `POST :id/migrate` with `assetIds`.
- **What migration writes** (`asset-templates-migrate.service.ts`): `assets.template_id`, `asset_points` rows for *measured* additions only, one audit row. It writes no rule, no dashboard and no telemetry. A derived addition creates no `asset_points` row; `CalcWriteService` creates the `computed` row at the first value. Overrides key on `(asset_id, point_key)` and stay; `refuseOverridesThatDoNotSurvive` re-validates them. `asset-templates.migrate.integration.spec.ts` already holds "a derived-only delta must migrate".
- **Migration seeds no rules.** ADR 0058 decision 1: a seeded rule is a one-time copy at instantiation (and at adoption, `asset-templates-adopt.service.ts`). The 12 existing assets get rules from the Rule Engine.
- **Rules** (`packages/shared/src/contracts/rule-writes.ts`, `apps/api/src/alarms/alarm-engine.service.ts`, `alarm-lifecycle.ts`): a threshold rule is `(asset, point_key, operator gt|gte|lt|lte|eq, threshold, severity, clear_hold_seconds)` with `condition.window = "latest"` only. It raises on the **first** matching sample. It clears after fresh samples stay non-matching for the hold (default 120 s); a sample older than 15 minutes changes nothing. There is **no raise delay, no deadband and no second-point condition**.
- **A derived template key is a legal rule target** before any value exists (`apps/api/src/rules/rule-points.ts`: the pinned template's keys join the union, with no `kind` filter).
- **Batch create** (`POST /rules/batch`, `rules-batch.service.ts`): up to 25 rules, one organization, created **and published**, all or none. The web wizard (`apps/web/src/components/rules/rule-batch-wizard.tsx`) sends `action: { type: "notify", target: "Operations" }` on every row and has no action, category or clear-hold field.
- **Health score.** `apps/api/src/asset-health/health-rollup-sql.ts` counts every published, enabled threshold rule. A new ruled tag enters the asset's rule-based health score at weight 1; `templateHealthSchema` allows a weight only above 0.
- **Backfill** exists for a templated asset only through the per-asset override `PUT /admin/assets/:assetId/calc-points/:pointKey` with `backfillDays` 1–31 (ADR 0109 note of 2026-11-04). An all-null body with `backfillDays` overrides nothing, creates the `computed` row and starts one run. Backfill rows are written without NOTIFY, so history raises no alarm.
- **Catalog keys.** `current_unbalance_pct` and `voltage_unbalance_pct` are in the code vocabulary (`packages/shared/src/constants.ts`, `packages/db/src/point-key-units.ts`, unit `%`).

## 3. The formulas, exactly

NEMA MG-1: with m = (a+b+c)/3, unbalance % = max(|a−m|, |b−m|, |c−m|) / m × 100. Because |a−m| / m = |2a−b−c| / (a+b+c), the mean is not needed:

**F-V — `voltage_unbalance_pct`** (215 characters, 3 references):

```
100 * max(abs(2 * {voltage_vry} - {voltage_vyb} - {voltage_vbr}), abs(2 * {voltage_vyb} - {voltage_vry} - {voltage_vbr}), abs(2 * {voltage_vbr} - {voltage_vry} - {voltage_vyb})) / ({voltage_vry} + {voltage_vyb} + {voltage_vbr})
```

**F-C0 — `current_unbalance_pct`, no guard** (215 characters):

```
100 * max(abs(2 * {current_ir} - {current_iy} - {current_ib}), abs(2 * {current_iy} - {current_ir} - {current_ib}), abs(2 * {current_ib} - {current_ir} - {current_iy})) / ({current_ir} + {current_iy} + {current_ib})
```

**F-C1 — `current_unbalance_pct`, refused at or below a mean-current floor F** (333 characters; shown for F = 5 A, so the literal is 3F = `15`). It multiplies by `g / g`, where `g = max(sum − 3F, 0)`: above the floor that is exactly 1; at or below it, 0/0 is `non_finite` and nothing is written.

```
100 * max(abs(2 * {current_ir} - {current_iy} - {current_ib}), abs(2 * {current_iy} - {current_ir} - {current_ib}), abs(2 * {current_ib} - {current_ir} - {current_iy})) / ({current_ir} + {current_iy} + {current_ib}) * (max({current_ir} + {current_iy} + {current_ib} - 15, 0) / max({current_ir} + {current_iy} + {current_ib} - 15, 0))
```

**F-C2 — `current_unbalance_pct`, writes 0 at or below the floor** (300 characters):

```
100 * max(abs(2 * {current_ir} - {current_iy} - {current_ib}), abs(2 * {current_iy} - {current_ir} - {current_ib}), abs(2 * {current_ib} - {current_ir} - {current_iy})) / max({current_ir} + {current_iy} + {current_ib}, 0.001) * clamp(({current_ir} + {current_iy} + {current_ib} - 15) * 1000000, 0, 1)
```

Evaluated with the built `@bms/shared`:

|---|---|---|---|
| 110, 100, 90 | 10 | 10 | 10 |
| 10, 10, 10 | 0 | 0 | 0 |
| 0, 10, 10 (one phase lost) | 100 | 100 | 100 |
| 5.2, 5, 5 | 2.6315789473684235 | same | same |
| 5, 5, 5 | 0 | refused `non_finite` at 275 | 0 |
| 2, 1, 1 | 50 | refused `non_finite` at 275 | 0 |
| 0, 0, 0 | refused `non_finite` at 169 | refused at 169 | 0 |
| one key absent | refused `missing_input` | — | — |

**Point fields, both points:** `kind: derived`, `formulaDialect: bms-calc-v1`, `calcTrigger: streaming`, `calcIntervalSeconds: null`, `minCoverageRatio: null`, `unit: %`, labels "Current unbalance" and "Voltage unbalance" (the stock feeder's labels), `required: false`.

**`maxInputAgeSeconds` = M.** The risk is a value built from two payloads: at a pump start, two new phases and one old zero read as 100 %. So M is below the publish interval P: **M = max(30, floor(P / 2))**, with P from Task 1. If the canary (Task 3) shows `stale_input` on every payload, the device clock lags; raise M to `ceil(1.5 × P)` and record the accepted cost (one mixed-payload value is possible).

**Why streaming.** One value per payload, stamped with the payload's time, and the alarm engine sees it at once. `scheduled` gives a value up to one interval old on a fixed grid and is the fallback only if streaming cannot be made fresh.

## 4. The light-load guard: options

| Option | What happens at light load | Cost |
|---|---|---|
| A. No guard (F-C0) | A 1 A difference at 3 A reads 50 % and raises | False alarms at light load |
| **B. Refuse at or below F (F-C1) — recommended** | Nothing is written; the point shows "skipped · non_finite" | An alarm that is open when the pump stops stays open until the pump runs balanced again (no fresh sample, so no clear). One alarm for one fault. |
| C. Write 0 at or below F (F-C2) | 0 % is written | The alarm clears 120 s after a stop and raises again at each start; zeros enter the trend and its means; the row's "a zero mean writes nothing" no longer holds for current |
| D. Guard in the rule | Not possible today | Code plus an ADR amendment; a new row |
| E. Floor as a `$parameter` (`bms-calc-v3`) | Per-scope floor without an override | `scheduled` only and a new parameter key; not recommended |

The floor is a literal in the template formula. One meter that needs another floor gets its own formula through the calc override on its points page (ADR 0039 decision 6).

**Not covered by any option:** the rule raises on the first matching sample, so a sample taken during a motor start can raise. Task 4 Step 4 measures that before anybody is paged.

```ts
// ---- F4.387 — phase unbalance: the exact formula text on the PHE energy-meter template ----
//
// NEMA MG-1: the largest deviation from the three-phase mean, over that mean, times 100.
// The grammar has no variables, so the mean is removed by algebra:
// |a - m| / m = |2a - b - c| / (a + b + c). These strings are what the template stores;
// docs/plans/f4.387-phase-unbalance.md section 3 carries the same text.

const VOLTAGE_UNBALANCE =
  "100 * max(abs(2 * {voltage_vry} - {voltage_vyb} - {voltage_vbr}), abs(2 * {voltage_vyb} - {voltage_vry} - {voltage_vbr}), abs(2 * {voltage_vbr} - {voltage_vry} - {voltage_vyb})) / ({voltage_vry} + {voltage_vyb} + {voltage_vbr})";

const CURRENT_UNBALANCE_NO_GUARD =
  "100 * max(abs(2 * {current_ir} - {current_iy} - {current_ib}), abs(2 * {current_iy} - {current_ir} - {current_ib}), abs(2 * {current_ib} - {current_ir} - {current_iy})) / ({current_ir} + {current_iy} + {current_ib})";

/** Refused at or below a 5 A mean (15 = 3 x 5): g / g is 1 above the floor and 0 / 0 at or below it. */
const CURRENT_UNBALANCE =
  CURRENT_UNBALANCE_NO_GUARD +
  " * (max({current_ir} + {current_iy} + {current_ib} - 15, 0) / max({current_ir} + {current_iy} + {current_ib} - 15, 0))";

/** The textbook form with the mean written out, to hold the algebra. */
const CURRENT_UNBALANCE_TEXTBOOK =
  "max(abs({current_ir} - ({current_ir} + {current_iy} + {current_ib}) / 3), abs({current_iy} - ({current_ir} + {current_iy} + {current_ib}) / 3), abs({current_ib} - ({current_ir} + {current_iy} + {current_ib}) / 3)) / (({current_ir} + {current_iy} + {current_ib}) / 3) * 100";

const amps = (a: number, b: number, c: number) => ({ current_ir: a, current_iy: b, current_ib: c });
const volts = (a: number, b: number, c: number) => ({ voltage_vry: a, voltage_vyb: b, voltage_vbr: c });

export function runEvaluatePhaseUnbalanceTests(): void {
  expectValue(CURRENT_UNBALANCE, amps(110, 100, 90), 10, "110/100/90 A is 10 % current unbalance");
  expectValue(CURRENT_UNBALANCE, amps(10, 10, 10), 0, "balanced currents are 0 %");
  expectValue(CURRENT_UNBALANCE, amps(0, 10, 10), 100, "one lost phase is 100 %");
  expectValue(VOLTAGE_UNBALANCE, volts(420, 410, 400), 2.4390243902439024, "420/410/400 V is 2.44 % voltage unbalance");
  expectValue(VOLTAGE_UNBALANCE, volts(415, 415, 415), 0, "balanced voltages are 0 %");

  // A zero mean writes nothing: the refusal is at the division by the sum.
  const stopped = expectRefusal(CURRENT_UNBALANCE, amps(0, 0, 0), "non_finite", "all-zero currents are refused");
  assert(
    !stopped.ok && stopped.position === CURRENT_UNBALANCE.indexOf(" / ") + 1,
    "the all-zero refusal is reported at the division by the phase sum",
  );
  expectRefusal(VOLTAGE_UNBALANCE, volts(0, 0, 0), "non_finite", "all-zero voltages are refused");

  // The light-load floor: at or below a 5 A mean nothing is written; just above it the guard is exactly 1.
  expectRefusal(CURRENT_UNBALANCE, amps(5, 5, 5), "non_finite", "a 5 A mean is at the floor and is refused");
  expectRefusal(CURRENT_UNBALANCE, amps(2, 1, 1), "non_finite", "a light, unbalanced load is refused, not 50 %");
  const unguarded = evalExpr(CURRENT_UNBALANCE_NO_GUARD, amps(5.2, 5, 5));
  const guarded = evalExpr(CURRENT_UNBALANCE, amps(5.2, 5, 5));
  assert(
    unguarded.ok && guarded.ok && Object.is(unguarded.value, guarded.value),
    "above the floor the guard changes no bit of the value",
  );

  // One absent phase is a missing input, never a two-phase number.
  expectRefusal(CURRENT_UNBALANCE, { current_ir: 1, current_iy: 1 }, "missing_input", "a missing phase is refused");

  // The algebra: the stored form equals the textbook form on a grid.
  for (const a of [1, 7.5, 40, 133.3]) {
    for (const b of [1, 9, 38.2, 120]) {
      for (const c of [2, 8, 41, 140.7]) {
        const stored = evalExpr(CURRENT_UNBALANCE_NO_GUARD, amps(a, b, c));
        const textbook = evalExpr(CURRENT_UNBALANCE_TEXTBOOK, amps(a, b, c));
        assert(
          stored.ok && textbook.ok && Math.abs(stored.value - textbook.value) < 1e-9,
          `stored and textbook forms differ at ${a}/${b}/${c}`,
        );
      }
    }
  }
}
```
