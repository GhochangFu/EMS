# F3.77 — the site Overview leads with alarms, and a wall mode (plan)

Plan written on Fable (`plan-architect`) on 2026-10-01 at `main` `b21eadad` plus the
ADR docs that merged as #684 (`e53c1fb1`). Scope: ADR 0087
Amendment 3, rulings 1–10 (accepted 2026-10-01); copy and seed-upgrade rules from
Amendments 1 and 2; the brief `docs/plans/f3.73-overview-shape.md`; the product
record `apps/web/PRODUCT.md`. The step-2 gate is closed: nothing below invents
scope.

**Constraints carried into every PR:** no schema change (none is needed); the
seed runs only on a scratch database, never on the shared `bms` database;
`packages/db` edits go through `migration-reviewer`; the sign-in redirect goes
through `security-reviewer`; every PR is green on `pnpm typecheck`,
`pnpm typecheck:tests` and `pnpm test:coverage` with `DATABASE_URL` on a scratch
database, rebased onto `main` before review. Model per unit follows
`docs/build-operating-model.md` §2: Opus for every seam and every security unit,
Sonnet for the mechanical ones, effort `medium`, no Fable implementer.

## 1. Goal

The stock "SMOC standard" Overview becomes version 3: four problem tiles
(Active alarms, Offline assets, Total load, Asset health), the active alarms
rail (8 columns) beside one Systems list (4 columns, one row per domain tab
with status, counts and an Open link), the asset-class strip, and the state
legend as one compact 64 px row. `module_summary_card` leaves the stock
Overview but stays in the vocabulary. The seed upgrades a seeded copy's Overview
to v3 only while that tab holds exactly its own packed v2 plan, and supersedes
its own stock template row whenever the row's `stock_version` is below the
current one. The icon vocabulary gains `offline`. Every group tab of a tabbed
dashboard shows a status marker (tone plus "n alarms", or "Outside scope") in
the site view, the viewer and the builder. The site view gains a wall mode
(`?wall=1&every=30`): no app shell, larger type, a top bar with the site name, a
seconds clock and the time of the newest read, rotation through the dashboard's
tabs with equal turns, pause on a key or click, a visible resume control, a
"Session ended — sign in" state on 401 and a same-origin return to the same wall
URL after sign-in.

**Out of scope (Amendment 3):** colours and tokens; auth and the session
lifetime (a long-lived wall session needs its own ADR); the domain tabs'
content; the mimic and the compact SLD (`F3.74`, ADR 0088 — v4); `RSMOC-WC`
(`F3.75`); the generated view; a `chore(agents):` sweep (the F3.73 one is still
owed and stays a separate PR). Also not built: a return path for any route other
than a wall URL; a new API endpoint (ruling 5: the markers read the existing
`tabs[]`).

## 3. Design decisions

- **D1 v3 Overview rects** (12 columns, rows 0–11): tiles 3×2 at y0 in the
  order Active alarms (x0, `alert`), Offline assets (x3, **`offline`**), Total
  load (x6, `bolt`), Asset health (x9, `gauge`); rail 8×7 at (0,2) `rows: 8`;
  Systems list 4×7 at (8,2), `critical_systems_list`, title **"Systems"**
  (OQ1); strip 12×2 at (0,9); legend 12×1 at (0,11). Constants: `TILE_H`,
  `RAIL_H = 7`, `RAIL_W = 8`, `STRIP_Y = TILE_H + RAIL_H`, `LEGEND_Y = STRIP_Y +
  STRIP_H`, `LEGEND_H = 1`. **The v4 slot (ruling 10)** is the row at `STRIP_Y`:
  v4 puts the compact SLD at `(0, STRIP_Y)` 6 wide and moves the strip to
  `(HALF_W, STRIP_Y)` 6 wide; the docblock says so, and nothing else in v3 moves
  for it. `moduleCard` and the card row are deleted from the file. The template
  `description` no longer names module cards. `stockVersion: 3`.
- **D2 A compact legend.** `StateLegendWidget` renders without `WidgetFrame`:
  one `surface-raised` row, `h-full`, `items-center`, `px-3`, an inline muted
  11 px uppercase label (the widget title) then the pills, `overflow-hidden`.
  The legend is always `ready`, so the frame's three non-ready states are not
  lost. `smoc-standard.spec.ts` `VIEW_FLOOR_MIN_ROWS.state_legend` becomes 1
  with the new measurement in its docblock; the browser layer proves the fit
  (§7).
- **D3 Systems list rows.** Name as text, counts, pill, then an `Open` link
  (`aria-label="Open <label>"`) when `tabHref !== null`; the `<ul>`'s
  `aria-label` is the widget title, not the literal "Critical systems".
- **D4 Tab markers.** New `components/dashboards/tab-status-marker.tsx`
  (`TabStatusMarker({ status, severities })`): a dot in the tone plus text —
  `"n alarms"` (singular for 1) or `"Outside scope"` — never colour alone.
  `tabStatusLabel(status, severities)` is extracted from `TabStatusPill` into
  `site-widget-parts.tsx` so the pill and the marker share one rule;
  `tabAccessibleName(label, status, severities)` gives "HVAC, Warning, 2
  alarms" / "HVAC, Outside scope". New `hooks/use-tab-markers.ts`:
  `useTabMarkers(dashboardId, tabKey | null)` returns `Map<tabKey, SiteWidgetTab>`
  from `useSiteWidgets` (gains an `enabled` option: `tabKey === null` reads
  nothing) plus the severity vocabulary. The key is the dashboard's **first
  stored tab by `sortOrder`** — the Overview on a site layout, the "existing
  Overview read" of ruling 5 — so the cache entry is the one the Overview
  widgets already mount and a tab switch never flickers the markers. A tab absent
  from `tabs[]` (the Overview; any tab with no group) gets no marker, by
  construction; "Assets & RTUs" is outside the dashboard tabs. `DashboardTabStrip`
  gains `markers?: ReadonlyMap<string, SiteWidgetTab>` and sets each marked
  tab's `aria-label`; the site view's `<nav>` does the same on its `Link`s.
- **D5 The seed upgrade chain.** New `packages/db/src/site-layout-stock-history.ts`
  holds the frozen past: `SMOC_STANDARD_V1_RECTS` and `smocStandardV1Content()`
  (moved), plus `OVERVIEW_V2_WIDGETS` (the v2 Overview's 13 widgets: identity,
  rect, `config`) and `smocStandardV2Content()` = the current content with the
  Overview tab replaced by that list (a spec holds that every other tab is
  byte-equal between v2 and v3). `F3.74` appends the v3 Overview and SLD there.
  `planCopyWidgetUpgrade`'s default `to` becomes `SMOC_STANDARD_V2_RECTS`;
  `planCopyPackUpgrade`'s default `content` becomes `smocStandardV2Content()`.
  New pure `planOverviewUpgrade(widgets, copyTabKeys, from, to)`: the gate is
  "the stored Overview equals `packAfterRemoval(from.overview.widgets, keep cards
  whose target ∈ copyTabKeys)` exactly — same identities, no repeat, same rects,
  same `config` (jsonb equality), every value tile holds one source row and no
  point row, every other widget none". Ops: `delete` for every stored card
  (predicate: type, rect, config) and `update` for every kept widget whose
  v3 rect, title or config differs (predicate: the from rect, title and config;
  one `WIDGET_UPGRADE_SQL`). A title rename map (`"Critical systems" →
  "Systems"`) is data on the call, so identity follows the rename. `packCopy`'s
  read gains `config`. Order per copy: v1→v2 moves, pack, Overview v2→v3; every
  write checks `rowCount === 1`. Idempotent by the gate: a v3 Overview has no
  cards and other rects.
- **D6 The supersede rule (ruling 9).** `isSeedStockSiteTemplate(newest,
  currentStockVersion)` replaces `isSeedV1SiteTemplate`: published, `createdBy
  === null`, `stockVersion !== null && stockVersion < current`, content parses.
  The v1 rects check is dropped: a published row is immutable (ADR 0049 —
  `update` takes drafts only), so the stamp is the content. Archive under the
  same rule (newest row is the seed's own). `upgradeSeedSiteTemplate` writes
  `version + 1` with the current content, as now.
- **D7 Wall URL.** `?wall=1&every=<15|30|60|120>` on the site route; the tab
  stays the route's `:tab` segment (OQ2). `lib/wall-mode.ts` (pure):
  `parseWallParams(search)` (`wall` on iff `=== "1"`; `every` in
  `WALL_INTERVALS_S`, else `WALL_DEFAULT_S = 30`), `wallHref(sitePath, tabKey,
  everyS)`, `nextTabKey(keys, current)` (wrapping; equal turns), `newestReadMs(
  samples)`, `wallBar(newestMs, nowMs)` → `{ kind: "live", updatedAt } | { kind:
  "paused", since }` through `isStale`.
- **D8 Wall rendering.** `site-page.tsx` branches: when `wall.on && showsDashboard`
  it renders `components/control-room/wall-frame.tsx` instead of `AppShell`
  (header, nav, sidebar, ribbon and footer gone), with the same
  `SiteDashboardView` inside. The frame's top bar (`data-wall-bar`): site name
  (`h1`), `StatusBarClock precision="second"` (one clock component; the footer
  keeps `"minute"`), "Updated hh:mm:ss" or "Live data paused since hh:mm:ss",
  an interval `<select>` (15/30/60/120), "Paused — Resume" (visible only while
  paused), "Exit wall" (the path without params). A "Wall" link in the page
  header's actions when `showsDashboard` (OQ3). `hooks/use-wall-rotation.ts`:
  `setInterval(everyMs)` → `navigate(wallHref(next), { replace: true })`;
  document-level capture listeners for `keydown` and `pointerdown` pause,
  ignoring events whose target is inside `[data-wall-bar]`; Resume restarts.
  Type scale: class `wall-root` on the frame with `zoom: 1.25`, and `2.5` at
  `min-width: 3000px` in `index.css` (OQ4) — `zoom` scales px literals too;
  the canvas measures the zoomed width, so `viewRowHeightPx` follows. (Superseded by
  the 2026-10-02 follow-up: `viewRowHeightPx` is gone, a view canvas's rows are auto
  tracks, and the wall zoom is computed — `docs/plans/f3.77-fit-content-and-wall.md`.)
- **D9 Newest read.** `DashboardLiveCanvas` reports
  `newestReadMs({ latestByRef, catalogResolvedAt, siteWidgetsUpdatedAt })`
  through a new `NewestReadContext` (`useReportNewestRead`, default no-op), where
  `siteWidgetsUpdatedAt` is `queryClient.getQueryState([...siteWidgetsQueryPrefix,
  dashboard.id, tabKey])?.dataUpdatedAt`. The bar re-evaluates `isStale` every
  second with its own clock (OQ5).
- **D10 Session ended and the return path.** `clearSessionOnAuthFailure`
  (`api/http.ts`) calls `rememberWallReturnPath(window.location)` before
  clearing: it stores `pathname + search` in `sessionStorage` under
  `bms-return-path` **only when `wall=1`**. The route's `<Navigate to="/login">`
  stays as it is (the f3.66 gate). `LoginPage` shows a full-width "Session ended
  — sign in to return to the wall view" banner when a return path is stored,
  and both `LoginPage` and `AuthCallbackPage` navigate to
  `takeReturnPath() ?? "/"`. `lib/return-path.ts`: `safeReturnPath(value)`
  accepts a string that starts with exactly one `/`, parses with `new URL(value,
  origin)` to the same origin, contains no `\`, no `//` prefix, no control
  character, and returns `pathname + search` — else `null`; `takeReturnPath`
  removes the key and validates on read. No `?return=` query parameter (YAGNI:
  the store is written by this code only; the guard is defence in depth).
  `tests/f3.72-control-room-entry.test.ts` E2 is amended to the new literal
  (`navigate(takeReturnPath() ?? "/", { replace: true })`) with its positive
  control kept.
