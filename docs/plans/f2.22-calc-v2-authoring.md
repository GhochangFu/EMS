## Goal

Give an author every control needed to write, check and store a `bms-calc-v2`
formula from the browser, on the three surfaces that already accept one through
the API: the Calculations tab, the KPIs tab, and the per-asset override panel.
Concretely, the nine deferrals of `docs/plans/f2.9-cross-asset-calc-v2.md`
§"Deferred to F2.22": a dialect control on each surface (1); which reference form
answers which question, plus `@` completion (2); author-facing wording for the ten
`v2` error codes, in `packages/shared` so the API says the same thing (3); a
coverage-ratio input whose empty state reads as **fail closed** (4); a trigger
control that admits only `scheduled` under `v2` and says what that costs (5); a
live preview that takes a sample value per cross-asset reference (6); the
save-time cycle refusal mirrored in the editor for the within-template cases (7);
KPI `v2` authoring with local-only `pointKeys` derivation (8); and a save-time
refusal of a qualified reference that resolves nowhere, on the one write path that
knows the asset (9).

**Out of scope, deliberately.** No KPI evaluation or display, `v1` or `v2` —
`F2.33`, ADR-gated. No migration: `min_coverage_ratio` exists (`0062`). No npm
dependency: `@codemirror/autocomplete` is already declared (ADR 0038 Amendment 2),
so §9.4 is not triggered. No membership-cycle surface in the editor — ADR 0055
decision 8 puts that on the operator, and `F2.9` Task 16 shipped it as the runtime
pill. No template-side check of a qualified code against a location — a template
has no asset. No per-asset override of the coverage ratio (decision 11). No change
to what the calc engine reads or writes.

## Four findings that reshape the row — read before the tasks

1. **The live preview panel does not exist in the UI.** `previewFormula` has no
   caller outside its own spec (`apps/web/src/lib/calc-preview.ts:97`; CodeGraph:
   8 callers, all in `calc-preview.spec.ts`). Neither tab imports
   `calc-preview.ts`. ADR 0038 decision 5 shipped in `F2.5` as a pure module and
   a spec, and `kpis-tab.tsx:18` ("the field gains highlighting, the preview and
   the two-way check") and the `F2.5` plan's browser claim (line 506) describe a
   panel that never rendered. Item 6 — "sample-value rows for aggregates" —
   therefore has no `v1` rows to sit beside. **Open question Q1.**
2. **A `v2` KPI is treated as unvalidated by the tab.** `kpis-tab.tsx:186` reads
   `const validated = kpi.dialect === CALC_DIALECT;`, so a stored `v2` KPI shows
   "Not checked", the manual `Points this KPI reads` select and a Validate button
   — while `isCheckedDialect` (widened in `F2.9`) tells the editor it is checked.
   Item 8 fixes a `v1`-literal restatement, not only adds a control.
3. **A `v2` self-reference gets no client diagnostic today.**
   `validateDerivedFormula` returns `ok` for `v2` before the derived-reference
   scan (`template-formula-validation.ts:204-206`), and `brokenFormulaRefs`
   refuses only under `v1` (`template-points-grid.ts:528`). `{SELF}` and
   `sum({SELF} @site)` on `SELF` reach the server and are refused there as a
   one-edge cycle. Item 7's mirror closes a real gap, which is its anti-vacuity
   case.
4. **The calc-points read carries no coverage ratio.**
   `assetPointCalcConfigDtoSchema` (`packages/shared/src/contracts/admin.ts:557`)
   holds `template`/`override`/`effective` as the five override fields; the ratio
   is not one of them (decision 11). The deferral list names the Calculations tab
   and the stock viewer for item 4 — **two** surfaces, not three. Showing the
   ratio on the override panel needs one read-side contract field. **Open
   question Q3.**

## Design decisions settled at this gate

Each is the plan's own call, reviewable at step 5.

1. **A preview of an aggregate shows one sample-value row per cross-asset
   reference, keyed by `crossRefKey(node)`.** The author types the aggregate's
   value, not its members: the member set is resolved only by the database, and
   `calc-preview.ts` is purity-gated (`tests/adr-0038-formula-editor.test.ts`
   scans it for network symbols and requires its only import to be
   `@bms/shared`). `evaluate()` reads `crossInputs` by the same key
   (`evaluate.ts` imports `crossRefKey`), so the panel and the evaluator cannot
   disagree on the key. Local keys stay in `previewInputKeys` (local only — the
   Q3b property); cross references come from a second function.
2. **The dialect select never rewrites a stored row by itself.** ADR 0055
   decision 3: an author opts in by re-saving under `v2`. `calculations-tab.tsx:194`
   already preserves the row's dialect on a formula edit; the select is the only
   thing that changes it, and only on the author's action. A `v2 → v1` change on
   a formula with `v2` syntax is not refused by the select — the linter reports
   the `@` at once and Save is blocked; on the KPIs tab, where the row's dialect
   gates whether checks run at all, the change is applied only when the
   expression validates under the target (decision 9's atomicity, extended to
   the dialect).
3. **`setFormulaDialect(row, v2)` flips a `streaming` trigger to `scheduled` and
   seeds no interval.** `scheduled` is the only legal trigger under `v2`
   (decision 10), so this is not a choice made for the author — the same shape
   as `setCalcTrigger` clearing an interval the schema forbids. The interval
   stays empty and `calcConfigErrors`' existing "A scheduled formula needs an
   interval." fires. `setFormulaDialect(row, v1)` clears `minCoverageRatio`,
   which the server refuses off a `v2` derived point
   (`asset-templates.schema.ts:187-198`).
4. **The empty ratio renders as a disabled-or-editable number input with the
   placeholder `fail closed` and a hint sentence, on the Calculations tab only.**
   Not a text row when frozen: the tab's three sibling fields render as disabled
   controls on a frozen version, and the stock viewer's sweep
   (`asset-template-stock-view-page.spec.tsx:311-318`) requires every field to be
   disabled, not absent. The hint states decision 11 in the author's words (T4).
   The override panel shows the template's value read-only, with "not
   overridable per asset" (T12, if Q3 is ruled in).
5. **The `streaming` option is disabled under `v2`, not hidden.** Hiding it
   leaves a React `<select>` blank the instant a row flips while its stored
   trigger is `streaming`; disabling keeps the value visible while
   `calcConfigErrors`' server-verbatim sentence names the problem.
6. **The within-template cycle mirror is a client re-implementation of
   `templateCycles`' rule, in `apps/web/src/lib`, wording-gated by a `tests/`
   scan.** `apps/web` cannot import `apps/api`, and moving `calc-graph.ts` into
   `packages/shared` would move the definition ADR 0055 part (a) machine-holds
   under `apps/api/src`. The mirror is wording, not authority — the same reasoning
   `draftProblems` records. **Open question Q5** names the alternative.
7. **No `v2`-specific "not evaluated" marker on the KPIs tab.** A `v1` KPI
   computes no more than a `v2` one (nothing reads `kpis[].expression` outside
   authoring), so a `v2`-only marker would say the false thing about `v1`. The
   tab's "Checked · reads …" line is about validation and stays. The tab's
   docblock gains one sentence pointing at `F2.33`, so no reader infers a
   computed value.
8. **Item 9 lives on the override write path, in the API, and nowhere on the
   template path.** `AssetPointCalcOverrideService.setOverride` knows the asset;
   `CalcScopeService.resolveMembership` already resolves a qualified code at the
   owner's `location_id` and returns `null` for one that resolves nowhere. A
   template has no asset, so its save cannot check a code — by construction
   (correction 56). What the template author gets instead: the preview's one
   row per qualified reference (they see each code they typed), and after
   instantiation the runtime pill's `skipped: unknown_asset_reference`. **The
   refusal must not say whether the code exists at another location** —
   `assets.code` is unique globally and that sentence would confirm another
   tenant's code.
9. **The override panel's `inherit` sends `formulaDialect: null`, with or without
   a formula.** Today `draftToBody` stamps `v1` beside any formula
   (`asset-point-calc-override.ts:153`), which a dialect select makes wrong: an
   author who types `v2` syntax and leaves the select on `inherit` against a `v2`
   template would be refused for a `v1` label they never chose. The API accepts a
   formula-only override (`assertFormulaAloneInheritsTheDialect`,
   `asset-point-calc-override.schema.spec.ts:236`), and decision 4 makes the
   inherited label safe for a `v1`-shaped formula. **Open question Q2**, because
   it changes a shipped behaviour and a shipped assertion.

## Serial or parallel

**Serial, hands-on, one feature branch (`feat/F2.22-calc-v2-authoring`), two
PRs.** Not a ⭐ enabler. The units chain: the shared wording (T1) and the preview
module (T2) are what the KPI rules (T3), the tab rules (T4, T5) and every
component (T6–T8, T12) hang off. The override half (T11, T12) is file-disjoint
from the template half and could run in a worktree after PR 1 — but its dialect
select, guidance text and clearing rules must match the Calculations tab's
exactly, and a cold agent re-deriving those is the seam risk §2's ladder names.
Two units at most would be parallel, for about three unit-days; the cold start
does not pay. Model per unit is given per task, from the §2 ladder.

### PR 1 — the template surfaces (Calculations tab, KPIs tab), and the shared wording

#### T1 — author-facing wording for the ten `v2` error codes (item 3) — Sonnet

Files: `packages/shared/src/calc-dsl/parser.ts:503-532` (`ERROR_MESSAGES`);
`packages/shared/src/calc-dsl/parser.spec.ts`.

The ten codes, enumerated from `ast.ts:95-106`, not trusted from the deferral
list: `unknown_scope`, `unterminated_string`, `empty_string`,
`malformed_qualified_reference`, `malformed_scope`, `scope_required`,
`scope_not_allowed`, `aggregate_needs_point_reference`,
`qualified_reference_in_aggregate`, `too_many_cross_refs`. Ten.

Each entry becomes one sentence that names the fix. `ast.ts:108-114`'s rule
holds: no source text, no point key, no function name. The grammar's own fixed
vocabulary (`@`, `site`, `domain('…')`, `group('…')`, `{ASSET_CODE.point_key}`) is
not an echo, but **read the `offending` fragment list in `parser.spec.ts` (~line
285) before choosing words** — no fixed sentence may contain any fragment that
list tests, and none may contain `sum` or `avg`. Proposed:

- `unknown_scope` — "unknown scope after @ — a scope is site, domain('code') or group('code')"
- `unterminated_string` — "unterminated quoted code — close the scope's code with a second quote"
- `empty_string` — "empty quoted code — domain('…') and group('…') need a code between the quotes"
- `malformed_qualified_reference` — "malformed qualified reference — write {ASSET_CODE.point_key}, one dot between the asset code and the point key"
- `malformed_scope` — "malformed scope — @site takes no code; @domain and @group take one quoted code in parentheses"
- `scope_required` — "an aggregate needs a scope after its point reference: @site, @domain('code') or @group('code')"
- `scope_not_allowed` — "a scope belongs inside an aggregate only — put the reference in an aggregate, or remove the scope"
- `aggregate_needs_point_reference` — "an aggregate takes exactly one {point_key} reference, then its scope"
- `qualified_reference_in_aggregate` — "an aggregate cannot take a qualified {ASSET_CODE.point_key} reference — its scope already names the assets"
- `too_many_cross_refs` — `` `the formula has more than ${MAX_FORMULA_CROSS_REFS} distinct cross-asset references (aggregates and qualified references)` ``

This changes what the **API** returns through `templatePointsBodySchema`
("Invalid formula: …"), `templateKpiSchema` ("Invalid expression: …") and
`validateMergedCalcOverride`. `asset-templates.schema.spec.ts:713` composes its
expectation through `formatCalcError`, so it stays green by construction; any
spec that pins a `v2` sentence literally updates its expectation — never the
wording back.

Tests first — a new exported `runV2ErrorWordingTests` in `parser.spec.ts`: for
each of the ten codes, `formatCalcError({ code, position: 0 })` (a) is not the
`F2.9` one-liner (keep the ten old strings in an `OLD` table — the assertion that
the rewording landed), (b) contains no `offending` fragment, (c) ends with
`at character 0`. The existing no-echo table (`:305-318`) is untouched.
**Mutation:** restore one entry to its old string → (a) reddens for that code.
Gate: `pnpm --filter @bms/shared build` — shared is a runtime package and both
apps consume `dist`.

Docblock: `parser.ts:518-520` ("Author guidance beyond this is `F2.22`'s") is
rewritten to say the sentences are the author-facing form.

## Corrections found during the build — appended, never rewritten in

1. **(T2) A point key inside an aggregate is not a local ref.**
   `previewInputKeys("sum({kw} @site) + {TX_01.kwh}", v2)` is `[]`, not
   `["kw"]` — the `{kw}` is the aggregate's member key and `parseFormula`
   returns it under `crossRefs`, not `refs`. The spec asserts the measured `[]`
   and uses `"sum({kw} @site) / {kw}"` → `["kw"]` as the positive control.
   Verified against `@bms/shared` `dist` at `f11717d5`. T3's fixture
   `"{FLOW} / sum({FLOW} @site)"` → `["FLOW"]` is unaffected (its `{FLOW}` is
   local).
2. **(T2) `calc-preview.ts` does not import `crossRefKey`.** Under the plan's
   own `toInputMap(crossValues ?? {})` form the module never handles a node —
   the caller keys the map — and `noUnusedLocals` fails an unused import. The
   module imports `CALC_DIALECT` and the types only; the purity scan holds.
3. **(T2) The named mutation moves to T8.** "Key the cross map by
   `node.pointKey`" has no site in the module; it is the T8 component's
   keying, and T8's spec carries it. T2's mutations were: drop the third
   argument to `evaluate` → only `runV2PreviewComputesTests` reddened; default
   `previewCrossRefs` to `v2` → only `runPreviewCrossRefsTests` reddened.
4. **(T2, pre-existing) No standard gate type-checks a web spec.**
   `apps/web/tsconfig.json` excludes `src/**/*.spec.ts` and `typecheck:tests`
   lists no web spec, so `pnpm typecheck` never sees a call to a changed
   signature from a spec; vitest transpiles without checking. Not this row's to
   fix (it is `apps/web`'s gate shape since ADR 0042), but every unit that
   changes a signature runs an ad-hoc `tsc --noEmit` over its own spec, as T2
   did, and says so. A row for the gate itself is owed at closure.
5. **(T2) `CalcPreviewOptions` is a named export**, not the inline literal the
   plan wrote, so T6/T7/T8 import one type.
6. **(T3) `setKpiDialect` needs a return-the-input guard.** The plan's
   one-liner, `validateKpiRow({ ...row, dialect: target }, declared)`, returns
   a row that reads `target` on failure, because `upgradeKpiToCalcDialect`
   returns its candidate unchanged — and the plan's own atomicity test refuses
   that. On `error` the function returns the input `row` itself
   (`row === input` is asserted).
7. **(T3) `templateKpiSchema` lives in
   `apps/api/src/admin/asset-templates/asset-templates-content.schema.ts:291`**,
   not in `packages/shared/src/contracts/admin.ts`. The `MAX_KPI_POINT_KEYS`
