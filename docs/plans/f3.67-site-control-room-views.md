# F3.67 — the site view setting: `bms.site_control_room_views`

Plan by `plan-architect` (Fable), 2026-09-25, from ADR 0076 decisions 3–6 (merged
#549) and the `F3.67` row. Measured read-only at `32f8de32`.

**Owner rulings, 2026-09-25:** **OQ1 (b)** — only the global `admin` may set
`builtin`; the API answers 403 for other roles and the option is hidden for them.
**OQ2 (a)** — the seed inserts the `RSMOC-WC` row only if absent; a re-seed never
overrides an admin's change (operator-owned, like `ingest_enabled`, F1.7).

## Goal

Add one tenant table, `bms.site_control_room_views` (at most one row per site),
the API that writes it (master-data roles, in scope, audited) and reads it back
for the admin form, **and one resolve read that every later row consumes**:
`GET /api/v1/control-room/sites/:locationId/view` answers the *effective* view for
a site — `generated`, `dashboard` (with the dashboard id and slug) or `builtin`
(with its key) — with the fail-safe applied (a removed or re-scoped dashboard, or
a built-in key the code does not know, answers `generated` plus a notice code). A
"Control Room view" field lands on the location admin page. The seed sets
`RSMOC-WC` to `builtin`/`smoc`.

**Why a resolve read.** `F3.66`, `F3.68`, `F3.69` and `F3.70` all need "which
view does this site show" and all must apply the same fail-safe. The pure
resolver (`site-control-room-view.pure.ts`) is written once, unit-tested once,
and served once. Access to the resolve read is "can read the site" (ADR 0076
Q14) — the `DashboardController.locationDashboard` rule at
`apps/api/src/dashboard/dashboard.controller.ts:46-70`: `scope.kind === "global"`
or `scope.locations` holds the id. `access-scope-sources.ts` fills `locations`
for every source, including `asset_group`.

**Out of scope.** No Control Room routes or pages (`F3.66`); no generated view,
no `point_keys.headline_rank` (`F3.68`); no dashboard rendering (`F3.69`); no
`/cr-*` move (`F3.70`); no web client for the resolve read (its first consumer
ships it); no site target for section templates; no lookup table for
`kind`/`builtin_key` (decision 4: CHECKs). AGENTS.md is not touched in this
branch (§3 layout will need `apps/api/src/control-room/` — a separate
`chore(agents):` PR after merge, §9.10).

## Decisions (engineering)

- **D1 — `dashboard_id` is `ON DELETE SET NULL`, and its CHECK is one-way**:
  `dashboard_id IS NULL OR kind = 'dashboard'`. RESTRICT would 500
  `DashboardsService.remove`; CASCADE would lose the evidence the notice needs.
  SET NULL leaves `(kind='dashboard', dashboard_id=NULL)` = "removed dashboard →
  generated with a notice". The `builtin` pair stays two-way:
  `(kind = 'builtin') = (builtin_key IS NOT NULL)`.
- **D2 — the policy carries two legs**: a `locations` leg and a `dashboards` leg,
  the `0073` shape. The service enforces the same-organization rule first; the
  policy is the backstop.
- **D3 — `PUT {kind:"generated"}` upserts a row, it does not delete one.**
- **D4 — the resolve read lives in a new `apps/api/src/control-room/` module.**
  The admin read/write are two handlers on `LocationsAdminController`
  (`GET`/`PUT /api/v1/admin/locations/:id/control-room-view`) backed by the same
  service, which `ControlRoomModule` exports and `AdminModule` imports.
- **D5 — the resolver re-checks scope at read time** (a dashboard can be
  re-scoped after it was chosen). Notice codes are a closed enum:
  `dashboard_removed` | `dashboard_out_of_scope` | `builtin_unknown`.
- **D6 — an `asset`-scoped dashboard is never eligible.**
- **D7 — no index beyond the primary key.**
- **OQ1 (owner) — `builtin` is admin-only**, server-enforced (403
  `"Only the global admin may set a built-in Control Room view"` for every other
  role), and the option is hidden in the web field for non-admins.
- **OQ2 (owner) — the seed row is insert-if-absent** (`onConflictDoNothing`).

```sql
SET ROLE bms_owner;
CREATE TABLE IF NOT EXISTS bms.site_control_room_views (
  location_id uuid PRIMARY KEY REFERENCES bms.locations(id) ON DELETE CASCADE,
  organization_id uuid NOT NULL REFERENCES bms.organizations(id),
  kind text NOT NULL,
  dashboard_id uuid REFERENCES bms.dashboards(id) ON DELETE SET NULL,
  builtin_key text,
  updated_at timestamptz NOT NULL DEFAULT now(),
  updated_by uuid REFERENCES bms.users(id),
  CONSTRAINT site_control_room_views_kind_check CHECK (kind IN ('generated', 'dashboard', 'builtin')),
  CONSTRAINT site_control_room_views_builtin_key_check CHECK (builtin_key IS NULL OR builtin_key IN ('smoc')),
  CONSTRAINT site_control_room_views_dashboard_id_check CHECK (dashboard_id IS NULL OR kind = 'dashboard'),
  CONSTRAINT site_control_room_views_builtin_pair_check CHECK ((kind = 'builtin') = (builtin_key IS NOT NULL))
);
ALTER TABLE bms.site_control_room_views ENABLE ROW LEVEL SECURITY;
ALTER TABLE bms.site_control_room_views FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS tenant_isolation ON bms.site_control_room_views;
CREATE POLICY tenant_isolation ON bms.site_control_room_views
  USING ( organization_id = nullif(current_setting('app.current_organization', true), '')::uuid
    AND EXISTS (SELECT 1 FROM bms.locations l WHERE l.id = site_control_room_views.location_id
               AND l.organization_id = nullif(current_setting('app.current_organization', true), '')::uuid)
    AND (dashboard_id IS NULL OR EXISTS (SELECT 1 FROM bms.dashboards d WHERE d.id = site_control_room_views.dashboard_id
               AND d.organization_id = nullif(current_setting('app.current_organization', true), '')::uuid)) )
  WITH CHECK ( <the same three conjuncts> );
COMMENT ON TABLE bms.site_control_room_views IS 'No row = the generated view (ADR 0076 decision 3).';
RESET ROLE;
```
