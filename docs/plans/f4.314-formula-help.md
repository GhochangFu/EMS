# F4.314 — plan: formula help in the calculated-point formula editor

Written by plan-architect (Fable), 2026-11-05, against `main` at `215ae250`. The owner ruled the eight questions of §6 on 2026-11-05 (§7). No build starts before the ADR amendment is accepted.

## 1. Goal

An author typing a calculated-point formula — on the template Calculations tab, the asset **Add calculated point** panel, the asset list's bulk wizard, and the per-point override wizard — sees, beside the field, what the field's grammar admits and what formulas already exist for the chosen key, and can take either with one click. Two halves:

1. **Formula help** — a list, per dialect in force, of the operators, the functions (with arity), the reference forms, the `@` scopes (`v2+`), the `$key` parameter and the window forms (`v3`), one parsed example each, click to insert. Generated from `@bms/shared`'s own calc-dsl constants (`CALC_FUNCTION_ARITY`, `CALC_AGGREGATE_FNS`, `CALC_SCOPE_KINDS`, `CALC_WINDOW_FNS`, `CALC_CALENDAR_WINDOWS`, `CALC_ROLLING_UNITS`) and from the existing `V2_REFERENCE_FORMS`, with a spec that parses every example under its dialect, so a function the parser gains or loses reddens the spec rather than drifting. Plus **function-name completion** in the CodeMirror editor (today only `{key}` and `@scope` complete).
2. **Suggested formulas** for the chosen point key — the stock catalog's derived points for that key, and the derived points of the organization's published templates of the asset's domain that declare that key — each labelled with where it comes from and with the input keys the asset does not have, one click to take (formula + dialect).

**Out of scope (recommended):** any change to the grammar, the parser or the validator; a new column anywhere (no `default_formula` on `bms.point_keys`); a copilot card or prompt change; caret-position insertion inside CodeMirror (a `forwardRef` API through the lazy boundary — append-at-end via the existing `onChange` serves every surface identically, see Q3); replacing the override wizard's plain `<input>` with the editor; the KPIs tab unless Q1 says otherwise.

## 2. Facts measured from the code

- **The editor** (`apps/web/src/components/asset-templates/formula-editor.tsx`, 457 lines) is the only CodeMirror importer (`tests/adr-0038-formula-editor.test.ts` scans every import form). Its `autocompletion({ override: [completions, scopes] })` has two sources: `{` → `completionKeys(rules)` and `@` → `scopeCompletions(rules)`. No function-name source. Every rule it reads lives in `apps/web/src/lib/formula-editor-rules.ts` (346 lines) and is inside the coverage denominator (`vitest.config.ts` `include: apps/web/src/lib/**`); the `.tsx` is outside it.
- **The vocabulary is already constants, all exported from `@bms/shared`** (`packages/shared/src/calc-dsl/limits.ts`): `CALC_FUNCTION_ARITY` (`abs` 1, `round` 1, `min`/`max` 2..20, `clamp` 3), `CALC_AGGREGATE_FNS` (`sum`, `avg`), `CALC_SCOPE_KINDS` (`site`, `domain`, `group`), `CALC_WINDOW_FNS` (`sum`, `avg`, `min`, `max`, `delta`), `CALC_CALENDAR_WINDOWS` (4), `CALC_ROLLING_UNITS` (`m`/`h`/`d`), `MAX_ROLLING_WINDOW_DAYS` 366, and the predicates `isCrossAssetDialect` / `isParameterDialect` / `isWindowDialect`. `hours` is a parser literal, not in any constant (`parser.ts:263`), and the operator glyphs are the tokenizer's private `SINGLE_CHAR_TOKENS` (`tokenizer.ts:82`, not exported). So functions, scopes and windows can be *generated*; `hours` and the four operators are restated and must be held by a parse/tokenize check in the spec.
- **The existing teaching** is `V2_REFERENCE_FORMS` (two entries, each parsed by `runReferenceFormsTests` in `formula-editor-rules.spec.ts:378`) rendered as an ad-hoc `<ul>` in three places — `calculations-tab.tsx:253`, `kpis-tab.tsx:466`, `point-calc-override-panel.tsx:209` — followed by `V3_PARAMETER_HELP` / `V3_WINDOW_HELP` (`apps/web/src/lib/template-calc-config.ts:137,155`). `calculations-tab.spec.tsx` and `kpis-tab.spec.tsx` assert on that text; `point-calc-override-panel.spec.tsx` does not.

### PR 1 — key tasks (TDD: spec first, then the code)

1.1 **`apps/web/src/lib/formula-help.ts`** (new). Export `type FormulaHelpEntry = { group: "operator" | "function" | "reference" | "scope" | "parameter" | "window"; label: string; says: string; example: string; insert: string }` and `formulaHelpEntries(dialect: CalcDialect): readonly FormulaHelpEntry[]`. ## 6. Open questions for the owner (rule one at a time; recommended answer in bold)
