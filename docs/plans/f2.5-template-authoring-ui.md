## 1. Goal

Build the entire asset-template authoring surface in `apps/web`, which today does not exist in any form — no client, no page, no route, no reference. Two routes: `/admin/asset-templates` (a list grouping versions under their `code`, filterable by status) and `/admin/asset-templates/:id` (a lifecycle-aware detail page of **exactly five tabs**: Details · Points · Calculations · KPIs · Alarms). Inside it, one reusable `<FormulaEditor>` built on CodeMirror 6 serves **both** authored-formula surfaces — `template_points.formula` and `content.kpis[].expression` — with two distinct validation contexts, inline errors placed by the parser's `position`, syntax highlighting driven by the *existing* `tokenize()`, `{pointKey}` autocomplete, and a live preview that calls `evaluate()` from `@bms/shared` so the browser and the API's write-time validation can never disagree about what a formula computes. The page makes the draft → published → archived lifecycle a visible state, never a disabled-field detail: a published version is read-only and its primary action is **Edit this version** (`POST /:id/draft`). The API, the database schema and the seeds are untouched.

## 2. Explicitly out of scope

Straight from ADR 0038 *Not in this ADR*, plus two the constraints add:

- **No API change, no migration, no seed change (D8).** `templatePointBodySchema` (`apps/api/src/admin/asset-templates/asset-templates.schema.ts:33`) already accepts every F2.4 calc column, and `AssetTemplatesAdminController` already exposes all nine routes. **If implementation finds it needs an endpoint or schema change, that is a signal the plan drifted — surface it, do not act on it.**
- Per-asset overrides of formula / trigger / staleness → `F2.6`.
- Version-change propagation to already-instantiated assets → `F2.6`.
- Bulk tag mapping and the Excel mapping sheet → `F2.7`. The Points tab edits `sourceDataKeyPattern` one row at a time.
- Maintenance plan authoring (`content.maintenance`) — open in the contract, but no ruling exists on where it is authored. `maintenance-schedules-panel.tsx` is a **different entity** (maintenance *schedule* templates that generate work orders) and must not be conflated or reused as a model for entity semantics.
- Dashboard widget authoring → `F3.1`. No `dashboards` tab; `sortOrder` on the Points tab is the whole of it.
- **No `health` tab, no `optimisation` tab.** The API validator *rejects* those sections (`RESERVED_SECTIONS`, `asset-templates-content.schema.ts`). A tab that always errors is worse than no tab.
- A second rule builder. The Alarms tab is **class-level authoring** on a template; ADR 0034 records that no `automation_rules` row links back to a `TemplateAlarm`. Do not read or build it as a way to edit live rules.
- `F2.8` (PUE), backfill, new RBAC.
- **No sweep of the other ~30 pages to `React.lazy`.** `echarts` and `leaflet` stay eagerly bundled. The lazy boundary is scoped to the authoring route only.

**Two findings the ADR does not address.** Both are handled in the plan below and both are also flagged as owner questions:

1. **`PATCH /:id` replaces `content` wholesale.** `updateAssetTemplateBodySchema.content` is optional but is *not* a merge. The KPIs tab and the Alarms tab both write `content`. If either sends only its own section, stored `content.maintenance` and `content.dashboards` are **destroyed** — and maintenance authoring is explicitly out of scope, so this UI would silently delete content it refuses to edit. Unit 6 fixes this with a read-merge-write helper.
2. **`tokenize()` throws on partially-typed text.** An unbalanced brace is the *normal* intermediate state while a user types. An uncaught throw inside a CodeMirror `ViewPlugin` breaks the editor, and no pure test in `lib/` will see it. Unit 5 wraps it explicitly.

## 4. Serial or parallel

**Predominantly serial, with exactly two real fan-out points.**

F2.5 is not marked ⭐ in `BACKLOG.md` (`F2.1` and `F2.3` are), so the enabler rule does not literally apply. But `build-operating-model.md` §3's *reason* does: **Units 4, 5 and 7 each define an interface every later unit hangs off** — the validation result shape, the `<FormulaEditor>` prop contract, and the tab-shell contract. **Build those three hands-on, inline, not via a cold `implementer` subagent.** A subagent inventing the `<FormulaEditor>` prop shape without the ADR conversation produces a seam five tab components then inherit.

The two genuine fan-outs:

- **Unit 5 ∥ Unit 6.** Disjoint files (`components/asset-templates/` + `apps/web/package.json` vs. four new `lib/` modules), no shared symbol. Unit 5 is the hands-on one; Unit 6 is a clean cold hand-off to a Sonnet `implementer` under TDD.
- **Unit 9a–9e, the five tabs.** One file per tab is what *makes* this parallel; five tabs inside one page file parallelizes nothing. Only after Units 5, 6 and 7 have merged, each in its own git worktree, each `model: sonnet`.

Everything else runs serially on one feature branch. Pass `model:` on every dispatch — an unpinned agent inherits the Opus session.

### Unit 4 — Formula validation core, the two contexts (D4) · **INTERFACE UNIT — hands-on**

Serial. Every later formula-touching unit hangs off this module's result type. **Do not delegate cold.**

**Files**
- `apps/web/src/lib/template-formula-validation.ts` — **create**
- `apps/web/src/lib/template-formula-validation.spec.ts` + `.test.ts` — **create**

**Why `lib/` and not inside the component:** the root `vitest.config.ts` coverage `include` reaches `apps/web/src/lib/**` and nothing above it, and `apps/web/vitest.config.ts` runs `environment: "node"` with `include: ["src/**/*.test.ts"]`. Logic in a `.tsx` is both untestable here and invisible to the gate. `apps/web/src/lib/vocabulary.ts`'s docblock already argues this; follow it.

**Naming trap:** `apps/web/vitest.config.ts` includes `src/**/*.test.ts` — a `.test.tsx` wrapper is **never discovered**, while `tests/repo-invariants.test.ts` would still see the pair and pass. So **every spec/wrapper pair in `apps/web` stays `.ts`**, and no `.spec.tsx` is created anywhere in this item.

**Do not port `findUnresolvedContentRefs`.** It lives in `apps/api/src/admin/asset-templates/asset-templates-content.schema.ts:412` and walks the whole content tree. The client needs only the KPI-scoped subset over the `points[]` array it has already fetched: set membership, three assertions. State this in the module docblock or a reviewer will read it as duplication of an API-owned walker.

**The exported shape** (frozen here, consumed by Units 5, 9c, 9d):
```ts
type FormulaDiagnostic = { message: string; from: number; to: number };
type FormulaValidation =
  | { state: "ok"; refs: string[] }
  | { state: "error"; diagnostics: FormulaDiagnostic[] }
  | { state: "unvalidated" };          // D9 — never an error
```

**Test cases (all concrete, all gating).** Fixture template points: `A` measured, `B` measured, `D` derived, `SELF` derived.

| # | Case | Input | Assertion |
|---|---|---|---|
| 1 | **valid formula** | derived mode, `"({A} + {B}) / 2"` | `state === "ok"`, `refs` deep-equals `["A","B"]` |
| 2 | **unknown ref** | derived mode, `"{A} + {ZZZ}"` | `state === "error"`; exactly one diagnostic; `from === 6` (offset of `{`) and `to === 11` — see case 8 for why the literals |
| 3 | **ref to a derived sibling** | derived mode, `"{D} * 2"` | error; message says a derived formula may only reference **measured** points; and the self-reference variant `"{SELF} + 1"` on point `SELF` produces the *distinct* "references itself" message. Both mirror `templatePointsBodySchema.superRefine` (`asset-templates.schema.ts:159–171`) — the editor applies the same rule or the user learns it from a 400 |
| 4 | **unused `pointKeys` entry** | KPI mode, expression `"{A}"`, `pointKeys: ["A","B"]` | error attributed to `pointKeys`, message matching `templateKpiSchema`'s "Every entry in pointKeys must be referenced by expression at least once". **This is the half a naive editor misses** |
| 5 | **ref not in `pointKeys`** | KPI mode, `"{A}+{B}"`, `pointKeys: ["A"]` | `unknown_reference` at `B`'s offset — the other direction of the two-way check |
| 6 | **ref not declared by the template** | KPI mode, `"{A}"`, `pointKeys: ["A"]`, but `points[]` has no `A` | error — this is the `findUnresolvedContentRefs` half. A KPI ref must be in `pointKeys` **and** in `points[]` |
| 7 | **unbalanced brace** | `"{A"` | Assert **which path it takes**, not merely "it errors": `tokenize("{A")` **throws** `CalcTokenizeError` with `parseError.code === "unterminated_reference"` and `position === 0`, while `validateFormula("{A", ["A"])` returns `{ ok: false }` without throwing. The wrapper under test returns `state:"error"` and **never throws** |
| 8 | **position-accurate placement** | `"1 + {NOPE} + 2"` | one diagnostic, `from === 4`, `to === 10`. Derive the range as `position` and `position + text.length + 2` for a `ref` token (braces are not in `text`), `position + text.length` for every other kind, `0` for `eof`. **Take the numbers from the first red run and then assert them as literals** — never compute the expected offset inside the test from the same code under test |
| 9 | **`"unvalidated"` dialect** | KPI mode, dialect `"unvalidated"`, expression `"whatever ###"` | `state === "unvalidated"`. **Never an error.** D9: opening a template to fix an alarm message must not reject a KPI the author did not touch |
| 10 | **opt-in upgrade, both directions** | `validateKpiExpression` | on a parse success returns the *new* KPI object with `dialect: "bms-calc-v1"`; on failure returns `{ok:false, diagnostics}` and the input object is **unchanged** — assert deep-equality against a frozen copy. Nothing is written on failure: not the dialect, not the expression |

**Test first**

`calc-decorations.spec.ts`:
1. `"{A} + 1"` → three decoration ranges; the `ref` range is `{from:0,to:3}` (braces included, `text.length + 2`), the `number` range is `{from:6,to:7}`.
2. A number token keeps its **source** length: `"1.50 + {A}"` → the number range is `{from:0,to:4}`, not the length of `String(1.5)`. `tokenizer.ts:121` stores the raw slice; a plugin that used `numberValue` would mis-highlight.
3. `eof` produces **no** decoration.
4. **`safeTokenize("{A")` returns `[]` and does not throw** — the ViewPlugin runs on every keystroke and an unbalanced brace is the normal intermediate state. An uncaught throw inside a `ViewPlugin` breaks the editor and no pure test would otherwise see it.
5. `safeTokenize("2 @ 3")` (`unexpected_character`) also returns `[]`.

`calc-preview.spec.ts`:
1. `"{A} * {B}"` with `A=2, B=3` → `6`.
2. A missing typed value → the evaluator's `missing_input` refusal surfaces as a preview message, not a crash.
3. `"{A} / {B}"` with `B=0` → `non_finite`, refused **at the divide node** (ADR 0037), and the preview shows the refusal rather than `Infinity`.
4. `-0` normalises to `0`.
5. Preview is **pure** — the module imports nothing that fetches. Assert no network symbol is referenced; the ADR is explicit that a template has no asset until `F2.2` instantiates it, so there is no live reading to read.

**Implementation notes**
- Import `EditorView` from `codemirror`, plus `linter`/`Diagnostic` from `@codemirror/lint`, `autocompletion` from `@codemirror/autocomplete`, `ViewPlugin`/`Decoration` from `@codemirror/view`. All of these resolve through the meta-package's transitives — do **not** add them as separate `package.json` lines.
- **Do not import `basicSetup`. Compose from `minimalSetup`.** Ruled by the owner on 2026-08-21, recorded as **ADR 0038 Amendment 1**. Verified against the published source of `codemirror@6.0.2`: `basicSetup` imports and uses `highlightSelectionMatches` and `searchKeymap` from `@codemirror/search`, so importing it would make D7's tree-shake claim false and Unit 10 step 2 unpassable. `minimalSetup` uses neither.

  ```ts
  const extensions = [
    minimalSetup,          // specialChars, history, drawSelection,
                           // syntaxHighlighting, default + history keymap
    autocompletion({ override: [pointKeyCompletions] }),
    linter(calcLintSource),
    calcHighlightPlugin,   // ViewPlugin over safeTokenize()
    EditorView.editable.of(!readOnly),
  ];
  ```

  `minimalSetup` already carries `history`, so **Ctrl+Z works** and D7's undo requirement is met without `@codemirror/commands` appearing as its own import. The 13 `basicSetup` extensions this drops — line numbers, fold gutter, bracket matching, rectangular selection, crosshair cursor, active-line highlight — are chrome for a code file, not for a one-line expression. **`@codemirror/search` must never be imported by this module.** That is what keeps Unit 10 step 2 a real assertion.
- Highlighting is a `ViewPlugin` mapping `safeTokenize()` output to `Decoration.mark`. **No Lezer grammar** — that would mean `@lezer/generator` as a build dependency and a second definition of the same syntax.
- The `linter()` source calls Unit 4's validator and maps each `FormulaDiagnostic` straight to a CodeMirror `Diagnostic` `{from,to,severity:"error",message}`.
- Autocomplete completes `{pointKey}` from the props' resolvable keys — in derived mode, **measured siblings only**.
- Props (frozen here): `{ value, onChange, mode: "derived" | "kpi", resolvableKeys, kpiPointKeys?, readOnly, dialect }`. `readOnly` is how D3 is honoured on a published template.
- `formula-editor-lazy.tsx` is the **first `React.lazy` + `<Suspense>` in this app.** There is no existing example to copy. Give it a real fallback (a sized skeleton, not `null` — a zero-height fallback makes the tab jump) and keep it in its own file so the static invariant in Unit 8 can assert that nothing else imports CodeMirror.

**`template-lifecycle.ts`** — `capabilities(status)` → `{ editable, actions }`. Test cases:

**`template-authoring-access.ts`** — D10's role half, built on `admin-access.ts`. Test cases:

## 9. Risks

1. **Bundle size — the highest-consequence risk, and the one the ADR made measurable.** ~3.1 MB unpacked is on-disk source plus types plus source maps, and *"it is the wrong number to reason about"* — **no shipped figure has ever been measured here.** If the lazy chunk does not actually split, or `@codemirror/search` does not tree-shake, every dashboard and control-room route pays for an editor they never open. Mitigations: the Unit 8 static invariant (no eager import), the Unit 10 measurement, and the separate `formula-editor-lazy.tsx` file. **A tree-shake failure is a real finding to report, not a formality to wave through.**
2. **The `Suspense` boundary is a genuine architectural first.** There is no `React.lazy` and no `Suspense` anywhere in `apps/web` today — no example to copy, and no existing failure mode to reason from. Specific hazards: a `null` fallback collapsing the tab height; the boundary placed at page level so Details blanks while a chunk loads; a chunk-load failure (offline, stale deploy) with no error boundary, which in React surfaces as a blank page rather than a message. Add an error boundary around the lazy tab bodies, and verify the fallback in the browser by throttling the network.
3. **The five-tab limit violated by accident.** A tabbed authoring page is *exactly* the thing that quietly opens a closed section — the ADR says so in its Context. The realistic vectors are: someone adding a `dashboards` tab because `content.dashboards` exists in the contract; someone adding `health` because the DTO's `content` is `z.record(z.unknown())` and accepts it client-side; or the tab registry being built dynamically from content keys, which would make the invariant unreadable **and** open all three at once. Mitigations: the registry is a literal array, the Unit 8 invariant reads it, and the invariant has an anti-vacuity guard.
4. **`PATCH /:id` destroying unowned content.** Covered by Unit 6, but it is the highest-probability *silent* defect in this item — nothing errors, the data is simply gone. The spec case asserting an unknown key survives a KPI edit is the gate.
5. **`tokenize()` throwing inside the ViewPlugin.** Covered by `safeTokenize`, but note the shape of the risk: it fires on the *normal* intermediate state of typing, and no pure test in `lib/` sees a broken editor. Only the browser pass proves it.
6. **A legacy draft holding a reserved section is unsaveable through this UI.** A row written before ADR 0019 tightened the validator can hold `content.health`; `GET` returns it (the DTO is a bare record) but any `PATCH` is rejected by `RESERVED_SECTIONS`. Render the API's message — it names the blocking item (`E1.1` / `E1.6`) — and **never strip the section to force a save.** Also an owner question below.
7. **Coverage ratchet turning CI red mid-branch.** New `lib/` modules land inside the denominator the moment they exist. Ship each spec in the same commit as its module; do not batch the tests to the end.
8. **A 500-point template in an editable grid.** The ADR's 16–20 effort explicitly buys headroom for this. If the Points tab renders 500 controlled inputs without virtualisation or per-row state isolation, every keystroke re-renders the grid. Keep row state local to the row.
