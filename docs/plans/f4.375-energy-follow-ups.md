## 2. Plan-gate questions — ruled 2026-11-15 (owner, in chat, one at a time; option A each time)

Q1, Q5, Q6 and Q7 widen Amendment 2's words; they are recorded in the amendment's "Plan-gate rulings" paragraph.

1. **Q1 — what the Total load tile shows. Ruled A ("Server figure").** The tile shows the server's `totalKw` (4 s poll). The socket keeps the Live/Stale pill and the chart tail. The tile and its "vs yesterday" line then use one definition. Cost: the figure refreshes every 4 s instead of every frame; the Copilot tool description loses its socket sentence. (Rejected: B keep the socket sum; C filter the socket by shown assets.)
2. **Q2 — do other power keys count in the hide predicate? Ruled A ("kw only").** "Energy shown" is itself defined by `kw` (decision 2), so a hidden widget never has fresh data to show. Consequence: on a pump-station layout the Electrical tab loses "Total load" and keeps Frequency, the three cost tiles and the daily cost chart. (Rejected: B a wider key list.)
3. **Q3 — where the widget is hidden. Ruled A ("Site page + wall").** The Dashboards viewer (`/dashboards/:slug`) and the builder draw every stored widget, so an author can find and edit it. (Rejected: B the viewer too.)
4. **Q4 — the hole a hidden tile leaves. Ruled A ("Close the gap").** Inside a uniform tile row — tiles with the same `gridY` and `gridH` to the right move left by the hidden width; any other arrangement is left as stored. +0.25 day. (Rejected: B leave the hole.)
5. **Q5 — the organization page's KPI strip. Ruled A ("Hide when none").** Hide a kW-only strip tile when no site of the organization in the caller's scope shows energy (same predicate; the strip reflows by itself). +0.15 day. (Rejected: B leave the strip.)
6. **Q6 — the `PATCH` path for the two settings. Ruled A ("One path only").** `PATCH`'s strict body refuses both keys; the Edit dialog loses the two selects; both roles use the new **Energy settings** dialog. Every change then has one audit shape that the organization's own admins can read (today's `master.organization.update` rows carry no organization id). This moves the control off the Edit form (decision 6's wording). (Rejected: B two paths.)
7. **Q7 — the two load charts. Ruled A ("Hide when none").** Do not draw the estate "Campus load" card when the KPI read says `energyShown: false`, and do not draw the organization "Load · last 60 minutes" card when no site of that organization shows energy. Web only, +0.15 day. (Rejected: B leave both.)

Also ruled: the learned-interval product issue (§9 risk 11) becomes backlog row `F4.376` (needs an ADR 0075 amendment; not built here).

## 3. Design decisions (no ruling needed)

| # | Decision | Why |
|---|---|---|
| D1 | **Contract:** `dashboardKpisSchema` gains `energyShown: z.boolean()` (required) and `totalKw` becomes `z.number().nullable()`. `energyShown` = at least one location in scope shows energy. `totalKw` is `null` when it is false, and `null` (not `0`) when it is true but no shown asset has a `kw` value. | The location summary's own vocabulary (decision 4). Nullable alone cannot tell "`on`, no meter" (tile with `—`) from "not shown" (no tile); a flag alone leaves a false `0` on the wire for the Copilot tool to repeat. |
| D2 | **One rule.** SQL returns per-location facts; a new `isEnergyShown(energyFeatures, hasEnergyData)` in `energy-features.ts` decides, and `resolveLocationEnergy` calls it. No `CASE` copy of the rule in SQL. | F4.364 D2: "SQL returns facts; one table-tested rule". |
| D3 | **Card parity.** The ribbon's population is the cards': in-scope assets at **active** locations. `kpis(scope).totalKw` equals the sum of the non-null `totalKw` of `locationKpis(scope)` (before the cards' rounding), and `energyShown` equals `items.some(energyShown)`. | One testable invariant. **Behaviour change beyond the filter:** `kw` of an asset at an inactive location no longer counts (it does today). Listed as risk 2. |
| D4 | `prior.totalKw` sums over the locations shown **now**. `priorTotalKw` and `readKpiPrior` take the shown location ids. | The delta must compare one population (`kpi-prior.ts` docblock). |
| D5 | An empty scope answers `energyShown: false, totalKw: null`. | No location shows energy. |
| D6 | `kpis()` returns `Promise<DashboardKpis>`. | The service cannot drift from the contract. |
| D7 | **First load.** While the KPI read has never answered, the tile is drawn in its loading state; after that it follows the last answer (TanStack keeps `data` across refetches). | Hiding while pending would make the tile pop in for every energy user. A no-energy user sees one skeleton leave once — never a value. |
| D8 | **The predicate** (`apps/web/src/lib/energy-widgets.ts`): a widget is kW-only when the list `[...points.map(p => p.pointKey), ...sources.map(s => typeof s.params.pointKey === "string" ? s.params.pointKey : null)]` is **not empty** and every entry is exactly `"kw"`. A source with no `pointKey` parameter counts as "not kW". | Ruling 2's words. The not-empty guard matters: `every` over an empty list is true, and a mimic, trend strip, alarm rail and legend bind nothing. Exact match keeps `it_kw`, `site_kw`, `kwh_today` drawn. |
| D9 | `DashboardLiveCanvas` gets `energyShown?: boolean` (default `true`) and filters **inside** the tab-slice memo, before `useDashboardTelemetry`. `SiteDashboardView` gets a **required** `energyShown`. | A hidden widget is not read. A required prop makes the compiler name both call sites. |
| D10 | A tab that had widgets and now shows none says "No widget on this tab is shown while energy is not shown for this site." (`role="status"`, `data-testid="site-energy-hidden-tab"`). | "This tab has no widgets yet." would be false and invites a duplicate. |
| D11 | **Route:** `PUT /api/v1/admin/organizations/:id/energy-settings`, body `{ energyFeatures, cardPrimaryMetric }` — both required, `.strict()`. **Audit action:** `master.organization.energy_settings.update`, `organization_id` = the organization, payload `{ from: {…}, to: {…} }`, written in the same `withTenant` transaction. Unchanged values write nothing (no `UPDATE`, no audit row). 403 before any read: "Only an administrator of this organization can change its energy settings". | Amendment 2 leaves the choice to the plan. A dedicated route keeps the appearance body a two-key theme body (`null` = inherit does not fit a NOT NULL enum), follows the `appearance` / `colour-profile` / `ingest` precedent, and gives one action one meaning. The no-op rule is `setIngestEnabled`'s. |
| D12 | Web gate: a new `canEditOrganizationEnergySettings(role)` (`admin`, `organization_admin`) in `lib/admin-access.ts`, its own predicate. After a save: invalidate `["admin","organizations"]`, `["dashboard","locations"]` and `["dashboard","kpis"]`. | The file's stated convention; the cards and the ribbon follow without waiting for a poll. |
| D13 | **The flake fix pins the cadence, not the clock.** A fixture RTU whose subject is not the unknown-cadence path gets `expected_interval_seconds = 1` (window = the 25 s floor; configured wins over learned). The unknown-cadence cases are restaged so that no fixture sample can enter a completed hour. | The judging clock is Postgres `now()` and `date_trunc('hour', now())` inside product SQL. Vitest fake timers do not move it, and the fixture times are already relative to it — so neither "fake timers" nor "times relative to a fixed now" reaches the cause. Changing the `learned` CTE instead is ADR 0075 Amendment 3 territory and is not done (row `F4.376`). |
| D14 | No new file under `tests/`. | Nothing to add to `tsconfig.typecheck-tests.json` or `.github/workflows/ci.yml`. If the build adds one, both are wired in the same commit. |
