# F4.57 — `time` becomes the receive time, `device_time` keeps what the RTU said

Worktree: `.claude/worktrees/F4.57-ingest-clock-skew`, branch
`F4.57-ingest-clock-skew`. Governing record:
[`docs/adr/0061-ingest-receive-time-and-device-time.md`](../adr/0061-ingest-receive-time-and-device-time.md),
decisions 1–8 and Amendment 1. Backlog row `F4.57`: ⬜, P1, effort 2–3, Wave 1,
no `Depends`, not a ⭐ enabler.

## Goal

Every row the ingest host writes to `telemetry.point_values` carries the host's
receive time in `time`, and the device's own timestamp — unclamped — in a new
nullable `device_time timestamptz`. Nothing reads the new column yet. The
dashboard and map recency windows and the four continuous aggregates become
correct **without being edited**, because `time` now means what they always
assumed. A device timestamp the host cannot read still counts
`invalidTimestamp`. The in-batch dedupe keys on the stored primary key, and a
collapse names the first `(assetId, pointKey)` it discarded.

## Q1 — blocking, owner's to answer

**The disk-buffer replay path is not covered by ADR 0061, and decision 2 applied
literally breaks ADR 0016 Amendment 4.**

Evidence, all verified in this worktree:

- `apps/ingest/src/host/disk-buffer.ts:325-341` `serialise()` writes the **spill
  instant** into the line's `at` when a sample carries none. Its own comment:
  *"replay must write the same `(time, asset_id, point_key)` every time, or a
  re-replayed segment lands duplicate rows instead of an idempotent upsert."*
- `disk-buffer.spec.ts:267` and `:319-320` pin that stamp.
- `supervisor.ts:715-727` `replayLoop` calls `writeSamples` per 500-sample
  slice; `main.ts:165` then calls
  `resolveSamples(samples, index, new Date(), soleDeviceKey)`.
- ADR 0016 Amendment 4 decision 5: *"Replay is safe because `writeResolved` is
  `ON CONFLICT DO UPDATE`: a replayed row is idempotent."* Decision 8: a
  mid-segment failure *"re-replays at most one minute, idempotently."*

Four consequences of `time = receivedAt` on that path:

1. A replayed sample that never had a device timestamp gets
   `device_time = spill instant` — a **fabricated** device time, which decision 4
   says the column must never carry and ruling 2 refused to invent.
2. Every replayed row takes the **replay instant**, so an hour of backlog lands
   within seconds. Every recency window reads the whole backlog as "now".
3. A re-replayed segment gets a new `new Date()`, a new primary key, and writes
   **duplicate rows**. ADR 0016 Amendment 4 decisions 5 and 8 become false in
   writing, and `disk-buffer.ts:330-333` becomes a false comment.
4. Within one `writeSamples` call all rows share one `time`, so two buffered
   samples for one point in one 500-slice collapse. ADR 0061 §Context measured
   zero collisions on the **live** path; the replay path batches by
   construction.

**The options:**

- **(a) The original arrival.** The buffer already records it. The segment line
  carries it in its own field, `at` becomes optional on disk, and the host passes
  a per-sample receive time into `resolveSamples` through a host-internal shape —
  **not** `SourceSample`, because `adapter-contract.spec.ts:414-418` forbids an
  adapter fabricating a time. A segment-format change under ADR 0016 Amendment 4
  decision 7, so an amendment plus a Fable-ladder unit. Segments already on disk
  at deploy are ambiguous, so the deploy step must check `buffered = 0` first.
- **(b) The replay instant.** No code beyond the ADR, but consequences 1–4 must
  be recorded as accepted, ADR 0016 Amendment 4 decisions 5 and 8 amended, and
  decision 4 gains a fourth case.

The ADR's own reasoning points to (a) — ruling 2 refuses to invent a device
timestamp, and ADR 0016 requires idempotent replay. **Tasks 1–2 are independent
of the answer. Do not start Task 3 until it is answered**, because Task 3 is the
commit that changes what a replayed row means.

## Two observations, no ruling needed

**Observation 1 — decision 5's counter never fires on the MQTT wire.**
`mqtt.ts:188-196` already drops a non-finite or invalid `ts` before the
normaliser sees it, returning no `at`; `mqtt.spec.ts:151` pins that. So on MQTT
an unreadable `ts` is decision 4 case 2, not case 3, and `invalidTimestamp`
stays 0. Decision 5 is worded at the normaliser boundary and this plan tests
there. Record it for `F3.16`.

**Observation 2 — decision 6's "so the host log can name it" depends on an
existing gate.** `main.ts:171-174` logs `samples discarded` only when
`droppedCount(counters) > 0`. A collapse is not a drop, so a collapse-only batch
logs nothing. The datum will be on the counters and appears whenever that log
fires. Making the log fire on a collapse alone is one guarded `logger.warn` in
`main.ts` with no unit test. **This plan does not add it.**

## Step 6 — verification on the running stack

Coordinate first: the compose stack is shared with the session building `F3.49`.
`0069` adds a nullable column, harmless to its suites; `up -d ingest` restarts
only ingest. Say so before doing it. Run one heavy gate at a time. Compose runs
from the repo root and Postgres is on **5433**; build the ingest image from the
**worktree** with absolute `-f` and context paths and `--no-cache`, then start it
from the root with `--no-build`, or the container serves `main`'s code.

**Deployment order is load-bearing: migrate first, then the ingest image.** A new
image against an un-migrated database fails every INSERT, the `F1.10` buffer
spills to disk, and the replay then meets Q1 in production.

1. Before migrating: `buffered = 0` on the health endpoint for every endpoint.
2. `pnpm db:migrate`. Then as `bms_fleet` (never `bms_owner`; `docker exec -i`
   for a heredoc): the column exists and is nullable; `count(*) WHERE device_time
   IS NOT NULL` = 0; the primary key is unchanged; `timescaledb_information.chunks`
   shows compressed chunks — the case CI cannot reach.
3. Idempotency, live: apply the file a second time, expect
   `NOTICE: column "device_time" ... already exists, skipping` and exit 0. Hash
   the file against `__drizzle_migrations`.
4. Baseline `count(*) WHERE time > now()` and note the time.
5. Build, tag, `up -d --no-build ingest`. Check the container's `Created` time is
   after the commit and `grep -c device_time` in the container's compiled output
   **before** reading any log line.
6. Within two minutes: `count(*) WHERE device_time IS NOT NULL` > 0 and growing;
   every such row has `time <= now()`; no `samples discarded` line names
   `duplicateInBatch > 0` — a non-zero here is a finding, not a pass.
7. After five minutes and again after ~40: step 4's count has not grown and
   trends to 0.
8. Derive each RTU's offset **from the new rows themselves**, joining
   `bms.asset_points → bms.rtus`: per `r.code`, `avg/min/max(device_time - time)`
   and a count. Pass criterion: within one RTU the spread is seconds, and the
   RTUs are consistent **relative to one another**. Do **not** compare to the
   2026-08-22 numbers — the ADR forbids pinning to them, and a re-synced device
   would fail a correct build.
9. Both directions of decision 4: `device_time IS NULL` is 0 for MQTT assets
   after the cutover, and non-zero for simulator assets, which bypass the
   normaliser.

**API — N/A by decision 7**, with one observation that is not a gate: the five
enabled RTUs' tiles read online inside the 20 s / 25 s windows once `time` is
receive time. **Browser — N/A.** No web change.
