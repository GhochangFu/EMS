## 0. Goal and out of scope

**Goal.** Make the Energy Consumption report run itself. Migration `0078` creates `bms.report_schedules` tenant-scoped from birth and gives `bms.report_files` its `schedule_id` and the `(schedule_id, period_end, format) WHERE schedule_id IS NOT NULL` idempotency row. A pure `reports/report-period.ts` computes, in the schedule's IANA zone over `Intl.DateTimeFormat`, the next run instant and the previous-complete-unit period (daily; weekly on Monday over the seven local days ending Sunday; monthly on day 1 over the previous calendar month). Two queues join `ALL_QUEUES` and the worker host in slot order: `reports-dispatch` (fleet, repeatable every `REPORT_DISPATCH_INTERVAL_MS`, claims due rows `FOR UPDATE SKIP LOCKED`, enqueues one `reports-render` job per row, then advances `next_run_at`) and `reports-render` (tenant; loads the schedule under RLS, resolves `location_ids` to asset ids under RLS, renders on the fleet pool exactly as the controller does, writes one `report_files` row and one object per format skipping a format whose unique row exists, prunes to `REPORT_RETENTION_PER_SCHEDULE`, then emails the files through `EmailTransport` with `NotificationMessage.attachments` under a `REPORT_EMAIL_MAX_BYTES` ceiling, landing the outcome on `report_files.delivery_status` / `delivery_error`). A loop-free `ReportsCoreModule` (`ReportsService`, `ReportRenderService`, `ReportDispatchService`, `CalcParametersService` **as a provider, never `CalcModule`**) is imported by `WorkerModule` beside `RuleSweepModule` and by `ReportsModule`. Five routes — `GET|POST /api/v1/reports/schedules`, `GET|PATCH|DELETE /api/v1/reports/schedules/:id` — with create/edit gated on manage rights over every named location and `canManageNotificationChannel` for `channel_id`. The Reports page gains a Schedules section for users who can create one. Two counters join `countQueueJob`.

**Out of scope (named deferrals kept or added):** a weekday / day-of-month column (decision 7); CSV as a scheduled format; templates other than `energy_consumption`; a `bms.notification_deliveries` row for a report (decision 10); **catch-up of missed periods** after a worker outage (R-9, Q-3 — one run per due row per tick, never a backfill); the orphan sweep (ADR 0066 decision 11 — the worker now has its second job kind, so **the closure files the sweep row**; nothing here builds it); a presigned download; report files for asset-group-only users; a bundled Unicode font; a channel of kind other than `email` on a schedule (refused, R-12); a per-schedule "run now" route; a `last_error` column on the schedule (R-6 keeps the poison-row signal in the log).

- **R-6 — timezone validation, and the poison row.** `isValidTimeZone(zone)` in `report-period.ts`: `zone.includes("/")`, `new Intl.DateTimeFormat("en-US", { timeZone: zone })` constructs without `RangeError`, **and** `resolvedOptions().timeZone === zone` (exact case — E4.1b's ruling for `locations.timezone`; §8 measures whether ICU canonicalises `asia/kolkata`). The create and PATCH bodies carry it as a Zod `.refine(isValidTimeZone, { message: "timezone is not a known IANA zone" })`, so the 400 names the field. Inside the tick each row's `periodFor`/`nextRunAt` runs in its own `try`: a throw is one `warn` naming the schedule id and `err.name`, counted `skippedInvalid`, and **the row is left due and enabled** — a background job has no actor for the audit row a disable would owe, and one warn per tick per row is the bounded, Loki-retained signal; a PATCH re-validates the zone and clears it. An `enqueue` throw is **not** per-row: it aborts the tick (rows stay due, BullMQ retries).
- **R-7 — `report-period.ts` signatures and fixtures** (pure, `Intl.DateTimeFormat` only, no date library):
  - `export class ReportPeriodError extends Error` (`name = "ReportPeriodError"`; an unknown zone, an unparsable clock).
  - `export type LocalDate = { readonly year: number; readonly month: number; readonly day: number }`; `export type LocalClock = { readonly hour: number; readonly minute: number }`.
  - `export function isValidTimeZone(zone: string): boolean` (above).
  - `export function parseRunAtLocal(value: string): LocalClock` — accepts `HH:MM` and `HH:MM:SS` (what `pg` returns for `time`); seconds must be `00`.
  - `export function utcOffsetMinutes(instant: Date, zone: string): number` — `formatToParts` in `zone` → wall components → `Date.UTC(wall) − instant`.
  - `export function localDateOf(instant: Date, zone: string): LocalDate`; `export function formatIsoDate(date: LocalDate): string`; `export function addLocalDays(date: LocalDate, days: number): LocalDate` (calendar arithmetic via `Date.UTC`); `export function weekdayOf(date: LocalDate): number` (ISO: Monday = 1 … Sunday = 7).
  - `export function toInstant(date: LocalDate, clock: LocalClock, zone: string): Date` — two-pass offset resolution; a wall time inside a DST **gap** resolves to the first instant after the gap; a wall time in a **fold** resolves to the earlier occurrence.
  - `export function nextRunAt(schedule: { cadence: ReportCadence; runAtLocal: string; timezone: string }, now: Date): Date` — the first instant **strictly after** `now` whose local wall time is `runAtLocal` and whose local date satisfies the cadence (daily: any day; weekly: Monday; monthly: day 1).
  - `export function periodFor(cadence: ReportCadence, runAt: Date, zone: string): { periodStart: string; periodEnd: string }` — ISO dates: daily → the local day before `runAt`'s local date, both ends; weekly → the Monday..Sunday week strictly before `runAt`'s local date's week (the seven local days ending the previous Sunday); monthly → the calendar month before `runAt`'s local month.
  - `ReportCadence` is `import type … from "@bms/shared"` (U1's `z.infer`), never restated.
  - **Fixtures the spec pins** (values, not procedures): Asia/Kolkata daily `00:30`, `now = 2026-09-21T10:00:00Z` → `2026-09-21T19:00:00Z`, period `2026-09-21..2026-09-21`; daily `00:00`, `now = 2026-09-21T18:29:59Z` → `2026-09-21T18:30:00Z`, and `now = 2026-09-21T18:30:00Z` (exactly due) → `2026-09-22T18:30:00Z` (strictly after). Europe/London daily `06:00`: `now = 2026-03-27T12:00Z` → `2026-03-28T06:00Z` (GMT); `now = 2026-03-28T12:00Z` → `2026-03-29T05:00Z` (BST, the crossing); `now = 2026-10-24T12:00Z` → `2026-10-25T06:00Z` (GMT again); gap `01:30` on 2026-03-29 → `2026-03-29T01:30:00Z` (= 02:30 BST); fold `01:30` on 2026-10-25 → `2026-10-25T00:30:00Z` (the BST occurrence). Weekly Monday `07:00` Europe/London, `now = 2026-09-21T09:00Z` → `2026-09-28T06:00Z`, `periodFor` → `2026-09-21..2026-09-27`. Monthly `05:00` Asia/Kolkata, `now = 2026-09-21T10:00Z` → `2026-09-30T23:30:00Z`, `periodFor` → `2026-09-01..2026-09-30`; `periodFor("monthly", 2028-02-29T23:30Z /* Mar 1 05:00 IST */)` → `2028-02-01..2028-02-29`. `daily` on the run after the crossing: `periodFor("daily", 2026-03-29T05:00Z, "Europe/London")` → `2026-03-28..2026-03-28` (a 23-hour local day is still one day).
- **R-8 — who computes `next_run_at`, and Q-3.** The create route computes the first `next_run_at = nextRunAt(body, now)`. The tick computes the render period from the row's **due instant** — `periodFor(cadence, row.next_run_at, tz)` — so a tick that runs five minutes late still covers the right period, and advances with `nextRunAt(row, now)`: a row three days overdue is enqueued **once** for the period ending before its due instant, and its next run is the next occurrence after now. Missed periods are not caught up (out of scope). A PATCH that changes `cadence`, `runAtLocal` or `timezone`, **or turns `enabled` from `false` to `true`**, recomputes from now; any other PATCH leaves `next_run_at` alone. **Q-3 (owner, before U3):** skip missed periods (recommended — a queue that never promises exactly-once should not promise catch-up either; a "run now"/backfill route is a later row) or enqueue every missed period?
- **R-9 — the render job's shape.** Phase A in `ctx.tx`: `SELECT … FROM report_schedules WHERE id = $scheduleId` (RLS-scoped — a foreign or deleted row is absent) → absent or `enabled = false` → one `info` with counts, outcome `skipped`, no continuation. Asset ids: `location_ids = {}` → `SELECT id FROM bms.assets` on `tx` (the policy bounds it to the organization); else `WHERE location_id = ANY($location_ids)`. For each format in `REPORT_FILE_FORMATS` order that the row names: the unique row exists → counted `skippedExisting`; else `ReportsService.energyPdf|energyXlsx({ startDate: periodStart, endDate: periodEnd }, assetIds)` (fleet pool, as the controller), `describeBuffer` (sha256, byteSize), `reportFilename(periodStart, periodEnd, format)` — **never the schedule name (Amendment 1 item 12: the `Content-Disposition` filename is quoted, not escaped, and the only writers build it from two bounded dates and an enum)** — `fileId = randomUUID()`, `buildReportObjectKey`, `putObject`, insert with `created_by = NULL` (a schedule runs as the system, not as its author — an author deactivated later would otherwise stamp rows for years; `created_by` is the schedule's, readable through `scheduleId`), `schedule_id`, `location_ids` copied from the row, `delivery_status = 'none'`, then `countReportFileWritten(format)`. Prune: `SELECT id, object_key FROM report_files WHERE schedule_id = $id ORDER BY created_at DESC, id DESC OFFSET $retention` on `tx` → delete those rows, collect keys. Any throw in phase A deletes every object this run put (best-effort, one warn per key naming the file id — the rows cannot commit because the throw aborts the transaction, so no committed-row re-check is needed; say so in the docblock) and rethrows. Continuation (phase B/C, `finish(outcome)`): delete the pruned keys best-effort (warn, orphan sweep row); then delivery (R-11).
