# F4.164 — four shell states made visible to keyboard and screen-reader users

Plan by `plan-architect` (Fable), 2026-09-27, from the `F4.164` row
(`docs/BACKLOG.md`) and the owner's step-2 ruling: no ADR; markup, ARIA and one
visual label change; no dependency, schema or API change. Measured at
`b257a95b`. Not an enabler; serial, one worktree, one PR.

## 1. Goal and out of scope

**Goal.** `AppShell`'s locked Settings entry becomes a focusable button with
`aria-disabled="true"`, an accessible description carrying the reason, and
text at ≥ 3:1 on `bms-green-dark`. `KpiTile`'s error branch carries
`role="alert"`; its stale caption follows the stale ring instead of
`status === "ready"`. Every pending button that swaps its label carries
`aria-busy` while pending, and a `tests/` scan reddens on a new site without
it. Every sidebar link carries `aria-label={label}`, and a path-keyed override
table makes the 23 collapsed codes unique, gated by a spec over the full list.

**Out of scope.** The `disabled:opacity-60` token (D4). Buttons disabled while
pending with a static label (OQ-2). `F4.160` (the general no-network gate for
shell specs). `AGENTS.md` §5 wording for the focusable-disabled affordance (a
later `chore(agents):` PR). Anything under `packages/*`, `apps/api`,
`apps/ingest`.

## 3. Units, in build order

### U1 — `KpiTile`: the error is an alert; the caption follows the ring (Sonnet)

Files: `apps/web/src/components/kpi-tile.tsx`; create `kpi-tile.spec.tsx` and
`kpi-tile.test.tsx` (jsdom wrapper, ADR 0042 d2); prose sweep in
`dashboard-page.tsx` and `dashboard-page.spec.tsx`.

Tests first, one claim per `it()`:
- K1 `status="error"` → `getByRole("alert")` has text "Could not load".
- K2 `status="ready" value="12"` → no alert; "12" present.
- K3 `stale status="loading"` → the stale caption is present (red today).
- K4 `stale status="error"` → the caption is present beside the alert.
- K5 `stale status="ready"` → caption present.
- K6 `stale={false} status="ready"` → caption absent; value present.

Change: the error `p` gets `role="alert"`; the caption renders on `stale` alone.

**D1.** The caption shows in every status: the ring already draws for any
truthy `stale`, and the caption explains the ring. The caller decides whether a
non-ready tile is stale.

Mutations: revert the role → K1; revert the caption guard → K3; drop the guard
→ K6.

### U2 — the locked Settings entry (Opus)

Files: `apps/web/src/layouts/app-shell.tsx`; `app-shell.spec.tsx`

Tests first (role `operator`, scope `GLOBAL`, within the navigation):
- S9 `getByRole("button", { name: "Settings" })` has `aria-disabled="true"`.
- S10 the button has the accessible description `SETTINGS_LOCKED_REASON`.
- S11 the button takes focus and is not natively disabled.
- S12 no `link` named "Settings" for `operator`.
- S13 `organization_admin` gets the `/admin` link and no button.
- S14 the button class has `text-white/70`, not `text-white/50`.

**D2.** `DisabledCommandButton` is reused in language, not as the component:
it sets native `disabled` (not focusable), has no reason slot, and its palette
is for light surfaces.

Mutations: span back → S9; native `disabled` → S11; drop `aria-describedby` →
S10; button for `organization_admin` → S13; `text-white/50` → S14.

### U3 — collapsed rail: `aria-label` on every link, unique letters (Opus)

Files: `apps/web/src/layouts/app-shell.tsx`; `app-shell.spec.tsx` /
`app-shell.test.tsx`.

Change:
1. `COLLAPSED_LABEL_OVERRIDES` beside `temporarilyHiddenModulePaths`, keyed by

3. Exported `collapsedRailEntries()` — every item of both lists, hidden ones

Tests first:
- L1 the codes of `collapsedRailEntries()` are unique; the message names the
  duplicates (red today).
- L2 `collapsedRailEntries().length >= 23`.
- L3 every override key is the path of some entry.
- L4 (collapsed, `admin`, `GLOBAL`) every sidebar link's `aria-label` equals

- L5 (collapsed) exactly one link named "Dashboards" and one named "Dashboard".
- L6 (collapsed) the visible codes are unique and "Dashboards" reads "DS".
- L7 (expanded) "Dashboards" reads "Dashboards".

One render covers every role: visibility rules only remove items, and `admin`

Mutations: delete an override → L1, L6; rename a key → L3; drop `aria-label` →
L4/L5; `collapsedRailEntries` returns `[]` → L2. Run the four `tests/` text

### U4 — `aria-busy` on every pending label-swap button (Sonnet)

Rule: the `<button>` whose children swap the label on a pending flag gets
`aria-busy={<the same flag>}`; the label swap stays.

Sites (all under `apps/web/src/`): 43 on `X.isPending`, 3 on a local
`deleting` (`asset-image-gallery.tsx`, `report-history.tsx`,
`report-schedules.tsx`), 1 on `listQ.isFetchingNextPage` (`alarms-page.tsx`).
The U5 scan is the authoritative list. In `asset-templates-page.tsx` the
per-row import hoists `importingThis` for both label and `aria-busy`.

Tests first: `report-schedules.spec.tsx`, `report-history.spec.tsx` and
`assets/mapping-sheet-panel.spec.tsx` each gain a pending `aria-busy="true"`
case and an idle `aria-busy="false"` case.

**D4.** The opacity token is not changed: WCAG exempts inactive components,
the defect is the unannounced state, and no opacity value reaches 3:1 — the
lever is the palette. The owner declined a follow-up row (OQ-3).

### U5 — `tests/` gate: a pending button without `aria-busy` reddens (Opus)

Files: create `tests/f4.164-pending-buttons-aria-busy.test.ts`; add it to the
root `typecheck:tests` script with `pnpm pkg set`.

Design: walk `apps/web/src/**/*.tsx` (no `.spec.`/`.test.`), cut `<button` …
`</button>` segments, split the opening tag from the children at the first `>`
at brace depth 0 (not a bare regex — `onClick={() => …}` sits in the tag),
collect pending identifiers in the children, and require an `aria-busy={…}` in
the tag that names each one. Export
`pendingButtonsMissingAriaBusy(src): string[]`.

Tests:
- G1 a synthetic button with an arrow in `onClick`, a multi-line pending label
  and no `aria-busy` → one finding.
- G2 the same with `aria-busy={X.isPending}` → none.
- G3 `aria-busy={Y.isPending}` for a label on `X.isPending` → one finding.
- G4 `deleting ? "Deleting…" : "Delete"` without `aria-busy` → one finding.
- G5 the real tree has no findings; the message lists `file:line`.
- G6 the real tree has at least 47 pending-button segments.

Mutations: remove one site's `aria-busy` → G5; a bare `>` splitter → G1.
