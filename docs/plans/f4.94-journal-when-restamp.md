## 1. Goal

Journal entries `idx 57–62` in `packages/db/drizzle/meta/_journal.json` are stamped 2026-09-05T12:33 … 2026-09-10T12:33 UTC — a hand-made `+86400000` step that overtook the wall clock. Drizzle applies a file only when `Number(lastDbMigration.created_at) < migration.folderMillis`, where `lastDbMigration` is the row with the largest `created_at` (`drizzle-orm/pg-core/dialect.js:57-67`). So a `0063` generated today with `when = Date.now()` sorts *below* `0062` and is skipped, without an error, on every database that has already run `0062` — dev and the PHE pilot — while still running on a fresh CI database. This row (1) re-stamps the six entries into real past time, (2) adds a pre-flight to `packages/db/src/migrate.ts` that pushes the journal's `when` values into `drizzle.__drizzle_migrations.created_at` by hash before `migrate()` runs, so existing databases stop blocking, (3) adds a fourth invariant — `when` not ahead of now — to the shared journal gate both hooks import, and (4) adds a `tests/` invariant that reads the real journal and asserts all of it.

**Shape** — two exports, one pure, one thin, so the fake client sees only the SQL:

```ts
import { readMigrationFiles } from "drizzle-orm/migrator";

/** The two columns of a `drizzle.__drizzle_migrations` row the pre-flight reads. `created_at` is bigint, so `pg` hands it back as a string. */
export interface AppliedMigrationRow { readonly hash: string; readonly created_at: string | number | null }
/** The two fields of drizzle's `MigrationMeta` this uses. */
export interface JournalStamp { readonly hash: string; readonly folderMillis: number }
export interface JournalResync {
  readonly restamps: ReadonlyArray<{ readonly hash: string; readonly from: number; readonly to: number }>;
  readonly blockingStrays: ReadonlyArray<{ readonly hash: string; readonly createdAt: number }>;
}
/** The subset of `pg.Client` the pre-flight needs; `pg.Client` satisfies it structurally. */
export interface StampQueryable {
  query(text: string, values?: unknown[]): Promise<{ rows: unknown[]; rowCount: number | null }>;
}

/** Pure. Rows whose stamp differs from the journal (matched by hash), and rows the journal does not know that still sit ahead of its last entry. */
export function planJournalResync(applied: ReadonlyArray<AppliedMigrationRow>, journal: ReadonlyArray<JournalStamp>): JournalResync;

/** F4.94. Runs on the `bms_app` connection `main` already holds, before `migrate()`, and issues no SET ROLE (ADR 0045 decision 3). */
export async function resyncJournalStamps(
  client: StampQueryable,
  journal: ReadonlyArray<JournalStamp>,
  log: (line: string) => void = (line) => console.error(line),
): Promise<JournalResync>;
```

`resyncJournalStamps` does, in order:
1. `SELECT to_regclass('drizzle.__drizzle_migrations') AS present` — NULL means a fresh database (drizzle creates the table itself); log `F4.94 journal re-sync: no drizzle.__drizzle_migrations yet, nothing to do` and return the empty plan. No `CREATE`, no `SET ROLE`.
2. `SELECT hash, created_at FROM drizzle.__drizzle_migrations` → `planJournalResync(rows, journal)`, comparing `Number(created_at)` — the same coercion drizzle uses.
3. For every restamp: `UPDATE drizzle.__drizzle_migrations SET created_at = $2 WHERE hash = $1 AND created_at <> $2` with `[hash, to]`, exactly as ruled. No explicit transaction: every statement is guarded and the whole thing is idempotent, so a crash halfway leaves the next run to finish — and `main()` throws before `migrate()` runs, so nothing is applied against a half-fixed table.
4. Log one line per restamp — `F4.94 journal re-sync: <hash[0..12]> created_at <from> -> <to>` — then always a summary `F4.94 journal re-sync: <n> row(s) re-stamped` (the `0` case is what verification step (iv) reads). For each blocking stray: `F4.94 WARNING: drizzle.__drizzle_migrations row <hash[0..12]> (created_at <n>) is not in the journal and is ahead of the journal's last entry (<max>). Drizzle will skip every migration stamped below it. Delete or re-stamp that row by hand.` Warn-only is the plan's proposal (§10 Q1) — a deployment must not be refused over bookkeeping the script cannot repair safely, and the warning names the row.

stderr via `console.error`, matching `migrate.ts:74` and the `refresh-aggregates.ts:90-95` precedent; the style hook accepts it. `main()` becomes:

```ts
const migrationsFolder = resolve(pkgRoot, "drizzle");
try {
  await resyncJournalStamps(client, readMigrationFiles({ migrationsFolder }));
  await migrate(db, { migrationsFolder });
} finally {
  await client.end();
}
```

Add a short paragraph to the header JSDoc (why the pre-flight exists, the dialect.js line, and that it runs as `bms_app` because `bms_app` owns the table) — but keep the literal `resyncJournalStamps(` out of comments (see (d) below).
