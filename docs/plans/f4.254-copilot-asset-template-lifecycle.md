## 1. Goal

Make five asset-template lifecycle routes copilot catalog entries with wizards — `assetTemplate.create`, `.draft`, `.archive`, `.importStock`, `.instantiate` — each proposable by the model, confirmable from the dock with the `via: copilot` audit mark, and submittable by a person through a `WizardShell` on the pages that today run them as direct mutations; give the four routes that stay manual (`migrate`, `seeded-rules/reapply`, `default-dashboards`, `migration-preview`) and the asset-point bulk update a permanent exclusion reason; move the instantiate body to `packages/shared/src/contracts/` so the catalog can hold it by identity; add the resolver's deploy-authority variant so a `location_admin` can be offered an instantiate card on a site it manages; and raise the tool-definition cap to 48,000 with the reason recorded.

**Out of scope:** any new catalog entry beyond the five (ruling 2); a multi-target card or a `list_rtus`/template read tool (no ADR names one; see §10 risk 3); the propose-time template-status check and the card's 160-character value cut (`F4.246`); `If-Match` (`F4.247`); the `DELETE /admin/asset-templates/:id` draft delete (decision 3, `NO_DELETE`); the Versions and migration page (untouched — its routes stay manual); `F4.252`'s union-body message (the instantiate body here is one object with a refinement, so its Review message is the refinement's own sentence).
