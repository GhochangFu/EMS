## 1. Goal

Every asset's health read shows the **five SOW §4.3 inputs**, each with an honest status: operational conditions (the `E1.3` rule score, unchanged), historical performance (anomaly history, advisory), maintenance records (open corrective work orders and how many are past SLA; a fact, zero weight), environmental factors ("No source yet") and equipment utilisation ("No rated duty set"). Beside the unchanged rule score an asset may show one **advisory figure**: the rule score minus a capped anomaly penalty. A new compact card, **"Bad actors — advisory"**, lists the top 5 assets by anomaly evidence in the last 7 days, with a second tab, **"Lowest health score"**, for the 5 lowest rule scores. The plant and enterprise view shows a **count** of assets that lose points, never an average. Everything is computed at read time in `apps/api`. Every failure of the new reads is quiet.

**Out of scope** (the amendment's "Not in this amendment"; named so nobody builds it):
- Any change to `E1.3`'s score, bands, donut, `GET /asset-health/assets/:assetId`, `GET /asset-health/summary`, `scoresByLocation` or the `assets.health.score` metric.
- Any threshold or detector constant. `ANOMALY_UNUSUAL_SCORE` is imported, never restated, never changed.
- An alarm, notification, work order, report, export, copilot answer or copilot tool from the advisory figure or the list. Nothing is sent to `E1.9`'s AI paragraph.
- Scoring maintenance, environment or utilisation. A weather source. A rated-duty field on templates.
- A new widget kind, a new table, a migration, a grant, an npm or Python package, any `apps/ml` change, the owed `bms_ml` role.
- Any edit to an `E1.9` or `E1.6` file (`apps/api/src/ml/*`, `apps/api/src/ml-findings/*`, `apps/web/src/components/ml/*`, `apps/web/src/lib/ml-findings.ts`, `contracts/ml-*.ts`, `apps/api/src/advisories/*`). They are imported only.
- The card on the control-room wall or in a stock template.

## 3. Refinements (each is a call inside the amendment; veto at skim)

- **R-a — the new files live in `apps/api/src/asset-health/` as `health-inputs.*`, and the e1.4a gate is not edited.** The reads file composes `currentAnomalyScoresCte` (imported) and reads its `current_scores` rows, so it **never names `anomaly_scores`**. The gate "only `ml-anomalies.*` names the table" stays true as written. `E1.8`'s own containment test holds that the reads file does not name the table.
- **R-b — the web computes the asset card's advisory figure from the score it shows.** `GET …/inputs` returns the hours and the **penalty**; it does not recompute the rule score. The card calls one shared pure function, `advisoryHealthScore(ruleScore, penalty)` (`@bms/shared`), with the score from `E1.3`'s own response. So the figure on screen is always exactly "the score shown, minus the penalty", and the route costs two small reads. The API uses the same function for the list's rows and the count.
- **R-c — the constants live in `packages/shared/src/contracts/asset-health-inputs.ts`.** `HEALTH_ANOMALY_CAP = 0.05` and `HEALTH_ANOMALY_BASELINE_ONLY_WEIGHT = 0` (the name of the second is this plan's; the amendment names only the first). They are exported from the same barrel as `ANOMALY_UNUSUAL_SCORE`, so the import site is the same. Reason: `contracts/ml-anomalies.ts` is `E1.2`/`E1.9`'s file, and the penalty function that uses the constants lives in the health contract file.
- **R-d — the bad-actors route narrows the way the summary does, not with `AssetFilterScopeService.narrow`.** The handler reads `readableAssetIds` (or `readableAssetIdsInOrganization`) and builds the same `HealthLocationFilter`; the service calls the summary's own `assetsInScope`. So "N of M scored assets" has the donut's M. `narrow` does not filter on `assets.active` and returns `null` for an unfiltered admin, so it would give a different M.
- **R-e — the count is not a field of the summary response.** It rides on the bad-actors response (`scoredAssetCount`, `anomaly.losingAssetCount`). The summary response feeds the copilot tool `get_health_summary`, and decision 2 keeps the advisory number out of every copilot answer.
- **R-f — pending Q3: each row also carries "unusual hours in all".** The order stays the amendment's (strong, then Baseline-only, then asset code).
- **R-g — each fact has its own transaction.** The asset route runs the anomaly read and the maintenance read in two `withReadScope` calls, each in its own `try`. A failure gives `null` for that fact, one `warn` log line with a fixed message and the error's class name, and no error to the caller. The bad-actors route does the same for its anomaly half.
- **R-h — one response serves both tabs and the count.** The route scores every asset in scope once (the same three reads the summary runs), so M, N and both lists come from one instant. - **R-j — the caption shows in two places:** under the *Bad actors* list and under the asset card's advisory line. The amendment says "the card's caption".
- **R-k — a row that keeps its data shows a zero-penalty figure.** An asset with scored hours and no strong hour shows its advisory figure, equal to its rule score. That is what "the 28 assets … can never lose a point" looks like.
- **R-l — the maintenance and history rows say why they are empty in fixed words** (section 4.4). A failed read and an empty read look the same, as decision 9 asks.
- **R-m — the *Lowest health score* rows link to the asset's history page** (`assetHistoryPath`), with no range.
- **R-n — the *Advisory* pill sits in each row and beside the caption, not in the card header.** The second tab holds rule scores, and a header pill would label them advisory.

## 4. The rules, exactly

### 4.1 The window and the hours

- The window is `anomalyListSinceOf(undefined, now)`: the last 7 days, floored to the hour — the same hours the Anomalies page and the `E1.9` cards read.
- Per asset and hour, from `current_scores` (the newest succeeded run per hour and detector):
  - `baseline_marked` = the `baseline_mad` score ≥ `ANOMALY_UNUSUAL_SCORE`; `forest_marked` = the `isolation_forest` score ≥ it. Both names come from `ANOMALY_DETECTORS`, bound.
  - **scored hour** = an hour with at least one current row.
  - **unusual hour** = any detector ≥ the line.
  - **strong hour** = `baseline_marked AND forest_marked`.
  - **Baseline-only hour** = `baseline_marked AND NOT forest_marked`.

### 4.2 Penalty and advisory figure (`@bms/shared`, pure)

```ts
healthAnomalyPenalty({ scoredHours, strongHours, baselineOnlyHours }): number | null
  // scoredHours <= 0 → null
  // share = (strongHours + HEALTH_ANOMALY_BASELINE_ONLY_WEIGHT * baselineOnlyHours) / scoredHours
  // → min(HEALTH_ANOMALY_CAP, share)
advisoryHealthScore(ruleScore: number | null, penalty: number | null): number | null
  // either null → null;  else max(0, ruleScore - penalty)
```

No rounding on the wire. An asset **loses points** when `advisoryHealthScore(score, penalty) < score`.

### 4.3 The five inputs (fixed order, fixed status)

| `key` | `status` | Label on screen |
|---|---|---|
| `operational` | `scored` | Operational conditions — Scored |
| `historical` | `advisory` | Historical performance — Advisory |
| `maintenance` | `fact_only` | Maintenance records — Fact only, not scored |
| `environmental` | `no_source` | Environmental factors — No source yet |
| `utilisation` | `no_reference` | Equipment utilisation — No rated duty set |

### 4.4 Words on the asset card

- Operational: the score and band as today (no new words).
- Historical, with data: `<u> unusual hours in the last 7 days · <s> marked by both methods`, then, when the asset has a rule score, a smaller line **after** the score block: `With anomaly history: <advisory, 1 decimal %> · advisory` with `StatusPill label="Advisory" tone="info"`, then the caption `Only hours both detection methods mark are counted.` Without data: `No anomaly history to show.`
- Maintenance, with data: `<n> open corrective work orders · <p> past SLA` (`work order` for 1). Without data: `No open corrective work order to show.`
- No element of these rows carries a band, alarm or severity colour class.

### 4.5 The maintenance fact

Pending Q1(a): a ticket on the asset that is **open** (status not `resolved`, `closed` or `cancelled` — the `openWorkOrderWhere` rule) and **not linked by any `maintenance_history` row**. **Past SLA** = `sla_minutes` and `sla_due_at` both set and `sla_due_at < now` (the request's clock). An integration case holds this equal to `workOrderSlaState(...) === "breached"` for every fixture ticket. Zero open corrective tickets → `maintenance: null` (no zero on screen).

### 4.6 Bad actors — advisory

- From every scored asset in scope: keep those with `unusualHours > 0`.
- **Order:** `strongHours` descending, then `baselineOnlyHours` descending, then `assetCode` (plain code-unit order), then `assetId`.
- The top `HEALTH_BAD_ACTORS_LIMIT` (5) go out. `unusualAssetCount` is the number before the cut.
- **Row:** asset label fields, site (`assetLocationName`), `strongHours`, `baselineOnlyHours`, `unusualHours`, `scoredHours`, `lastUnusualAt`, `topPoints` (the last unusual hour's contributing points, the detectors' lists joined in detector order, no repeats, the first 3), `href` = `anomalyFindingHref(assetId, lastUnusualMs, asOfMs, <all those points>)`, `ruleScore` and `advisoryScore` (both `null` when the asset has no rule score), `weak` = `strongHours === 0 && baselineOnlyHours === unusualHours`.
- `losingAssetCount` = assets among **all** scored-hour rows (not only the top 5) that lose points (4.2).
- `caveat` = `BASELINE_ONLY_SENTENCE` when every unusual hour in scope is Baseline-only; `MIXED_SENTENCE` otherwise; `null` with no unusual asset. Both sentences are imported from `E1.9`'s file, never copied.
- On screen a `weak` row shows the words `Weak signal`.

### 4.7 Lowest health score (rule score, not advisory)

Assets in scope with `score !== null`, ordered by `score` ascending then `assetId`; the first 5. Each row: label fields, `score`, `band` (may be `null`), `scoredTagCount`. The tab says `Rule score only. Not advisory.`

### 4.8 The count line

`<N> of <M> scored assets lose points to anomaly history · advisory`, with the info pill. `M` = `scoredAssetCount`, `N` = `anomaly.losingAssetCount`. Shown only when the read answered, `anomaly` is not `null` and `N ≥ 1` (R-i).

### 4.9 Contract — `packages/shared/src/contracts/asset-health-inputs.ts`

```ts
export const HEALTH_ANOMALY_CAP = 0.05;
export const HEALTH_ANOMALY_BASELINE_ONLY_WEIGHT = 0;
export const HEALTH_ANOMALY_WINDOW_DAYS = ANOMALY_LIST_MAX_DAYS;        // derived, not restated
export const HEALTH_BAD_ACTORS_LIMIT = 5;
export const HEALTH_BAD_ACTOR_POINTS = 3;
export const HEALTH_ANOMALY_CAPTION = "Only hours both detection methods mark are counted.";
export const HEALTH_INPUT_KEYS = ["operational","historical","maintenance","environmental","utilisation"] as const;
export const HEALTH_INPUT_STATUSES = ["scored","advisory","fact_only","no_source","no_reference"] as const;
export const HEALTH_INPUTS = [/* the five { key, status } pairs of 4.3, in order */] as const;

const iso = z.string().datetime();
const count = z.number().int().nonnegative();
const unit = z.number().min(0).max(1);
const assetLabelFields = {                       // spread into each row, as `windowFields` is in health.ts
  assetId: z.string().uuid(), assetCode: z.string(), assetName: z.string(),
  assetRtuName: z.string().nullable(), locationId: z.string().uuid(), assetLocationName: z.string(),
} as const;

assetHealthInputSchema       = z.object({ key: z.enum(HEALTH_INPUT_KEYS), status: z.enum(HEALTH_INPUT_STATUSES) });
healthAnomalyHistorySchema   = z.object({ windowDays: z.number().int().positive(), scoredHours: z.number().int().positive(),
                                          unusualHours: count, strongHours: count, baselineOnlyHours: count, penalty: unit });
healthMaintenanceFactSchema  = z.object({ openCorrective: z.number().int().positive(), pastSla: count });
assetHealthInputsResponseSchema = z.object({ assetId: z.string().uuid(), asOf: iso,
                                          inputs: z.array(assetHealthInputSchema).length(5),
                                          anomalyHistory: healthAnomalyHistorySchema.nullable(),
                                          maintenance: healthMaintenanceFactSchema.nullable() });
healthBadActorSchema         = z.object({ ...assetLabelFields, scoredHours: z.number().int().positive(),
                                          unusualHours: z.number().int().positive(), strongHours: count, baselineOnlyHours: count,
                                          weak: z.boolean(), lastUnusualAt: iso,
                                          topPoints: z.array(z.string().max(128)).max(HEALTH_BAD_ACTOR_POINTS),
                                          href: z.string().max(2000), ruleScore: unit.nullable(), advisoryScore: unit.nullable() });
healthLowestScoreSchema      = z.object({ ...assetLabelFields, score: unit, band: healthBandSchema.nullable(),
                                          scoredTagCount: z.number().int().positive() });
healthBadActorsAnomalySchema = z.object({ windowDays: z.number().int().positive(), unusualAssetCount: count,
                                          losingAssetCount: count, caveat: z.string().max(300).nullable(),
                                          items: z.array(healthBadActorSchema).max(HEALTH_BAD_ACTORS_LIMIT) });
healthBadActorsResponseSchema = z.object({ asOf: iso, scoredAssetCount: count,
                                          lowestScores: z.array(healthLowestScoreSchema).max(HEALTH_BAD_ACTORS_LIMIT),
                                          anomaly: healthBadActorsAnomalySchema.nullable() });
```

`anomaly: null` means the anomaly read failed, or the scope is empty. `anomaly` with `items: []` means the read answered and no asset has an unusual hour.

**Encoding (§4.8 / ADR 0030), named so a reviewer checks it:** every schema is one plain `z.object`. There is no `A & B` type to encode and no all-readonly object, so neither `z.intersection` nor `.readonly()` applies. The label fields are a field map spread into each row's one `z.object` (the `windowFields` shape in `contracts/health.ts`); nothing is built with `.merge()` or `.omit().extend()`. **None is `.strict()`** — unlike `contracts/health.ts`: these are new responses, and `E1.8d`/`e` will add keys an older bundle must still parse (the `ml-*.ts` rule). `healthBandSchema` is embedded by reference and stays `.strict()` as it is. `key` and `status` are `z.enum`. Types are `z.infer`, exported from this file. One `export * from "./asset-health-inputs";` line in `contracts/index.ts`; `packages/shared/src/index.ts` is not touched.

```sql
-- anomalyHealthHoursStatement(ids, sinceMs): one row per scored asset among ids
<currentAnomalyScoresCte(ids, sinceMs)>          -- imported; recent_runs, scored (LATERAL … OFFSET 0), current_scores
, hours AS (
  SELECT asset_id, bucket,
         bool_or(score >= $U) AS marked,
         bool_or(score >= $U AND detector = $BASELINE) AS baseline_marked,
         bool_or(score >= $U AND detector = $FOREST) AS forest_marked
    FROM current_scores GROUP BY asset_id, bucket
), per_asset AS (
  SELECT asset_id, count(*) AS scored_hours,
         count(*) FILTER (WHERE marked) AS unusual_hours,
         count(*) FILTER (WHERE baseline_marked AND forest_marked) AS strong_hours,
         count(*) FILTER (WHERE baseline_marked AND NOT forest_marked) AS baseline_only_hours,
         max(bucket) FILTER (WHERE marked) AS last_unusual
    FROM hours GROUP BY asset_id
), last_rows AS (
  SELECT c.asset_id, jsonb_agg(c.contributing_points ORDER BY c.detector) AS last_points
    FROM current_scores c JOIN per_asset p ON p.asset_id = c.asset_id AND p.last_unusual = c.bucket
   WHERE c.score >= $U GROUP BY c.asset_id
)
SELECT p.asset_id AS asset_id, p.scored_hours::int AS scored_hours, p.unusual_hours::int AS unusual_hours,
       p.strong_hours::int AS strong_hours, p.baseline_only_hours::int AS baseline_only_hours,
       (extract(epoch FROM p.last_unusual) * 1000)::float8 AS last_unusual_ms, lr.last_points AS last_points,
       a.code AS asset_code, a.name AS asset_name, rtu.display_name AS asset_rtu_name,
       l.id AS location_id, l.name AS location_name
  FROM per_asset p
  LEFT JOIN last_rows lr ON lr.asset_id = p.asset_id
  JOIN bms.assets a ON a.id = p.asset_id
  JOIN bms.locations l ON l.id = a.location_id
  LEFT JOIN bms.rtus rtu ON rtu.id = a.rtu_id
 ORDER BY a.code, p.asset_id

-- openCorrectiveStatement(assetId, nowMs): the maintenance fact of one asset   (pending Q1(a))
SELECT count(*)::int AS open_corrective,
       (count(*) FILTER (WHERE w.sla_minutes IS NOT NULL AND w.sla_due_at IS NOT NULL
                           AND w.sla_due_at < to_timestamp($now::float8 / 1000)))::int AS past_sla
  FROM bms.work_orders w
 WHERE w.asset_id = $assetId::uuid
   AND w.status <> ALL($closed::text[])          -- ["resolved", ...TERMINAL_WORK_ORDER_STATUSES], bound
   AND NOT EXISTS (SELECT 1 FROM bms.maintenance_history h
                    WHERE h.asset_id = w.asset_id AND h.work_order_id = w.id)

-- assetLabelsStatement(ids): the labels of the lowest-score rows
SELECT a.id AS asset_id, a.code AS asset_code, a.name AS asset_name, rtu.display_name AS asset_rtu_name,
       l.id AS location_id, l.name AS location_name
  FROM bms.assets a JOIN bms.locations l ON l.id = a.location_id LEFT JOIN bms.rtus rtu ON rtu.id = a.rtu_id
 WHERE a.id = ANY($ids::uuid[])                  -- uuidArray(ids), imported from ml-forecasts.reads
```
