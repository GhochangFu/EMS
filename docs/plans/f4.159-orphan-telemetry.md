# F4.159 — kW sums count telemetry whose asset no longer exists

Short plan, session-written (owner ruling 2026-09-25: no ADR, no
`plan-architect` dispatch).

## The defect

`telemetry.point_values` and its continuous aggregates carry no foreign key to
`bms.assets`. A read that sums `kw` (or `site_kw` / `it_kw`) with a `null`
scope — a global user — and never joins `bms.assets` counts every `asset_id`
that still has a sample, including ids whose asset row is gone. A scoped user is
not affected: `AccessControlService` builds the scope from existing rows. Dev
database, 2026-09-25: two such ids (last `kw` 40 and 1) put `kpis.totalKw` at
2652.09 against 2611.09 for the assets that exist.

## Owner rulings (2026-09-25)

1. No ADR — a defect inside the existing contracts.
2. Population: **existing assets only** (a `bms.assets` row), with no active
   location filter. That is the population `kpis` already uses for
   `sites_total` and `alarms_open`.
3. Scope: **the whole class**, not only the two reads the row named.
4. The Energy Centre reads leave `dashboard.service.ts` first (it sat at 994 of
   AGENTS.md §4.5's 1000 lines).
5. ADR 0070 gets Amendment 5 in this change set: decision 7's last sentence
   (orphan telemetry fails the cost read closed) is superseded. Ruled after the
   compliance review found the contradiction; ruling 1 predates it.

**Coupling (6, 4, 7).** `perAssetEnergy` is LEFT-joined on purpose (`E4.1c`
PR 1 review C1): its totals counted orphan ids, so an orphan row with a `null`
currency makes the cost `null` rather than smaller than the total. It turns
INNER in the same change as reads 4 and 7, never alone — alone, it brings C1
back in the report.

## The fix

The join goes **after** the `DISTINCT ON` / aggregate scan, in the step that
sums, so the measured scans (ADR 0025) keep their plans:
`INNER JOIN bms.assets a ON a.id = <cte>.asset_id` (the PUE reads join in the
pairing step). No contract, web, migration or seed change.

## Tests first

The join is unconditional, so a **scoped** read with an orphan id in the scope
list gates it deterministically; a live caller never passes such an id, but the
SQL is the same for `null`. Each case pairs the orphan with a real-asset
positive control and asserts the result equals the result without the orphan.

- `kpi-prior.integration.spec.ts` (rolled back): reads 1, 2 scoped; plus both
  at `null` scope under `REPEATABLE READ`, as a delta against a baseline
  (the shared database carries the simulator's live `kw`).
- `energy-cost.integration.spec.ts` (committed fixture, which already seeds an
  orphan): D6 turns — the orphan no longer changes `totalKwh` and the cost is
  priced; new cases for reads 3, 5, 7, 8.
- `pue-ratio.integration.spec.ts`: reads 9, 10 with an orphan pair.

Each case reddens when its own join is removed (mutation per read).
