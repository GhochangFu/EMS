Written by plan-architect (Fable), 2026-11-07, against `main` at `1c737dd1`

## 1. Goal

An MQTT RTU connects without TLS **only** when its stored config carries the
literal `tls: false` **and** its broker host is on the operator's
`MQTT_PLAINTEXT_HOSTS` list (ADR 0114 rulings Q1–Q4). One parser and one
decision predicate in `@bms/shared` serve `apps/ingest`, `apps/api` and the API
worker, so the three processes cannot disagree. Ingest skips an unlisted
`tls: false` RTU as `plaintext-host-not-allowed` and never falls back to TLS;
discovery and the onboarding validator refuse the same case with a fixed
message and the refusal class `plaintext not allowed`; a plain RTU is
disclosed by a "Plain MQTT" pill, a "TLS: off — credentials and data cross the
network unencrypted" line, a `tls: false` record in the commit audit entry, and
one ingest `warn` per plain endpoint. Unset or empty `MQTT_PLAINTEXT_HOSTS` is
today's behaviour exactly.

**Out of scope.** The onboarding-agent defects `F4.327`/`F4.328`; any value in
the AWS `.env` (the owner sets `MQTT_PLAINTEXT_HOSTS=shapoorji.thinkiot.co.in`
through `bms-ctl` after merge — only the compose *pass-through line* is in
scope, PR 1 T1.7); the BCPL onboarding itself and the password rotation; a
per-organization allowlist, certificate pinning, plain mode for any other
protocol (ADR 0114 decision 8); a migration (none — `tls` is a JSONB key the
draft already writes); a dependency (none, `mqtt ^5.10.4` serves both schemes).

## 3. Drafter refinements (ADR 0114 lines marked *(drafter)*)

- **R1 (decision 3, endpoint key).** The TLS key stays `host:port` (unchanged
  for the whole fleet) and only a plain endpoint is keyed `mqtt://host:port`.
  A TLS RTU and a plain RTU on one host still never share a connection, and
  the disk-buffer directories, the health keys and every existing fixture are
  untouched. (Q1)
- **R2 (decision 1, parser).** As written (trim, lower-case, exact match, no
  wildcard, no port, no range, boot refusal on a bad entry) plus: an IPv4
  literal passes; a bracketed IPv6 literal and anything with `:`/`/`/`@`/
  whitespace is refused; the refusal message names the entry's **position**,
  never its text. One predicate, `mqttPlaintextDecision`, sits beside the
  parser so the four call sites share the rule.
- **R3 (decision 2).** `tls: z.boolean().default(true)` in `mqttConfigSchema`;
  the draft schema gains `tls: z.boolean().optional()` (so the string
  `"false"` is a schema issue, not a silent TLS connect) and stops calling
  `tls` draft-only.
- **R4 (decision 6, `/admin/rtus`).** `adminRtuDtoSchema` gains
  `tls: z.boolean().nullable()` (`null` = no connection row or not MQTT) from a
  LEFT JOIN on the list read. The edit form shows a read-only line and gains
  **no** field. (Q4, Q5)
- **R5 (decision 6, card wording).** A TLS RTU's card says `TLS: on.`; four
  pinned specs change. (Q2)
- **R6 (decision 4, `expected`).** `expected` gains `tls: z.boolean().optional()`;
  the route answers 409 when `(body.expected.tls ?? true) !== (draft tls !== false)`.
  A plain RTU needs an explicit `tls: false` in the hashed body. (Q3)
- **R7 (decision 7, docs).** `docs/env-inventory.md` (API, Worker, Ingest
  tables) and `docs/ingest-host.md` (Environment table, skip reason, warning
  line, plain key format).
- **R8 (Consequences, the count).** A step in PR 1, run locally by the builder
  and on AWS by the owner.
