### 6.5 The interceptor (decision 4.5)

`copilot/copilot-change.interceptor.ts`, provided as `{ provide: APP_INTERCEPTOR, useClass: CopilotChangeInterceptor }` in `CopilotModule`. `intercept(context, next)`:

1. `context.getType() !== "http"` → `next.handle()` (the two Socket.IO gateways also receive `APP_INTERCEPTOR`).
2. No `X-Copilot-Change` header → `next.handle()` untouched.
3. Header present: not a uuid → 409; `req.user` absent → 409; `recalledIdentity(req.user)` null or role not one of the four → 403.
4. A query string on the request → 409 (release-1 catalog routes read no query parameters).
5. **Claim**, in `withUser(tenantDb, identity.id)`: `UPDATE bms.copilot_pending_changes SET status = 'applying', claimed_at = now() WHERE id = $1 AND user_id = $2 AND status = 'pending' AND expires_at > now() RETURNING method, path, body_hash, organization_id, catalog_id`. No row → 409 with one generic message.
6. Availability now, for the row's `organization_id` (`decide(identity, organizationId)`; never null) → not available: compare-and-set back to `pending` (`WHERE id = $1 AND status = 'applying'`), 403.
7. Compare `req.method` and the **raw `req.path`** (Express path, prefix included, no query, **no decode**) against the stored path — the propose tool validated each path parameter against the route's parameter schema and stored the path with each parameter `encodeURIComponent`-encoded, so no `decodeURIComponent` (which throws `URIError` on a malformed `%` and would leave the row `applying`) runs here — and `bodyHash(req.body, entry.clientOnly)` against `body_hash` → any mismatch: set back to `pending`, 409.
8. `store.change = { via: "copilot", changeId }`; `return next.handle().pipe(tap(body => record("applied", status, resourceId = typeof body?.id === "string" ? body.id : null)), catchError(err => { record("failed", statusOf(err)); return throwError(() => err); }))`. **`statusOf`: `err instanceof HttpException ? err.getStatus() : err instanceof ZodError ? 400 : 500`** — the global `ZodErrorFilter` (`main.ts:39`) turns a `ZodError` into a 400, and the row must record what the client saw. `record` runs in its own `withUser` transaction with `WHERE id = $1 AND status = 'applying'`, writes `finished_at`, `result_status`, `resource_id`, then (PR 8) triggers the follow-up turn.

## 8. PR 6 — daily usage limits (decision 11, drafter choice 2) — **gated on ADR 0099 Amendment 1**
