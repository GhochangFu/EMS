## 1. Goal

Replace the single-shot JSON `handleOpenAiTurn` in `apps/api/src/admin/onboarding/onboarding-chat.service.ts` with a tool-calling loop inside `POST /api/v1/admin/onboarding/sessions/:id/chat`: model → tool calls → model, until a final text or a cap (8 tool calls, 45 s). Tools edit an in-memory copy of the session draft through the existing element schemas; `propose_commit` records a proposal bound to a SHA-256 of the stored draft; server code commits only when the next user turn is the exact phrase `confirm commit` (or the Commit button). Each draft write adds a code-written `action` message (new `role` in the shared contract), rendered as a small line in the web chat. **Amendment 1:** three providers behind the port — `openai`, `openrouter` (the `openai` package with `baseURL https://openrouter.ai/api/v1`) and `anthropic` (`@anthropic-ai/sdk ^0.131.0`, a new dependency) — chosen per chat turn by a resolver: an organization row in the new tenant table `bms.organization_llm_settings` (key encrypted with `CredentialCryptoService`) wins; with no row the `.env` platform default (`LLM_PROVIDER` + the per-provider key and model) applies; `off` and an incomplete row mean the guided (rule-based) mode. A new admin route group `/api/v1/admin/organizations/:orgId/ai-assistant` (GET, PUT, DELETE, POST `/test`) and a new web page let an organization admin set provider, model and key. A provider error discards the turn's edits and runs the rule-based path with a one-sentence notice; the 45 s deadline keeps completed edits and does not fall back. One structured log line per turn, no text. The key never appears in a response, a log, an audit row, an error or the chat.

**Out of scope** (ADR §Consequences, Deferred, and Amendment 1 Deferred): templates (`F3.22`), point-key/mapping Q&A (`F3.23`), protocol discovery (`F3.24`), per-step confirm/rollback (`F3.25`), retrieval (`F3.26`), rule-based parity (`F3.27`), streaming, per-organization cost limits, a global-admin platform setting in the UI (the platform default stays in `.env`), model lists fetched from providers, a sidebar change (`F3.29` stays open), any change to `handleRuleBasedTurn`'s behaviour, any change to the Excel upload / `PATCH draft` / `validate` / `commit` routes or the commit transaction, the backlog close and the `chore(agents):` sweep (separate PRs).

### Q1 — where the proposal lives, the hash, the clearing rule (unchanged)

- **Store:** top-level `_commitProposal` on `onboarding_sessions.draft`, beside `_secrets`: `{ draftHash /* 64 hex */, summary, proposedAt }`. Read back with `commitProposalSchema.safeParse` → `null` on any mismatch.
- **Not forgeable by a client:** `patchDraftBodySchema` parses through `onboardingDraftSchema`, which declares no `_commitProposal` and strips unknown keys. **Not forgeable by the model:** tool arguments parse with element schemas that declare no such key; `propose_commit` takes no arguments; `OnboardingService.chat` writes the proposal, only when the loop reports one, hashed on the merged draft it is about to store.
- **Hash:** `sha256(canonicalJson(withoutCommitProposal(draft)))`, hex; `canonicalJson` sorts object keys (jsonb does not preserve key order). `exceedsDepth(draft, MAX_ONBOARDING_DRAFT_DEPTH)` → `null`. `_secrets` is inside the hash on purpose.
- **Clearing:** `mergeDraft` deletes `_commitProposal` on every call; `chat`, `patchDraft`, `uploadExcel`, `setCredentials` all write through it. `chat` re-attaches only when the turn proposed. Inside the loop, a successful write after `propose_commit` drops the pending proposal.
- **Stale:** `draftHash(session.draft) !== proposal.draftHash` → `STALE_PROPOSAL_REPLY`, proposal cleared, no commit.

### Q2 — the confirm phrase (unchanged)

`isConfirmCommitPhrase(m) = m.trim().toLowerCase() === "confirm commit"`. Order in `OnboardingService.chat`: `loadSession` + status gate → `looksLikeCredential` refusal → confirm check → org lookup → `handleTurn`. No model call, no rule-based turn on the confirm path. No proposal → `NO_PROPOSAL_REPLY`, messages stored, draft untouched. Stale → `STALE_PROPOSAL_REPLY`, proposal cleared. Match → `commitService.commit(jwt, sessionId)`; on success append `user`, `action` (`Committed: location <name>, N RTUs, …`), `assistant`; on `BadRequestException` reply `Commit refused: <message>`, clear the proposal, do not rethrow; `ForbiddenException`/`NotFoundException` propagate.

### Q3 — the port, the factory, the three adapters, the fake  (A1)

```ts
// onboarding-llm-port.ts
export type LlmProviderName = "openai" | "openrouter" | "anthropic"; // = llmProviderNameSchema.options in @bms/shared, re-exported not restated
export type LlmToolDefinition = { name: string; description: string; parameters: Record<string, unknown> };
export type LlmToolCall = { id: string; name: string; arguments: string }; // raw JSON text; the Anthropic adapter JSON.stringify()s block.input
export type LlmMessage =
  | { role: "system" | "user" | "assistant"; content: string }
  | { role: "assistant"; content: string | null; toolCalls: LlmToolCall[]; providerContent?: unknown } // A1: opaque, echoed back unchanged within the turn
  | { role: "tool"; toolCallId: string; content: string; isError: boolean };
export type LlmReply =
  | { kind: "tool_calls"; calls: LlmToolCall[]; content: string | null; providerContent?: unknown }
  | { kind: "final"; text: string };
export interface OnboardingLlmProvider {
  readonly name: LlmProviderName;
  complete(input: { messages: LlmMessage[]; tools: LlmToolDefinition[]; signal: AbortSignal }): Promise<LlmReply>;
}
export class LlmProviderError extends Error { constructor(message: string, readonly cause?: unknown) }
```

No `isConfigured()` any more and **no env read in any adapter**: the resolver decides whether a provider exists for this turn and builds it with its key and model.

- `OpenAiCompatibleProvider({ apiKey, model, baseURL? })` — dynamic `import("openai")`, `new OpenAI({ apiKey, baseURL })`, `create({ model, messages, tools, tool_choice: "auto" }, { signal })`; ≥1 `function` tool call → `tool_calls` (no `providerContent` — the generic form round-trips), else `final` with `content ?? ""`; missing `choices[0].message` → `LlmProviderError`; SDK rejections rethrown as-is. `createLlmProvider("openrouter", …)` is this class with `baseURL: "https://openrouter.ai/api/v1"` — pinned by a constant `OPENROUTER_BASE_URL` and a spec.
- `AnthropicProvider({ apiKey, model })` — dynamic `import("@anthropic-ai/sdk")`; the `system` `LlmMessage` becomes the `system` param; `user`/`assistant` text as-is; an assistant message with `toolCalls` → `{ role: "assistant", content: providerContent }` when present (always, within a turn), else rebuilt `tool_use` blocks; a run of `tool` messages → one `{ role: "user", content: [tool_result…] }` with `is_error` from `isError`; `tools` → `{ name, description, input_schema: parameters }`; the call shape in §2. Reply: `stop_reason === "refusal"` → `LlmProviderError("refusal")` (ruling 6 → guided mode); `max_tokens` → `LlmProviderError`; ≥1 `tool_use` block → `{ kind: "tool_calls", calls, content: joined text blocks, providerContent: response.content }`; else `final` with the joined text. `pause_turn` cannot occur (no server tools) and is treated as `final`.
- **History across turns stays text**: `buildHistory` never carries `providerContent`; only the loop's in-turn `assistant` messages do.

Testing without network: `FakeLlmProvider` (scripted replies, records every `messages` array, `behaviour: "reject" | "hang-until-abort"`); adapter specs mock the SDK module in the `.test.ts` wrapper (`vi.mock("openai")`, `vi.mock("@anthropic-ai/sdk")`) and capture `create`'s two arguments. `runAgentTurn` takes `{ maxToolCalls, deadlineMs }` so a spec can drive the deadline at 20 ms.

### Q3b — the resolver  (A2, A4)

`platformDefault()` reads `LLM_PROVIDER`, `OPENAI_API_KEY`, `OPENAI_MODEL` (default `gpt-4o-mini`), `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` (no default), `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`) on **every call** (specs toggle env per case). An unknown `LLM_PROVIDER` value is `incomplete` with `missing: "LLM_PROVIDER"`. `onModuleInit` logs **one** `warn` for the `incomplete` state: `{ variable: missing }` + "LLM platform default is incomplete; the onboarding agent is off" — the name, never a value; `off` logs nothing.

`resolveForOrganization(orgId)`: `withTenant(tenantDb, orgId, tx => select from organizationLlmSettings)` (a tenant read runs inside a transaction, §4.4). Row `provider = 'off'` → `null`. Row with provider, model and all four key columns → `crypto.decrypt(key_ciphertext, key_iv, key_version).apiKey` → `createLlmProvider(provider, { apiKey, model })`, `source: "organization"`. Row with provider ≠ off and no key (or no model) → `warn({ organizationId, provider }, "organization LLM setting is incomplete; guided mode")` and `null` — **never the platform key**. No row → `platformDefault()`; `ready` → provider with `source: "platform"`, else `null`. The decrypted key lives in the provider instance for the turn and is not cached.

### Q5 — the deadline and the two failure classes (unchanged, plus refusal)

An `AbortController` aborts at `deadlineMs`; its `signal` goes to every `complete` and is checked before each model and tool call. `signal.aborted` → `cap_time`: working draft and action lines kept, `STOPPED_EARLY_TIME_REPLY`, no fallback. Otherwise → `provider_error` (SDK rejection, `LlmProviderError`, **an Anthropic final `stop_reason: "refusal"**): `draftPatch {}`, `actionLines []`; the chat service runs `handleRuleBasedTurn` and prefixes `AGENT_UNAVAILABLE_NOTICE`. With no resolved provider (off, incomplete, no key) the rule-based path runs as now with no notice. `cap_calls`: the ninth tool call is not made; `STOPPED_EARLY_CALLS_REPLY`; edits kept.
