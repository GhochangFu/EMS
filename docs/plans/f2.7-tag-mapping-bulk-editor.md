## Goal

Ship ADR 0056's eleven decisions end to end: five nullable metadata columns on
`bms.template_points` and `bms.asset_points` with three within-row CHECKs each
(migration `0063`); a shared vocabulary (`QUALITY_POLICIES`, the five field
names, the `{token}` pattern grammar) declared once and wired into the API write
bodies, the merged-pair check, the ingest host, the Points tab, the stock
viewer, the mapping sheet and the instantiate dialog; the ingest host applying
quality policy → scale → finite → range per target and counting `outOfRange`;
`GET /admin/asset-points/mapping-sheet.xlsx?locationId=` exporting one location
as one `MAPPINGS` sheet seeded from the template pattern; `POST …/mapping-sheet/
preview` and `…/commit` (valid rows written, the rest returned by row and
column); `POST /admin/asset-points/bulk-update` (all-or-nothing, ≤ 500 ids); the
Asset Points page's row multi-select, "Edit selected" panel and mapping-sheet
panel; the Points tab's five template-default columns on a draft; and the
instantiate dialog collecting `sourceDataKeyVars` (closing `F4.56`).

**Out of scope, deliberately (ADR 0056 decision 11 and Q-rulings):** the
campus tier and asset parent/child (`F2.10`); any column on
`telemetry.point_values` (decision 5 — ADR 0050 is not amended); bulk import of
template points; scaling of `F1.8`/`F1.9` values; any change to how a `computed`
point is bound or evaluated; the operator surface for drop counters (`F3.16`);
persisting `sourceDataKeyVars` (ADR 0039 Q-A stands). Everything found beyond
the ADR is in §"Deferred", never built silently.

## Serial or parallel

## Design decisions settled at this gate

These are the plan's own calls, each reviewable. None re-opens an ADR decision.

1. **One vocabulary, three homes, declared once.**
   `QUALITY_POLICIES = ["discard_bad", "accept_bad"] as const` and
   `type QualityPolicy` live in `packages/shared/src/ingest.ts` (the zod-free
   module the host already imports; the policy is the host's own rule).
   `packages/shared/src/contracts/point-metadata.ts` builds
   `qualityPolicySchema = z.enum(QUALITY_POLICIES)`, `pointMetadataShape` (the
   five nullable read-side fields, **no bounds** — that file's own rule for
   read DTOs) and `pointMetadataFieldsSchema = z.object(pointMetadataShape)`.
   The two DTOs gain the five by **spreading `pointMetadataShape` into their
   existing `z.object({...})` literals** — not `.merge()`, not `.extend()`,
   not `z.intersection`: neither DTO is an intersection type, so there is
   nothing to preserve and a flattening combinator would only trip ADR 0030's
   source scan. Closed vocabulary by §4.8's test: what the engine needs is a
   branch in `resolveSamples`, so `z.enum` + a CHECK, not a table.
2. **The `{token}` grammar moves to `packages/shared/src/source-key-pattern.ts`**
   (pure, no zod): `SOURCE_KEY_PATTERN_TOKEN = /\{([a-zA-Z0-9_]+)\}/g`,
   `SOURCE_KEY_RESERVED_VAR = "asset_code"`, `patternTokens(pattern)`,
   `patternVariables(patterns)` (distinct tokens across many patterns, minus the
   reserved one, first-appearance order) and
   `substituteSourceKeyPattern(pattern, vars): { key; unresolved: string[] }`
   (known tokens replaced, unknown left **literal**, reported by name; `vars`
   read with `Object.prototype.hasOwnProperty.call`, so `{constructor}` stays
   unresolved — the instantiate service's own guard, kept). The instantiate
   service imports it and keeps byte-identical behaviour (`null` when
   `unresolved.length > 0 || key === ""`). This is "one vocabulary, wired
   twice" (ADR decision 10) made structural.
3. **`rtu_code` is `bms.rtus.code`, resolved within the location.** Not
   `rtus.rtu_code` (the nullable MQTT device key — a synthetic RTU has none).
   `rtus_location_code_unique` makes the lookup unambiguous and the location is
   already scope-checked, so "an RTU the caller may manage" is the same test.
   Open question Q-A.
4. **A blank `active` cell means "no change here".** On an existing row it
   keeps the stored state; on a row with **no** existing mapping it means the
   pre-fill suggestion was **not taken** — nothing is written, and the row is
   counted as `untouchedSuggestions` in the preview. The export writes
   `TRUE`/`FALSE` for existing rows and **blank** for pre-fill rows. This is
   the only reading under which decision 6 (pre-fill rows in the export) and
   decision 7's round-trip property (zero creates, zero updates) both hold with
   the fixed twelve-column header. To accept a suggestion the person types
   `TRUE`. Open question Q-B.
5. **Blank cells.** `unit` blank → `NULL` on an update (an explicit clear) and
   `template.unit ?? catalog.unit ?? NULL` on a create (the instantiation
   rule). The five metadata cells blank → `NULL` (inherit) on both, per the ADR.
   `rtu_code` blank → `rtu_id NULL`; on an existing `manual` row the kind stays
   `manual`, on a `measured` row it becomes `unmapped`, on a create it is
   `unmapped`. Non-blank → `rtu_id` set, `source_kind = 'measured'`. This is
   what keeps a `manual` row's round trip an `unchanged`.
6. **`asset_name` is informational on import** — the sheet does not edit
   assets; a changed name is neither an update nor an error. Open question Q-D.
7. **File-level refusals are HTTP 400 whose body is one `MappingSheetErrorDto`**
   (`row: null`): `{ row: null, column, code, message }`. Row-level problems
   ride in `errors[]`. Same shape both ways so the web renders one table.
8. **A uniqueness the ADR did not name is validated in the plan step, not left
   to the index.** `asset_points_asset_source_key_idx` (unique on
   `(asset_id, source_data_key)`) would raise 23505 inside the commit
   transaction and roll back every valid row. `source_data_key_duplicate` is
   therefore a row error, checked within the sheet and against the location's
   existing rows.
9. **Reads for the sheet run inside `withTenant`**, not on `fleetDb` — one
   location is one organization, so §4.3's default applies and no named reason
   is needed; the organization is resolved from `locations` on `fleetDb` after
   `canManageLocation`, the `assets.service.ts` `resolveLocationOrg` pattern.
   Preview and commit both run in one `withTenant` transaction; commit's writes
   and audit rows share it.
10. **Audit is per written row, through a new `MasterDataAuditService.writeMany`**
    that resolves the actor once and inserts in one statement — the single-row
    routes' actions (`master.asset_point.create` / `.update`), the same payload
    shape, without 6,000 round trips for a 3,000-row sheet. Open question Q-G.
11. **`asset-templates.service.ts` is at 998/1000 and may not grow.** Its
    `mapPoint` and the `values()` mapper inside `replacePoints` move to a
    sibling `asset-templates-point-rows.ts` (`toTemplatePointInsert`,
    `toTemplatePointDto`), which is where the ten new lines land. The service
    shrinks by ~50 lines. Mechanical, typecheck-forced, spec'd.
12. **`resolveSamples` applies decision 4 per target, after device and source
    key resolution.** Today `good === false` is dropped before the device is
    resolved; the policy is a property of the target, so the check moves inside
    the target loop. One observable counter change: a `good:false` sample for an
    **unknown** device now counts `unknownDevice` rather than `badQuality`. The
    raw `typeof value !== "number" || !isFinite` pre-check stays where it is
    (an unscalable value is dropped once, not per target). With both scale
    fields `null` the stored value is the sample value **object-identical** (no
    `x * 1 + 0`, which would turn `-0` into `0`). A new `droppedCount(counters)`
    in `normaliser.ts` replaces `main.ts`'s hand-summed list so a new counter
    cannot be forgotten there again.
13. **Bulk update refuses a mixed-organization selection (400) and refuses any
    `computed` row when the patch carries a metadata key** — all-or-nothing per
    decision 8; the page filters by location, so the first case is
    unreachable from the UI and exists for the API caller. Open question Q-E.
14. **The write-side `rtuId` lands on the create body and, per the owner's Q-H
    ruling (2026-09-06), on the update body too** — `rtuId: uuid | null`
    optional on `PATCH`: a uuid wires the point (RTU asserted in the asset's
    location, `source_kind = 'measured'`), `null` unwires it (`rtu_id NULL`;
    `measured` → `unmapped`, a `manual` row stays `manual` — design decision
    5's rule), absent leaves it. ADR 0056 decision 3 said "create body"; the
    ruling widens it by one nullable field and the sweep adds a pointer
    sentence to the ADR.
15. **The single-row Add/Edit form gains the five metadata inputs and the list
    gains three compact columns (Scale, Range, Quality) showing the *stored*
    asset values** — blank reads "inherits the template". The *effective*
    (coalesced) value on the list is §"Deferred" item 3.

## The `MAPPINGS` sheet contract

**Header row (row 1), exactly this order, lower-case, trimmed; trailing blank
header cells ignored; anything else is `header_mismatch` on the file:**

```
asset_code · asset_name · point_key · rtu_code · source_data_key · unit ·
scale_multiplier · scale_offset · eng_min · eng_max · quality_policy · active
```

**Sheet selection:** an `.xlsx` must carry a sheet named `MAPPINGS`
(`sheet_missing` otherwise); a `.csv` has one unnamed sheet and it is used.

**Export row set** for every **active** asset in the location, ordered by
`asset_code` then `point_key`:

- every `asset_points` row with `source_kind <> 'computed'`, values as stored:
  `rtu_code` = `rtus.code` via `asset_points.rtu_id` or blank; `unit` as
  stored or blank; the five as stored or blank; `active` = `TRUE`/`FALSE`;
- **the pre-fill**: every `template_points` row of `assets.template_id` with
  `kind = 'measured'` and **no** `asset_points` row for `(asset_id, point_key)`:
  `source_data_key = substituteSourceKeyPattern(pattern, { asset_code }).key`
  (so `{asset_code}_KW` → `TX01_KW`, and `CH{unit}_CHW_SUPPLY_T` stays
  literal); blank when the pattern is `NULL`; `rtu_code` = the asset's RTU
  code or blank; `unit = template.unit ?? catalog.unit ?? ""`; the five blank;
  `active` **blank** (design decision 4).

Cells are written through `aoa_to_sheet` as literals (strings and numbers);
per ADR 0026's finding the safety is the absence of any `<f>` element, and the
spec asserts it on the produced buffer.

**Import row evaluation order** (deterministic, so a row reports one code):

1. `asset_code` blank → `asset_code_required`.
2. `point_key` blank → `point_key_required`.
3. `(asset_code, point_key)` seen earlier in the sheet → `duplicate_row` on the
   later row, message naming the first.
4. `active` not blank and not one of `true/false/1/0/yes/no` (any case, or a
   boolean cell) → `active_invalid`.
5. asset not in this location → `asset_not_found` (same wording for
   "nowhere" and "elsewhere"); inactive → `asset_inactive`.
6. existing row is `computed`, or no existing row and the pinned template
   declares the key `derived` → `point_key_computed`.
7. no existing row and `active` blank → **untouched suggestion**; stop.
8. key neither active in `bms.point_keys` nor declared by the pinned template
   → `point_key_unknown`.
9. `rtu_code` non-blank and no active `rtus.code` match in the location →
   `rtu_not_found`.
10. `source_data_key` blank → `source_data_key_required`; > 128 chars →
    `source_data_key_too_long`; contains `{…}` → `source_data_key_unresolved_token`.
11. `unit` > 32 chars → `unit_too_long`.
12. each non-blank numeric cell not a finite number → `number_invalid` (column
    named); `scale_multiplier` = 0 → `scale_multiplier_zero`; `quality_policy`
    not in the enum → `quality_policy_invalid`.
13. resolved band (`sheet value ?? template default`) with both ends set and
    `min >= max` → `eng_range_inverted`; the message names the inherited side
    and its value ("eng_max 100 (inherited from the template)").
14. same `source_data_key` twice for one asset in the sheet, or matching an
    existing row of another `point_key` on that asset that this sheet does not
    change → `source_data_key_duplicate`.
15. diff against the existing row → `updates[]` (field-level `from`/`to`) or
    `unchanged`; no existing row → `creates[]`.

**Error-code vocabulary** (`MAPPING_SHEET_ERROR_CODES` in
`packages/shared/src/contracts/mapping-sheet.ts`; the web's
`MAPPING_SHEET_ERROR_LABELS: Record<MappingSheetErrorCode, string>` is
typecheck-exhaustive over it, which is what makes the API and the web agree
from the first commit):

| `code` | Level | `column` | Meaning |
| --- | --- | --- | --- |
| `file_unreadable` | file | null | not CSV or XLSX |
| `file_too_large` | file | null | over `MAX_IMPORT_FILE_BYTES` (5 MiB, `F1.9`'s) |
| `sheet_missing` | file | null | no `MAPPINGS` sheet in an `.xlsx` |
| `header_mismatch` | file | null (offending header named in the message) | header row ≠ the twelve, in order |
| `no_data_rows` | file | null | header only |
| `too_many_rows` | file | null | over `MAX_IMPORT_ROWS` (20,000, `F1.9`'s) |
| `asset_code_required` | row | `asset_code` | blank |
| `asset_not_found` | row | `asset_code` | not an asset of this location |
| `asset_inactive` | row | `asset_code` | asset is `active = false` |
| `point_key_required` | row | `point_key` | blank |
| `point_key_unknown` | row | `point_key` | not in the catalog and not on the template |
| `point_key_computed` | row | `point_key` | computed/derived point — refused whole |
| `duplicate_row` | row | `point_key` | same `(asset_code, point_key)` earlier |

## Tasks in build order

Build order is `shared → db → api → ingest → web`. **Where a typecheck-forcing
edit crosses packages, the halves are one commit** (named below), so every
commit leaves `pnpm build`, `pnpm typecheck:tests` and root `pnpm test` green.
Every new `*.spec.ts(x)` gets its name-sibling `*.test.ts(x)` wrapper
(`tests/repo-invariants.test.ts` fails the build on an orphan). Every new file
under `tests/` is added **by hand** to the root `typecheck:tests` script. Where
a task names a mutation, **run it and confirm red before committing**; a
mutation that "drops a gate" must **invert** it instead (`F2.9` findings 18, 23).
Use the Write/Edit tools for source, never a shell heredoc (CRLF and backslash
mangling on this machine). After every parallel review round, `git status` —
reviewers share the working directory.

Integration specs gate on `DATABASE_URL` and skip silently without it. **Every
unit that adds one proves it ran** by pasting the exact runner line
(`pnpm vitest run --project api <file>` with the four role URLs set, or
`--project ingest`) and its summary showing `Tests N passed (N)` with **no**
`skipped`, plus the spec's own non-vacuity assertion (a row count > 0). Never
gate on `pnpm --filter api test` — it can exit 0 having run nothing.
