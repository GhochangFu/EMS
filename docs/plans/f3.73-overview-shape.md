# Site Overview redesign and wall mode — design brief (`/impeccable shape`)

Shaped 2026-10-01 after the Impeccable critique of the F3.73 site layout (20/40)
and the critique-fix PR #681 (`b21eadad`). Product record: `apps/web/PRODUCT.md`.
This brief is a plan, not code. Its build is row `F3.77`, created by ADR 0087
Amendment 3 (proposed), which records the rulings below; the build starts after
the owner accepts it.

## Owner rulings (2026-10-01, one question at a time)

| Question | Ruling |
|---|---|
| Who uses the Overview first | The shift operator and the site engineer, **equal weight** |
| Colour / HMI standard | **No colour change.** Keep the palette, the state colours and the brand accent |
| Wall mode | A **toggle on the site view**; it rotates through the site's tabs |
| Duplicated status | **Tab markers + one Systems list**; the alarm rail is the only alarm list |
| v3 rollout | **Upgrade untouched** Overview tabs; admin-edited ones stay; new copies get v3 |
| Wall session expiry | **No auth change**; a visible "session ended" state, back to the same view after sign-in |

## 1. Job and audience

Operate mode. The operator glances at a wall screen from across the room and
must see what is wrong now and where. The engineer sits at a desk and wants the
same answer, then load and health. Both use the same Overview; wall mode is a
presentation of it, not a different dashboard.

## 2. Outcome and proof

Within one glance: the number of active alarms and offline assets, the newest
alarms with their site location, and which domain tab holds them. Success is the
critique's P1 "Overview hierarchy buries the alarms" closed: the alarm rail is
above the fold at a 1168 px canvas. The critique measured its top at y≈1114 on
a 922 px viewport before #681; after #681 it still starts at canvas row 10, below
the tiles, the class strip and the cards. Real data only: the seeded ESKOM and PHEWB sites on the shared stack.

## 3. Selected direction

The incumbent visual world stays (owner ruling: no colour change; ADR 0085
surfaces). The change is structure, order and emphasis, not palette.

**Overview, stock v3, top to bottom (12 columns):**

1. **Problem tiles row** (height 2): Active alarms, Offline assets, Total load,
   Asset health, in that order. What is wrong comes first. Offline assets gets a
   new seventh widget icon, `offline`, so it no longer shares `alert`.
2. **Alarms and systems** (height 7): the **alarm rail** on the left, 8 columns
   wide, and one **Systems list** on the right, 4 columns wide. The Systems list
   has one row per domain tab: name, status pill (the server's `tabTone`),
   "n alarms · m offline · k assets", and an Open link. It replaces both the
   module cards and the critical-systems list in the stock template. Both widget
   types stay in the vocabulary for admins.
3. **Asset class strip** (height 2), full width.
4. **State legend**, last, as one compact row. It explains colours and is
   reference, not the first thing to read.

**Tab markers.** Every tab in the site view's tab links, and in the viewer's and
builder's tab strip, shows the tab's status: a small marker in the tab's tone,
plus a count of active alarms (text, never colour alone; ARIA name "HVAC,
warning, 2 alarms"). The Overview read already returns every tab's status
(`tabs[]`), so the markers need no new endpoint.

**Wall mode** (`?wall=1` on the site view, toggled by a "Wall" button):

- The app shell (sidebar, header, KPI ribbon) is hidden. The site name, a live
  clock (local time, seconds) and "Updated hh:mm:ss" (from the newest read) form
  a thin top bar.
- The type scale is larger (a wall class on the canvas root), tuned for
  1920×1080 and 3840×2160.
- Rotation through the site's dashboard tabs (not "Assets & RTUs"), default
  30 s, choices 15 / 30 / 60 / 120 s in the top bar. A key press or a click
  pauses it, and a visible "Paused — resume" control resumes it. The URL keeps
  the mode, the interval and the current tab, so a wall PC opens straight into it.
- **Session ended:** when the API answers 401, wall mode shows a full-screen
  "Session ended — sign in" state, never the last data as if live. After sign-in
  the app returns to the same wall URL.
- **Connection lost:** when the socket drops or the reads are stale, the top bar
  says so ("Live data paused since hh:mm"), using the existing stale rule.

## 4. Scope and boundaries

- In scope: the stock template v3 Overview content, the seed upgrade of untouched
  Overview tabs, tab markers (site view, viewer, builder), the Systems list as the
  critical-systems widget with Open links, the `offline` icon, wall mode on the
  site view.
- Not touched: colours and tokens; auth and session lifetime; the domain tabs'
  content; the mimic (F3.74 owns it); `RSMOC-WC` (F3.75); the generated view.
- Anti-goals: a second alarm list on the Overview; status shown by colour alone;
  a wall mode that shows stale data as live; a v3 upgrade that changes an
  admin-edited Overview.

## 5. States and ranges

- Active alarms: 0 (the rail says "No active alarms" in a calm state), typical
  1–10, maximum hundreds (the rail scrolls; its header carries the total).
- Domain tabs: 1–7 per site (the Systems list never scrolls at 7 rows).
- Offline assets: 0 to all; an all-offline site reads as a warning, not as
  "normal".
- Loading, read error (keep the last good drawing; the frame says so), session
  ended, socket lost, stale reads.
- A site with no layout keeps the generated view and its notice (ADR 0087 D7).

## 6. Interaction and layout

- Desktop canvas ≥ 1024 px: the order above. ≤ 1024 px and ≤ 640 px: the #681
  breakpoints (span 6 or 12, then one column) in reading order, so the rail stays
  second after the tiles.
- Tab markers update from the same read and socket refresh as the Systems list.
- Wall mode keeps keyboard use: Tab reaches the pause control and the tabs; the
  ARIA tabs pattern stays.
- No hover-only information anywhere (wall use).

## 7. Constraints and open decisions

- **Process:** a backlog row and an ADR 0087 amendment (template v3 content, the
  `offline` icon in the closed icon vocabulary, wall mode) before the build. The
  owner gates both.
- **v3 upgrade gate:** an Overview tab upgrades only while it holds exactly the
  v2 content at its v2 rects **as the #681 packing left them**. Each site packs
  its cards differently, so the gate compares against that site's own packed
  plan, not the raw template.
- **Icon vocabulary:** `offline` widens `widgetIconSchema`, the web icon map and
  the F3.35 tile-icon gate together.
- **Wall URL contract:** `?wall=1&every=30&tab=<key>`; unknown values fall back
  to the defaults.
- Proposed, to confirm with this brief: the rotation default 30 s and the
  choices 15 / 30 / 60 / 120 s; the tab marker counts alarms only, and offline
  shows in its tone.
- Open: whether the Overview should appear more often in the rotation than the
  domain tabs (default: equal turns).
