## 1. Goal

Give a work order the depth the SOW reference layouts show, and close `E3.4` with it. Nine things:

1. A frozen human reference, `WO #ELEC-000042`, beside the uuid. Prefix order: the asset's template, else its domain, else `GEN`.
2. An SLA in whole minutes, snapshotted at create from a per-organization, per-priority policy; its state is computed on read.
3. A checklist on `bms.work_order_tasks`, copied from a reusable template.
4. Root-cause fields and a coded cause on the ticket.
5. `E3.4`: the alarm's enrichment (root cause, corrective actions, skill, ETR) copied onto the ticket once, at create, and shown read-only.
6. Closure approval: `resolved` means "waiting for approval"; `POST /work-orders/:id/close` becomes the approval under a new third write class, `approval`. Self-approval is allowed and recorded. `reject` sends a ticket back.
7. Cancel: a sixth, terminal status `cancelled`, through `POST /work-orders/:id/cancel` (approval class, reason required).
8. An append-only `bms.work_order_events` timeline that keeps the actor's display name.
9. A five-step stepper in a new detail drawer on `/work-orders`, and admin screens for domain prefixes, SLA policies and checklist templates.

**Out of scope** (ADR 0122 "Not in this record"): mobile execution and photos (`E3.2`); a CMMS connector (`E3.3`); a live view of the alarm's current enrichment beside the snapshot; SLA breach notification, escalation, pause, business hours, response SLA; parts, labour, cost; audit hash-chaining (`F4.15`); degradation and RUL (`E1.5`); any device command; any new npm package. Also out, by this plan: a prefix on the **stock** template catalog (R3); a copilot read tool for cause codes or checklist templates; dropping the legacy `work_order_tasks.status` column; any AGENTS.md edit inside a feature PR.

## 8. Risks

1. **Concurrent reference counter.** Held by T1.4's 20-way claim. Creates in one organization run one at a time while the counter row is locked.
2. **Backfill on a live table.** One transaction under the first `ALTER`'s lock; the table is human-scale. The zero-row trap is D2.
3. **Breaking `PATCH :id/status`.** A caller sending `closed` gets 400. The repository has no such caller.
4. **Operators lose close.** Intended. Between PR 5 and PR 6 an approver can approve from the board but can reject or cancel only through the API. A release note is owed.
5. **Existing `resolved` rows** have a NULL `resolved_by`, so their approval is never marked self-approved.
6. **A sixth status.** A reader missed in T5.3 fails quietly, not loudly: a `<> 'closed'` test counts a cancelled ticket as open. The web's `Record` types and `switch` do fail the build; the SQL readers do not, which is why each has a spec claim.
7. **Cancelled rows and the board.** Without the `buildReorderItems` skip, one cancelled ticket breaks every drag (400).
8. **The prefix on a published template** cannot be edited (R2). A site with assets on a published STP template gets `STP-` only after a new version is published and the assets are migrated to it.
9. **A stale snapshot** is by design (ADR Consequences); the drawer labels it *From the alarm*.
10. **Copilot close card.** The wording changes; the body, and so the hash, does not. A close an operator proposed before the deploy is refused at confirm.
11. **File caps.** Four files are within 17 lines of 1000.
12. **Migration D's status `CHECK`** fails the deploy if a database holds an off-vocabulary status; the `DO $$` pre-check names the value.
13. **Seven PRs** cost about 12 more billed minutes than six (R1).
