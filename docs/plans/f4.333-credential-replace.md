## 1. Goal and out of scope

**Goal.** A user with the right role can enter a new broker credential (a)
for an RTU in an onboarding draft whose credential is already set, and (b)
for a committed MQTT RTU on `/admin/rtus`. The value is encrypted at the
current key version, never shown again, audited without the value, and the
running ingest connection uses it within one reload (`INGEST_RELOAD_MS`,
60 s) with no restart.

**Out of scope** (ADR 0129 decision 7): read-back or partial edit; host, port
or TLS changes; non-MQTT credentials; per-RTU credentials on a shared
endpoint (`F1.7`); edge gateway credentials; a copilot tool; key rotation
changes; the BCPL rotation itself (the owner does it on AWS after merge).

### PR 3 — API route for a committed RTU

> **From the PR 2 security review (L2), for this PR's review:** one ingest
> endpoint can serve two organizations (`host:port`, first non-empty
> credential wins). A wrong password replaced on organization B's RTU can now
> break organization A's connection within one reload. Decide in the build
> whether the route refuses, or warns, when the target RTU's broker endpoint
> is shared with another organization's RTU.

**Tests first**
- T3.1 `packages/shared` contract test: `replaceRtuCredentialsBodySchema`

- T3.2 `apps/api/src/admin/rtus/rtus.service.credentials.spec.ts` (+ `.test.ts`),

- **Each PR:** `pnpm build`, `pnpm test`, `pnpm test:coverage` (the `verify`
  skill), and the §4.6 layers named under each PR. Skipped layers are named
  with the reason.
- **Security review** (`security-reviewer` agent) on PRs 1–3, and on the whole
  branch before PR 4 merges. Checklist:
  1. No plaintext in any response, log line, audit row, error message,
     query cache or URL (§9.6). Grep the diff for `password`/`username`
     reaching a logger.
  2. The fingerprint holds no secret and nothing derived from one.
  3. The `UPDATE` cannot change `config` (host, port, TLS, topic) — ADR 0093
     freeze.
  4. Role and scope: a `location_admin` and another org's admin are refused;
     siblings cannot cross an organization or a broker.
  5. Zod: `.strict()`, length caps, control characters.
  6. Fail closed: no key → 503 and nothing written; 0 rows → no audit.
  7. Encryption at the current key version; IV fresh per write.
  8. Edge-served refusal.
- **Mutation checks** recorded in each PR: remove the role check (T3.2 red),
  add `config` to the set clause (T3.2 red), fingerprint the plaintext
  (T2.2 red), drop the `credentials-changed` branch (T2.1 red).
- **AWS check on BCPL LALMATI** (owner, after each PR deploys through
  `bms-ctl`):

     **new** BCPL password. The pill stays "Set". `bms.audit_log` has a
