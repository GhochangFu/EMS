## 1. Goal

One new read tool, `find_existing { kind: "location" | "rtu" | "asset", search?, locationCode? }`, lists the session organization's **committed** rows of that kind — codes, names, protocol, domain, template code and version, `active` — so the model follows the organization's naming and sees a same-organization collision before the commit. The read is tenant-only (`organization_id` of the session is the first predicate of every query), selects **no** `rtu_connection_configs.config`, no credential column and no `meta`, is capped at `TOOL_LIST_MAX_ITEMS` = 100 with an exact `moreTail`, writes nothing and writes no action line, and every result carries one constant scope note written by code. `list_point_keys` gains optional `domain` and `unit` filters (case-insensitive equality) and an in-use order: the keys the organization already maps in `asset_points` come first, each row carries `inUse`. One sentence in `buildSystemPrompt` tells the model to call `find_existing` before it chooses a new code. A new `OnboardingInventoryService` on `FLEET_DRIZZLE` reads the rows (the `getContextForOrganization` precedent, `onboarding-protocol.service.ts:73-88`); `OnboardingCatalogService` gains `listInUsePointKeys`; `listPointKeys` and its three callers do not change. The registry grows 28 → 29. No migration, no `packages/shared` change (tool results stay inside the loop; §4.8 / ADR 0030 is **N/A**), no `apps/web` change, no new dependency, **one PR**.

**Out of scope (owner, ADR 0095).** Any fleet-wide availability check or a database pre-check in `validate_draft` (D2 — a new F4 row with a security review if wanted); a read of a committed asset's points or `source_data_key` (D4 — the F2.7 sheet); `list_protocols`, its service and `formatForAssistant` (D5 — F3.24a, which also owns the empty live `protocol_catalog`); embeddings (D1-C); the cap of 8 calls, the 45 s deadline and the result bound (D6, ADR 0090 decision 3); the guided path (`handleRuleBasedTurn` is not edited — retrieval needs a model; decision 9); `AGENTS.md`; the ADR 0090/0091 texts (ADR 0095 *Amended records* already names them).

## 3. Open questions (the owner rules before U1; the plan assumes the recommendation)

- **Q-A — inactive rows.** *Recommended: list them, with `active: boolean` on location and RTU rows.* `locations_slug_unique` and `rtus_location_code_unique` do not filter on `active`, so an inactive row still blocks a code; hiding it would send the model into a collision it could have seen.
- **Q-B — `rtus.rtu_code` (the F4.182 device id) on the RTU row.** *Recommended: no.* `draftRtuSchema` (`onboarding.schema.ts:87-101`) carries `code`, `displayName`, `protocol` and `config`; the chat never sets a device id, so the row would list a value the model cannot act on. The scope note names it as a commit-time refusal. U1 confirms with one grep that the draft has no `rtuCode` field; if it does, flip to yes.
- **Q-C — `find_existing` in `CREDENTIAL_CHECKED_TOOLS` (`onboarding-agent-tools.ts:97-107`).** *Recommended: no.* The arguments are search strings and are never stored; the prompt-marker refusal (`:294-296`) and the Zod bounds run on every tool. T7 proves the marker refusal reaches this tool.
- **Q-D — the scope note (ADR decision 2, F4.109).** *Recommended text, exported as `EXISTING_SCOPE_NOTE`:* `Only this organization's locations, RTUs and assets are listed. A location slug, an asset code, an MQTT topic, an RTU device id or an external RTU id can still be refused at commit as already taken; the commit result is the only check for that.` — "already taken" is the admissible global form in `onboarding-commit-conflict.ts:79-82` and `:219`, `:237`, `:255`; it names no other organization. The compliance review checks it.
- **Q-E — how the tail is counted.** ADR decision 1 says "at most one row more than the cap" and names `moreTail`; with limit+1 the tail would read "…and 1 more assets" when 400 exist, which is false. *Recommended:* the service runs the `LIMIT 100` select plus one `COUNT(*)` with the same predicates and returns `{ rows, total }`; the tool writes `moreTail(total - rows.length, "<kind>s")`, exact. Two cheap statements on an `organization_id`-filtered table; no whole-table load. If the owner prefers the literal limit+1, the tool writes a fixed sentence `More exist; narrow with search or locationCode.` and never a count.
