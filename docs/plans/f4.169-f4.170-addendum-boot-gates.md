  `withOrganization`, which issues `BEGIN` … `COMMIT` on the `max: 1` seed pool.

## Commit 1 — make the verifier testable without a COMMIT (pure refactor)

Files: `packages/db/src/verify-hierarchy-seed.ts`; new
`verify-hierarchy-seed.spec.ts` + `.test.ts`.

```ts
export type HierarchyCheck = { label: string; actual: number; wanted: number; kind: "exact" | "atLeast" };
export function failingChecks(checks: readonly HierarchyCheck[]): string[];          // pure
export async function readGlobalChecks(pool): Promise<HierarchyCheck[]>;
export async function readEskomChecks(pool, eskomOrgId, options?): Promise<HierarchyCheck[]>;  // caller holds ESKOM context
export async function readPhewbChecks(pool, phewbOrgId): Promise<HierarchyCheck[]>;           // caller holds PHEWB context
export async function verifyHierarchySeed(pool, organizationIds?, options?): Promise<void>;   // same behaviour
```

`failingChecks` keeps today's message shapes. A `NaN` actual fails for both kinds.
Unit tests: mismatch message carries label and both numbers; match gives
nothing; `atLeast` passes at the floor and fails one below; `NaN` fails.
Integration cases call `read*Checks` inside their own `BEGIN` + GUC + `ROLLBACK`
in `finally`. Every integration assertion is a delta against a baseline read in
the same transaction before the fixture, never `ok === true`.
