*Backlog row `docs/BACKLOG.md` (Track B, `| F2.13 |`) · P1 · Effort **6–8** (was 3–4; see §11) · Wave 2 · Depends `F2.5`, `F2.6`, ADR · Branch `feat/F2.13-stock-asset-template-catalog`, base `main` at `1cbeac8`*

## 1. Goal

Give `bms.asset_templates` the delivery mechanism `bms.dashboard_templates` already has, and prove it end to end with one real entry. Concretely: a stock stamp on the table (`stock_code` / `stock_version` + a `CHECK`), a TypeScript catalog under `apps/api` shipping **one pack module with the `electrical-feeder` class at `stockVersion: 1`**, two routes that list the catalog and import an entry as a stamped **draft** through the *same* write path a hand-authored draft takes, a stamp `createDraftFrom` copies forward, the two fields on `AdminAssetTemplateDto` plus a new `StockAssetTemplateDto` in `@bms/shared/contracts`, an import control on the asset templates admin page, and a build-time guard that refuses a catalog entry naming a point key the platform does not hold. Authoring the feeder entry requires ADR 0019 Amendment 2's paired-optional `thresholdValue`/`operator`, so that contract change lands here, and it requires `meta.tier` to be authorable on a template point, so that lands here too.

## 2. Out of scope

- **The other five electrical classes.** `F2.12` still ships transformer, DG set, UPS, solar PV and APFC. This row ships **only** feeder/incomer.
- **The water, mechanical and facility packs** (`E5.1`, `E5.2`, `E5.3`) — each under its own gates. Do not create `water.ts`, `mechanical.ts` or `facility.ts`.
- **Any derived point or KPI.** All six of the tag list's "Derived:" codes are deferred (§5). Zero `kind: "derived"` points, zero `kpis[]`, **zero promotions into `ELECTRICAL_CLASS_POINT_KEYS`** — ADR 0051 Amendment 6 decision 8: a code with no formula is not vocabulary.
- **Maintenance plans on the entry.** The tag list §1 carries none; F2.12 adds them with the other classes.
- **Any seed-time import.** ADR 0052 decision 9. `db:seed` gains nothing, `BASELINE-*` is untouched. A re-import is a version bump (decision 4), so a seeding path would open a new draft on every `compose up`.
- **`E2.4` rule seeding.** ADR 0019 A2 decision 4 binds `E2.4`, which is unbuilt. This row only makes pair-absent rows *authorable* and proves nothing invents a number.
- **The dashboard side's missing peer-mutation test** — ruled to its own row, **F4.77** (§6 Task 9 supplies its text; the row is added to `docs/BACKLOG.md` with this plan).
- NULL-organization "system" templates; `meta.provenance` (ADR 0040 decision 6, discharged by the stamp); the `F2.5` tab registry.

## 3. Serial or parallel

**Serial, hands-on. Do not fan out.**

The row is not marked ⭐, but it is an enabler in substance — `F2.12`, `E5.1`, `E5.2` and `E5.3` list it in `Depends`, and ADR 0052 exists so none of them re-decides delivery. The tasks are one chain: the migration feeds the drizzle schema, which feeds the DTO; the ADR 0019 A2 contract change gates the catalog entry, which gates the guard's real anti-vacuity bound; the service gates the routes, which gate the web client, which gates the browser layer.

The one *apparently* separable unit — Task 2b, the ADR 0019 A2 surface — is not independent either: it spans `apps/api`, `packages/shared` and `apps/web` and touches eight fixture files. **No unit is safe to fan out.** The build runs as two consecutive `implementer` passes on one branch: pass A = Tasks 1, 2, 2b, 2c (schema, contracts, the two contract changes); pass B = Tasks 3–8 (catalog, entry, service, routes, guard, web). Pass B starts only when pass A is green.

## 5. The catalog entry, authored — `electrical-feeder`, stock v1

Source: `docs/electrical-derived-taglist-v1.md` §1 *"Feeder / incomer — multifunction energy meter (HT panel, LT panel, MCC feeder, sub-meter)"*. **The entry's `description` cites that file and section by name** — ADR 0052 decision 6: the stamp plus the citation is the provenance, and there is no `meta.provenance`.

- `code: "electrical-feeder"` · `name: "Feeder / incomer — multifunction energy meter"` · `assetType: "feeder"` · `domain: "electrical"` · `stockVersion: 1`.
- **`points`: all 33 rows, in table order** (`sortOrder` 0…32). `required: true` for the 17 `C` rows, `false` for the 16 `X` rows. **`kwh_today` is `C/D` → `required: true`, `kind: "measured"`** — the table says "meter or derived", and no `bms-calc-v1` formula can express energy-today (it needs a time window the grammar cannot name), so authoring it derived would need a placeholder formula, which is the guessing ADR 0019 exists to prevent. Every point carries `unit` from the table's Unit column (spelled as `UNIT_BY_KEY` spells it — `kVAr`, `kVArh`) and `label` from its Description column. **Every point carries `meta.tier`** — `"core"` for `C`, `"extended"` for `X` (Task 2c, ruled in).
- **`content.alarms`: 11 philosophy rows, every one pair-absent** — no `thresholdValue`, no `operator`, per ADR 0019 A2 decisions 1 and 2 and B7's "limit values are set per site at commissioning". The tag list's ten bullets, with under/over-voltage split into two because they are different meanings at different bands. **Ruled 2026-09-02: confirmed as drafted.**

  | `code` | `pointKey` | `severity` | `category` | meaning carried by `message` |
  |---|---|---|---|---|
  | `overload` | `current_a` | `critical` | `operations` | Load above the feeder's rating (page-9 *Overload (112%)*) |
  | `undervoltage` | `voltage_vry` | `warning` | `operations` | Supply below band |
  | `overvoltage` | `voltage_vry` | `warning` | `operations` | Supply above band |
  | `frequency_out_of_band` | `frequency_hz` | `warning` | `operations` | Grid / DG supply quality |
  | `pf_low` | `pf` | `warning` | `energy` | Power factor below the tariff band — penalty |
  | `thd_high` | `thd_v_pct` | `warning` | `operations` | Harmonics from VFDs / UPS (page-9 *THD High*) |
  | `unbalance_high` | `voltage_unbalance_pct` | `warning` | `operations` | Single-phasing or uneven load |
  | `breaker_trip` | `breaker_trip` | `critical` | `safety` | Breaker tripped on fault; relay code in `relay_trip_code` |
  | `earth_fault` | `earth_fault_state` | `critical` | `safety` | Earth-fault indication |
  | `demand_approaching_contract` | `demand_kw` | `warning` | `energy` | Demand nearing contract demand |
  | `meter_comms_loss` | `meter_comms_ok` | `info` | `operations` | Meter unreachable |

  **`overload` binds `current_a` rather than `load_pct` — ruled 2026-09-02**, because `load_pct` is deferred and an alarm may only reference a key the template declares (`assertContentRefsResolve`). Four rows bind `X`-tier optional points (`thd_v_pct`, `voltage_unbalance_pct`, `demand_kw`, `earth_fault_state`) — legal, because the reference check requires the key to be *declared*, not required. The severities and categories are drawn from the live vocabularies, which `assertTemplateAlarmVocabularies` closes at create time.
- **`content.kpis`: absent. Zero derived points.** All six "Derived:" codes are **deferred and listed as deferred in the entry's docblock**, never authored with a placeholder — ADR 0051 Amendment 6 decision 8: `load_pct` (needs the asset's kVA rating) · `demand_vs_contract_pct` (contract demand) · `pf_penalty_flag` (tariff PF band) · `kwh_per_unit_output` (production) · `specific_energy_kwh_kl` (KL throughput) · `losses_pct` (incomer − Σ feeders, a cross-asset sum). Each needs an asset attribute or a cross-asset aggregate `bms-calc-v1` cannot name (ADR 0036; `F2.9` records the fork). **Therefore no code is promoted into `ELECTRICAL_CLASS_POINT_KEYS` in this row**, and `tests/f3.38`'s `vocabulary.size` bound of 185 does not move.
