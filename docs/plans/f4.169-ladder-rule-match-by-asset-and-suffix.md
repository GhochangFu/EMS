## Goal

`seedEskomLadderRules` (`packages/db/src/automation-rules-seed.ts`) stops deciding
"already seeded" by rule code. For each `(asset, ladder rule)` it skips when
(1) the condition tuple already exists (kept, unchanged) or (2) the asset already
carries a `source = 'simulator_threshold'` rule whose code ends `_${suffix}`;
otherwise it computes the code with `ladderRuleCode`, and if a *different* row in
the organization already holds that code it logs one warning naming both assets
and skips that one rule; else it INSERTs. No UPDATE of any stored code.
`upsertRuleByCode` and the five CR seeders are byte-for-byte unchanged.

**Out of scope:** `upsertRuleByCode` behaviour; a shared helper in another file;
closing L1 fully; backlog/roadmap edits (separate `docs(backlog):` PR after
merge); AGENTS.md; F4.170.

## Design decisions

1. **Match key = `(asset_id, source = 'simulator_threshold', code ends _${suffix})`.**
   `asset_id` keeps `ups-a`/`UPS-A` apart and survives a rename. Migration `0033`
   writes `'simulator_threshold'` on all five INSERTs and the seed writes the same
   literal, so the narrowing misses no `0033` row; `ruleDraftBodySchema`
   (`.strict()`) has no `source` field, so an operator edit cannot clear the
   marker; `verify-hierarchy-seed.ts` already treats `source` as the ladder
   marker. No suffix in `ESKOM_LADDER_RULES` is a `_`-delimited tail of another
   (gated by T3). Read all rules once, filtered by `organizationId`.
2. **No code rewrite.** A rewrite can itself hit `automation_rules_org_code_idx`
   inside the seed transaction. No reader keys on a ladder code.
3. **Collision = pre-read, never catch.** The seed runs inside `withOrganization`'s
   single transaction; a caught `23505` leaves it aborted (`25P02`). Build
   `Map<code, {id, assetId}>` from the pre-read; on a hit, warn and `continue`;
   after each INSERT add the new code to the map.
4. **Warn via a `log` parameter defaulting to `console.error`** (the `migrate.ts`
   shape). The message carries asset codes, asset ids, the rule code and the
   holder's rule id only (AGENTS.md §9 rule 6). Do not cite F4.172 in code.
5. **Keep the condition-tuple guard** first in the chain (the `UPS-A`
   `demand_ceiling_notify` case).

## Residual (owner ruling 4)

`updateRule` (`apps/api/src/rules/rules.service.ts`) accepts `code`, upper-cases
it, and does not refuse `simulator_threshold` rows. If an operator renames a
seeded ladder rule's code so it no longer ends `_${suffix}` and also edits its
threshold, the next seed adds a second rule with the original condition. Not a
boot failure. Named in the `seedEskomLadderRules` docblock; recorded in F4.172 at
closure.
