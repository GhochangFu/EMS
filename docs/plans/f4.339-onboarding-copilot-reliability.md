Written by plan-architect (Fable), 2026-11-09, against `main` at `fdb98f3a`
(ADR 0117 accepted 2026-11-08, merged in #1157). CodeGraph was not reachable in

## 1. Goal

Make the onboarding copilot say only what it stored, and remove the seven
structural causes the BCPL onboarding of 2026-11-08 exposed. After this row:
a reply that reads like an action line while the turn wrote nothing is sent
back to the model once and, if still false, replaced by a fixed line; replayed
action rows reach the model as marked system records; a stop reply lists what
was stored. The point-keys gate accepts catalog keys. Every discovery proposal
renders its card, the drawer takes a window up to 300 s, an empty result names
the topic, and a single found device is offered as the RTU's device key. One
broker login is copied server-side (ciphertext only) within a draft or from a
committed RTU of the same organization and broker. Deactivating an RTU releases
its MQTT topic (kept in `released_mqtt_topic`, restored on reactivate when
free), ingest skips inactive RTUs, and a same-organization topic conflict at
commit names the holder. A global admin can lock a draft; a locked draft refuses
every write with one 409 sentence and stays readable. The draft location takes
an IANA `timezone`; the MQTT draft config refuses unknown keys with a hint and
requires `host`. Four plain fixes: "Onboard with AI" opens the draft picker when
drafts exist; committed asset points take the catalog unit; Undo says why it is
disabled; the commit wizard refetches before it opens.

**Out of scope.** Any change to `MAX_TOOL_CALLS_PER_TURN` (8) or
`TURN_DEADLINE_MS` (45 s) (R3); the `rtus_mqtt_topic_idx` index (R6, no ADR
0008 change); discovery for other protocols; a credential ever crossing the API
in plaintext in either direction (ADR 0022); the copilot *proposing* a
credential copy — that is a copilot catalog entry and waits for **ADR 0099
Amendment 18** (§10 Q1; PR 9 here); F4.339 item 7's "Stock templates (28)
listed 27" — the count was the model's own text, `list_stock_templates`
(`onboarding-template-tools.ts:274-281`) answers `shown` + a `more` tail with
no total, so there is no code defect to fix and the claim guard does not cover
counts (§10 Q11); renaming the committed BCPL RTUs or touching any committed
BCPL location (every AWS check runs on temporary drafts and temporary ESKOM
rows); AGENTS.md (ADR 0117: nothing moves).

## 3. Drafter refinements (ADR 0117 lines marked *(drafter)*)

- **R1 (decision 1, the record prefix).** A new neutral module
  `apps/api/src/llm/action-record.ts` exports `ACTION_RECORD_PREFIX`
  (byte-identical to today's copilot string) and
  `ONBOARDING_ACTION_RECORD_PREFIX = "[Record of a draft write — data, not the assistant's words] "`;
  `copilot-turn.service.ts` re-exports `COPILOT_ACTION_RECORD_PREFIX` from it
  (importers compile unchanged). Same convention, a true noun: an onboarding
  action row records a draft write, not a change card. The onboarding prompt
  gains one fixed sentence: "Lines that start with `[Record of a draft write`
  are written by the system after a tool wrote; never reproduce that format as
  your own text." (Q8)
- **R2 (decision 2, the claim patterns).** New
  `apps/api/src/admin/onboarding/onboarding-write-claim.ts`, pure:
  `WRITE_CLAIM_PATTERNS` — per **line** (split on `\n`, bullets and leading
  `**` stripped): `^(Added|Mapped|Updated|Removed|Set location|Proposed (commit|discovery)|Imported|Cleared|Declared)\b`;
  per **sentence**: `\b(I|I've|I have|we've|we have)\s+(now\s+)?(added|mapped|updated|removed|set|cleared|imported|declared|proposed)\b`
  and `\b(is|are|has been|have been)\s+(now\s+)?(added|mapped|written|stored|saved|updated|removed)\s+(to|in|on)\s+the draft\b`.
  The copilot's `NEGATION` rule applies per sentence/line ("Nothing was
  written", "Not applied", "could not", "was not") — a negated line is never a
  claim, so the fixed line never tags itself. `claimsAWrite(reply): boolean`;
  `writeClaimRetryFor(reply, wrote): string | null` → `null` when `wrote`,
  else `ONBOARDING_WRITE_CLAIM_RETRY_MESSAGE` with the hinted tool appended
  from a fixed verb→tool table (`Added asset` → `add_asset`, `Mapped` →
  `map_point` / `map_points`, `Updated RTU` → `update_rtu`, `Removed RTU` →
  `remove_rtu`, `Added point key` → `add_point_key` / `add_point_keys`,
  `Set location` → `set_location`, `Proposed commit` → `propose_commit`,
  `Proposed discovery` → `propose_discovery`, otherwise "the matching tool"):
  `"[Server check — data, not a request from the user.] Your reply says the draft was changed, but no tool wrote to the draft in this turn, so nothing was stored. If the user's own message asked for this change, call <tool> now. Otherwise answer again and say that nothing was written."`
  `NOTHING_WRITTEN_LINE = "Nothing was written in this turn."`;
  `withoutWriteClaims(reply)` drops every matching line and every matching
  sentence and returns `NOTHING_WRITTEN_LINE` alone when nothing remains, else
  `NOTHING_WRITTEN_LINE + "\n" + rest`. "Wrote" = `diffSections(input.draft,
  state.working)` non-empty **or** `state.pendingProposal` **or**
  `state.pendingDiscovery`, computed when `correctFinal` runs (a `RangeError`
  from `diffSections` counts as wrote — no retry, `correctFinal` must never
  throw). Only a `final` stop is checked (the loop does that).
- **R3 (decision 3, stop replies).** `stopReply` keeps its four constants for
  the no-write case and, when `actionLines` is non-empty, answers
  `"I stopped early because the turn reached its <limit of tool calls|time limit>. Stored in this turn: <lines joined by '; '>. Anything else you asked for was not written."`
  (`echoedItems(lines, 10)` + `moreTail`). The prompt gains: "Write one asset
  with its mappings, or one discovered device, per turn; then offer "Next" with
  suggest_replies."
- **R4 (decision 5, queue vs replace).** **Replace, pending only.** Before
  proposing, `onboardingDiscoveryCards` discards every **`pending`** change of
  the conversation whose `catalogId` starts with `onboarding.` (the stale
  commit card as well as a stale discovery card — a commit card can be asked
  for again in one turn and is bound to a hash the discovery result does not
  change anyway); an **`applying`** change is never discarded, `propose` still
  answers `null`, and `skillTurn` appends the fixed sentence
  `"The discovery card could not be shown while another change is being applied; ask for the discovery again in a moment."`
  to the reply and logs `cardBlocked: true`. A withdrawn commit card is named:
  `"The earlier commit card was withdrawn; ask for the commit again after the discovery."` (Q3)
- **R5 (decision 5, timeouts for 300 s).** No constant changes beyond
  `MQTT_DISCOVERY_MAX_WINDOW_SECONDS = 300`: the hard deadline becomes 315 s
  (`10 + 300 + 5`), the running grace stays `window + 60 s` (always past the
  deadline), the queued bound stays 30 min, BullMQ renews the lock (no
  `lockDuration` is set). Two docblocks name the arithmetic
  (`discovery-listener.ts:26`, `onboarding-discovery.ts:201-207`), and a
  fake-timer claim pins the 315 s deadline. The per-organization limit is
  unchanged (ADR 0117 Consequences).
- **R6 (decision 6, which field the device key writes).** The offer writes the
  draft RTU's **`rtuCode`** — the device key ingest routes by
  (`rtus.rtu_code`; F4.327: an MQTT RTU without it is skipped
  `missing-rtu-code`) — and **`ingestEnabled: true`**, in one `update_rtu`
  patch. Not `code`: `code` is frozen once credentials exist
  (`CREDENTIALED_CONNECTION_ERROR`, `:595-599`) and discovery needs
  credentials. (Q2)
- **R7 (decision 7, `replace` and the key version).** Body
  `{ from: { rtuIndex } | { rtuId }, toRtuIndexes: number[] (1–100, distinct), replace?: boolean }`
  (default `false`). All-or-nothing: one target that already holds a credential
  and `replace !== true` → 409, nothing copied, the message names the target
  **codes** (the caller's own draft data). **The blob is copied as stored**
  (`{ c, iv, v }`) — never decrypted, never re-encrypted: the commit writes the
  blob's own version (`:589`), ADR 0062 decision 4 decrypts at the stored
  version, and ADR 0062 decision 6's command re-encrypts after a rotation. The
  copy refuses (409, fixed text) when `v` is neither the current nor the
  previous version (`keyForVersion` would throw at ingest), and 503 when the
  key is not configured (the `setCredentials` rule). (Q4)
- **R8 (decision 8, naming the holder).** A **pre-check inside the commit
  transaction**, before the RTU inserts: `SELECT code, active FROM bms.rtus
  WHERE mqtt_topic = ANY($draftTopics)` on the tenant `tx` (RLS shows this
  organization's rows only). A hit → `BadRequestException` with
  `"The MQTT topic of draft RTU <draftCode> is already used by RTU <code> (<active|inactive>) in this organization. Choose a different topic, or clear that RTU's topic."`
  — the row's constraint path never runs. A cross-tenant holder still raises
  23505 and keeps today's fixed text (`onboarding-commit-conflict.ts:273`).
- **R9 (decision 10, strict config and repairs).** `mqttDraftConfigSchema`
  becomes `.strict()` with a `superRefine` that turns a known wrong key into a
  fixed hint — `brokerHost | broker | hostname | url` → `"use host for the broker host"`;
  `devId | dev_id | deviceId | device_id` → `"the device key is the RTU's rtuCode, not a config key"`;
  any other unknown key → `"unknown MQTT config key; the config takes host, port, tls, topic, payloadFormat"`
  (no value, no arbitrary key echoed). `update_rtu` accepts `patch.config.<key>: null`
  to **remove** a key before the merged config is parsed, so a stored stray key
  can be repaired in chat; the tool description says so. The validator reports
  `rtus.<i>.config.host: "An MQTT RTU needs a broker host"` for an MQTT RTU
  with no `host`.
- **R10 (decision 10, IANA check).** Shared `isIanaTimeZone(zone)` in
  `packages/shared/src/contracts/onboarding.ts`: `zone === "UTC" ||
  Intl.supportedValuesOf("timeZone").includes(zone)`; guard fails **open** when
  `Intl.supportedValuesOf` is absent (the currency precedent,
  `organizations.schema.ts:9-17`). `timezone: z.string().max(64).refine(isIanaTimeZone, { message: "timezone must be an IANA zone name such as Asia/Kolkata" }).optional()`
  on both location schemas. The commit writes
  `timezone: loc.timezone ?? metaTimezone(loc.meta) ?? null`, where
  `metaTimezone` reads a string `meta.timezone` that passes the same check (the
  fallback for drafts made before this ADR).
- **R11 (decision 10, "top level").** Code stamps it: when the user's message
  matches the guided path's B6 phrase set (`no parent`, `none`, `root`,
  `top level`, `top-level`; `onboarding-chat-rule-based.ts`, ADR 0098
  Amendment 2 B6 — the matcher is exported and reused) **and** the turn's
  `set_location` call omits `parentCode`, `runAgentTurn`'s `runTool` wrapper
  sets `parentCode: null` before the tool runs, as `source: "discovery"` is
  code-stamped today. The description also tells the model. (Q12)
- **R12 (decision 9, lock details).** `locked_by uuid null` with **no FK**
  (ADR text; the DTO joins `users` for a display name at read). Lock a
  non-draft session → 409; lock an already-locked draft → 409 (unlock first);
  unlock an unlocked draft → 200, idempotent. Fixed 409 text on every refused
  write: `"This draft is locked: <reason>. A global administrator can unlock it."`
  (`SESSION_LOCKED_PREFIX`). A discovery job already running when the lock is
  set may still write `_discovery` (the lock refuses *starting*).
- **R13 (F4.328 closure, default coordinates).** The `Set location …` action
  line gains the code-written tail
  `" (default coordinates applied — tell me the real ones if the site is elsewhere)"`
  when `deriveLocationPatch` applied `ONBOARDING_DEFAULT_COORDINATES`. F4.328's
  fix list asks for it; ADR 0117 decision 2's "code-written lines" list admits
  action lines. (Q9)
