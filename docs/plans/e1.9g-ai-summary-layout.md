## 1. Goal

On every surface that shows the findings card (`/forecasts`, `/anomalies`, the control-room organization and site cards, the `ml_findings` widget) the AI text sits in its own tinted box labelled **"AI summary · advisory"**, with an AI mark, a one-line headline, up to four key points and a muted line that says the text is written by AI. Asset references show as code-only chips (full label as `title`) in the box and in the fact lines. Under the box the facts sit under a plain heading **"Computed facts"**, the first two lines shown and the rest behind "Show N more". Prompt version 2 asks the model for that shape. On the control-room organization page the *Findings — advisory* card moves directly above *Asset health*.

**Out of scope** (named so nobody builds it):
- The facts routes and their sentences; the paragraph route, its states and polling; pseudonymisation; `findings-paragraph.guard.ts`; the cache table and its key parts; the 200-a-day cap, the 15 s timeout, the in-flight limit; the widget's `paragraph` switch.
- Any migration, grant, dependency, `apps/ml` change, new route or new widget kind.
- The stored text: it stays one paragraph. The split is on screen only.
- The wall: no findings card there, as today.
- The site page order (Findings is already above *Bad actors*; it has no *Asset health* section).
- `HealthBadActorsCard`, the Forecasts and Anomalies tables, the advisories card: they keep `assetLabelOf`. Q3 covers the findings card only.
- A "Show fewer" control, a persisted open state, a per-user setting.

## 3. Refinements (each is a call inside the amendment; stand unless vetoed)

- **R-a — `code` is required in the schema** (`z.string().min(1).max(64)`), not optional. The compiler and the contract spec then hold "every producer fills it", and the web needs no fallback that reads `label`. Old bundles ignore the extra key (the schemas are not `.strict()`). Cost: the web fixtures that pass through these schemas get `code` in PR 1 (T1.5).
- **R-b — `finishCard` takes `nameOf: (assetId) => { code; label }`** in place of `labelOf`. One lookup, no argument-order trap. An unknown id gives `{ code: id, label: id }` (today's label fallback).
- **R-c — the AI mark is the existing `BotIcon`, moved to `apps/web/src/components/bot-icon.tsx`**; `copilot-dock-parts.tsx` re-exports it, so `copilot-dock.tsx` is not edited. No copy of the SVG, no copilot-store import in the ML card.
- **R-d — the new rule goes directly after the one-paragraph rule** in `FINDINGS_SYSTEM_PROMPT`.
- **R-e — a spec pins the SHA-256 of `FINDINGS_SYSTEM_PROMPT` beside the version.** Today "bump the version when the text changes" is a comment only.
- **R-f — the E1.9g card cases live in a new spec file** (`ml-findings-card-summary.spec.tsx` + `.test.tsx`), so the 717-line spec stays under the §4.5 cap.
- **R-g — selectors.** The box keeps `data-ml-paragraph`; new: `data-ml-headline`, `data-ml-points`, `data-ml-note`, `data-ml-facts` (the facts `<ul>`). The specs and the demo-host `javascript_tool` asserts use them.
- **R-h — "Computed facts" is an `<h3>`** (the card title and the section heading are `<h2>`). "Show N more" is a `<button type="button">`; after a click the rest shows and the button is removed. The state is `useState` in the organization card; a remount starts closed.
- **R-i — a known display limit of the split, accepted:** a rule name that holds ". " and a capital (for example "Temp. High") is cut into two points; a sentence that starts with a time or a lower-case rule name is not cut. Every word stays on screen in both cases.
- **R-j — the org-page order ships inside the web PR**, not as a third PR (one CI run less; Actions minutes are short).

## 4. The rules, exactly

### 4.1 Contract — `packages/shared/src/contracts/ml-findings.ts`

```ts
export const mlFindingAssetSchema = z.object({
  ref: assetRef,
  assetId: z.string().uuid(),
  /** `E1.9g`: the asset code alone (`bms.assets.code`, at most 64), for the short chip. */
  code: z.string().min(1).max(64),
  label: z.string().max(330),
  href: z.string().max(2000),
});
```

**Encoding (§4.8 / ADR 0030):** still one plain `z.object` with one added key. No `.merge()`, no `z.intersection`, no `.readonly()`, not `.strict()`. `MlFindingAsset` stays `z.infer`. No other schema in the file changes.

### 4.3 The sentence split — `apps/web/src/lib/ml-findings.ts` (pure)

```ts
export type FindingPart = { readonly text: string }
  | { readonly code: string; readonly label: string; readonly href: string | null };
export const ML_SUMMARY_MAX_POINTS = 4;
export const ML_SUMMARY_COMPACT_POINTS = 2;
export function splitSentences(parts: readonly FindingPart[]): FindingPart[][];
export function summaryOf(parts: readonly FindingPart[], maxPoints: number):
  { headline: FindingPart[]; points: FindingPart[][] };
```

- Input: the output of `resolveSegments` (text parts and asset parts). Never raw placeholder text.
- A cut is made **after** a character of a text part when all hold: the character is `.`, `!` or `?`; the next character is a space (U+0020); after the run of spaces the next thing is an ASCII upper-case letter `[A-Z]`, a literal `[`, or an asset part. The look-ahead crosses into the following part when the text part ends.
- No cut when the spaces run to the end of the paragraph, or the next thing is a digit or a lower-case letter. So `-41.25`, `tank.level_m` and `approx. 3` are never cut.
- An asset part is one unit. It is never scanned, whatever its code or label holds.
- The run of spaces at a cut is dropped. A sentence with no part left is dropped.
- `summaryOf`: `headline` = sentence 1; `points` = the next sentences, at most `maxPoints`. One sentence gives `points: []`.
- **OQ-1 (a), owner 2026-11-17:** when a sentence past the cap is the only sentence that holds the word "weak" (case-folded, whole word), it takes the last shown point slot, for both caps. A "weak" already shown changes nothing.

### 4.5 Chips (the box and the fact lines)

An asset part draws its `code`. `title` = the full `label`. A safe `href` gives a `<Link>` to the same target as today; an unsafe one gives a `<span>` with the same text and `title`. An unknown reference stays the text "an asset". The web never splits or searches `label`.

### 4.6 Computed facts (full card)

- **With the AI box:** `<h3>Computed facts</h3>`, then the first two fact lines (API order; **OQ-2 (a), owner 2026-11-17**), then `Show N more` (N = lines − 2) when there are more than two. A click shows all lines and removes the button. Not persisted.
- **With no AI box** (switch off, `none`, `pending`, a failed or malformed read, `paragraph={false}`): no heading, every line, no button — the markup of today, chips aside.

### 4.7 Compact card (control room)

Per kind: with an `ok` paragraph, the box with the headline and at most 2 points (OQ-1 (a) applies), and the note **"Written by AI from the computed facts."**; else `compactLines` as today. No "Computed facts" heading and no button.

`OrganizationStripCharts` → `MlFindingsCard` → `HealthSummarySection` → `HealthBadActorsCard` → `OrganizationLoadTrend` → `ScopedDashboardsList`. Props do not change.
