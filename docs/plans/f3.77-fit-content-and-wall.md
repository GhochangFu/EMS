## 2. Design decisions (recommended; Q1–Q5 in §7 are the product choices)

**D1 — Mechanism: CSS auto row tracks over compacted stored rows ("bands as tracks").** `grid-auto-rows: auto` in view mode. The stored `gridY`/`gridH` still place every tile, but the row indices are **compacted**: the sorted set of distinct boundaries `{gridY, gridY + gridH}` over all tiles becomes the track list, and a tile spans the tracks between its two boundaries. The Overview v3 rects (`{0,2,9,11,12}`) give 4 tracks: tiles / rail + Systems / strip / legend. A tall tile beside two stacked tiles spans two tracks; CSS distributes its height across them. An empty stored row produces no track, so it adds no gap. Side-by-side tiles share a track, so the band is the tallest content and the shorter tile **stretches** (the frame fills the band, the content sits at the top); the four KPI tiles therefore stay equal in their row. Rejected: nested "band" DOM (duplicates what grid tracks already do; breaks `data-canvas-tile` targeting and the overlap rule); measured spans (a ResizeObserver per tile, a feedback loop with CSS zoom, and nothing to test in jsdom).

**D2 — Per-type minimum heights come from the content, not the canvas.** The chart and the gauge already carry `flex-[1_1_220px]` with an absolutely filled ECharts box, so their natural height is 220 px plus chrome in an auto host; ECharts gets a definite height. The tank keeps `max-h-[220px]`. Lists have no minimum. No per-type constant enters the canvas.

**D3 — The mimic keeps `useCanvasTileAspect`; the canvas turns the report into a `min-height` in px, not into rows.** `aspectHeightPx(span, containerWidth, aspect) = round(tileWidth × ratio + chromePx)`, set as `minHeight` on the tile wrapper in view mode once the width is measured (null before). The SVG (`h-full w-full`, `meet`) also resolves its own aspect height, so the two agree; the `minHeight` is the deterministic, jsdom-testable half. The breakpoints (`<= 1024` half, `<= 640` single) keep `spanFor`; their `gridRow` becomes `auto` (one track per auto-placed tile) and the mimic gets the same `minHeight` at its reflowed span. "A desktop mimic never shrinks below its stored rows" (M2) is retired: a view tile has no stored height any more.

**D4 — Builder exemption stays in one place, `canvasLayout`:** `arranging` returns `gridAutoRows: "72px"`, the stored rects unshifted, `minHeightPx: null`. `measuredCellSize()` keeps `ROW_HEIGHT_PX`.

**D5 — Wall fit = computed `zoom`.** `wallBaseZoom(viewportWidth)` is 2.5 at `>= 3000`, else 1.25 (moved from `index.css` into `lib/wall-mode.ts`, one source). `wallFitZoom({ base, viewportHeight, naturalPx, floor })` = `floor2(min(base, viewportHeight / naturalPx))`, clamped to `[floor, base]`; `naturalPx` is the bar's plus the content wrapper's `offsetHeight` (unscaled CSS px, zoom-independent). Feedback loop: a zoom change changes the content width in CSS px, so the content's ResizeObserver fires again; the hook recomputes and sets state only when the value differs, and a **growth needs +0.05 hysteresis** (`settleWallZoom(current, target)`), so a wrap-induced two-cycle damps. `min-h-screen` moves to an unzoomed outer div so `100vh` is never measured inside the zoomed box. `.wall-root` CSS zoom rules are deleted (an inline `style.zoom` is the one source).

**D6 — Wall chrome.** `SiteDashboardView` takes `wall?: boolean`. With it, the body renders in a plain `<section>` with an `sr-only` `<h2>` (the dashboard name, keeps h1 → h2 → h3) and no `SectionCard` header; the tab nav stays. `site-page.tsx` passes `wall` only in the `WallFrame` branch.

**D7 — Known limit, flagged (Q4):** a full-width mimic tab's height is width-bound (`W × ratio` in viewport px, constant under zoom), so zoom alone cannot fit the domain tabs at 1920 × 1080. Task 7 caps a fixed-aspect tile in wall mode; it is optional.

## 9. Post-review (2026-10-02)

- **D5 superseded in one point.** The +0.05 growth step alone does not damp a large re-wrap: a content jump above about 5 % gave a permanent two-cycle (1100 px → 0.98, 1000 px → 1.08). `settleWallZoom(current, target, ceiling)` now also keeps an overflow ceiling: the lowest zoom at which the content was seen to overflow. A growth never passes it. A window resize or a new tab clears it. Known limit: a transient content growth (an alarm burst) keeps the zoom smaller until the next tab or resize; the page is then small, never overflowing.
- **H4 and the probe elements.** The hook spec sets `offsetHeight` with a prototype getter (an element property cannot be set before the first layout effect), and it uses its own fake observer (the canvas spec's `fireWidth` is not exported).
- **Deviations.** `compactRowTracks` also drops the row intervals that no tile covers (R1). `VIEW_FLOOR_MIN_ROWS` was renamed to `BUILDER_MIN_ROWS`. The `wall-root` class was removed with its CSS; `[data-wall-root]` is the hook. `wallAspectCapPx` and `WALL_ASPECT_CAP_FRACTION` live in `lib/wall-mode.ts`, and the frame memoises the fit context.
- **Reviews.** `code-reviewer` found 1 minor (the two-cycle above); it is fixed. `agents-compliance-reviewer` found 1 major (the table cap and the builder). The mechanism was refuted: the scroll box is a flex child with `overflow-auto`, so its minimum height is 0. The guard was hardened anyway.
