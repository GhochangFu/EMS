# F4.156 — gate the Control Room 2D menu and the `/cr-*` routes on a readable `CR-*` asset

Plan by `plan-architect` (Fable), 2026-09-25. Owner rulings the same day:
**OQ1 yes** (the route guard applies the per-area `asset_group` rule too),
**OQ2 yes** (`staleTime: 5 min` on the shell/guard observer). No ADR (owner-gated
2026-09-25).

## Goal

A user who cannot read any Eskom `CR-*` asset must not see the *Control Room
2D* sidebar group and must not be able to open any of the seven `/cr-*` pages.
Today `apps/web/src/layouts/app-shell.tsx:128-139` `isVisible` returns `true`
for every scope kind except `asset_group` (line 132), and
`apps/web/src/app.tsx:288-347, 706-715` guards the seven routes on
`accessToken && user` only. The fix adds one predicate, one hook and one route
guard, reuses the `["assets"]` TanStack query the schematic provider already
issues, fails closed while that read is pending or failed, and keeps the
existing per-area `asset_group` gate (`lib/control-room-access.ts`) on top.

**Out of scope.** No API change, no contract change
(`packages/shared/src/contracts/` untouched), no ADR, no per-organization
Control Room (ADR 0076, in design), no change to the seven page files, no
change to the API's `readableAssetIds` filter. AGENTS.md is not touched.

**Two corrections to the row text, measured.** (1) There is no `organization`
scope kind: `accessScopeKindSchema` is `global | location | asset_group | none`
(`packages/shared/src/contracts/auth.ts:50`). An `organization_admin` such as
`phe-admin@bms.local` receives `kind: "location"` with its organization's
locations (`apps/api/src/auth/access-scope-sources.ts:83-124`). Spec fixtures
use `kind: "location"` for the PHE user. (2) The client never sees
`readableAssetIds`; it sees the filtered `GET /api/v1/assets` body
(`apps/api/src/assets/assets.controller.ts:80`). The gate tests the body for a
`CR_TRACKED_ASSET_CODES` code. A global admin reads all 43 `CR-*` rows and
needs no special case.

## Decisions

- **Denied route → `<Navigate to="/" replace />`.** Precedent:
  `components/admin-route.tsx:37`, `components/dashboard-author-route.tsx:29`.
- **Pending read → render a status line, do not redirect.** On a hard reload
  the persisted session restores `accessToken` and `user` before the assets
  query resolves; redirecting on pending would bounce every legitimate user off
  a cold load of `/cr-*`. Render `<p role="status">Checking Control Room access…</p>`.
- **Decide from `data`, never from `status`.** TanStack v5 sets
  `status: "error"` on a failed *background* refetch while keeping `data`.
  Rule: `data` defined → decide from `data`; `data` undefined and `isPending` →
  pending; `data` undefined and not pending → denied.
- **Query key `["assets"]`, `queryFn: () => fetchAssets()`**, exactly as
  `components/live-svg/schematic-telemetry-context.tsx:100-103`. Other
  `fetchAssets` callers use `["assets","list"]`, `["assets","picker",org]`,
  `["assets","dashboard-scope",org]` — no collision. `pages/sld-page.tsx:191`
  and `pages/crac-page.tsx:214` also use `["assets"]` with the bare call.
- **`staleTime: 5 * 60_000` on the shell/guard observer** (OQ2, ruled yes).
  Per observer: the provider's own `["assets"]` observer keeps `staleTime: 0`.
- **The predicate takes the code list as a parameter** and lives in `lib/`,
  mirroring `lib/schematic-access.ts` `hasCompleteSchematicAssets`. The hook
  binds `CR_TRACKED_ASSET_CODES`.
- **Per-area scope check also in the route guard** (OQ1, ruled yes).
- **`none` and `null` scope.** Kept as is; covered by shell case S6.

```ts
/** `F4.156` — true when the caller's readable asset list holds at least one tracked code. */
export function hasAnyControlRoomAsset(
  assets: readonly Pick<AssetRow, "code">[] | undefined,
  assetCodes: readonly string[],
): boolean {
  const tracked = new Set(assetCodes);
  return assets?.some((asset) => tracked.has(asset.code)) ?? false;
}
```

### Task 2 — the hook

`apps/web/src/hooks/use-control-room-access.ts`:

```ts
export type ControlRoomAccess = "pending" | "granted" | "denied";
export const CONTROL_ROOM_ACCESS_STALE_MS = 5 * 60_000;
export function useControlRoomAccess(): ControlRoomAccess {
  const assets = useQuery({ queryKey: ["assets"], queryFn: () => fetchAssets(), staleTime: CONTROL_ROOM_ACCESS_STALE_MS });
  if (assets.data === undefined) return assets.isPending ? "pending" : "denied";
  return hasAnyControlRoomAsset(assets.data, CR_TRACKED_ASSET_CODES) ? "granted" : "denied";
}
```

No separate hook spec: Tasks 3 and 4 exercise every state.

```tsx
export function ControlRoomRoute({ children }: { children: ReactNode }) {
  const { pathname } = useLocation();
  const scope = useAuthStore((s) => s.scope);
  const access = useControlRoomAccess();
  if (access === "pending") return <p role="status">Checking Control Room access…</p>;
  if (access === "denied" || !canAccessControlRoomPath(scope, pathname)) return <Navigate to="/" replace />;
  return children;
}
```
