## Goal

On the web, a self-contained `GeneratedSiteView` (`{ locationId }`) renders the site KPIs from the existing `/dashboard/locations/:id` read, then the domain panels and asset cards, and overlays `/ws/telemetry` readings with the ADR 0027 staleness gate. PHEWB's 50 assets have no `template_id`, so nothing here reads a template.

**Out of scope.** Routes, menu, breadcrumb, the resolve-read call and the fail-safe notice banner (`F3.66` owns `app.tsx`, `app-shell.tsx`, the three `/control-room*` pages). The dashboard site view (`F3.69`), the SMOC tabs (`F3.70`), the mimic (`F3.32`). No `ActiveAlarmsRail` on the site view. No site target for templates. No change to `/locations/:id`. No `AGENTS.md` edit in this branch (a `chore(agents):` sweep after merge, §9.10).

## Decisions (engineering)

- **D1 — rank semantics.** `headline_rank smallint NULL`, CHECK `headline_rank IS NULL OR headline_rank > 0`. Lower shows first. Ties by `point_key ASC`. Not unique. One ordering rule: `ORDER BY headline_rank ASC NULLS LAST, point_key ASC`, take the first four — so an asset with no ranked point shows its first four by `point_key`.
- **D2 — the points of an asset are its active `bms.asset_points` rows**, not the distinct keys in `point_values`. Rank and catalog name from `LEFT JOIN bms.point_keys pk ON pk.code = ap.point_key`; unit `COALESCE(ap.unit, pk.unit)`.
- **D3 — an asset's live status is the newest sample among its registered points**, judged with the shared 25 s window: `freshness = "live" | "stale" | "none"` at `asOf`, re-derived on the web with `isStale` on a `STALE_TICK_MS` timer. This can differ from `/locations/:id`'s `freshAssetCount` (any point, registered or not); stated, not hidden.
- **D4 — two SQL statements per request, whatever the asset count** (no N+1): (1) the site's assets in scope with their domain label, ordered `asset_domains.sort_order, code, assets.code`; (2) the points with latest values — `scoped_assets` ⨝ `asset_points` ⟕ `point_keys` ⟕ `LATERAL (… WHERE pv.asset_id = ap.asset_id AND pv.point_key = ap.point_key AND pv.time > now() - interval '7 days' ORDER BY pv.time DESC LIMIT 1)`. **Amended by owner ruling (2026-09-26, step-5 blocker):** the first build's `DISTINCT ON (asset_id, point_key)` over the whole site ran 69.7 s for `RSMOC-WC` (an external merge sort of 411 MB); the per-point `LATERAL` bounded by a literal 7-day window plans in 31–41 ms and runs in ~13 ms there. The window is the exported constant `GENERATED_LATEST_WINDOW_SQL`, interpolated as a literal — never a bound `now() - $1`, which plans every chunk (an unbounded `LATERAL` planned in 574–1228 ms). **A point silent for more than 7 days shows "—"** (`latest: null`), and an asset with no sample in 7 days reads `none`. Grouped by domain in TypeScript. No template table, no `LIVE_ASSETS_CTE_SQL` interpolation. No `assets.active` filter (parity with the KPI header).
- **D5 — site KPIs come from the existing `/locations/:id` read, on the web** (`fetchLocationDashboard`, refetch 8 000 ms): six `KpiTile`s and the partial-scope line. No API change, no cross-module import.
- **D6 — the generated read returns every active point of every asset**, server-ordered; the card slices `HEADLINE_POINT_COUNT = 4`; "All points" expands inline (OQ2).
- **D7 — access.** `GeneratedSiteViewService.forUser(jwt, locationId)`: the F3.67 readable rule, else the same 404; `assetIds` into the `WHERE` (`$2::uuid[] IS NULL OR a.id = ANY($2)`), on `FLEET_POOL`. `read(locationId, assetIds)` is the pool-only half.
- **D8 — the seed ranks in a separate step, after the last catalog writer.** `seedPointKeyHeadlineRanks(pool)`: one `UPDATE bms.point_keys SET headline_rank = <CASE> WHERE headline_rank IS NULL AND (<predicate>)` driven by `HEADLINE_RANK_SEED` (OQ1 values), parameterised, `LIKE` patterns escape `_`. Runs after `seedPointKeyCatalog` and after the PHE pilot seed. Idempotent. Never overwrites a rank (OQ3). Not in the migration.
- **D9 — freshness helper extracted, narrowly.** `telemetryFreshnessAt(latestIso: string | null, nowMs: number): "live" | "stale" | "none"` in `telemetry-freshness.ts`; `DashboardService.telemetryFreshness` delegates.
- **D10 — no `.parse` on stored rows.** Rows mapped by hand.
