## 1. Goal

Write, read and show advisory anomaly scores. `E1.2a` adds an anomaly job to `apps/ml`: every hour, after the forecast child, a second child process scores the last complete hour of each eligible asset with a median/MAD baseline and (for an asset with two or more scored points) an Isolation Forest, and writes every scored hour to `ml.anomaly_scores`. `E1.2b` grants `bms_tenant` `SELECT` on that table, adds two `GET` routes with contracts, and marks unusual hours on the asset history chart. `E1.2c` adds the `/anomalies` list page and its navigation item. `E1.2d` adds the `anomaly` dashboard widget kind. ## 3. Refinements (each is a call inside the amendment; veto at skim)

- **R1 — ties: "strictly below" (pending Q1).** Section 4 counts the window hours whose statistic is **less than** this hour's. The amendment says "at or below"; with those words a flat point scores 1.0 every hour.
- **R2 — one rule for the baseline's history.** Median and MAD are always taken over the baseline window (up to 91 days before the scored hour), in both slot modes. The percentile is always taken against the 28-day reference window. The amendment allows the 91-day read "only for the median/MAD"; it does not say that hour-of-day must use 28 days.
- **R3 — the MAD floor** (ruling 3 leaves it to the plan): one floor per point, section 4.3.
- **R4 — minimums.** A slot needs 8 samples in either mode. A percentile needs 336 reference hours. A forest needs 336 complete training rows. Below a minimum, that score is not written and the reason is counted.
- **R5 — an asset is all-or-nothing** (ruling 1's words). Consequence to know: one dead or stale target point on a meter stops the whole meter. `eligibility --job anomaly` shows which point.
- **R6 — one tick, one hour.** `serve` computes the tick's hour once and passes it to the anomaly child as `--as-of`. A slow forecast child then cannot make the anomaly child score the next hour before HH:05 and freeze it in the ledger. The forecast child is not changed.
- **R7 — jobs retry alone.** The scheduler runs a list of jobs. After a failure, the retry runs only the failed job. A failing anomaly job must not reload Chronos every 300 s.
- **R8 — health.** The body keeps `lastCycle` (forecast) and gains an `anomaly` object. `status` is the worst of the enabled jobs.
- **R9 — history is read per asset** (one `HISTORY_SQL` call per asset, at most 15 points × 2,185 hours), so the child's memory does not grow with the asset count.
- **R10 — the SQL guard's allowlists grow by two names:** `ml.anomaly_scores` in `READ_SOURCES` (the ledger must read it, as it reads `ml.forecasts`) and `string_to_array` in `ALLOWED_FUNCTIONS` (the insert). Both are a visible diff in two files, as the guard intends.
- **R11 — the wire carries no model name or version.** A-e's list is a ceiling (S3). No surface shows them. Adding them later is one column.
- **R12 — "newest run wins", then the threshold.** A re-run writes new rows. Both reads take the newest succeeded run per `(asset, hour, detector)` first and apply `score >= 0.99` after. A re-run that lowers a score removes the mark.
- **R13 — `since` is clamped, not refused.** `GET /ml/anomalies?since=` uses `max(since, now − 7 days)`; without `since` it is `now − 7 days`. The list returns at most 500 rows, newest first, with `truncated`.
- **R14 — chart marks only on windows of 31 days or less** (the route's cap), beside `avg`. The `1y` preset draws none.
- **R15 — `anomaly` is refused in both template surfaces**, as `forecast` is (ruling 4c: "builder palette only").
- **R16 — the widget's config is `{}`.** The bound point names the asset and is not drawn.
- **R17 — `bms-ml` stays at version 0.1.0** and the lock step must move no existing pin, so the forecast `config_hash` does not change and the deploy re-scores nothing.
- **R18 — the scorer does not know 0.99.** `ANOMALY_UNUSUAL_SCORE` lives in `packages/shared` only (ruling 3: applied at read time).

## 4. The score, exactly

All times are whole UTC hours. `H` = `as_of_hour` (the clock, or `--as-of`, floored). **`S = H − 1 h`** is the scored hour.

### 4.1 Windows and values

- Baseline window `B` = the 2,184 hours `[S − 2,184 h, S)`. Reference window `W` = the last 672 hours of `B`, `[S − 672 h, S)`. Neither holds `S`.
- One read per asset: `HISTORY_SQL` with `from_hour = S − 2,184 h` and `as_of_hour = H` (so `S` is included).
- `x_p(t)` = `sum_value / sample_count` of the point's `_1h` row. The hour is **missing** when there is no row, `sample_count` is null or 0, `sum_value` is null, or the quotient is not finite. A missing hour is `NaN` in the grid and is never filled (`tests/test_no_imputation.py` scans the new modules too).
- An on/off point is scored on this mean (the fraction of the hour it was on).

### 4.2 Eligibility (ruling 1)

`ELIGIBILITY_SQL`, unchanged, with `ML_ANOMALY_TARGETS` and the 400-day look-back. Per point, the first failure wins: `no_data` → `too_few_days` (`days_with_data < 28`) → `low_coverage` (`< 0.8`, the CLI's full-span formula) → `stale` (`last_bucket < H − 3 h`) → `ready`. An asset's **scored points** are the target points the read returns for it. **The asset is scored only when every scored point is `ready`**; otherwise the asset is skipped as `asset_not_ready` and each failing point is counted under its own reason.

### 4.3 Baseline (`baseline_mad`)

Per scored point `p`:

1. **Slot mode.** `how(t) = weekday(t) × 24 + hour(t)` (Monday = 0; 2026-11-16T00:00Z is slot 0, 2026-11-22T23:00Z is slot 167). Count the non-missing hours of `B` per `how` slot. If the smallest of the 168 counts is **≥ 8**, the mode is hour-of-week (168 slots). Else it is hour-of-day (`slot = hour(t)`, 24 slots).
2. **Slot statistics**, over the non-missing hours of `B` in the slot: `n_k`, `m_k = median`, `MAD_k = median(|x − m_k|)` (`numpy.median`). A slot with `n_k < 8` is **undefined**.
3. **Floor**, one per point, over all non-missing hours of `B`: `floor_p = max(1e-6, 1e-4 × median(|x|), 0.01 × (P95(x) − P05(x)))` (`numpy.percentile`, default interpolation).
4. **Robust z:** `z_p(t) = |x_p(t) − m_k| / (1.4826 × max(MAD_k, floor_p))`, `k = slot(t)`. Undefined when `x_p(t)` is missing or the slot is undefined.

Per asset: **`b(t) = max` of `z_p(t)` over the scored points where it is defined.** `b(t)` is undefined when no point has a defined `z`.

- Reference `R = { b(t) : t ∈ W, b(t) defined }`, `n = |R|`. If `n < 336`: no baseline row (`reference_too_sparse`).
- If `b(S)` is undefined: no baseline row (`no_data_at_hour`, or `slot_too_sparse` when a value is present but its slot is undefined).
- **`score = count(r ∈ R : r < b(S)) / n`** (R1). Always in `[0, 1]`.

Worked values the tests pin: reference `[0, 0, 0, 0]`, value 0 → **0.0**; reference `[1, 2, 3, 4]`, value 5 → 1.0, value 4 → 0.75, value 2.5 → 0.5. With `n = 672`, a score is ≥ 0.99 when at least 666 window hours are strictly below (value 666.5 against 1…672 → 0.99107; 665.5 → 0.98958). A point that is 1.0 in every hour has `floor_p = 1e-4`; at 1.0 its `z` is 0 and the score is 0.0; at 0.98 its `z` is `0.02 / (1.4826 × 1e-4) ≈ 134.9` and the score is 1.0.

### 4.4 Isolation Forest (`isolation_forest`)

Only for an asset with **two or more scored points** (counted from eligibility, not from the hour).

- Features: the asset's scored points in ascending point-key order, raw `x_p(t)`, no scaling, no time feature.
- Training rows: the hours of `W` where **every** scored point is present. If fewer than 336 rows: no forest row (`if_too_few_rows`). If any scored point is missing at `S`: no forest row (`if_incomplete_hour`). The baseline row is still written.
- `IsolationForest(n_estimators=100, max_samples=256, contamination="auto", max_features=1.0, bootstrap=False, n_jobs=1, random_state=135, warm_start=False)`, `float64` input, fitted new every cycle.
- Statistic `i(t) = −score_samples(row)`: higher is more unusual. Reference = `i` of the training rows; `score = count(reference < i(S)) / rows` (R1).
- An exception in one asset's forest skips that row (`forest_failed`, class name only in the log) and keeps the asset's baseline row.

### 4.5 Both detectors

- **Contributing points:** the scored points with a defined `z_p(S) > 0`, sorted by `z` descending, then point key ascending; the first 3. A point that is missing at `S` is never listed. Both rows of the hour carry the same list. The list may be empty.
- A score that is not finite is not written (`non_finite_score`).
- **Run row (A-a):** one per organization per cycle. `model_name = 'bms-anomaly'`. `model_version = 'bms-ml=<v>;scikit-learn=<v>'`. `config_hash` = sha256 of the canonical JSON of: the job name, the targets, the thresholds (28 days, 0.8, 3 h, 400 days), every constant of 4.1–4.5 (672, 2,184, 8, 336, 1.4826, the three floor constants, 3, `"ties": "strict"`), the forest's keyword arguments, and the versions of `bms-ml`, `numpy`, `scikit-learn` and `scipy`. The run row and its scores are written in one transaction; a failed run writes `error_text = '<stage>:<ExceptionClass>'` and no score.
- **Ledger (A-a):** an organization's hour is skipped when a succeeded run with the same name, version and hash holds a row at bucket `S`, unless `--force`. Known limits, accepted: a point that arrives late for `S` is not scored for `S`; an organization that wrote zero rows for `S` is scored again on a catch-up.
- The in-sample reference makes the share of unusual hours a little above 1 %. Step 6 reads the real share after a week (section 12). No accuracy figure is shown anywhere.

## 17. Questions only the owner can rule

1. **Ties in the percentile (needed before PR 1's first line of code).** Ruling 3 says the score is the share of window hours "at or below" this hour's statistic. With those words, a point that does not move (an on/off point, `controller_power_status`) has every statistic equal, so every hour scores 1.0 and is "unusual". *Recommended:* count only the hours **strictly below** (R1). A flat hour then scores 0, a new maximum scores 1.0, and for a point that moves the two readings give the same number. The other option is the mid-rank (a tie counts half; a flat hour scores 0.5).
   **Ruled 2026-11-16 (owner): strictly below** (R1). Recorded in ADR 0135 Amendment 5 as a correction to ruling 3.
2. **The lock step (needed before PR 1).** `uv add scikit-learn` must reach `download.pytorch.org`, which this cloud environment blocks (A-g, Amendment 2 item 6). *Recommended:* allow `download.pytorch.org` for this session's environment; the step is then one command with `uv 0.8.13`.
