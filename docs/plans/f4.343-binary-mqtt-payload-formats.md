## 1. Goal

Add a third definition kind, `binary`, to the ADR 0116 payload-format catalog so
a vendor whose devices publish a **fixed-length binary record** onboards with a
catalog row, not a code change. The one shared decoder, `decodeMqttPayload`,
takes **bytes** instead of a UTF-8 string; `builtin` and `declarative` decode
those bytes as UTF-8 exactly as today, so PHE and BCPL behave byte-for-byte as
before, and `binary` reads them with a `DataView`: an exact `length`, a required
`byteOrder`, optional time from six date fields with a fixed UTC offset (or a
uint32 epoch), and typed readings at byte positions with `scale`/`offset` and
`sentinels` that make a reading absent. Both callers — the ingest MQTT adapter
and the discovery collector — pass the payload bytes; discovery tries a binary
format only for a message that is not valid UTF-8 JSON and whose length matches.
The admin test route and the web test box accept a **hex** sample. A seed
migration adds `wbldc-temp-100` (16 × `int16` tenths of °C, IST date fields).
Golden tests cover WBLDC (three real captures), BCPL and PHE.

**Out of scope.** The WBLDC onboarding itself and the AWS `MQTT_PLAINTEXT_HOSTS`
edit (owner tasks, §5 "After deploy"); variable-length frames, bit fields,
checksums, Modbus RTU framing, a byte-range device key (ADR 0119 Consequences —
a later ADR/amendment); `uint8` date fields (§3 R2); base64 samples (§3 R4);
calibration offsets in a format (R5: they go on the point's `scale_offset`);
any change to `parseMqttEnvelope`; any AGENTS.md edit (ADR 0119: nothing moves).

## 3. Drafter refinements (ADR 0119 lines marked *(drafter)*)

- **R1 — decoder signature (decision 2).** `decodeMqttPayload(definition, topic, raw: Uint8Array)`. One input type, no string twin. `builtin`/`declarative` decode with `new TextDecoder().decode(raw)` (non-fatal, so invalid bytes become U+FFFD and `JSON.parse` fails → `not-json`, exactly what `Buffer.toString("utf8")` gave). A `Buffer` is a `Uint8Array`, so the adapter passes `payload` as is; the collector keeps `offer(topic, Uint8Array | string)` and encodes a string with `TextEncoder` (40+ spec calls stand); the test service encodes text or parses hex. Rejected: a `decodeMqttPayloadBytes` twin — two entry points for one function, and the string one is silently wrong for `binary`. (Q1)
- **R2 — date field width (decision 1).** `uint16` only. YAGNI: WBLDC is the only known vendor; a `width` field later is an optional key with a default — additive, no migration. (Q3)
- **R3 — field naming (decision 1).** The byte position of a reading, and of the epoch time variant, is **`byte`**, not `offset`: the ADR's text uses `offset` for both the position and the affine correction, and F4.334 ruling 3 chose `index` for the register start so `scale`/`offset` keep the affine meaning. Date fields are plain byte positions: `fields: { year: 4, month: 6, day: 8, hour: 10, minute: 12, second: 14 }`. (Q2)
- **R4 — hex only (decision 5).** The test body gains `encoding: z.enum(["text", "hex"]).default("text")`. Hex: whitespace ignored, no `0x`, odd nibble count or any other character → 400 with the fixed text `"sample is not hex"`. No base64. The parser `hexToBytes(text): Uint8Array | null` lives in the shared binary module so the web disables Decode on bad hex client-side. (Q7)
- **R5 — seed (decision 6).** Migration `0135`, INSERT-only, `ON CONFLICT DO NOTHING` (the 0130 precedent, F4.334 ruling Q6): AWS gets the row at deploy, no manual step; a later admin edit is never reverted. No `SET ROLE` (a row has no owner); no DDL. It lands **last** (PR 3) so the schema that validates the joined/seeded definition is already deployed. (Q6)
- **R6 — ADR 0099 (decision 7).** No amendment. No route is added or changes method; `EXCLUDED_ROUTES` keeps exactly `POST …/test`; the three catalog entries keep their `bodyName`s and their body schemas simply widen through the shared union. The read tool `decode_payload_sample` gains an optional `encoding` argument (its sample is "the test route's twin"); that is an input detail of a tool Amendment 17 already defines. (Q5)
- **R7 — sentinel → absent as "key omitted"** (R3 ruling). A sentinel hit omits the key from `values` (the adapter's `missing` path), so the discovery drawer lists only live channels for `Haringhata_VAP`; a non-finite float stays `null` (ADR 0116 decision 3). (Q4)
- **R8 — `byteOrder` required** on a binary definition (no default): a silent big-endian default on a little-endian vendor would decode plausibly wrong numbers. Per-reading `byteOrder` optional override as the ADR says. (Q8)
- **R9 — caps.** `length` 1–4096, readings 1–128, sentinels ≤ 8 integers, `utcOffsetMinutes` −720…+840 (the ADR's drafter values). A field whose `byte + size(type) > length` is a `superRefine` issue at its path. (Q10)
- **R10 — impossible date.** `fields` time: month 1–12, day 1–31, hour 0–23, minute/second 0–59, year 1970–9999; build `Date.UTC(y, m−1, d, h, mi, s)` and require the round trip (`getUTCMonth() === m−1 && getUTCDate() === d`, so 31 February is absent); subtract `utcOffsetMinutes × 60 000`. All-zero fields → absent. Epoch variant: `uint32` at `byte`, `epoch_s` ×1000 / `epoch_ms`; `0` is accepted as the declarative path accepts it.
- **R11 — discovery (decision 4).** One pass over the ordered formats (chosen first, as `loadDiscoveryFormats` already orders). A `binary` format is tried only when `definition.length === bytes.byteLength` **and** the message is not JSON — computed once per message, lazily at the first binary format: `TextDecoder("utf-8", { fatal: true })` succeeds and `JSON.parse` succeeds ⇒ JSON ⇒ skip every binary format. JSON formats cannot decode non-JSON bytes, so the relative order of JSON and binary formats in the list does not matter.
- **R12 — module split.** The binary schema, decoder and `hexToBytes` go in a new sibling `packages/shared/src/ingest-adapters/mqtt-payload-format-binary.ts` (the main file is at 418 lines; keeps each file well under the §4.5 cap and keeps the JSON decoder diff to the signature).
