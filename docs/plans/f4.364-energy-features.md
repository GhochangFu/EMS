## 2. Plan-gate rulings (owner, 2026-11-14, in chat, one at a time)

1. **Q1 — Trends & Energy also holds the segment trends.** *Ruled: keep the entry as **Trends** when energy is not shown; omit only the **Energy** sub-tab and open the first segment.* The one-line note shows on an explicit `?view=energy` or when the site has no segment. Recorded as **ADR 0133 Amendment 1** (amends decision 5). +0.5 day in PR 2.
2. **Q2 — where the settings are edited.** *Ruled: the Edit dialog and `PATCH` — global admin only, audited `master.organization.update`.* An `organization_admin` cannot change them.
3. **Q3 — which assets the card's health score covers.** *Ruled: the node's own active assets* — one asset set per card, equal to the endpoint for every leaf location. ADR build note.
4. **Q4 — the other kW readers.** *Ruled: when `energyShown` is false, do not render the "Total load" tiles (site view, Assets & RTUs) and omit the accordion header's kW part; when shown with `null`, show `—`.*
5. **Q5 — `card_primary_metric = 'kw'` while energy is not shown.** *Ruled: honour it — `primaryMetric: "kw"`, figure `—`.* Only `auto` reads the energy state.
6. **Q6 — when `healthScore` is computed.** *Ruled: only for locations whose resolved `primaryMetric` is `health`; `null` otherwise.* ADR build note on decision 4.

## 3. Design decisions (no ruling needed)

| # | Decision | Why |
|---|---|---|
| D1 | "Has energy data" = `bool_or(a.active AND latest.kw_time >= now() - make_interval(days => $3))` inside the existing `kw_by_location` CTE. | The newest `kw` time is already there; no new scan, same `$2` scope. |

## 9. Risks

7. **The estate ribbon still reads "Total load 0.0 kW"** for a user who reads only no-energy organizations (`kpis()` is out of scope). Possible follow-up row.
