# F4.311 — step-3 plan: per-asset calculated points (ADR 0109)

Gate check: ADR 0109 is **Accepted 2026-11-04**, merged on `main` at `3f931462`. BACKLOG row `F4.311` (`docs/BACKLOG.md:976`): Status 🟡, P2, 2–3, Depends `—`, no ⭐. Scope is settled; this plan does not re-open the eight rulings. CodeGraph was not reachable (no `codegraph` binary on PATH, no MCP tool), so the blast radius below was built by reading the files directly.

## 1. Goal

An administrator can give an asset whose `assets.template_id IS NULL` a calculated point of its own: an `asset_points` row with `source_kind = 'computed'`, `rtu_id` NULL, and all five calc columns set. The calc engine computes it beside the template-derived points. The point is created from the asset's points page, from the copilot, and from a 25-asset batch, through one set of write rules. An optional backfill of up to 31 days runs on the worker and shows its progress on the page.

**Out of scope** (ADR 0109 Consequences): adopting an existing asset onto a template version (later amendment); turning a per-asset row into an override on adoption (ruling 8); any change to the template query or the asset-first coalesce; any change to `asset_points` columns; AGENTS.md edits inside a feature PR.
