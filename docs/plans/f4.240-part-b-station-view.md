# F4.240 part b — plan: the combined PHE station view (ADR 0140, two web PRs)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans (or superpowers:subagent-driven-development) to work this plan task by task. Steps use checkbox (`- [ ]`) syntax. Not a ⭐ enabler. Two PRs, serial (section 8).

Written 2026-11-19 against `main` = `c9d7f8f`. Paths are relative to the repository root. Drafted by `plan-architect` (Fable, effort high). CodeGraph was not available in the drafting session, so the blast radius in section 6 comes from ripgrep over `apps/web/src`. ADR 0140 cites `2d0c1cda`; #1458 moved `site-page.tsx` by about ten lines, and every anchor below is re-read at `c9d7f8f`. **Status: approved 2026-11-19** (owner: "Yes, build both PRs"; rulings Q1 and Q2 in section 10.1).

**Goal.** `/control-room/site/<station id>` shows the station as one screen for a caller who can read it. PR 1 adds the totals, the site cards, the active alarms of both sites, the kept advisory cards, a dashboards list without the old empty copy, and an "Assets & RTUs" entry that links to each site. PR 2 adds both sites' dashboard tabs side by side under one tab chooser, and a Trends & Energy tab with the subtree energy view, one bill per site and their sum. The organization page's station header gains an **Open** link, and the station crumb on a site page becomes a link.

**Architecture.** `apps/web` only. No API, contract, schema, route, migration or dependency change (ADR 0140 decision 5). The station rule is a pure function over the KPI items the page already reads. Every panel reuses an existing component and an existing read; each site half is that site's own read behind that site's own check.

**Tech stack.** React 18 + TanStack Query + react-router (`apps/web`), Vitest with jsdom opted in per `.test.tsx` wrapper.

**Scope gate.** ADR 0140 is merged (#1455) and its rulings Q1–Q8 are the scope. `F4.388` release C is deployed (#1457, #1460), and `F4.390` PR 3 is merged (#1458), so both preconditions of decision 7 are met. One finding does not fit decision 5 as written and is put to the owner as Q1; nothing in this plan works around it silently.

**Out of scope** (ADR 0140 decision 8, plus what this plan adds):

- a merged mimic or a combined trend strip;
- a station bill priced on both meters;
- calc over a subtree;
- subtree reads for the generated view or the Assets table;
- deleting the station's old dashboard;
- a partial view for a one-site grantee;
- a wall for the station;
- a combined view for a parent that holds assets;
- Export and Schedule buttons on the station's energy tab (not in decision 3f; say if wanted);
- tab status markers on the station's tab chooser;
- any change to the other pages' 8 s list poll.

## 2. Plan decisions (drafter lines the ADR lets the plan refine)

- **D1 — the station rule.**
  - `stationGroupOf(items, locationId)` returns the `groupSitesByParent` group whose parent is `locationId`, when that parent's `assetCount` is 0; else `null`. For a two-level tree this is exactly decision 1's rule.
  - In a deeper tree, an asset-less grandparent whose children are all asset-less parents has no direct site, so it keeps today's page (`location-kpi-groups.ts:146-147` already says deeper trees are not nested). PHE is two levels.
  - The rule holds whatever the station's view row says.
- **D2 — totals are the header's sentence.** Extract `siteGroupRollupText(group)` from `site-card-groups.tsx:79` and render it in both places. The station adds ` · <kW> kW` from the exported `sectionKw(group.sites)`: one decimal, the `org-location-accordion.tsx:78` format, omitted when `null`.
- **D3 — the Open link.**
  - A sibling of the header button or heading, never inside it, shown when `group.parent.assetCount === 0`.
  - On all three hosts, as one component; the parent is always readable there.
  - Text "Open", accessible name "Open <station>".
  - ADR decision 2 names only the organization page; restricting the link to it is one condition.
- **D4 — every readable parent crumb links** to `/control-room/site/<parent id>`. A parent the caller cannot read is not in the items, so it has no crumb (C8, `control-room-levels.spec.ts:251-268`).
- **D5 — the alarms component is `ActiveAlarmsRail`**, with a third `{ locationId }` arm, beside the site cards as on the organization page.
- **D6 — the station draws no view notice and no layout wizard.** `SiteViewBody` is not mounted, so "Make site layout" cannot create another empty copy at the station.
- **D7 — PR 1 shows two strip entries, "Station view" and "Assets & RTUs".**
  - Any other segment at a station, `trends` included, redirects to the bare path until PR 2.
  - Nothing links to the station page today, so no working screen is removed, and PR 1 never mounts the station bill.
- **D8 — the chosen tab is the route's `:tab` segment** (PR 2), because widget links inside each half already point there (`site-widget-live.tsx:95-103`).
  - The chooser lists the union of the sites' dashboard tab keys, first seen wins: sites in list order, then `sortOrder`.
  - The bare path is the first key.
  - A segment in no site's dashboard redirects to the bare path once every site's reads have settled.
- **D9 — `SiteDashboardView` gains an optional `embedded` prop** (PR 2).
  - Embedded, it draws no inner tab strip, never returns a `<Navigate>`, and calls `useTabMarkers(id, null)`, so no marker read runs. Without the prop nothing changes.
  - The halves pass no `role`, so "Set up trend strips" stays on the site's own page.
  - The alternative, leaving the component untouched, puts three tab strips on screen, two of which leave the station.
- **D10 — one month selector for the station's bills** (PR 2).
  - `MonthlyBillCard` gains an optional `title` and a controlled `month`. When controlled, it hides its own selector.
  - The total reads the same query keys as the cards, so it adds no request.
- **D11 — the station total.**
  - It shows when every site bill is priced for the same month in the same currency.
  - Otherwise it reads "—" with one fixed sentence naming the reason and the site.
  - When every site answers `no_mapping` for the current month, the bills block renders nothing.
- **D12 — the station page widens to `max-w-[1800px]`** on the Station view only (PR 2), and the halves use `lg:grid-cols-2`. Step 6 checks 1366 px and 1920 px; the fallback is `xl:`.
- **D13 — the new station modules join `tests/adr-0108-no-org-or-segment-literals.test.ts`'s `MODULES`.** That turns decision 1's "no code names a level, a type or an organization" into a gate. The file is ADR 0108's; the PR body says so.

## 11. Risks

- **Two dashboards poll on one screen.** Per station page: two site-widgets reads every 15 s, the trend strips every 60 s, two bills every 5 min, and one `/ws/alarms` socket per canvas. Each socket invalidates the whole site-widgets prefix on an alarm event (`use-site-widgets.ts:43-55`), so one event can start each read twice. Measured in step 6, not fixed here.
- **A redirect inside a half moves the whole page.** Held by D9 and cases E2, HV3 and HV5.
- **Query-key sharing is deliberate; a second `queryFn` under a shared key is the hazard.** Every reuse in section 6 must call the same API function with the same arguments as the existing observer.
- **Wall and layout-wizard paths.** A station whose view row is later set to `dashboard` must still render the station view and no wall (ST9). The station offers no "Make site layout" (D6).
- **Half-width canvases.** A 12-column dashboard at half width may crowd its tiles and mimic. D12 and the two-width check are the guard; the fallback is one more breakpoint.
- **Wording inside reused views.** At the station, `SiteEnergyView` says "This site and its readable children" and "the site's energy views". Left as is; say if the copy should change.
- **The Dashboards card will usually read "No dashboards for this scope."** at a station once the copy is hidden, because the list is per location.
- **The tripwire sees only what mounts in jsdom.** The alarm bar's two station reads appear only in the browser check.
- **Deeper trees.** An asset-less grandparent keeps today's empty page, and its crumb still links there (D1, D4). No such tree exists.
