# F4.307 — the mimic builder chooses which points each unit shows (ADR 0081 Amendment 1)

**Status: approved, revision 1 (2026-11-05).** Open questions ruled; the owner approved the plan ("yes") on 2026-11-05.
Checked against `main` at `21019d8`.

**Precondition.** Settled. ADR 0081 Amendment 1 is merged (#1006). Its four
rulings are the scope: a child table `bms.mimic_layout_node_points`; layouts

## 1. Goal

A layout unit that has a role may carry an ordered list of up to 3 point-key
codes. The inspector offers the list from the active point-key catalog (add,
order, remove; a deactivated key already listed stays, marked). The list is
stored in a new tenant child table, saved and read back with the layout
(replace-on-save, same transaction). The resolver
(`GET /dashboards/:id/mimic-nodes`) answers the listed keys for that unit — in
list order, per node, for every fan-out member too — in place of the asset's
top-3 headline points. A listed key the shown asset does not hold active
answers its catalog name with no sample, so the frame draws the name and "—".
An empty list keeps the headline behaviour. The copilot's layout write accepts
the same body, so a copilot replace cannot clear a stored list by accident.

**Out of scope.** KPI overlays (`F3.82`); a list on a preset node or a
dashboard template; a per-site list; a larger bound or a taller frame; any
change to `/admin/point-keys`, `headline_rank`, state points (ADR 0088) or
`ROW_Y`; a seed row; any `AGENTS.md` edit.

## 3. Migration `0124_mimic_layout_node_points.sql` (PR 1)

Journal idx 125, tag `0124_mimic_layout_node_points`, `when` = `Date.now()` at
authoring (never ahead of the clock). Forward-only, idempotent, inside
`SET ROLE bms_owner; … RESET ROLE;`, no `GRANT` line (0041's default
privileges fire because the table is created as `bms_owner`; the header comment
says so, as 0123 does).

```sql
-- guarded by DO $$ IF NOT EXISTS (pg_constraint) $$
ALTER TABLE bms.mimic_layout_nodes ADD CONSTRAINT mimic_layout_nodes_id_kind_key UNIQUE (id, kind);
CREATE TABLE IF NOT EXISTS bms.mimic_layout_node_points (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id uuid NOT NULL REFERENCES bms.organizations(id),
  node_id uuid NOT NULL,
  node_kind varchar(16) NOT NULL DEFAULT 'unit',
  point_key varchar(128) NOT NULL REFERENCES bms.point_keys(code),
  ord smallint NOT NULL,
  CONSTRAINT mimic_layout_node_points_node_fkey FOREIGN KEY (node_id, node_kind)
    REFERENCES bms.mimic_layout_nodes (id, kind) ON DELETE CASCADE,
  CONSTRAINT mimic_layout_node_points_unit_check CHECK (node_kind = 'unit'),
  CONSTRAINT mimic_layout_node_points_ord_check CHECK (ord BETWEEN 0 AND 2),
  CONSTRAINT mimic_layout_node_points_node_ord_key UNIQUE (node_id, ord),
  CONSTRAINT mimic_layout_node_points_node_key_key UNIQUE (node_id, point_key)
);
-- ENABLE + FORCE ROW LEVEL SECURITY; tenant_isolation:
--   USING / WITH CHECK (organization_id = <GUC> AND EXISTS (SELECT 1 FROM bms.mimic_layout_nodes n
--     WHERE n.id = mimic_layout_node_points.node_id AND n.organization_id = <GUC>))
```

`<GUC>` = `nullif(current_setting('app.current_organization', true), '')::uuid`.
`bms.point_keys` is global vocabulary (ADR 0051): no leg. `ord BETWEEN 0 AND 2`
restates `MIMIC_HEADLINE_POINTS - 1`; a static gate compares them. The point
key FK has no `ON DELETE` (keys are deactivated, never deleted).

A proof block after `RESET ROLE` (0123 idiom) raises unless RLS is enabled and
forced, `bms_tenant` holds INSERT and `bms_fleet` holds SELECT (the grants are
inherited from 0041, proven here, never written here), and the two FKs and the
`_ord_check` exist by name.

Drizzle: `mimicLayoutNodePoints` in `packages/db/src/schema/mimic-layouts-schema.ts`.

Reviews on PR 1: `migration-reviewer` and `security-reviewer`.

## 10. Open questions for the owner

1. **Units-only held in the database (C10)?** (a) the pipes idiom —
   `UNIQUE (id, kind)` on nodes, a composite FK and `CHECK (node_kind = 'unit')`;
   (b) the body refine and service only, a plain `node_id` FK.
   *Recommended: (a).*
2. **What "holds inactive" means in the resolver.** (a) `asset_points.active =
   false` or no `asset_points` row; a catalog-inactive key with a live asset
   point still draws its value (the editor marks it); (b) also draw a
   catalog-inactive key as "—". *Recommended: (a).*
3. **The copilot write accepts `pointKeys` (C8)?** (a) accept; (b) strip it and
   keep the list editor-only. *Recommended: (a)* — with (b) every copilot
   replace clears a stored list, because save is replace-all.
4. **A fan-out unit's list applies to every member?** (a) yes; (b) the first
   member only. *Recommended: (a).*
