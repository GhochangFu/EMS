## Goal

`ensureEskomDomainRtus` (`packages/db/src/hierarchy-seed.ts`) writes
`SIM-RTU-${loc.code}-${suffix}` into `bms.rtus.code varchar(64)` and
`${loc.name} ${domain.toUpperCase()} Simulator` into
`bms.rtus.display_name varchar(255)` for every ESKOM location on every seed. The
admin location schema accepts `code` up to 64 and `name` up to 255, and
`bms.locations.code` has no charset CHECK (0070 constrains only `assets.code`
and `point_keys.code`). Two pure helpers, `simRtuCode(locationCode, suffix)` and
`simRtuDisplayName(locationName, domain)`, return the current value
byte-identical when it fits, and otherwise cut to exactly 64 / 255 characters.

Out of scope: widening a column; any migration or ADR; `automation-rules-seed.ts`;
`resolveEskomSimRtuId` (keys on location name + domain + source_type — superseded by
`f4.169-f4.170-addendum-boot-gates.md` commit 4, which resolves by location);
`phe-pilot-seed.ts`; the stale "44 RTUs" figure in
`tests/f4.60-rtu-code-unique.integration.test.ts`; the backlog closure.

## Facts

- Thresholds. Code: `8 + n + 1 + s`; longest suffix `WATER` (5) → overflow at
  `n >= 51`. Name: `n + 1 + D + 1 + 9`; longest `ENVIRONMENT` (11) → overflow at
  `n >= 234`. The overflow code `SIM-RTU-<cut>-<hash8>-<suffix>` is `18 + k + s`,
  so `k = 46 - s` code points fill 64 exactly. Name budget is `244 - D`.
- Postgres counts `varchar` length in characters, so both the fit check and the
  cut count code points (`Array.from`). A fitting code that holds a surrogate
  pair has `.length > 64`; a `.length` check would cut it and move a stored code.
- Readers by column: none parse or rebuild the template. `apps/sim` reads
  `bms.assets` only. `apps/ingest` routes on `rtu_code`, NULL for every simulator
  RTU. `rtus-conflict.ts` maps the constraint name `rtus_location_code_unique`.
  `verify-hierarchy-seed.ts` joins on `r.id`. The seed does not write `rtu_code`.
- `tests/e4.3-demo-water-plant.test.ts` scans `hierarchy-seed.ts` for the literal
  `electrical: "ELEC"`; exporting `DOMAIN_RTU_SUFFIX` keeps it intact.
- `packages/db/src/index.ts` does not re-export `hierarchy-seed.ts`.

## Task 2 — the helpers and the wiring (green)

Edit `packages/db/src/hierarchy-seed.ts` only: import `createHash`; export
`DOMAIN_RTU_SUFFIX`; add `RTU_CODE_MAX = 64`, `SIM_RTU_HASH_WIDTH = 8`,
`RTU_DISPLAY_NAME_MAX = 255` and exported `simRtuCode` / `simRtuDisplayName`
with F4.129-style docblocks that state the differences (no fold; the fit check
and the cut count code points because `locations.code` has no charset CHECK —
the F4.104 lesson; uppercase hex for symmetry with `ladderRuleCode`, with no
compare here that needs it; the duplication is deliberate per ruling 3). Replace
the two template lines with the helper calls. Extend the
`ensureEskomDomainRtus` docblock with one F4.170 paragraph.

```ts
const raw = `SIM-RTU-${locationCode}-${suffix}`;
if (Array.from(raw).length <= RTU_CODE_MAX) return raw;
const hash = createHash("sha256").update(locationCode).digest("hex").toUpperCase().slice(0, SIM_RTU_HASH_WIDTH);
const cutWidth = RTU_CODE_MAX - "SIM-RTU--".length - SIM_RTU_HASH_WIDTH - "-".length - suffix.length; // 46 - s
const cut = Array.from(locationCode).slice(0, cutWidth).join("");
return `SIM-RTU-${cut}-${hash}-${suffix}`;
```
