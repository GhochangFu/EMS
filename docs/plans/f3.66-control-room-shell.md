## Owner rulings (2026-09-25)

- **OQ1 — `kind: 'builtin'` before `F3.70`: (a).** The site page renders the seven `/cr-*` links (label + path, the `moduleGroups` list moved into the page), filtered by the per-area `asset_group` rule (`canAccessControlRoomPath`); `ControlRoomRoute` stays on the `/cr-*` routes. `F3.70` replaces the links with tabs.
- **OQ2 — `kind: 'dashboard'` before `F3.69`: (a).** A short card "This site shows the dashboard <name>" with a link to `/dashboards/<slug>?organizationId=<org>`. `F3.69` replaces the card.
- **OQ3 — zero readable sites at `/control-room`: (a).** A card "No sites in your access scope" with a link to `/`.
- **OQ4 — where the entry sits: (a).** An item in the *Operations* group directly after *Alarm Centre*.
- **OQ5 (2026-09-26, step-5 code review) — the organization rail above 200 assets: fix inside F3.66.** `assetIdsQueryField` caps a request at 200 ids, so the rail as first built (every readable asset id of the organization) showed "Alarms unavailable" for a larger organization. `GET /alarms` and `GET /alarms/summary` now take an optional `organizationId`, intersected with `readableAssetIds` (never widened); the rail sends it instead of asset ids, and the organization page no longer calls `fetchAssets`. **This supersedes** the `fetchAssets` fact below, the rail's `assetIds` prop description, the page paragraph in U3, and rows G4a/G4b (now: the rail gets the organization id; no asset ids; `fetchAssets` never called; no rail for an unreadable organization). F3.66 is therefore no longer web-only: it adds one API query field.

## Goal

One sidebar entry, **Control Room**, visible to every role whose scope is not `none`, replaces the *Control Room 2D* group (decision 1). It opens three levels (decision 2): `/control-room` — a card for each readable organization with its site count, sites online and active alarms, grouped from `GET /api/v1/dashboard/locations` exactly as `/` groups them; `/control-room/org/:organizationId` — a card for each readable site with live status and KPIs (the `/` card, re-linked), plus `ActiveAlarmsRail` over that organization's readable assets; `/control-room/site/:locationId` — the site view host, which calls `F3.67`'s resolve read `GET /api/v1/control-room/sites/:locationId/view`, renders the fail-safe notice, and renders one body per `kind`. A level that holds one item is skipped. A breadcrumb names the levels above. The `/cr-*` routes and their `ControlRoomRoute` guard (`F4.156`) stay untouched until `F3.70`.

**Out of scope.** No API change and no contract change (the resolve DTO `resolvedSiteControlRoomViewDtoSchema` already exists in `packages/shared/src/contracts/site-control-room-views.ts`). No `GeneratedSiteView` (`F3.68`), no dashboard rendering inside the site page (`F3.69`), no `/cr-*` move or redirect (`F3.70`), no change to `/` or `/locations/:id/dashboard` (Q8: both stay, their links stay). No change to `lib/control-room-access.ts`, `hooks/use-control-room-access.ts` (code) or `components/control-room-route.tsx`. AGENTS.md is not touched in this branch: the ADR lists the `chore(agents):` owed after merge (the `/cr-*` mentions, the §2 *Operations* row, §3 layout for `apps/web/src/pages/control-room/`). `F4.160` stays its own row; this branch only stubs the status read in the specs it writes or rewrites.

## Measured facts the plan rests on

- **The data the levels need is already served and already filtered.** `fetchLocationKpis()` (`apps/web/src/api/locations.ts:13`, key `["dashboard","locations"]`, `refetchInterval: 8000` on `/`) returns `LocationKpiSummary[]` with `organization {id, code, name}`, `freshAssetCount`, `assetCount`, `openAlarms`, `criticalAlarms`, `totalKw`. `lib/location-kpi-groups.ts` already has `groupByOrganization` (sorted by org code, sites by name) and `orgSectionSummary` → `{locationCount, totalKw, openAlarms, freshLocationCount}`; **neither has a spec**. "Sites online" = `freshLocationCount` (`freshAssetCount > 0`), the same 25 s rule `/` uses (`F3.30`, `LIVE_ASSETS_CTE_SQL`).
- **The organization's readable assets are one existing call.** `fetchAssets(organizationId?)` (`api/assets.ts:30`) sends `?organizationId=`; the API also filters by `readableAssetIds`, so the body is "readable ∩ organization". Use key `["assets","control-room",orgId]`.
- **`ActiveAlarmsRail`** (`components/control-room/active-alarms-rail.tsx:57`) takes `{ assetIds: readonly string[]; assetsStatus?: "pending"|"success"|"error" }` and opens `/ws/alarms` through `useAlarmsSocket` — a page spec must mock the rail or the socket.
- **The resolve read has no web client yet.** `apps/web/src/lib/site-control-room-view.ts` holds only the admin field's pure helpers; `api/admin/locations.ts:102` `fetchSiteControlRoomView` is the **admin** GET. This row ships the resolve client. The resolve read answers 404 for an unreadable site (`site-control-room-view.service.ts:153-159`).
- **The shell today** (`layouts/app-shell.tsx`): `moduleGroups` holds the seven-item *Control Room 2D* group (L40-50); `isVisible` (L133-141) gates `/cr-*` on `useControlRoomAccess()` + `canAccessControlRoomPath`; a group with no visible item hides (L248-253). Sidebar highlight is `location.pathname === m.path` (L270); the admin group uses `startsWith` (L310).
- **The scope has no organization kind**: `accessScopeKindSchema` = `global | location | asset_group | none`; `AccessibleScope.locations` rows carry no `organizationId`. So "which organizations can I read" comes from the KPI list, never from the scope — which is also why the level skip is decided from the list.
- **Spec harness precedents**: `app-shell.spec.tsx` (fixtures `GLOBAL`, `LOCATION`, `HVAC_ONLY`, `NONE`), `location-dashboard-page.spec.tsx` (`MemoryRouter` + `<Routes>` with a param route), `control-room-overview-page.spec.tsx` (`vi.mock("socket.io-client")`), `components/system-status-indicator.spec.tsx` exports `OPERATIONAL` and shows the `vi.spyOn(systemStatusApi, "fetchSystemStatus").mockResolvedValue(OPERATIONAL)` stub (`F4.160`).
- **Gates that read the old shape**: `app-shell.spec.tsx` S1–S8 assert `/cr-` links and the text `Control Room 2D`; `pages/assets-page.spec.tsx:191` `findByText("Control Room 2D")`; `tests/f3.31-assets-browser-reachable.test.ts:65` R2 reads `title: "Control Room 2D"`; `tests/f4.156-control-room-route-gate.test.ts:108` `unwrappedPageUses` matches **every** `<ControlRoom\w*Page` in `app.tsx` — a new page named `ControlRoom…Page` on a `/control-room*` route reddens it.

## Decisions (engineering; reviewable at step 7)

- **D1** — the level skip and the breadcrumb are pure functions over the KPI list (`lib/control-room-levels.ts`), decided only after the read has data — never from `[]` while pending.
- **D2** — a crumb for a skipped level is omitted, and the breadcrumb renders nothing with one crumb (the `AdminBreadcrumb` rule).
- **D3** — one route guard, `ControlRoomScopeRoute`: `scope === null` → a status line, `scope.kind === "none"` → `<Navigate to="/" replace />`, else children. The API is the access control; the guard mirrors decision 15.
- **D4** — `LocationKpiCard` gains an optional `to?: string` defaulting to `/locations/${id}/dashboard`. An optional prop at an adapter is invisible to tsc, so the org page spec asserts the card `href`.
- **D5** — the pages are `ControlRoomOrganizationsPage`, `ControlRoomOrganizationPage`, `ControlRoomSitePage` under `apps/web/src/pages/control-room/`; the F4.156 invariant's `unwrappedPageUses` regex is narrowed to the seven SMOC page names (`/<(ControlRoom(?:Overview|Sld|It|Ups|Battery|Hvac|Env)Page)\b/`) with a docblock sentence saying why. `F3.70` retires the file.
- **D6** — the resolve read's key is `["control-room","site-view",locationId]`; a rejected read renders the "not available in your access scope" card, never an interim body.
- **D7 — seam with `F3.68`.** For `kind: 'generated'` the site page renders an inline interim body (a `SectionCard` "Generated site view" saying the view arrives with `F3.68`, plus a link to `/locations/:id/dashboard`). **This branch must NOT create `apps/web/src/components/control-room/generated-site-view.tsx` or any stub of it. Whichever of the two PRs merges second adds the one-line wire-up** — import `GeneratedSiteView` from that file and render `<GeneratedSiteView locationId={locationId} />` in place of the interim body, with one jsdom case. Expected conflicts: `packages/shared/src/contracts/index.ts` and the BACKLOG rows; keep them additive.
- **D8** — the site page does not consult `useControlRoomAccess`. `ControlRoomRoute` still guards each `/cr-*` click; the per-area rule filters the interim links (OQ1).
- **D9** — the sidebar highlights the entry for any `/control-room/*` path (`pathname === path || (path !== "/" && pathname.startsWith(`${path}/`))`).
