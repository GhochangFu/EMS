## Goal

`^[A-Za-z0-9_-]+$` declared once in `@bms/shared`, applied at the five Zod
sites with one shared sentence, enforced by migration `0070` as two plain
`CHECK` constraints that fail loudly on a violator, the chat producer slugified
so it can no longer manufacture an illegal code, no automatic repair,

case-insensitive resolution; harmonising `.min(1)`/`.min(2)`; a tokenizer

2. **`cutToBoundWithHashSuffix` is closed under the class**
   (`onboarding-draft-caps.ts:351-369`). `value.length <= max` returns the value
   byte-identical. Otherwise `prefix = cutToBound(value, 55).replace(/-+$/,
   "")` — a prefix of an in-class string is in-class or empty, and the
   surrogate strip never fires on ASCII — and `suffix` is 8 hex chars
   upper-cased (`[0-9A-F]{8}`), joined by `-`. Output is `<prefix>-<hex8>`,
   always inside `[A-Za-z0-9_-]+`, at least 9 chars. **Order in the producer
   matters:** slugify *before* `toUpperCase()`, because `"ß".toUpperCase() ===
   "SS"` and `"ſ".toUpperCase() === "S"` fold non-class letters into class
   letters; the class is safe either way, but which code a name yields differs,
   and the spec pins the order.

## Decisions this plan makes inside the ADR (reviewable at step 5)

- **D1** `CATALOG_CODE_PATTERN` (a `RegExp`, **no flags**) and
  `CATALOG_CODE_MESSAGE` both live in `packages/shared/src/constants.ts`. A
  `RegExp` is not a Zod instance, so the `@bms/shared`-vs-local-`zod`
  module-instance trap (`asset-roles.schema.ts:6-20`) does not apply; the five
  sites call `.regex()` on their own `z`.
- **D2** The shared response contracts `onboardingDraftAssetSchema` /
  `onboardingDraftPointKeySchema` (`packages/shared/src/contracts/onboarding.ts:187-199`)
  get **no** regex. They type the `preview` a session response carries; a
  draft stored before this row must still be readable so the wizard can show
  `validate`'s per-field error and the operator can fix it.
  `tests/f4.104-draft-string-bounds.test.ts` parity holds because `.max()`
  stays on both copies and its `STRING_FIELD` parser (`:98-99`) already
  tolerates a chained `.regex(...)`.
- **D3** `catalogCodeSlug` lives in `onboarding-draft-caps.ts` beside
  `cutToBoundWithHashSuffix` — two halves of one derivation. Not in
  `@bms/shared`: no second consumer.
- **D4** No `check()` in the Drizzle schema. No shipped migration mirrors a
  `CHECK` there (`0031`, `0056`, `0061`, `0064`); the precedent is a column
  docblock naming the constraint (`dashboard-schema.ts:105`,
  `telemetry-schema.ts:24`). Add one line each on `assets.code` and
  `pointKeys.code` in `packages/db/src/schema/bms-schema.ts`.
- **D5** `0070` takes the `SET ROLE bms_owner` / `RESET ROLE` bracket
  (AGENTS.md §4.4, `0061`) and bounds `lock_timeout` like `0069`: `ADD
  CONSTRAINT` takes `ACCESS EXCLUSIVE` on `bms.assets`, which every ingest
  write FK-checks.
- **D6** No `apps/web` change. `assets-page.tsx:143` and
  `point-keys-page.tsx:92` render `err.message`, which is the raw `flatten()`
  body — `{"formErrors":[],"fieldErrors":{"code":["letters, digits, '_' and
  '-' only — like TX_01 or kwh_total"]}}` — so the sentence is on screen. The
  wizard renders `draft: <sentence>` for a PATCH (`apiErrorMessage`, top-level
  key only — F4.103's residual) and `assets.0.code: <sentence>` for
  `validate`. Unwrapping on the admin pages is `api-error-message.ts:22-28`'s
  recorded scope decision, not this row.
- **D7** `codePool` in `cross-ref.spec.ts:86-103` keeps `(`, `)@`, `c/d`,
  `e f`: the kind prefix is the proof and a wider pool is a stronger test.
  Same for `REF_POOL` in `dialect-superset.spec.ts`. Prose only.
