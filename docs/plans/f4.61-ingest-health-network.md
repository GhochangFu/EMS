## Goal and out of scope

**Goal.** `docker-compose.yml` publishes 9102 on loopback, but declares no
`networks:`, so every service on the default bridge can `GET http://ingest:9102/`
and read the unauthenticated RTU roster. The handler
(`apps/ingest/src/host/health-server.ts`, `startHealthServer`) also ignores the
method, the path and `Host`. After this row: (a) `ingest` sits on a
user-defined network `ingest` shared with `postgres` only; (b) the handler serves
only `GET` on `/` and `/health`; (c) a non-loopback `Host` is refused, which
closes the DNS-rebinding path from an operator's browser.

**Out of scope.** Authentication; `prom-client` (`F3.16`); a compose
`healthcheck:`; a `bms_ingest` database role; segmenting other services; a
non-root `USER`; any change to the body format, `renderHealth` or the 500 path.

## Facts from the source

- **Consumers.** The only real consumer is an operator `curl 127.0.0.1:9102` on
  the host (`GET /`, `Host: 127.0.0.1:9102`). No compose `healthcheck:`;
  `infra/observability/prometheus.yml` scrapes api, sim, worker, prometheus
  only; CI builds the ingest image but never runs it; no `scripts/`, `apps/api`
  or `apps/web` caller (`apps/web/nginx.conf` has no `proxy_pass`). The only
  compose file is `docker-compose.yml`; the gitignored override in the main
  checkout remaps ports only.
- **Network needs.** `ingest` (profiles `ingest`, `pilot`, `phe`) reaches only
  `postgres:5432` in-cluster, plus the external broker
  `phe.thinkiot.co.in:8883`. Nothing reaches ingest. The timescale image's
  `pg_hba.conf` accepts all hosts with scram, so a second interface on
  `postgres` needs nothing.
- **ADR.** ADR 0016 line 40 and line 755 name the endpoint but no path, method
  or Host rule; ADR 0007 never mentions it; ADR 0075 fact 5 calls it `/health`
  in prose. No ADR was required; the owner chose Amendment 8.
- **Host.** Node exposes `request.headers.host`. curl sends `host:port`; an
  HTTP/1.0 client or `curl -H 'Host:'` sends none. Regex:
  `/^(?:localhost|127\.0\.0\.1|\[::1\])(?::\d{1,5})?$/i`.
- **Tests.** `health-server.spec.ts` (893 lines, cap 1000) tests `renderHealth`
  only; no spec opens a socket, and `startHealthServer` has no covering test.
  A new spec/test pair is needed (precedent: `logger.spec.ts` split out of the
  same file). `tests/` compose readers to copy: `tests/f1.10-ingest-buffer-volume.test.ts`,
  `tests/f3.3-object-storage-invariants.test.ts:70-95` (helpers are file-local
  and copied, not imported).

## Design

**Compose.** Top-level `networks: { ingest: }` (no `internal`).
`postgres.networks = [default, ingest]`. `ingest.networks = [ingest]`. `ports`
stays `"127.0.0.1:9102:9102"`; its comment is rewritten to name both boundaries.

**Handler.** A pure exported gate in `health-server.ts`:

```ts
export type HealthRefusal = {
  readonly status: 421 | 405 | 404;
  readonly body: string;
  readonly headers: Readonly<Record<string, string>>;
};
export function refuseHealthRequest(request: {
  readonly method: string | undefined;
  readonly url: string | undefined;
  readonly host: string | undefined;
}): HealthRefusal | undefined
```

An object parameter, not three positional strings. Constants beside it:
`LOOPBACK_HOST`, `HEALTH_PATHS = new Set(["/", "/health"])`,
`ALLOWED_METHOD = "GET"`. The handler calls it first; on a refusal it writes
`status`, `content-type: text/plain` plus `headers`, ends with `body`, returns.
The `renderHealth` try/catch and the 500 path stay byte-identical.

**Bound port.** `HealthServer.port` echoes the argument today, so
`startHealthServer(0, …)` would report 0. Report `server.address()`'s port.
`main.ts` logs it; nothing else reads it.
