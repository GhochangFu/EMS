## 1. Goal

Build release 3 of the administrator copilot as ADR 0099 Amendment 3 decides it. **Eight catalog entries** enter (A1; nine schemas move, eight entries land): the two layout writes as one whole body on one card that **draws** the proposed layout from the body alone, lists the node diff by key against the **snapshot stored at propose time** (ruling Q5), and shows ADR 0101 d14's editor warnings without blocking Confirm (A2); the three library writes, the symbol update, and `mimicSymbol.upload` as the catalog's **first multipart entry** — the SVG attached by the admin or drawn by the model, parsed by `svg-symbol-parser.ts` at propose time, stored as text in the pending row, drawn on the card as an `<img>` from a blob URL, and sent on Confirm as the real multipart call whose file bytes the interceptor hashes (A3); `assetRole.create` for the global admin (A1, A6), offered **before** a layout whose units name a role the vocabulary lacks (ruling Q4). The propose tools for layouts and libraries are offered to `admin` and `organization_admin` only; four read tools (`list_mimic_layouts`, `get_mimic_layout`, `list_mimic_symbols`, `list_asset_roles`) serve every copilot role through the user's read scope (drafter choice 1, D16). An administrator may attach up to three files per message (PNG, JPEG, WebP, PDF, 10 MB each, magic-byte checked) that go to the turn's own key and model as native content parts and are **never stored** — the message row keeps a placeholder with the SHA-256 (A4, A5, drafter choice 3); the attachment turn counts as one turn (drafter choice 2), cannot propose an access change (A7) nor an asset or point create the words did not ask for (D8), and is allowed only when `bms.copilot_org_settings.attachments_enabled` (default off, one migration `0110`) is on — written by the global admin and the organization admin, checked on the server for every attachment, with the button saying the file goes to the provider unscrubbed (A7). After a layout change is applied, the follow-up turn offers `assetGroup.member.add` and `assetGroup.member.setRole` one card at a time (A6, ruling Q4). Before any of that, the nine body schemas move from `apps/api` to `packages/shared/src/contracts/` (ADR 0101 decision 17, ADR 0030) — PR 1, in flight.

**Out of scope** (Amendment 3 *Still out*, decision 12, and §0): storing attachments; attachments for operators and viewers, or inside the onboarding skill; DWG or any CAD file; creating assets or points from an image without the administrator's words (D8 is the guard, not a feature); live state in the card's preview; the layout `DELETE` and the role-vocabulary `PATCH` by the copilot; a separate vision model setting; a vocabulary admin page; the asset-images routes; any change to `MIMIC_FANOUT_MAX` (a read-time cap, §11); a port change that exposes the provider's HTTP status (D5's residual); a `CanActivate` guard that reads the switch before multer buffers (noted, §9.2); the `F4.244`–`F4.262` follow-ups except where a PR below touches the same line and says so.
