## 1. Goal

A site box runs the ingest image with a second entry point. It collects from
local devices, keeps samples on disk while the uplink is down (72 h default,
6 d ceiling), and posts them over HTTPS to a receiver in the cloud ingest
host. Each sample keeps the receive time the edge stamped, so a retried batch
writes the same row. The cloud accepts a sample only for an RTU bound to the
calling gateway's token, notifies only rows inside the live window, and
repairs the continuous aggregates over each backfilled window. A global admin
creates gateways, mints tokens and assigns RTUs from one page.

**Out of scope.** Local alarms or dashboard on the box; commands to devices;
any new protocol adapter; a broker; hardware, OS, VPN, OTA, `arm64` build;
cloud-pulled edge config; retrospective alarms; calc backfill for the gap; a
seeded demo gateway; a `bms_ingest` role; any `AGENTS.md` edit in a feature PR.

## 11. CI minutes and commit shape

- **One push per PR.** All commits are local. The review agents read the local branch diff; their fixes are folded in before the push. A PR is never closed and reopened, and nothing is pushed just to re-run CI. A red run is reproduced locally, then fixed in one further push.
- **Before every push:** `pnpm typecheck`, `pnpm typecheck:tests`, `pnpm test:coverage` with `DATABASE_URL` on a migrated, seeded local Postgres/Timescale and `MQTT_TEST_URL` set; name any suite that skipped (the Redis, MinIO and Keycloak gates skip locally and throw in CI). PR 3 and PR 5 also run the image build.
- **Budget:** six full runs, about 72 billed minutes, plus the `e2e` label on PR 6 (about 4, P9). PR 7 and the `chore(agents):` sweep are docs-only and take the short job. ADR amendments ride inside the code PR that changes the behaviour. No `arm64` build.
- **Commits:** one per task, test and code together, `feat(E7.2): … (PR n of 7)`. The commit that adds `@bms/db` to the manifest also stages a `docs/adr/` file, which is what the commit-time dependency gate checks. No `AGENTS.md` or `docs/roadmap.md` edit in any feature commit.

1. **P1 — cloud-side spill. Folded into ADR 0123 as Q3a.** No replay loop exists outside a supervisor, so a cloud-side spill needs T3.6. 3. **P3 — the route breaks `F4.61`'s isolation** (M8). (a) a third network `edge-uplink` joined by `web` and `ingest` only, and the health listener bound to loopback; (b) publish the uplink port on host loopback and route it in Caddy (not in this repository); (c) `web` joins `ingest` (it could then reach Postgres). *Recommended: (a)*. **Folded into ADR 0123 as Q3b and its "Would amend" list.**
