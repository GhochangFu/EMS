Drafted by `plan-architect` on 2026-11-07 against `main` at `b086323` (ADR
0115 accepted and merged as `6d7d05aa`). The orchestrating session re-checked
the main code claims by hand (the role at `docker-compose.yml:644`, the journal
tail, the `0039` grants, the health snapshot type, the supervisor stop timeout,
the spec claim names, the RTU form checkbox). CodeGraph was not available, so
the blast radius in §6 was measured with grep and reads.

**Status: approved.** The owner answered §9 and said "yes" to the build in

## 1. Goal

A global administrator switches one organization's ingestion off, and later
back on, from the organization admin page. The ingest host applies that, and
every per-RTU "Ingest enabled" change, at its next reload with no restart.

- Migration `0128` adds `bms.organizations.ingest_enabled boolean not null
  default true` (R1).
- `PUT /api/v1/admin/organizations/:id/ingest` flips it, global admin only,
  with one platform audit row (R2).
- The host's `BINDING_QUERY` joins the organization, and `planEndpoints` skips
  every RTU of a switched-off organization as `organization-ingest-disabled`
  (R3).
- The reload reconciles the endpoint set (start, replace = stop old then start
  new, stop, or swap the point index) through a pure, unit-tested diff plus a
  tested registry. `main.ts` stays as wiring (R5).
- A stopped endpoint's disk segments stay and replay when its key next starts.
  A stopped endpoint that still holds a backlog is named on the health body
  (R6).
- The organization page gets the switch with a confirm step and an "Ingest
  off" badge. The RTU edit form says its box is overridden (R7).
- Alarms, rules and escalations are untouched (R4). `organizations.active` is
  not coupled (decision 10).

**Out of scope.** Any change under `apps/api/src/alarms` or
`apps/api/src/rules`; a `bms_ingest` database role (the compose comment's owed
ADR 0045 amendment); handling a connection-config or credential change on a
running endpoint with an unchanged device set (ADR 0115 decision 6, drafter;
see §3 R5); a per-RTU badge on `/admin/rtus`; a copilot/admin-wizard catalog
entry for the new route (F4.310's colour-profile route has none either); the
disk-buffer bounds (unchanged, ADR 0016 Amendment 4); AGENTS.md (ADR 0115:
nothing moves).

## 2. Facts measured from the code

- **Reload today.** `apps/ingest/src/main.ts:117-133` holds `pointIndexes`,
  `supervisors` and `servedDevices` as three `Map`s keyed by
  `endpointGroupKey(protocol, endpointKey)` (`bindings.ts:277-279`, NUL
  separator). The boot loop (`:189-237`) builds one `createSupervisor` per plan
  and calls `start()`. The `setInterval` at `:253-313` re-plans and only does
  `pointIndexes.set(key, plan.pointIndex)`, then logs `endpoint device set
  changed; restart required to apply`, `new endpoint requires a restart to
  serve` and `endpoint no longer in the binding plan; still running`. The
  `writeSamples` closure reads `pointIndexes.get(key) ?? plan.pointIndex`
  (`:208`). **No unit test covers any of this**; `main.ts:166-172` says so.
- **Supervisor seam.** `Supervisor` (`supervisor.ts:191-199`) is `{ protocol,
  endpointKey, start(): void, stop(): Promise<void>, health() }`. `start()` is
  idempotent; `stop()` aborts the adapter, disconnects it, and settles within
  `stopTimeoutMs` (10 s, `:92`), never rejecting. `health()` builds `devices`
  from `plan.bindings` and reads `buffered: deps.buffer.buffered`.
  `plan.bindings` is captured at construction.
- **Disk buffer.** `DiskBufferStore.handle(protocol, endpointKey)`
  (`disk-buffer.ts:946-950`) returns the same `DiskBufferHandle` per key. The
  handle's `buffered` (`:101`) counts **samples**, not bytes. `sweep()` applies
  both bounds host-wide and is called once a minute from each supervisor's
  replay loop (`supervisor.ts:472`). With zero running supervisors nothing calls
  it.
- **Health body.** `HealthSnapshot` (`health-server.ts:23-29`) is `{ endpoints,
  skipped, startedAt, staleAfterMs }`. `renderHealth` prints the header, one
  `endpoint …` line each, `stale`, `dark`, then `skipped rtu=<code> reason=<r>
  detail=<token>`. `token()` percent-encodes anything outside
  `A-Za-z0-9._:/-`; an organization code (`^[A-Z0-9_-]+$`,
  `organizations.schema.ts:56`) is already safe.
- **Binding query.** `BINDING_QUERY` (`bindings.ts:112-145`) joins `rtus →
  asset_points → assets → template_points → rtu_connection_configs`, `WHERE
  r.ingest_enabled = true` (`:143`), with no organization join. `BindingRow`
  (`:28-71`) mirrors the SQL columns. `planEndpoints` groups rows by RTU, and
  the per-RTU loop's first decision is the protocol. `bms.rtus.organization_id`
  is `NOT NULL` since `0047`, so `INNER JOIN bms.organizations o ON o.id =
  r.organization_id` drops nothing.
- **Database role — a correction to ADR 0115's Context.** The compose `ingest`
  service connects as **`bms_fleet`**, not `bms_owner`
  (`docker-compose.yml:644`). `0039` grants `SELECT, INSERT, UPDATE, DELETE` on
  all `bms` tables to `bms_fleet`, and no migration enables row-level security
  on `bms.organizations`. The join therefore needs **no grant change**. The
  ADR's wording is corrected in its next amendment (§9 Q6), not here.
- **Schema and journal.** `organizations` is `bms-schema.ts:39-60`. The last
  migration is `0127_pump_station_roles` (journal `idx: 128`, `when:
  1793969366525`), so the next is `0128`, `idx: 129`. `0125` is the shape to
  copy (`SET ROLE bms_owner; ALTER TABLE … ADD COLUMN IF NOT EXISTS …; RESET
  ROLE;`), and `tests/f4.310-organization-colour-profile-schema.test.ts` is its

- **Seeds cannot revert the switch.** `hierarchy-seed.ts` `ensureOrganizations`
  upserts `name`, `currency` and `timezone` only; `demo-ion-exchange.ts` is `ON

## 3. Drafter refinements (ADR 0115 lines marked *(drafter)*)

- **R1 (decision 1, grant).** Confirmed: no grant, no policy (§2). The
  migration header says so, as `0125`'s does.
- **R2 (decision 3, no-op write).** A `PUT` whose value equals the stored one
  returns the mapped row and writes nothing: no `UPDATE`, no audit row.
- **R3 (decision 4, RTU field name).** `organizationIngestEnabled: z.boolean()`
  on `adminRtuDtoSchema`, read from the `organizations` join both producers
  already have.
- **R4 (decision 5, own-box-off RTU).** Stays out of the query and out of
  `skipped`, as today. The organization skip is decided **first** in the
  per-RTU loop, before protocol resolution, so a switched-off organization's RTU
  with a broken config reports the organization reason — one reason per RTU,
  the one the operator can act on.
- **R5 (decision 6, config/credential change).** Not widened. Detecting it
  would mean fingerprinting `EndpointPlan.config` and plaintext `credentials`
  (§9.6). A restart still applies those.
- **R6 (decision 6, no overlapping reloads).** The registry's `reload()` holds
  an `applying` flag. A tick that arrives while the previous one is still
  applying returns `"busy"` and logs `reload skipped; previous reload still
  applying` once. No queueing: the next tick re-plans from the database anyway.
- **R7 (decision 7, the health line and its unit).** One line per stopped
  endpoint that still holds a backlog: `stopped protocol=<p> key=<token>
  buffered=<n>`, after the `endpoint` lines and before `stale`. **`n` is
  samples, not bytes** — `DiskBufferHandle` exposes only the sample gauge and
  every other `buffered=` on the body is samples. An endpoint with `buffered ===
  0` is not listed. It does not change the `ok`/`degraded` verdict.
- **R8 (decision 7, the sweep).** The reload tick calls `bufferStore.sweep()`
  after applying, so the 1 h / 256 MiB bounds keep running when no supervisor is
  left to call it. Idempotent and enqueued.
- **R9 (decision 9, the confirm step).** An in-page confirm dialog on the
  `surface-dialog` pattern the page's edit modal uses — not `window.confirm`,
  which jsdom and Playwright cannot assert on by text.
- **R10 (ordering of actions).** Stops and replaces run before starts, and a
  replace awaits the old `stop()` before `build()`/`start()` of the new one.
  The same broker may refuse a duplicate client id, and closing before dialling
  is what makes "that broker alone reconnects" true.
- **R11 (docs placement).** `docs/ingest-host.md` is rewritten in **PR 2**, with
  the behaviour it describes, so the doc never says "restart required" after
  the code stops needing one. PR 3 carries the BACKLOG row and the §4.6 results.

**T2.3 — the registry (tests first, same spec file).**

```ts
export type EndpointRegistryDeps = {
  build(plan: EndpointPlan, index: () => PointIndex): Supervisor;
  logger: AdapterLogger;
  buffered(protocol: IngestProtocol, endpointKey: string): number;
};
export type EndpointRegistry = {
  reload(next: readonly EndpointPlan[]): Promise<"applied" | "busy">;
  health(): { endpoints: readonly SupervisorHealth[]; stopped: readonly StoppedEndpoint[] };
  stopAll(): Promise<void>;
};
export type StoppedEndpoint = { protocol: IngestProtocol; endpointKey: string; buffered: number };
```

With a fake `Supervisor` whose `stop()` waits on a deferred, and an events log:

- boot builds and starts each plan and logs `endpoint started`;
- **replace awaits the old `stop()` before `build`/`start` of the new**, logs
  `endpoint replaced` with `added`/`removed`, and `health()` shows the new
  roster;
- `stop` drops the key from `health().endpoints` and logs `endpoint stopped`;
  with `buffered() > 0` the key appears in `health().stopped`, with `0` it does
  not; a later `start` of the key removes it from `stopped`;
- **no overlap**: a second `reload` while a `stop()` is pending returns
  `"busy"`, logs once and changes nothing; after release the next returns
  `"applied"`;
- `swap-index` changes what `index()` returns without a rebuild;
- a `build` that throws is logged with the key and the other actions still
  apply; a `stop` that rejects is logged and the key is still dropped;
- `stopAll` stops every running supervisor.
