# F3.28 — Domain dashboard parity: implementation plan

**Scope gate:** [ADR 0074](../adr/0074-domain-dashboard-parity.md), Accepted
2026-09-24 (PR #541). Plan written by `plan-architect` on 2026-09-24; open
questions OQ1–OQ6 ruled by the owner the same day (below). Not a ⭐ enabler.
No migration, no new dependency, no `dark:` class, no token layer.

**Goal.** Bring `/cr-overview` and `/` up to the client reference layout in
three serial PRs: (1) an alarms rail fed by `GET /alarms?state=active&assetIds=`
plus an active-count-by-severity read, with the breach value composed into the
alarm text on write; (2) a "vs yesterday" delta on the KPI tiles, computed on
the server as the same instant 24 h ago on each live value's own definition,
plus tile icons and the stale "Unacknowledged rows" hint; (3) a per-role class
strip with a server read, a data-driven state legend, a Diagram/List toggle
reusing the SLD breaker table, four radial gauges, and a static footer ribbon.
Every response shape is a Zod schema in `packages/shared/src/contracts` with
the type `z.infer`red (ADR 0030).

**Out of scope.** The dark theme (`F3.65`); the delta label for other windows
(`F4.154`); the two executive KPIs (B14 row); the `high` severity row (B9); a
page shell (E5.1); configurable mimics (`F3.32`); diagram navigation (`F4.47`);
a backfill of existing alarm text; moving the three existing 25 s / 20 s server
literals onto the new constant; the `AGENTS.md` §5 pointer sweep (separate
`chore(agents):` PR).

**Serial.** One branch per slice: `feat/F3.28-alarms` → `feat/F3.28-kpi` →
`feat/F3.28-page` (ADR 0074 decision 7). Units marked *Independent* touch
disjoint files but are built serially: each is under ~150 lines.

## Owner rulings (2026-09-24)

- **OQ1 — offline in the class strip: any point key, 25 s.** Offline = no
  sample of any point in the last 25 s — the `locationDashboard`
  `telemetryFreshness` bound (`dashboard.service.ts` ~L586–594) and the web
  gate `FRESH_MS = 25_000` (`apps/web/src/lib/schematic-telemetry.ts:37`,
  ADR 0027). One constant `LIVE_TELEMETRY_MAX_AGE_SECONDS = 25` in a new
  `apps/api/src/telemetry/telemetry-freshness.ts`, read only by the role-summary
  SQL; a `tests/` invariant pins it to `FRESH_MS / 1000`. Rejected: `kw`-only
  25 s (dashboard fresh count, map), `kw`-only 20 s (`sites_online`).
- **OQ2 — prior PUE uses the live 900 s window moved back 24 h.** ADR 0074
  decision 5 states that `pueEstimate` has no freshness bound; the source has
  one (`PUE_LATEST_MAX_AGE_SECONDS = 3 × 300 = 900`, `pue-ratio.ts:98,188`).
  The prior PUE uses samples in `(at − 900 s, at]`. Slice 2 carries a
  `docs(adr):` Errata line on ADR 0074 and fixes the stale comment at
  `dashboard.service.ts` L512–516. `totalKw` is unbounded and stays so.
- **OQ3 — Key Parameters: four gauges.** UPS-1 load % and UPS-2 load %
  (0–100; warning 80, critical 95), battery health % (average of
  `CR-BATT-1/2.health_pct`, 0–100; warning below 85, critical below 70), main
  power factor (`CR-Q1.pf`, 0–1, 2 decimals; warning below 0.9). Each gauge is
  stale-gated through `isStale` / `freshValue`.
- **OQ4 — the role read returns `worstCount`**: the number of assets in the
  role at the worst active severity, so the strip prints "MCCs 4 · 1 Critical".
- **OQ5 — Open alarms tile on `/`:** the delta goes in `hint`; "N critical"
  moves to `KpiTile`'s `note` line; with no delta the hint reads "Active — not
  yet cleared" (replaces "Unacknowledged rows").
- **OQ6 — the strip prints `asset_roles.label` verbatim.** No plural logic.

## Plan decisions (ADR silent; the plan chose; owner may veto)

1. `assetIds` on the new/changed reads is a repeated query parameter
   (`?assetIds=a&assetIds=b`), normalised to an array with `z.preprocess`,
   `uuid` each, bounded at `MAX_SCOPE_ASSET_IDS = 200` (the
   `migrateAssetsBodySchema` ceiling). If `zod-to-json-schema` drops the
   preprocess (ADR 0029 test), fall back to a comma-separated string with
   `.transform` + `.describe`.
2. The at-instant read is `GET /api/v1/telemetry/points/at-instant?at=<ISO>&refs=<ref>&refs=<ref>`,
   `refs` bounded at `MAX_AT_INSTANT_REFS = 50`. One ref outside the caller's
   readable assets → 403 for the whole request, the same answer
   `GET …/:pointRef/aggregate` gives.
3. `GET /dashboard/kpis` gains a nested
   `prior: { asOf, totalKw: number|null, alarmsOpen: number, pueEstimate: number|null }`.
   `alarmsOpen` is not nullable: `bms.alarms` is complete history.
4. `limit` on `GET /alarms` keeps today's clamp-to-100 semantics; `state`
   defaults to `all`.
5. The `/` Total load delta compares the server's `totalKw` with the server's
   prior, even while the tile displays the live socket sum; the docblock says so.
6. The message unit is always separated by a space — `Chiller supply temp high (31.5 °C)` —
   matching the four existing special cases. Rounding: up to one decimal, a
   trailing `.0` dropped, `|v| ≥ 100` rounded to an integer, `-0` printed as
   `0`, a non-finite value printed as-is.
7. The alarm summary returns every active severity row with its count (zero
   allowed), in rank order, plus `total`; the role summary includes a retired
   role that an asset still holds.
8. Icons: `/` Total load → `bolt`, Open alarms → `alert`, PUE → `gauge`, Sites
   online → none. `/cr-overview` Rule Warnings → `alert`, Total CR Load and
   Rack Load → `bolt`, the rest none.
9. The 25 s bound is evaluated in SQL as
   `SELECT DISTINCT asset_id FROM telemetry.point_values WHERE time > now() - (…)`;
   measured in slice 3 verification.
