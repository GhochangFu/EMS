## 1. Goal

Give an operator a screen and an authenticated endpoint that record a hand-read number into `telemetry.point_values` — the monthly meter walk, the water-quality lab result — and show them, in the same submit, whether it landed or why it did not. The whole write is delegated to the already-merged `TelemetryWriteService.writeReadings` (`D:\Projects\portal.bms\apps\api\src\admin\telemetry-entry\telemetry-write.service.ts`), so F1.8 adds **no** database logic: it adds a request schema that pins provenance to `manual` and caps the batch, a controller that maps `ZodError` → `BadRequestException`, a response envelope contract, one pure browser-side module that converts the form's `datetime-local` value into an unambiguous instant, and the page itself. F1.8 is the reference consumer of the Phase A core and merges before F1.9.

### Out of scope

- **No DDL, no migration.** `bms.asset_points` and `telemetry.point_values` are used as they stand. This item does not take the migration lock.
- **No edit or delete of a reading.** Append only. Correcting a typo means re-posting the same timestamp with `conflictPolicy: "overwrite"`, and the audit log holds both entries (OQ-2, decided).
- **No change to `apps/ingest`, `apps/sim`, `packages/db`, or `apps/api/src/rules`.** `bindings.ts`'s `ap.source_kind = 'measured'` filter keeps manual points out of the binding index and `RulesService.latestPointValue` stays provenance-blind (OQ-5, decided). Both are **verified** in step 6, not modified.
- **No edit to the three frozen Phase A files** — `telemetry-write.service.ts`, `resolve-catalog-point-key.ts`, and (with one flagged, purely additive exception in task B1.0) `packages/shared/src/contracts/telemetry-entry.ts`.
- **No CSV/Excel upload.** That is F1.9, in its own worktree, rebased onto `main` after this merges.
- **No operator-role widening.** OQ-1 was decided master-data-only. `operator` and `asset_group_admin` are refused. Widening later is an amendment to ADR 0017, not a code tweak.
- **No multi-row entry grid in the first cut.** The request schema admits up to 50 rows so the endpoint never needs re-versioning, but the page posts one row per submit.
- **No new npm package.** Nothing here is a §9.4 dependency decision.

## 3. Serial or parallel — **serial, one worktree, no fan-out**

F1.8 is a single feature whose API and web halves are **dependent, not independent siblings**: the web client cannot be written until the response envelope exists, and the page cannot be written until the client exists. There are no 2+ non-overlapping units here, so §3's fan-out test is not met and spawning subagents would cost more and produce worse seams.

F1.8 is **not a ⭐ enabler** — Phase A was the enabler, it is built and merged, and its interface is frozen. So the "never fan out an enabler" rule is not what makes this serial; the absence of a real fan-out is. The parallelism in this pair was already spent: F1.8 and F1.9 are the two worktrees, and this plan covers worktree 1.

The step-5 review agents (`code-reviewer`, `security-reviewer`, `agents-compliance-reviewer`) still run **concurrently** at the end — they are read-only and cannot collide. **No `migration-reviewer`:** there is no `packages/db` diff.

## 4. Facts this plan depends on — verified in the worktree, not assumed

1. **The frozen service signature.** `WriteReadingsInput = { rows, sourceKind, conflictPolicy, auditAction }`, `WriteReadingsOutput = { result, rejected }`. No slot for a free-text note. Constructor `(db, pool, accessControl, audit)`.
2. **[correction to §6] Out-of-scope asset is a 200 with a rejected row, not a 403.** `requireMasterDataUser(jwt)` runs once up front and throws `ForbiddenException` → 403 for a non-master-data caller. `canManageAsset` failing inside `validateRow` returns a rejected row (HTTP 200) with the merged "Asset not found or outside your access scope" message.
3. **Seeded fixtures for both directions:** `wc-hvac-admin@bms.local` (`asset_group_admin`) is the 403 fixture; `wc-admin@bms.local` + `fx.outOfScopeAssetId` is the 200-with-rejected-row fixture. Reuse `loadFixtures`/`cleanup` exported from `telemetry-write.spec.ts`.
4. **[correction to §6] `unit` must be omitted unless the operator overrides it** — the mapping's own unit wins over the catalog's when a mapping exists; sending the catalog unit on such a point rejects every row.
5. **[correction to §6] `datetime-local` must be converted to an absolute instant in the browser** — an offset-less string resolves against the API process's zone, not the operator's.
6. **[correction to §6] `adminFetch(path, telemetryWriteResultDtoSchema, …)` cannot work** — the controller returns `{ result, rejected }`, not the bare result. An envelope schema is required (task B1.0).
7. **`.strict()` is load-bearing** on the request schema — without it a caller's `sourceKind: "measured"` is silently stripped, not rejected.
8. **`resolveCatalogPointKey` validates against the asset's organization catalog**, not the caller's selected one.
9. **Point-key catalog gate is fetched per-asset** — `asset-points-page.tsx:47-73` is the precedent.
10. **`apps/web` coverage counts `apps/web/src/lib/**` only**; no jsdom, so page components carry no test story — that's why logic goes in `src/lib`.
11. **Coverage thresholds today: 43.0 / 39.1 / 44.8 / 43.2.**
12. **No new file in top-level `tests/`**, so the root `typecheck:tests` script is unchanged.
13. **Static guards that will see this diff:** ADR 0029 (openapi contract), ADR 0030 (contract derivation), repo-invariants (`.spec` wrapper requirement, 1000-line cap), openapi-document's orphan/unexplained checks.
14. **`admin-access.spec.ts` does not assert the tab list** — adding a tab breaks nothing existing.
15. **AGENTS.md §6 does not list manual telemetry entry** — check again at the end; a real gap is its own `chore(agents):` commit.
16. **No Nest DI boot under Vitest** — every integration suite constructs services directly with `new`.
17. **Spec style:** exported `run…Tests()` + local `assert()` helper, not `expect` — see `source-kind.schema.spec.ts`.

### B1.0 — The response envelope contract

**Files:** `packages/shared/src/contracts/telemetry-entry.ts` (modify, additive), `packages/shared/src/index.ts` (one `z.infer` line), `apps/api/src/admin/telemetry-entry/manual-readings.schema.spec.ts` + `.test.ts` (new, shared with B1.1).

⚠ **Flagged for the human** — a narrow, named exception to the parent plan's freeze on editing `contracts/telemetry-entry.ts` during Phase B. The change is purely additive (one new export), the envelope is genuinely shared with F1.9, and no sibling worktree is live yet. Alternative: a new `contracts/manual-readings.ts`, costing F1.9 a rename or duplicate later. **Decision needed — see §10.**

Test first: a type-level `Strict<z.infer<typeof telemetryWriteResponseSchema>, WriteReadingsOutput>` assertion that fails the moment the schema and the frozen service type disagree (lives in `apps/api` since `packages/shared` can't import from it); runtime parse success on a full payload; runtime failure on a payload missing `rejected`; runtime success with a `rejected` entry proving `field`'s nullability survives.

Then write:
```ts
export const telemetryWriteResponseSchema = z.object({
  result: telemetryWriteResultDtoSchema,
  rejected: z.array(rejectedRowDtoSchema),
});
```
No `.readonly()` on the outer object (its properties are mutable on the real type — adding it would break the `Strict` assertion). No `.merge()`/`.omit().extend()`. `packages/shared/src/index.ts` gets `export type TelemetryWriteResponse = z.infer<typeof Te.telemetryWriteResponseSchema>;` — hand-writing this type instead fails ADR 0030's guard. Run `pnpm build` (or `pnpm --filter @bms/shared build`) after editing `packages/shared`, before api/web typecheck.

### B1.1 — The request schema

**Files:** `apps/api/src/admin/telemetry-entry/manual-readings.schema.ts` (new, pure — no DB gate), spec/test pair extended from B1.0.

Test cases (11, in order): default `conflictPolicy` is applied not merely allowed; explicit `"overwrite"` survives; `"merge"` fails; **unknown key `sourceKind` fails** (proves `.strict()`); empty `rows` fails; 51 rows fails (discharges A4a's M2 for this endpoint); exactly 50 rows parses; `NaN`/`Infinity` value fails; unparsable time fails; bad `assetId` fails; a row with no `unit` key parses.

Then write:
```ts
export const manualReadingsBodySchema = z
  .object({
    rows: z.array(telemetryEntryRowSchema).min(1).max(50),
    conflictPolicy: z.enum(["reject", "overwrite"]).default("reject"),
  })
  .strict();
```
`telemetryEntryRowSchema` imported from `@bms/shared`, never restated. `sourceKind` absent from the body by design — the controller hardcodes `"manual"`. **`note` is deliberately omitted — flagged for the human, see §10.**

### B1.2 — The controller, module wiring, and OpenAPI registry

**Files:** `manual-readings.controller.ts` (new), `admin.module.ts` (modify, controller registration), `openapi-registry.ts` (modify, one entry), `manual-readings.spec.ts` + `.integration.test.ts` (new, DB-gated, mirrors `telemetry-write.integration.test.ts`).

This suite tests the controller's own contract only — Phase A's mapping/unit/retention/dedup/CHECK-boundary behavior is already covered by `telemetry-write.spec.ts` and is not re-proven here. Nine cases: 403 for a non-master-data caller (`wc-hvac-admin@bms.local`), verified by SQL that nothing was written; out-of-scope asset is 200 with the non-disclosing rejection (not 403); happy path verified by independent SQL, never by reading the service's own return value; `sourceKind` is `'manual'` regardless of body (can't be set, proven at the outcome); `auditAction` is `'telemetry.manual_entry'`, asserted against the newest row's shape, never a row count; `conflictPolicy` defaults to reject; explicit `"overwrite"` overwrites; `ZodError` → `BadRequestException`, not a raw 500; the response satisfies `telemetryWriteResponseSchema.parse(...)` at runtime.

Then write the controller — `.parse()` inside the `try` so its `ZodError` is caught; `@HttpCode(201)`; no role check in the controller (already enforced inside `writeReadings`); comment noting `rejected[].reason` interpolates caller-supplied text and must never reach a logger or `dangerouslySetInnerHTML` (discharges A4a's L3). Module: add to `controllers` array, not `providers` (service already registered). OpenAPI: `ManualReadingsController_create` key, alphabetical position — operationId must match `ClassName_handlerName` exactly.

### B1.3 — The web API client

**File:** `apps/web/src/api/admin/manual-readings.ts` (new, no spec — outside coverage denominator, no jsdom). One `adminFetch` call validated through `telemetryWriteResponseSchema`, mirroring `asset-points.ts` exactly. Never `as Promise<T>` (ADR 0030 scans for it).

### B1.4 — The pure form logic

**Files:** `apps/web/src/lib/manual-reading-form.ts` + spec/test pair (new). This is where F1.8's web coverage comes from — keep the page a thin shell over these functions.

Five functions, each test-first:
- `localDateTimeToIso(value, offsetMinutes)` — deterministic given an explicit offset (not dependent on runner `TZ`); rejects malformed input rather than producing `"Invalid Date"`. This is the highest-value test in the web half.
- `defaultLocalDateTime(now: Date)` — produces the `datetime-local` control value from an injected `Date`.
- `buildManualReadingRow(form, catalogUnit)` — omits `unit` from the payload unless the operator edited it away from the catalog default (fact 4).
- `describeWriteOutcome(response)` — confirmation line that mentions mapping creation when it happened, and never claims success on `written: 0`.
- `validateManualReadingForm(form)` — client-side format checks only (required fields, parseable value/time); deliberately does NOT re-implement server semantic rules (future skew, retention horizon, catalog membership, unit agreement) — those stay server-owned, the page renders `rejected[].reason`.

### B1.5 — The page, route, and nav entry

**Files:** `manual-readings-page.tsx` (new, no spec — no jsdom, outside denominator), `App.tsx` (route), `admin-access.ts` (nav tab).

Follow `asset-points-page.tsx`'s shell exactly. `HierarchyFilterBar` levels `["organization", "location", "asset"]` — `"rtu"` omitted deliberately (a gateway-less asset is the whole point). Point-key `<select>` scoped to the asset's own organization (fact 8/9). Fields: asset, point key, value, unit (pre-filled, editable), timestamp (`datetime-local`, defaulted via `defaultLocalDateTime`), an unchecked-by-default "overwrite" checkbox. Render the outcome both directions — success line via `describeWriteOutcome`, rejections as escaped React text (never `dangerouslySetInnerHTML`), thrown errors inline. No `catalogOnly` flag on the nav entry (OQ-1 gated to all three master-data roles).
