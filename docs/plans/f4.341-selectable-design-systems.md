**Consequence of P1 for the design (D8 below):** class strings are shared by
every design system, so a weight or a capital written in a class string would
leak from `nexus-soft` into the others. The weight, the label case and the
letter-spacing therefore become **tokens** as well: `nexus-soft` keeps today's
values, and each other design system's token block sets A6's values. The A6
gates read the token blocks of the four non-default design systems, not the
class strings.

## 1. Goal

Five closed design systems (`nexus-soft` default = today's look,
`enterprise-flat`, `swiss-grid`, `bento-ops`, `control-room-dark`), each a set
of **design tokens** (type, weight, case, spacing, shape including shadows)
plus one **shell** (`sidebar` / `topbar` / `rail`). A design system never sets
a colour role and combines with any of **nine** colour profiles (six shipped +
`forest`, `sand`, `navy-pop`). The design system and the profile each resolve
**User > Organization > Portal**, are stored in `bms.portal_settings` (one
row), `bms.organizations` and `bms.users`, are written through three audited
routes, and are returned by `/auth/me` with the level each came from. The
sign-in page shows the portal default through an unauthenticated
`GET /public/appearance`. Fonts are self-hosted. One "Appearance" panel serves
the three levels. Until someone chooses a non-default design system, a site
sees **no pixel change**, except the ruled value fixes (A4 in PR 2, P6 in PR 2,
A5 in PR 7).

## 2. Out of scope

ADR 0118 Consequences and Amendment 1: per-page layouts, free tile placement,
a per-location design system, an organization lock, custom or uploaded design
systems, reports, emails, Keycloak, map tiles, mimic geometry, a live push, a
copilot action, glass, gradient or translucent grounds, accent tile fills and
decorative accent borders. Also: margins (`m-*`, 566 lines) stay literal,
because ADR decision 3 names text size, padding and gap only; `w-*`/`h-*` sizes
are not spacing tokens. The removal of the old route and field is `F4.342`
(P5).

## 4. Design decisions (drafter refinements)

**D1 — Tokenization by a Tailwind theme remap (P2).** `theme.fontSize` emits
tokens: `xs: ["var(--text-xs)", { lineHeight: "var(--leading-xs)" }]` … plus
two new steps `"2xs": "var(--text-2xs)"` (11px) and `"3xs": "var(--text-3xs)"`
(10px) with no line height (today's arbitrary sizes set none).
`theme.padding`, `theme.gap` and `theme.space` spread `theme("spacing")`, then
override steps `1…8` with `var(--space-N)` and `0.5/1.5/2.5` with midpoint
`calc()`s. With `nexus-soft` values equal to Tailwind's defaults, the emitted
CSS is pixel-identical; a gate proves the equality against
`tailwindcss/defaultTheme`. "Raw" then means an **arbitrary** value or an
inline literal, and the zero gate holds those at 0. About 450 changed lines.

**D2 — Design tokens live in `html`-keyed blocks, never in `:root {`.** Base
(`nexus-soft`, both surface variants): `html { … }` and
`html:not([data-design])[data-surface="flat"] { … }`. Each other design
system: `html[data-design="<name>"] { … }` and
`html[data-design="<name>"][data-surface="flat"] { … }`; its shadows in
`html[data-design="<name>"]:not([data-surface="flat"])` plus the dark twin.
The specificities are disjoint by construction. The colour parser is not
changed. A new parser `parseDesignBlocks` (`tests/support/design-tokens.ts`)
reads these blocks.

**D3 — The surface vocabulary becomes token-driven.** Base rules read
`var(--radius-card)`, `var(--shadow-raised)`, `var(--card-ground)`,
`var(--text-xs)`, `var(--space-1)` …; the flat rules read the same tokens with
the flat variant's values. So "each design system defines every `surface-*`
rule in both variants" (decision 14) holds by construction through "defines
every token in both variants". A design system adds an explicit rule only
where a token cannot express it (`swiss-grid`'s `border-top: 3px solid
rgb(var(--ink))`), always as `:where(html[data-design="x"]) .surface-…`
(specificity (0,1,0), so a call-site utility still wins).

**D4 — The token list** (`DESIGN_TOKENS` in `apps/web/src/lib/design.ts`):
type `--font-body --font-head --font-num --font-mono`,
`--text-3xs … --text-6xl` (+ `--leading-xs … --leading-6xl`),
`--text-wall-min`; weight and case (D8) `--weight-bold --weight-semibold
--caps-transform --caps-tracking-wide --caps-tracking-wider`; spacing
`--space-1 … --space-8`; shape `--radius-card --radius-card-sm --radius-well
--radius-control --radius-button --radius-pill`, `--card-ground --page-ground
--button-edge` (role references such as `rgb(var(--canvas))`, never a colour),
`--shadow-raised --shadow-raised-sm --shadow-pressed --shadow-pressed-sm
--shadow-pill --shadow-ribbon`. `nexus-soft` values are today's: Tailwind
defaults for text, leading and space; `3xs` 10px, `2xs` 11px;
`--weight-bold: 700`; `--caps-transform: uppercase` and today's tracking;
today's radii and shadows; `--button-edge: rgb(var(--ink-faint))` (A5).

**D5 — Two migrations.** The nine-name CHECK lands **with** the profile values
(PR 2), so a choice of `forest` between PRs cannot fail with `23514` on the
demo: `0133_colour_profiles_nine.sql` (PR 2) and `0134_portal_appearance.sql`
(PR 3). This refines decision 9's "one migration".

**D6 — `/auth/me` adds `appearance` beside `colourProfile`.** The old field
and the old route stay until `F4.342` (P5), because a green CI deploys `main`
to the demo and the API must never drop a field the deployed web reads.

**D7 — The rail shell always shows text labels** (≥ 12px, no hover reveal).

**D8 — Weight and case are tokens (P1).** `theme.fontWeight.bold` →
`var(--weight-bold)` and `semibold` → `var(--weight-semibold)`; the core
`textTransform` utility `uppercase` and the `letterSpacing` steps used with it
are replaced by token-driven utilities (`text-transform:
var(--caps-transform)`, `letter-spacing: var(--caps-tracking-*)`), so the
class strings stay and the design system decides. `nexus-soft` = today
(`700`, `uppercase`, today's tracking); every other design system sets
`--weight-bold: 600`, `--caps-transform: none`, tracking `0`,
`--text-3xs`/`--text-2xs` ≥ 12px. The breadcrumb renders through one
component whose kicker style reads the same tokens.

1. **A4 is strict.** Light accents against `info-ink` `#075985` (`ocean`

   `:where(html[data-design])`-wrapped; a test holds that no `.surface-` rule

   is the gate); the WOFF2 `tnum` parser is new code with a negative fixture;
   the §9.4 hook needs the ADR edit in the same commit.

   utilities must not change `nexus-soft`'s output; DT3 and a compiled-CSS
   snapshot of the affected utilities hold it.
5. **Topbar overflow** with 14+ module items: a scrollable strip; checked on
   a 1366px viewport locally.
6. **The public route** is unauthenticated by design and returns two enum
   strings only.
7. **The cloud build cannot see Docker.** The route specs run in CI's
   Postgres; the reviewers run on PRs 2 and 3; §10 is owed locally.
