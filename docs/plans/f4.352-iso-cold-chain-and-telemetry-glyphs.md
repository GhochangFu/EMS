## 1. Goal

Grow the built-in `iso` library (ADR 0121, `F4.345`) from 50 to 58 glyphs: `iso:telemetry-tower`,
`iso:gateway`, `iso:blast-freezer`, `iso:cold-room`, `iso:deep-freezer`, `iso:unit-cooler`,
`iso:temperature-probe`, `iso:reefer` — eight new glyph modules under
`scripts/mimic-symbols/sources/iso/glyphs/`, drawn with the same vendored kit, hidden-line step
and 1/40 ribbon, **appended after the existing 50** in the build order and in the generated key
order (never reordered; the existing 50 rebuild byte-identical). `generate.mjs --iso` regenerates
the shared and web `iso.generated.ts`; one migration (next free number at build time — `0139`
today) inserts the eight `bms.mimic_symbols` rows the `0092`/`0136` way and asserts 58 active
`iso` rows. In the web, an isometric-only **node override** makes the PHE presets' `rtu` nodes
(`pump_station_overview`, `pump_station_environment`) draw `iso:telemetry-tower` and the
`network` node draw `iso:gateway` when a widget's `glyphSet` is `iso`; the core set is untouched
(those nodes still draw `sensor`). After deploy, a **data step** on AWS — not a migration, not
the cloud build's job — backs up the two WBLDC layouts' node rows and re-links the 23 stand-in
units to the cold-chain glyphs.

**Out of scope.** A core tower symbol (`mimicCoreSymbolSchema` is unchanged — amendment
decision 3); per-asset-type default glyphs; glyphs for door switches, humidity or power meters
(amendment Deferred); any change to the library row, the upload parser, the shape grammar, the
API, `mimicConfigSchema`, the layout editor's "Start from" starter (`fromPreset` keeps copying
the core `sensor`), or the 50 existing glyph modules (their rebuild is a gate, §5 T1.1); any
`AGENTS.md` edit.

## 2. Facts measured from the code

- **Glyph sources.** `scripts/mimic-symbols/sources/iso/build.mjs` imports the kit from
  `../../vendor/anatomy-kit/` only; its `CORE` array (the build order: 29 core, then `flowmeter`,
  `rtu`, then 19 equipment kinds ending `"pressure-gauge"`) selects which `glyphs/<id>.mjs` build;
  `ONLY=a,b` builds a subset (preview only). It writes `out/fill/<id>.svg` (square `viewBox`,
  `<path d>` only, ribbon width = side/40), `out/manifest.json` and `out/preview.html`; `out/` is
  git-ignored. `validate.mjs` runs every `out/fill/*.svg` through the real upload parser, exit 1 on
  any failure.
- **A glyph module** exports `name` (ending " (isometric)"), `extent` (world points for the camera
  fit, usually `boxExtent(...)` from `lib/shapes.mjs`), `parts(k, G, P)` (paint order, back to
  front, of `{ name, solid }` or `{ name, lines }`), optionally `azimuth` (default 45) and `level`
  (the tank only). `shapesOf(k, G, P)` gives `box`, `vcyl`, `xcyl`, `ycyl`, `turned`, `flat`,
  `poly`, `circle`, `spokes`. World axes: x and y on the ground, z up; the viewer looks from +x +y.
  Lines closer than ≈5 world units merge at the mimic's 60-px glyph size. Limits: ≤ 200 shapes,
  each `d` < 8,192 chars (`ribbon.mjs` splits at 8,000) — today's largest file has 19 shapes.
- **Curation and key order.** `curation/iso.json` is `{ "<group>": [{ name, label }] }`, groups in
  file order `water, electrical, it_ups, hvac, mechanical, environment, facility, general`.
  `generate.mjs build()` (`:242-266`) walks `Object.entries(curation)` in **file order**, so a
  symbol's position — `--sql-rows`' `sort_order = 10 × position` and the order of
  `ISO_SYMBOL_KEYS` — is its position in that walk. A new `hvac` entry inside the existing `hvac`
  list would shift every later key. `GROUPS` (`lib/grammar.mjs:25`) holds the eight group codes;
  `build()` refuses a key not in it (`:251`). JSON cannot repeat a key, so the eight cannot be
  appended in the present format without a generator change (§3 R1).

SELECT l.name AS layout, n.layout_id, n.key, n.label, n.role_code, n.symbol,
       string_agg(DISTINCT a.name, ' | ') AS bound_assets
FROM bms.mimic_layout_nodes n
JOIN bms.mimic_layouts l ON l.id = n.layout_id
LEFT JOIN bms.asset_group_members agm ON agm.role = n.role_code
LEFT JOIN bms.asset_groups ag ON ag.id = agm.asset_group_id AND ag.organization_id = n.organization_id
LEFT JOIN bms.assets a ON a.id = agm.asset_id AND a.organization_id = n.organization_id
WHERE n.organization_id = '<WBLDC id>' AND n.kind = 'unit'
  AND n.symbol IN ('iso:compressor', 'iso:condensing-unit', 'iso:chiller')
GROUP BY l.name, n.layout_id, n.key, n.label, n.role_code, n.symbol
ORDER BY l.name, n.key;
