## 1. Goal

Asset health (ADR 0050) bands an asset from its template's
`content.health.bands` and weights its points from `content.health.weights`,
but no screen edits either. On 2026-11-11 the bands were added to six AWS
templates by hand through the API. This row adds:

- an **eighth template tab, `health`**, after Maintenance: a band table
  (code, label, minimum score in percent; add, remove, move up / down) and a
  per-point weight column (default 1);
- an explicit **Use the standard five bands** button (nothing pre-filled);
- **Remove health bands**, behind a confirm;
- on a published version, the tab read-only with a hint (asset counts on other
  versions, from the existing `GET :id/versions`) and a link to Versions &
  migration;
- the template list marks versions without bands;
- the stock catalog viewer shows the tab read-only.

## 2. Out of scope

- Any API route, migration, contract or seed-data change (beyond the import
  move in PR 1).
- An `optimisation` tab; any change to scoring, rule matching or the roll-up.
- Bands or weights per asset, location or organization; applying bands to
  assets automatically on publish.
- Writes to the AWS demo (`bms.demosites.co.in`).

### PR 2 — pure form rules (Opus-level)

- `apps/web/src/lib/template-health-form.ts` (+ `.spec.ts` / `.test.ts`):
  - types `HealthBandRow {code, label, minPercent: string}`,
    `HealthWeightRow {pointKey, label, kind, weight: string, declared}`,
    `HealthForm {bands, weights, removeBlock}`, `HealthWrite` none / remove / set;
  - functions `minScoreToPercentText`
    (`String(Number((x*100).toPrecision(12)))`), `percentTextToMinScore`
    (`null` for `""` / non-finite), `storedHealth`, `contentHasHealthBands`,
    `healthFormFrom`, `standardHealthBandRows`, `blankHealthBandRow`,
    `moveHealthBand`, `healthWriteFrom`, `healthFormErrors`,
    `healthHasChanged`, `otherVersionsHoldingAssets`.
- Rules: one weight row per template point (default `"1"`); a stored weight
  for a key that is no point becomes `declared: false` and is never dropped
  silently; weights equal to 1 are not written, and there is no `weights` key
  when it is empty; validation runs the shared `templateHealthSchema` (errors
  worded in percent; the lib never blocks what the schema accepts);
  `healthHasChanged` compares against the normalised stored block, so an
  untouched tab is clean.
- `apps/web/src/lib/template-content-merge.ts` gains a
  `{ section: "health"; value: TemplateHealth | null }` arm: `null` deletes
  only `health`; bands are copied, weights filtered through `UNSAFE_KEYS`.
- **Tests first:** percent round trip (0.95, 0.85, 0.7, 0.5, 0, 0.575, 0.999,
  0.123456, no float noise), untouched-is-clean, weight-1 omission, schema
  refusals per row / field, agreement with the schema over a fixture table,
  preset rows, move, remove, undeclared weights, `contentHasHealthBands`,
  `otherVersionsHoldingAssets`, and merge specs (other sections preserved,
  `null` deletes only health, unsafe keys dropped, no aliasing).
- Run `npx vitest run --coverage` directly (pnpm `--` drops flags); never
  lower thresholds.
