## 1. Goal and out of scope

**Goal.** The 188 hex literals and 2 colour functions left in 16 files of `apps/web/src` (`FLOOR`, palette already 0) become role colours, so the whole SPA follows `data-theme`: the six ECharts renderers and Leaflet read the 41 roles at render time through one resolver (`getComputedStyle` on `<html>`, injectable for tests) and re-render on a theme change; the CRAC, SLD, six SMOC views, the world map, the CodeMirror formula theme and the login hero move to role classes or `rgb(var(--role))` strings; the Amendment 2 §8 punch list (rack label, five zone labels, the Leaflet close button) is recoloured ink-with-fill; a two-state **Light / Dark** control in the header's user area writes `localStorage["bms.theme"]` and flips the attribute without a reload. The gate goes to zero: `hex` and `func` become hard zeros like `palette`, `FLOOR` and R11 are deleted, the `F3.65b` codemod and its test are deleted, and the stock palette and the `bms` block leave `tailwind.config.js`. Light pixels move only where a rare hex merges (every merge listed with its ΔE in §2.4) and at the six sites §2.4 marks **bold**.

**Out of scope.** A "System" choice or any `matchMedia` (decision 4). A per-user column or route. A new role (an ADR 0078 amendment; OQ1–OQ7 ask, this plan does not add). Tailwind preflight's `::placeholder` colour (stock `#9ca3af` by fallback, unchanged pixel; already in the gate's NOT-covered list). PDF/Excel/e-mail, Keycloak pages, the two mockup HTML files. `AGENTS.md` wording (a separate `chore(agents):` PR — §7 says what it must say). No contract, route or migration: `packages/shared/src/contracts/` is untouched, so §4.8 / ADR 0030 are not engaged.

### 2.2 The re-render contract of `echarts-for-react` 3.0.6 (manifest `^3.0.2`; `echarts` 5.6.0) — measured from `src/core.tsx`

| Prop that changes | What the wrapper does | Consequence for this row |
|---|---|---|
| `theme` or `opts` (`fast-deep-equal`) | `dispose()` the instance **then `renderNewEcharts()`**: `echarts.init(ele, theme, opts)` on a temporary instance, waits for `finished`, disposes it, re-inits at the measured size, `setOption`, rebinds events. `theme` is `string \| object`, passed straight to `init`. | A per-mode **theme object** re-creates the chart on toggle — every implicit default (text, axes, tooltip, legend, gauge chrome) re-reads. A new `<canvas>` element is created; that is the browser's cheap proof (§6). |
| `option`, `notMerge`, `replaceMerge`, `lazyUpdate`, `showLoading`, `loadingOption` (deep-equal on the picked keys) | `setOption(option, { notMerge, replaceMerge, lazyUpdate })` | A new `option` object with the same values is a no-op; new colour strings are a full replace under `notMerge` — all six call sites already pass `notMerge lazyUpdate`. |
| `style` / `className` | `resize()` | none |
| anything else | nothing (PureComponent) | a store subscription in the parent is what makes a chart re-render at all |

**Mechanism chosen (D1):** both halves — a **theme object built from the resolved roles** carries every chrome default in one place, and each option carries its **series colours from the same roles**. On a toggle both change together: dispose + init + setOption. The alternative (explicit chrome colours in each of six options, no theme) would have to restate ~9 keys × 6 options and still miss the gauge and pie internals; `registerTheme` with hex per mode is refused by the gate.

### 2.6 The palette removal — what consumes the stock palette or `bms` today

Measured: no `theme(` or `@apply` in `apps/web/src/**/*.css` (three files: `index.css`, `crac-styles.css`, `sld-styles.css`; the last two hold only `--crac-*` / `--sld-*` durations); no JS import of `tailwind.config.js` outside `tests/f3.65a-colour-tokens.test.ts` (T11) and docblock prose (`formula-editor.tsx:69`, `index.css:7`); `plugins: []`. Compiled from the real config with `postcss` + `tailwindcss` (measured): `fill-accent/20` → `fill: rgb(var(--accent) / 0.2)`, `stroke-ink-hint/50` likewise, `[stop-color:rgb(var(--canvas))]` → `stop-color: rgb(var(--canvas))`, `bg-transparent`, `text-current`, `fill-none`, `outline-none` all emit. **The exact change (D9):** move the 41 role entries from `theme.extend.colors` to **`theme.colors`** and add `transparent: "transparent", current: "currentColor", inherit: "inherit"`; delete the `bms` block; keep `extend.borderColor.DEFAULT` and `extend.ringOffsetColor.DEFAULT` as they are. ## 3. Design decisions

- **D1 — One resolver, one store, one chart theme.** `apps/web/src/lib/theme.ts` (pure): `THEME_STORAGE_KEY = "bms.theme"`; `ROLE_NAMES` (41, a `const` tuple — single-sourced against `index.css` by gate G1); `type RoleName`, `type Roles = Readonly<Record<RoleName, string>>` (values `rgb(r, g, b)`); `resolveRoles(read: (role: RoleName) => string): Roles` — parses `"r g b"`, **throws naming the role on an empty or malformed value** (fail closed: a chart that silently painted ECharts' `#333` on a dark card is the defect this row removes); `withAlpha(rgb, alpha)` → `rgba(r, g, b, a)` built from the parsed channels (no literal — the gate's `rgba(` needs a digit after it, `rgba(${` is not counted); `readRoleFromDocument(role)` = `getComputedStyle(document.documentElement).getPropertyValue(\`--${role}\`)`; `readDocumentTheme()` = `dataset.theme === "dark" ? "dark" : "light"` (never re-parses `localStorage` — the boot script is the one reader, so the boot test's "only `dark` gives dark" cannot drift). `apps/web/src/stores/theme-store.ts` (zustand `create`, like `auth-store.ts`, **no `persist`** — the key is written by hand so the boot script's contract stays the only format): state `{ theme, roles, setTheme }`; initial `theme = readDocumentTheme()`, `roles = resolveRoles(readRoleFromDocument)` when a `document` exists, else `null` and `useThemeRoles()` throws "no document". `setTheme(t)`: `setAttribute("data-theme", t)` **first**, then `try { localStorage.setItem(KEY, t) } catch {}` (a throwing storage still flips the page), then `set({ theme: t, roles: resolveRoles(readRoleFromDocument) })` — computed style re-reads synchronously after the attribute flips (§2.7). Hooks: `useTheme()`, `useThemeRoles()`. **Choosing Light writes `"light"`, it does not remove the key** — the state and the stored value are then equal, B3 already holds `"light"` → light, and the browser check is a positive string match rather than an absence assertion.
- **D2 — `apps/web/src/lib/chart-theme.ts`.** `echartsTheme(roles)` returns the ECharts theme object: `textStyle.color` `ink-muted`; `title.textStyle.color` `ink`; `legend.textStyle.color` `ink-muted`, `inactiveColor` `ink-hint`; `tooltip.backgroundColor` `surface`, `borderColor` `line-strong`, `textStyle.color` `ink`; for each of `categoryAxis`/`valueAxis`/`timeAxis`/`logAxis`: `axisLine.lineStyle.color` `line-strong`, `axisTick.lineStyle.color` `line-strong`, `axisLabel.color` `ink-muted`, `nameTextStyle.color` `ink-faint`, `splitLine.lineStyle.color [line]`; `axisPointer.shadowStyle.color` `withAlpha(ink-faint, 0.15)`, `lineStyle.color` `ink-hint`; `gauge`: `axisLabel.color` `ink-muted`, `detail.color` `ink`, `title.color` `ink-muted`, `axisTick`/`splitLine` `ink-hint`; `color` palette `[accent, info, warning, critical, ink-faint, simulated-ink]` (the generic `chart` widget's series). `useChartTheme()` = `useThemeRoles()` + `useMemo(() => ({ roles, theme: echartsTheme(roles) }), [roles])`. Every `<ReactECharts>` passes `theme={theme}`; the four standalone charts **drop** their explicit axis/legend colour keys (the theme supplies them, DRY) and keep only their series `color` arrays from `roles`. `load-trend-chart.tsx`'s `areaStyle.color` becomes `withAlpha(roles.accent, 0.12)`.
- **D3 — jsdom gets the real tokens.** `apps/web/src/test-setup.ts` appends `readFileSync(new URL("./index.css", import.meta.url))` in a `<style>` when `document` exists; a spec flips the theme with `useThemeStore.getState().setTheme("dark")` and the resolver returns the dark block (§2.7). `resolveRoles`'s own spec uses the injectable source: `fromTokenMap(parseTokenBlocks(css).light)`. A web spec that needs the maps reads `index.css` with `fs`, the same way; `tests/` files keep using `tests/support/colour-tokens.ts`.
- **D4 — JSX-owned SVG uses classes; library-painted surfaces use resolved roles.** CRAC, electrical SLD and the SMOC views: `fill-*`/`stroke-*` classes, status functions return **whole literal class strings** (Tailwind's scanner needs the literal; the gate's NOT-covered list names concatenation), e.g. `strokeFor(status)` → `"stroke-critical" | "stroke-ink-hint" | "stroke-accent"`; a `<marker><path fill>` takes `fill-accent`; gradient stops take arbitrary-property classes `[stop-color:rgb(var(--canvas))]` (compiles, §2.6 — the two CRAC gradients keep their light pixels). No `var()` in a presentation attribute. Leaflet `pathOptions.color/fillColor` (setStyle-driven — a `className` would not update when a site's status changes because Leaflet applies `className` at creation only), ECharts options and the CodeMirror `EditorView.theme` (CSS strings: `rgb(var(--line))`, R7 says these are not colour functions) read roles.
- **D5 — The schematic boards paint `surface`, not `well` [touches ruling].** `critical` on `well` is 2.97 in dark; on `surface` it is 3.32 and every status stroke's pair is already declared or allowlisted (§2.5). - **D6 — Halos are cut-outs.** The env marker `stroke="#fff"` ×3 → `stroke-surface` (the board colour in both themes); the letters are already `fill-on-dark`.
- **D7 — Green text on the ok tint is `accent-strong`** (`crac-schematic.tsx:511`; electrical-sld's three labels are already `#007C3C`): `accent` on `ok-wash` is 3.03 light. Green text on the board (`crac` 551/559 PMP-A1) stays `fill-accent` under the existing `accent on surface` allowlist entry.
- **D8 — `WIDGET_TONE_COLOR` becomes three declarations in `lib/widget-catalog.ts`:** `WIDGET_TONE_ROLE: Record<WidgetTone, RoleName>`, `WIDGET_TONE_FILL_CLASS: Record<WidgetTone, string>` (literal `fill-accent` … for `tank-level-widget.tsx`), `widgetToneColor(roles): Record<WidgetTone, string>` for ECharts. `buildRadialGaugeOption(config, value, roles)` and `buildChartOption(config, series, now, roles)` take `roles` (a required trailing parameter — an optional one at an adapter is invisible to `tsc` and the fakes).
