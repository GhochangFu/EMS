# E4.2 — Sustainability and benchmarking dashboards: implementation plan

Planned on Fable 2026-09-22 against [ADR 0072](../adr/0072-sustainability-and-benchmarking-dashboards.md)
(Accepted, seven gate questions ruled). Nothing in the ADR is re-opened
here. Eight plan questions (OQ1–OQ8, at the end) were put to the owner one
at a time on 2026-09-22 and **all eight were ruled as recommended**; the
material one, OQ2, is folded into ADR 0072 decision 1 (the organization-wide
instantiate arm) and becomes unit U8b below.

## Goal

Two serial pull requests, then a closure PR. **PR 1** adds two parameterised
`METRIC_CATALOG` entries (`sustainability.total`, `sustainability.by_location`)
with `{ pointKey, aggregate }` on their write schema, a point-key check at
every binding write, and a resolver that sums or averages the latest fresh
sample per carrying asset in the dashboard's scope ∩ the caller's scope,
with `coverage: { fresh, carrying }` and `currency`. **PR 2** authors twelve
`*_this_month` / `*_this_year` derived codes on eight stock classes, seeds
two executive codes with no formula, takes `sustainability-overview` to
`stockVersion: 2`, adds the organization-wide instantiate arm and
`GET /dashboards?section=`, adds one sidebar entry, and renders coverage on
the tile and in the benchmark table.

**Out of scope** (ADR 0072 decisions 4–5, ruled 6): any formula for
`water_recycle_pct` / `operational_efficiency_pct`; the `/` KPI ribbon
(`F3.28`); persona defaults (`F3.64`); water balance (`E4.3`); money on
advisories (`E1.6`); the campus tier (`F2.10`); per-bucket `$key` (Q7 (c));
a params editor in the builder (OQ3); new dependencies.

## Facts measured from source that shape the plan

1. `MetricCatalogService.resolveForDashboard`
   (`apps/api/src/dashboard-builder/metric-catalog.service.ts:127-188`) runs
   `withTenant(tenantDb, organizationId)` for the dashboard's ONE
   organization, and `resolveAssetScope` filters `assets.organizationId`.
   `bms.organizations.currency` is `NOT NULL` (`bms-schema.ts:45`). So on
   this route a roll-up can never see two currencies — `mixed_currency` is
   unreachable (OQ1).
2. `resolveForDashboard` resolves once per DISTINCT `catalogKey` (line 160:
   "the parameters that would make them differ do not exist yet"). Two tiles
   binding `sustainability.total` with different `pointKey`s must now
   resolve separately — the key becomes `(catalogKey, canonical params)`.
3. A section template instantiates into an **asset group only**
   (`instantiateSectionTemplateBodySchema.assetGroupId: z.string().uuid()`,
   `dashboard-templates.schema.ts:96-103`), and `asset_groups.location_id`
   is `NOT NULL`. Every `sustainability-overview` instance is therefore one
   location's asset group; its benchmark table has one row (OQ2 → U8b).
4. `MetricSourcePicker` / `WidgetEditor` add a source with `params: {}`
   (`F3.61`). For the two new entries that is a 400 at save (OQ3).
5. `datasetCellSchema` is `string | number | boolean | null` — a dataset
   column cannot carry `{ fresh, carrying }` (OQ4).
6. The per-asset interval is `COALESCE(asset_points.calc_interval_seconds,
   template_points.calc_interval_seconds)` (`bms-schema.ts:330-348`, ADR
   0039 decisions 6–7); "carrying" = `assets.template_id →
   template_points.point_key`. A measured point has no interval: ADR ruled
   `MEASURED_ROLLUP_FRESH_MS = 15 min`.
7. The latest-sample read must use the lateral-join idiom of
   `CalcInputsService.getLatestSamplesForPairs`
   (`apps/api/src/calc/calc-inputs.service.ts:72-95`: `DISTINCT ON` over a
   pair set sorted 431,648 rows / 14.3 s; the lateral took 10.1 ms).
8. `dashboards.service.ts` is **992 lines**; `dashboard-templates.service.ts`
   718; `metric-catalog.service.ts` 465; `dashboard-builder.ts` (contract)
   943; `point-keys-seed.ts` is 276; `point-key-units.ts` is 762. U3 and U9
   touch the 992-line file: measure after each edit.
9. `tests/f3.35-metric-catalog-containment.test.ts` parses
   `METRIC_CATALOG_PARAMS_WRITE` as text: every enum key needs a `"key":`
   line, `.strict()` count must equal the key count, no `.uuid(`, no
   `locationId|assetId|…` spelling. `tests/f3.35-metric-catalog-labels.test.ts`
   parses `columns:\s*\[([^\]]*)\]` — keep a dataset's `columns` on one
   line with no nested bracket.
10. The template write path validates `params` against
    `METRIC_CATALOG_PARAMS_WRITE` at **publish** only
    (`dashboard-templates.service.ts:304-334`); instantiation copies
    `params` verbatim (`dashboard-templates-instantiate.service.ts:251-261`).
    A stock import lands as a draft, then publishes — the point-key check
    goes beside the publish loop.
11. `tests/f3.38` scans `STOCK_DASHBOARD_TEMPLATE_CATALOG` for every
    `pointKey:` value — a `params: { pointKey: "…" }` in the stock dashboard
    template is checked against the vocabulary for free, so PR 2's

12. Pinned counts that move in PR 2: `tests/f3.38` floor for
    `sustainability-point-keys.ts` 29 → 43; `tests/f3.39` `UNIT_BY_KEY`
    floor 634 → 648; `asset-templates-stock.integration.spec.ts:367-368`

### U4 — Resolution, freshness, coverage, currency · **Opus**

**Files**
- New `apps/api/src/dashboard-builder/sustainability-rollup.ts` (shape of
  `energy-cost.ts`: pure half + DB half):
  - `export const MEASURED_ROLLUP_FRESH_MS = 15 * 60 * 1000` and
    `freshnessBoundSeconds(row)` → `3 × interval` for a scheduled point,
    else `MEASURED_ROLLUP_FRESH_MS / 1000`.
  - `rollup(rows, aggregate)` → `{ value, coverage: { fresh, carrying } }` —
    `carrying = rows.length`, `fresh = rows with a value`, `value = null`
    when `fresh === 0`, `sum` or `avg` over the fresh values, no `?? 0`.
  - `rollupCurrency(currencies: ReadonlySet<string | null>)` → the one
    currency, else `null` (OQ1: a pure function with a unit test; the
    route cannot reach the mixed case).
  - DB half `readRollupRows(tx, organizationId, scope, pointKey)` — one
    statement: `bms.assets` (id = ANY(scope), organization_id = $org) JOIN
    `bms.template_points tp ON tp.template_id = a.template_id AND
    tp.point_key = $key` LEFT JOIN `bms.asset_points ap` (COALESCE the
    interval) JOIN `bms.locations l` (code, name) LEFT JOIN `bms.point_keys
    pk` (unit) LEFT JOIN LATERAL `(SELECT v.value, v.time FROM
    telemetry.point_values v WHERE v.asset_id = a.id AND v.point_key = $key
    AND v.time > now() - make_interval(secs => <bound>) ORDER BY v.time DESC
    LIMIT 1) s ON true`, ordered by `l.code, a.code`. An empty `scope`
    returns `[]` before SQL.
  - Currency: `SELECT currency FROM bms.organizations WHERE id = $org`
    once; attach only when the point's catalog `unit` is `""` (the money
    spelling, E4.1c Q8) — else `currency: null`.
