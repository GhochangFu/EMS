# F3.80 — step-3 plan (revision 2): network mimics with switching units (ADR 0101)

Source note: `.codegraph/` exists but neither the MCP tool nor the `codegraph` binary is reachable in this run. Every anchor below was read from the source at `9bb9a800` with ripgrep and direct reads. Re-run the `rg` lines named in §9 at build time; treat each list as a claim.

## 1. Goal

Any drawn mimic layout whose switching units gate the energised walk becomes a live network mimic, electrical or flow. A unit switches when its new `is_switching` flag is true or its symbol is one of `MIMIC_SWITCHING_SYMBOLS` (`D:\Projects\portal.bms\packages\shared\src\breaker-state.ts:31`). Eight position roles bind units to devices. Two new tones, `flowing` and `shut`, let a valve or damper show OPEN / SHUT; the walk passes on `closed | flowing`. The editor warns about a broken graph; the API never refuses one. ESKOM (never PHEWB) gets two seeded live networks at RSMOC-WC, driven by the simulator. Everything builds on the F3.74 machinery: `energiseGraph` (`packages/shared/src/mimic-energised.ts:90-148`), `deriveBreakerState` (`packages/shared/src/breaker-state.ts:71-95`), migration `0097`'s flags, and `mimic-scene.tsx`.

**Out of scope (ADR 0101 d17, d18, d2):** moving the layout write schemas to `packages/shared` (F3.87); an API 400 on a bad graph; tones beyond the five; ATS/changeover logic; per-unit colours, free shapes, connector styles; layouts in templates (F3.81) or shared across organizations (F3.83); a live state preview in the editor; any breaker or valve command (F3.12); any change to `energiseGraph`'s algorithm; any PHEWB data.

## 2. PR shape — two compile-forced moves across the d20 boundary, stated here

ADR 0101 Consequences: the plan "may not move work across the db/API and web boundary without saying so." Two moves are forced by the compiler; both are stated so the owner can object before PR1.

**Move A — the tone vocabulary goes to PR2, not PR1.** `PointKeyStateTone` is `z.infer` of the contract enum (`packages/shared/src/index.ts:927`). That is PR2's derived-state work. Therefore: **PR1's migration carries the five-tone CHECK (harmless while no row uses it — `bms_tenant` cannot INSERT state rows, I9) and the two point keys; the contract enum, the four state rows and every rank/look edit land together in PR2.** The `0109`-vs-contract equality assertion also lands in PR2.

**Move B — PR1 carries type-follow web edits for `isSwitching`.** `EditorNode = MimicLayoutNodeDto` (`apps/web/src/lib/mimic-editor.ts:36`); `newNode` (`:213-230`) and `fromPreset` (`:552, :572, :592`) build `EditorNode` literals. PR1 adds `isSwitching: false` to those four literals and to every web spec fixture (§9). Behaviour (toggle, geometry rule, write body) stays in PR2.

**Serial, one branch per PR, no worktree fan-out.** PR2 consumes PR1's field; PR3 consumes both. Inside each PR the units share files. F3.80 is P3, not a ⭐ enabler, so units may go to `implementer`; each dispatch pins `model:`. No unit has a stated critical reason for Fable.
