## 1. Goal

Implement ADR 0064 decisions 1–9 as amended: a `rules-sweep` queue (`fleet`, `z.object({}).strict()`, `RETRY_DEFAULTS`) appended to `ALL_QUEUES`; one scheduler `rules-sweep` upserted at worker boot beside the heartbeat's, every `RULE_SWEEP_INTERVAL_MS` (default 60 000, floor 10 000, ceiling 3 600 000, integer only, `QueueConfigError` otherwise, the worker refuses to start); a loop-free `RuleSweepModule` providing `RuleSweepService`, whose body walks the same rows `POST /rules/evaluate` walks (`selectRuleRows` on the fleet handle, `enabled && lifecycleStatus === "published"`, one `batchedLatestPointValues` batch) and applies the **streaming engine's** write policy — `AlarmRaiser.raise` with its default trace, `raisedBy: "rule_sweep"`, `notifyOnRaise` only when `raised.raised`, `isSampleFreshEnoughToRaise` bounding every raise, per-rule `try/catch`, one `UPDATE … WHERE id = ANY($1)` per organization under that organization's GUC; `RulesService.evaluateRule` extracted to `rule-evaluation.ts` as the one function both paths call; a loop-free `AlarmRaiseModule`; `AlarmRaiser` losing `AlarmsGateway` and instead publishing `pg_notify('bms_alarms', {type, alarmId, organizationId})` as the last statement of its transaction; `AlarmNotifyService` in `AlarmsModule` running `LISTEN bms_alarms` on the `F4.34` loop shape, reading the alarm by id on the fleet pool and calling `AlarmsGateway.broadcastCreated`; `lastRuleSweep { finishedAt, evaluated, raised, durationMs }` written to one Redis key and read into `GET /health` on both processes (contract in `packages/shared`); `bms_rule_sweep_duration_seconds` and `bms_rule_sweep_raised_total`; one `info` line per sweep with counts only; the fence updated so a worker that reaches `RulesModule`, `AlarmsModule`, or any API controller reddens.

No schema change, no migration, no new npm package, no `apps/web` change, no compose change.

**Out of scope, deliberately.** `F4.133` (`acknowledged`/`cleared` on `NOTIFY` — the listener is built so that row extends it; the two direct `emitScoped` calls stay); `F4.128` (the three API sweeps stay in `api`); a per-rule schedule or any cron grammar (decision 1); a retention policy for `bms.rule_executions`; a second worker replica (decision 7); the `F3.47` throttle (decision 9 — it bounds the route, and the sweep is not a caller of the route: `rules.controller.ts:181-198`); an "off" value for the interval (decision 6); a `/health` verdict on sweep staleness (the ADR names the field and no verdict — §2); a boot refusal on a missing credential key (Amendment 1 A5); any `AGENTS.md`, `docs/roadmap.md` or `docs/BACKLOG.md` edit — the closure and the `chore(agents):` sweep (§9.10, ADR 0064 Consequences).
