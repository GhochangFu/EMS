## 2. Build (one commit, both files)

**`rtus.service.rls.integration.spec.ts`**
- `SvcWithFixtures` gains `createdIds: string[]`; `assertRtuWriteLifecycleSurvivesRealRls` pushes `created.id` into it straight after `create` and returns `void`.
- `assertLifecycleWroteFourAuditRows(ownerPool, id)` — the `master.rtu.*` actions for the id, ordered by `created_at`, equal `[create, update, deactivate, reactivate]`. It throws if the id is missing, so a skipped lifecycle reports here instead of passing.
- `assertNoFixtureRowsRemain(ownerPool, ids)` — `{ audit, rtus }` counts for the ids equal `{ 0, 0 }`. The docblock records why the pool must be `bms_fleet`.

**`rtus.service.rls.integration.test.ts`**
- `removeRtuFixtures(ids)` — delete `bms.audit_log WHERE entity_id = ANY($1)`, then `bms.rtus WHERE id = ANY($1)` (the sibling's order: a failure between the two leaves the RTU row, which names its author by code).
- `it` #1 keeps the lifecycle and drops its immediate RTU delete. `it` #2 asserts the four audit rows. `it` #3 removes the fixtures and asserts none remain. `afterAll` calls `removeRtuFixtures` as the safety net for a run that failed before `it` #3.

Built inline on the session model (`build-operating-model.md` §2 step 4 fallback: the unit is two files and smaller than a cold hand-off).
