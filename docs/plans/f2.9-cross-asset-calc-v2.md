> Written 2026-09-04 by `plan-architect` (Fable) at the `F2.9` plan gate, after
> [ADR 0055](../adr/0055-cross-asset-aggregation-calc-grammar.md) was Accepted
> (`7665945`, PR #321) and after the start-gate scope ruling that created
> `F2.22` (PR #323).
>
> **The owner's rulings on the open questions are recorded in
> §"Open questions" as they are made, rather than rewritten away.** Where the

> precedent.

## Goal

Ship the `bms-calc-v2` dialect ADR 0055 rules, end to end: a
tokenizer/parser/evaluator extension in `packages/shared/src/calc-dsl/` that is
a strict superset of `v1` by construction; one nullable column
(`min_coverage_ratio`) on `bms.template_points`; the three guards replaced with
dialect-gated ones (web `validateDerivedFormula`, the `apps/api` Zod sibling
rule, the `F2.6` override path); the trigger rule (`v2` is `scheduled` only)
mirrored on every write path; a membership resolver that applies the owning
asset's `location_id` filter to **both** reference forms; one graph builder and
one topological sort called from the save-time detector and from the per-tick
sweep; coverage-ratio evaluation with the four rules of decision 11; and the
`apps/web` minimum the owner ruled on 2026-09-04.

After this row, `F2.8` can write `sum({kw} @site) / sum({kw} @group('IT_LOAD'))`
on a site-representative asset and the engine computes it.

**Out of scope, deliberately:** every authoring affordance — see
§"Deferred to F2.22", kept as one list so that row can be written from it. No
`estimatePue()` replacement (`F2.8`). No KPI (`kpis[].expression`) evaluation
under `v2` (open question Q3). No backfill and no rewrite of any stored `v1`
row. No per-asset override of `min_coverage_ratio` — the ADR puts the column on
`template_points` only. No hook in the asset-group / asset-move / template-migrate
write paths: ADR 0055 Q1c explicitly refuses that shape, and the tick is the
authority.

## Serial or parallel

**Serial, hands-on, on one feature branch, in two PRs.** The units form one
chain (`ast.ts` → tokenizer → parser → evaluator → host → guards → web), every
seam is one the next unit hangs off, and `F2.8` and `F2.22` both build against
this surface — the same reason §3 keeps enablers on the serial spine. The only
file-disjoint pieces (the migration, the `derived()` overload) are too small to
pay a worktree cold start. Model per unit is given in each task, per the
`build-operating-model.md` §2 ladder.

## Design decisions settled at this gate

These are the plan's own calls, not the ADR's. Each is reviewable.

1. **One parser, one tokenizer, one evaluator, each taking `{ dialect }` and
   defaulting to `"bms-calc-v1"`.** Not a second entry point. The superset
   property (decision 4) is then **structural**: every `v2` production is an
   *added* branch behind `if (dialect === CALC_DIALECT_V2)`; no `v1` branch is
   edited or removed, and a caller that passes nothing gets byte-identical `v1`
   behaviour — which is also how decision 3 ("`v1` keeps its meaning forever")
   is held by construction rather than by care. The property test (Task 3) is
   the tripwire, not the guarantee.
2. **Two new `TokenKind`s, two new AST node kinds.** Tokens: `scope` (the run
   `@site` / `@domain` / `@group`; `text` includes the `@`) and `string`
   (`'...'`; `text` excludes the quotes). A qualified reference stays a `ref`
   token with an extra optional `assetCode` field (`text` stays the point key),
   so `tokenWidth` needs a case but no third kind. AST: `CalcQualifiedRef
   { kind: "qref" }` and `CalcAggregate { kind: "aggregate" }` — new kinds on
   purpose, so every exhaustive consumer must decide, rather than an optional
   field that lets a consumer silently treat a cross-asset reference as a local
   one.
3. **`ParseResult.refs` keeps its meaning** (local point keys, first-appearance
   order, `v1`-identical) **and gains `crossRefs: CalcCrossRef[]`** — always
   `[]` under `v1`. Every existing caller that reads `refs` keeps working
   unchanged.
4. **The evaluator stays pure; the host resolves cross-asset values before
   `evaluate()` runs.** `evaluate(ast, inputs, crossInputs = EMPTY)` — a third,
   optional map keyed by `crossRefKey(node)` (canonical: `TX_01.kwh`;
   `sum(kw)@site`; `sum(kw)@group:IT_LOAD`). A separate namespace, so a local
   point key can never collide with a cross reference. ADR 0037 decision 1
   unchanged: no clock, no database.
5. **Aggregate functions: `sum` and `avg`.** `F2.8` needs `sum`; `avg` is the
   second shape a site ratio needs and costs one line. `min`/`max` stay
   scalar-only (`scope_not_allowed` inside them). `count` is excluded — a member
   count is not telemetry and interacts badly with the coverage rule. Open
   question Q2.
6. **Bounds.** `MAX_FORMULA_CROSS_REFS = 8` distinct cross references per
   formula (`too_many_cross_refs`), beside the unchanged 20 local refs. An
   aggregate's member set is **not** capped: ADR 0037 decision 7 refused a
   per-tick cap because a silently computed subset is worse than being slow, and
   the same reasoning holds per aggregate. What bounds the cost instead: one
   batched `DISTINCT ON (asset_id, point_key)` read per sweep for every member
   pair (not one query per member), the existing `INPUT_READ_BOUND_SECONDS` time
   bound on that read, and a gauge `bms_api_calc_aggregate_members_max` so
   growth is visible before it hurts.
7. **Sweep ordering lives in `runScheduledSweep` (`calc-scheduler.service.ts`),
   with the pure pieces in a new `calc-graph.ts`.** The order is applied to the
   whole due set (`v1` nodes have no edges and sort first), each formula keeps
   its own `try`/`catch`, and the results of a layer are placed in an in-memory
   `computedThisTick` overlay consulted before the database, so a same-tick chain
   propagates within the tick while the write stays one batch. Cycle members are
   refused (`dependency_cycle`); formulas *downstream* of a cycle are **not**
   refused by the ordering pass — they read the stored value, and decision 5's
   staleness rule refuses them honestly once it ages out. Open question Q6.
8. **Membership resolution is a fleet read, not cached, once per sweep.**
   `CalcScopeService` on `FLEET_DRIZZLE`, for the same reason
   `CalcDefinitionsService` records: a cross-organization system read with no
   tenant actor (ADR 0043 Amendments 2 and 3). It runs every tick so the detector
   sees the membership set as it is — the ADR's stated reason for
   evaluation-time authority. "Declares the referenced point" = the asset's
   pinned template declares it **or** the asset has an active `asset_points` row
   for it (a hand-created asset with a mapped `kw` has real telemetry and would
   otherwise be silently missing from a site sum); `active = false` assets are
   not members. Open question Q5.
9. **Where a membership-induced cycle surfaces** — the one thing ADR 0055
   decision 8 defers to this plan gate. Three layers, cheapest first:
   1. the counter `bms_api_calc_skipped_total{reason="dependency_cycle"}` (the
      ADR's stated minimum);
   2. one `warn` log line per **transition** into or out of the cyclic set,
      naming asset ids and point keys, never formula text;
   3. **the per-asset calc-points page** (`GET /admin/assets/:assetId/calc-points`,
      `F2.6`) gains a `runtime` field per derived point —
      `{ lastOutcome, lastSkipReason, at }` — fed by an in-memory registry both
      hosts write to, and rendered as one status pill beside
      `effective.calcTrigger` on `asset-points-page.tsx`.

   The reason it is that page: an operator who moved an asset into a group looks
   at *that asset*, not at a formula editor and not at Prometheus. Layer 3 is
   Task 16 and is the one unit the owner can strike to reduce scope; layers 1
   and 2 then stand alone. Open question Q4.
10. **The qualified separator.** `{CODE.key}` splits at the **first** `.` under
    `v2`. Point-key codes and asset codes are both unconstrained strings today
    (`createPointKeyBodySchema.code` is `z.string().min(1).max(128)`; the
    tokenizer spec even asserts `{a.b-c/d e}` is one `v1` ref), so a `v1`
    formula naming a point key that contains `.` would change meaning under
    `v2`. No seeded or stock code contains a `.` (scanned). This plan scopes
    decision 4's property to point keys without `.`, states that in the property
    test, and raises the catalog charset as open question Q1 — constraining
    `point_keys.code` is a separate ruling this row must not make.
11. **`templateKpiSchema.dialect` is not widened in this row**, although
    decision 2's sentence names it. Nothing evaluates a KPI cross-asset
    reference (ADR 0037 §"Not in this ADR": KPI evaluation is read-time, from
    local values, `F2.5`/`F3.1`), and `pointKeys`' two-way cross-check has no
    defined meaning for `sum({kw} @site)`. `F2.8` needs a derived **tag**, not a
    KPI. Open question Q3 — if the owner rules the other way, it is one added
    Task 8b.

crosses packages, the two halves are one commit** (named below), so every commit

added by hand to the root `typecheck:tests` script.

arrays of *template* points and **never sees an asset's overrides**. Migrate
consumes `delta.refusals` alone, and a derived point's `formula`/`formulaDialect`

not close this. The `minCoverageRatio` half of finding 31 is the same shape with
a quieter failure: a version bump that changes only the ratio yields an empty
`derivedChanged`, `migration-preview` reports "no changes", and the migrated
asset picks up the new ratio at once — which under decision 11 can move a
formula from computing to fail-closed with no operator ever seeing it.

55. **Finding 30 is ruled: the save-time path resolves without counting.**
    `getAllDefinitionsFresh()` calls `reload()`, which counts every skip through
    `MetricsService`, so a cycle check on a template or override save moves
    `bms_api_calc_skipped_total`. An operator reads that counter as "the engine
    refused to compute N times"; if an author's keystroke also moves it, the
    number means two things at once and is readable as neither. ADR 0037
    decision 9 requires that no **evaluation** skip is silent — a validation
    read is not an evaluation, and counting one does not serve the decision it
    appears to serve. `reload()` therefore takes a flag (or splits) so the cache
    refresh counts and the detector's read does not. No shipped refusal changes;
    only the counter stops lying.
56. **The plan's `assertQualifiedReferenceIsConfinedToLocation` asserts a
    refusal that does not exist** (found during Task 12; the substitution is
    accepted). Task 12's spec says `{W_CODE.kw}` where W is at another location
    is "refused as an unknown reference". It is not: `validateFormula`
    (`packages/shared/src/calc-dsl/parser.ts`) iterates

    **never** checked against `knownRefs`. Verified directly on the branch.

    such a code to `null`, `buildCalcGraph` draws no edge, and Task 13 reports
    `unknown_asset_reference` at evaluation time. What is missing is only the

    §"Deferred to F2.22" item 9.

    Task 12 substituted a controlled pair — two assets on the same template with

60. **The `computedThisTick` overlay carries `bucketTimeMs(nowMs, interval)`,
    not `nowMs`** (decided at the Task 13 gate; the plan leaves it open and it
    is not a free choice). An aggregate member computed earlier in the same
    sweep is classified by the same `classifyInput` as any other member
    (decision 11's "like any other"), and `classifyInput` needs a `timeMs` — but
    an overlay entry has no stored row yet.

    It must carry the timestamp the **write** will carry, which is the bucketed
    one (ADR 0037 decision 8). The overlay is a read-through of a write that is
    about to happen, not a second freshness claim about the same number. Take
    `nowMs` instead and a same-tick read and a next-tick read of *the same
    value* disagree: fresh now, possibly stale one tick later, with nothing in
    the data explaining the difference.

    The cost is real and is the right cost. A downstream formula whose
    `max_input_age_seconds` is tighter than its input's own interval — a 60s
    budget over a 300s-interval input — reads `stale_input`, and that is
    decision 5 reporting a genuine misconfiguration rather than the overlay
    hiding it. `nowMs` would paper over exactly that case, quietly, and only in
    the tick where the member happened to be recomputed.
61. **Every Task 13 refusal goes BELOW `lastRunMs.set`, on the same side of that

    once per due window, and `bms_api_calc_skipped_total` stops meaning
    "refused per due window". This binds `dependency_cycle`,
    `membership_unresolved`, `coverage_below_floor`, `no_members`,
    `unknown_asset_reference` and `coverage_ratio_out_of_range` alike.
