## 1. Goal

`/energy` gets a filter (organization, then one or more locations of that organization's tree, a parent including its children), seven ranges (Today, 24 h, 7 d, 30 d, This month, 1 y, custom from/to), a compare with the previous period of equal length, and four KPI tiles with the change against the compare period: total kWh, peak kW with its time, average PF, and the rollup level the server chose. The server picks the level from the range, resolves "Today" and "This month" in the site's or organization's timezone, and reads only the assets the caller may read, with a "partial — your access covers N of M sites" note. One new read route carries the whole shape, so a later row (F4.299, F4.302) reuses it; no UI "call twice and diff".

**Out of scope.** Site ranking, trend stacked by site, heatmap, abnormal list (F4.299). Export, pin, share link, schedule (F4.303). Floor area (F4.304). Any change to `GET /reports/energy/preview`, the three export routes, the PDF, or the copilot `get_energy_report_preview` tool. A new rollup level or retention change. kWh per m². A kW-weighted PF.

## 2. The shape (decisions the plan makes)

The owner ruled "F4.298 owns the energy preview change"; the drafter applied that ruling to the new `/reports/energy/view` route, and the owner confirms it at ADR 0108 review (§2.1, §4.1).

**Query** (`energyViewQuerySchema`, `.strict()`, no body). It is registered in the `QUERY_SCHEMAS` map of `apps/api/src/openapi/strict-body-ledger.spec.ts` (lines 398-454) and gets **no** `STRICTNESS_LEDGER` entry in `apps/api/src/testing/strict-body-ledger.data.ts` — the walker reads `BODY_SCHEMAS` only, and `testTheLedgerHasNoEntriesForNodesThatAreGone` refuses an entry for a query node (the `mappingSheetQuerySchema` precedent, docblock at `strict-body-ledger.spec.ts:385-397`). ```

Cross-field rules (custom needs both instants, `from < to`, length ≤ `MAX_WIDGET_WINDOW_MINUTES` = 525,600 min = 365 d) live in the service as a 400, the `energyReportRange` precedent (`reports.service.ts:42-59`), not in a `superRefine`.

**Response** (`energyViewSchema`):

```
organizationId, timeZone, generatedAt
level:   "1m" | "5m" | "1h" | "1d"     the relation read (levelForRange)
bucket:  "1m" | "5m" | "1h" | "1d"     the display bucket of `series`
current: EnergyViewPeriod
compare: EnergyViewPeriod | null       null when compare was not asked
topConsumers: EnergyTopConsumer[]      current period only
partial: { readableSites, selectedSites } | null   null for a global admin
```

`EnergyViewPeriod` = `{ from, to, durationHours, hasData, totalKwh, peakKw, peakAt: string|null, avgPf: number|null, pueEstimate, indicativeCost, tariffPerKwh, currency (all nullable as today), sourceTotals: energyReportSourceTotalsSchema, series: energySourceMixPointSchema[] }`. `compare.series` is included (F4.299's dashed line needs it; one shape).

**Filter options** for every role: `GET /api/v1/reports/energy/filter-options` → `{ organizations: [{id, code, name}], locations: [{id, name, parentId, organizationId}] }`, the caller's readable set. `/admin/organizations` and `/admin/locations` refuse `operator` and `viewer` (`requireMasterDataUser`, `access-control.service.ts:811`), and `AccessLocation` from `/auth/me` carries no `organizationId`. No timezone goes to the client: the server resolves presets.

**Organization rule.** `locationIds` named → their one organization (`LocationAssetScopeService.readableAssetIdsInLocations`). Order (ADR 0108 §2.2): the locations and their grant check resolve first, so a location of another organization that the caller cannot read is a 403; only then is the organization compared, so readable locations that do not belong to the given `organizationId` are a 400. No `locationIds` and an `organizationId` → the caller must read it (`readableOrganizationIds` null or includes it, else 403) and the assets are `readableAssetIdsInOrganization`. Neither → if the caller reads exactly one organization, that one; a global admin with none is a 400 "organizationId is required". A fleet has no timezone, so there is no fleet-wide view.

**Asset-id bound (telemetry has no RLS).** Every read the view calls takes `assetIds: readonly string[]` — never `null`, never optional — and filters with `a.id = ANY($n::uuid[])`. The two new statements (`energyPeriodRead`, `averagePf`) have **no** `$n IS NULL OR` leg. The moved top-consumers SQL keeps its leg for the preview (byte-for-byte move, ADR 0108 decision 2.10), so the view reaches it only through `viewTopConsumers`, whose parameter type is the non-null list. An empty list returns the empty result in TypeScript before any statement runs (`hasData: false`, zero totals, `avgPf: null`, `topConsumers: []`). A global admin (`readableAssetIds === null`) never reaches a read with "no filter": the service always resolves one organization first (the rule above), and `readableAssetIdsInOrganization(jwt, organizationId)` (`access-control.service.ts:338`) turns `null` into that organization's explicit id list.

**What leaves the server about unreadable sites.** `partial` carries two counts only. No id, name or code of a location or asset the caller cannot read appears anywhere in the response (owner ruling: the "N of M" text tells a scoped user the size of the organization, accepted; the ids are not).

**Timezone.** The chain, per ADR 0108 ruling 4.3:
- Exactly one location named → `locations.timezone ?? organizations.timezone`.
- Two or more locations named, or none (an organization view) → `organizations.timezone`, even when every named location carries the same zone.
- `organizations.timezone` is `NOT NULL DEFAULT 'UTC'` (`packages/db/src/schema/bms-schema.ts:52`); `locations.timezone` is nullable (`:126`).

Trap: `isValidTimeZone("UTC")` is **false** (no `/`, `packages/shared/src/contracts/report-writes.ts:59-65`), so `report-period.ts`'s `formatterFor` (line 89) throws on it. `zoneForArithmetic` maps `UTC` to `Etc/UTC` for the arithmetic, and the response reports `timeZone: "UTC"`. Any other stored value that fails `isValidTimeZone` falls to the next link of the chain (location → organization → `Etc/UTC`), never a 500. The chain is one pure function, `packages/shared/src/contracts/time-zone-chain.ts` (U1), because the F4.297 asset history page uses the same rule (ADR 0108 §1.9). ADR 0108 records this mapping as a decision and as a verification item.

**Ranges.** Presets end at `now`. Today = `[toInstant(localDateOf(now, tz), 00:00, tz), now]`; This month = `[first local day of the month 00:00, now]`; 24h/7d/30d/1y = trailing from `now` (1 y = 365 × 24 h). Compare = the equal-length period ending at `start`. Bounds follow the existing inclusive convention: `end = nextStart − 1 ms`, SQL `bucket >= $start AND bucket <= $end`, so the two periods never share a bucket and `perAssetEnergy` / `windowedPueRatio` work unchanged.

**Level and bucket.** `displayBucketFor(hours)`: ≤ 3 h → `1m`; ≤ 48 h → `5m`; ≤ 45 d → `1h`; else `1d`. The read level is the bucket, except `1d` reads `_1h`: `point_values_1d` buckets are UTC days (migration 0027:104-111), so a zone day is `time_bucket(INTERVAL '1 day', bucket, $tz::text)` over `_1h` — the "several source rows fold into one output bucket" case `avgExpr` is built for (`point-aggregates.ts:104-110`). `levelForRange({ start: <the older period's start>, granularity })` is called once for both periods, so one level serves the whole view; if it coarsens past the bucket, bucket = level. Peak kW is always `MAX` over read-level buckets, so a 1 y view still reports the peak hour. Half-hour zones (ADR 0108 decision 2.12, owned by this row): only a `1d` bucket is realigned to the local day; `1m`, `5m` and `1h` buckets stay UTC-aligned, so in `Asia/Kolkata` an hourly bucket spans two local half-hours. The view does not realign an hour; it shows the level, the bucket and the zone in the rollup tile (`levelLabel`).

**KPIs.** Total kWh = Σ per read-level bucket of Σ per-asset mean kW × `bucketHours(level)` (as today). Peak = `MAX(total_kw)` with its bucket (`array_agg(bucket ORDER BY total_kw DESC, bucket ASC))[1]`). Avg PF = `avgExpr()` over `point_key = 'pf'` rows of the scoped assets at the read level, joined to `bms.assets`; `null` when no row (the simulator emits `pf`, `apps/sim/src/index.js:157,437`). `hasData` = at least one `kw` bucket. The change figure is computed on the web only when both periods have `hasData`.

**Partial.** `selectedSites` = the subtree of the named locations (`expandLocationSubtrees`), or all active locations of the organization when none is named; `readableSites` = those in `readableLocationIds`; `null` when `readableLocationIds` is `null`.

**Departure from ADR 0025 "Settled at the gate".** The reports path reads `_1h` by owner decision (`docs/adr/0025-aggregate-read-conversion.md:440-452`) because the export is a client deliverable. The view is a screen, not the CSV, and reads `_1m`/`_5m` for ≤ 48 h. ADR 0108 must record this.
