# F4.176 — a batched latest-value read for the schematic provider

Plan written 2026-09-30 by `plan-architect` (Fable) at step 3. **Authority:**
`docs/BACKLOG.md` row `F4.176` and `docs/adr/0074-domain-dashboard-parity.md`
Amendment 2. Hold rule: merge by 2026-09-30 end of day, or hold the branch.

## Goal

Add `GET /api/v1/telemetry/points/latest` (asset ids 1–50, point keys 1–64,
`windowMinutes` 1–60 default 15, 403 for the whole request on one foreign id,
one SQL statement with a plan-time constant lower bound). Make
`SchematicTelemetryProvider` hydrate from it in ⌈N/50⌉ calls and drop the
`prefetchQuery` loop. The SMOC site view goes from 2,924 `/recent` reads per
mount to 1 read.

**Out of scope:** removing `useTelemetryLive` or `/recent`; any change to
`use-dashboard-telemetry.ts`; the F3.71 `surface-*` classes; the at-instant
read; a migration or a dependency; the backlog close (a separate docs PR after
merge).

## Design decisions

1. **Query shape** `?assetIds=<uuid>&assetIds=…&pointKeys=kw&…&windowMinutes=15`,
   repeated parameters folded by `foldRepeatedQueryValue` (43 ids pass the `qs`
   `arrayLimit` of 20 and arrive as an object). UUID shape is checked in the
   schema. A point key is `z.string().min(1).max(128)` — the
   `varchar(128)` of `telemetry.point_values.point_key`.
2. **Response** `{ items: TelemetryReading[] }` through the existing
   `itemsOf(telemetryReadingSchema)`. Items pass to `applyReading` unchanged.
3. **SQL** on `TENANT_POOL`: `SELECT DISTINCT ON (asset_id, point_key) … WHERE
   asset_id = ANY($1::uuid[]) AND point_key = ANY($2::text[]) AND time >
   $3::timestamptz ORDER BY asset_id, point_key, time DESC`. `$3` is computed in
   the service as now − `windowMinutes`. An unnamed statement is planned at
   Bind with the value known, so chunks are excluded at plan time (`now() - $1`
   cannot fold — ADR 0074 Amendment 1 item 6). **Gate:** planning ≤ 100 ms with
   the 43 × 34 SMOC set and no startup exclusion. Fallback: an inlined ISO
   literal.
4. **Provider:** chunk the tracked ids into 50s, `Promise.all` the chunks, each
   in its own `try/catch` returning `[]`; seed every tracked id with
   `emptySlice()`; `applyReading` each item whose asset is tracked. Delete the
   prefetch effect and the imports it alone used.

## Units (serial, one session, Opus)

- **U1 contract** — `pointsLatestResponseSchema` and `PointsLatestResponse`;
  envelope spec (a reading list parses; a null value is refused). Build
  `@bms/shared` before U2/U3.
- **U2 API** — schema spec through Express's query parser (1/21/50/51/0 ids, a
  non-UUID, 64/65 keys, window absent → 15, 0/1/60/61/12.5, unknown key);
  controller spec (one foreign id → 403 and no read; admin reads; parsed values
  reach the service; 51 ids → 400 and no read; `{ items }` returned);
  integration spec (T−5m returned; T−30m only → empty; latest of two chosen; an
  unsampled pair absent beside a sampled one; an unasked asset not returned);
  OpenAPI registry and strict-body ledger count; the plan measurement.
- **U3 web** — client spec (path, `assetIds`, `pointKeys`, default window, a
  body without `items` throws); provider spec rendering the **real** provider
  with every fetch stubbed and `socket.io-client` mocked: zero `/recent`
  fetches; 51 codes → exactly 2 `/points/latest` calls of ≤ 50 ids covering all
  51; a returned reading shows its value; an absent pair stays empty. **Red on
  the base commit first.** Then the provider change and the `live-svg/README.md`
  prose line.

## Risks

- Planning time with `$3::timestamptz` — the measurement gate catches it.
- One failed chunk must not reject the others — per-chunk `try/catch`.
- A stale `packages/shared/dist` — build shared first.
- An unstubbed fetch in the provider spec reaches :4000.
