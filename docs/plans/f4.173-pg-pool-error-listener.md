## 1. Goal

When Postgres ends an idle pooled connection (restart, failover,
`pg_terminate_backend`, an idle-timeout proxy), `pg.Pool` emits `'error'`; with
no listener Node throws and the process exits. Attach one listener per pool that
logs the pool name and `err.message` — never the error object, never the
connection string (AGENTS.md §9 rule 6) — and does not exit, so the next query
opens a fresh client. The api/worker gate boots the real `DatabaseModule`
providers, ends only the test's own backend, and asserts the logged line and the
recovery. The sim gets the same one-block fix with a static gate, and its
runtime survival is proved at step 6.

## 3. Build order (TDD)

### T1 — the api gate, red first

Create `apps/api/src/database/database-module-pools.integration.spec.ts`
(assertions) and `apps/api/src/database/database-module-pools.integration.test.ts`
(wrapper; follow `apps/api/src/auth/access-control-rls.integration.test.ts`).

Wrapper: `requireIntegrationDb({ item: "F4.173", connection: "owner", … })`.
`beforeAll` derives `DATABASE_URL_{AUTH,TENANT,FLEET}` with `asRole` when unset
(`resolveDatabaseUrls` reads `process.env` and has no injection point — say so),
then boots the real module with
`NestFactory.createApplicationContext(DatabaseModule, { logger: false, abortOnError: false })`
and gets the three pools by token. **Fallback if the context refuses to boot
under esbuild:** read `Reflect.getMetadata("providers", DatabaseModule)`, pick the
entry whose `provide` is the token, and call its `useFactory()` — still the
module's own factory. Record which path was taken in the docblock. `afterAll`
ends the pools, then closes the context.

Spy: `vi.spyOn(Logger.prototype, "error")` per case; never assert on a count.

Spec exports, one claim per `it()`, each case performing its own terminate:

- `endIdleBackend(pool, url)`: `select pg_backend_pid()` through the pool (the
  client is idle once the promise resolves), then a separate `pg.Client` on the
  same URL runs `pg_terminate_backend($1)` on that pid. Never filter by role or
  `application_name` — the database is shared.
- `assertIdleClientLossIsLoggedForPool(name, …)`: `vi.waitFor` a logged line
  matching `^${name} pool: .*terminating connection due to administrator command`.
- `assertPoolServesTheNextQuery(name, …)`: terminate, wait for the line
  (synchronisation only), then `select 1` succeeds on the same pool.

Six cases: two per pool. The docblock says the spy assertion, not the absence
of an unhandled error, is the gate — with no listener vitest can report an
"Unhandled Error" while the `it()` stays green.
