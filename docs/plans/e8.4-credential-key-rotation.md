# E8.4 — Credential key rotation and unconfigured-key visibility (ADR 0062)

Branch `E8.4-credential-key-rotation`, base `main@13b32232`, ADR committed at
`4031534e`. Planned on Fable 2026-09-10. ADR 0062 is **Accepted**; the step-2
gate holds.

## 1. Goal

Implement ADR 0062 decisions 1–9 and 11: a shared key resolver with a two-key
window (`CREDENTIAL_ENCRYPTION_KEY`, `CREDENTIAL_ENCRYPTION_KEY_PREVIOUS`,
`CREDENTIAL_ENCRYPTION_KEY_VERSION`), used by both `CredentialCryptoService` and
the ingest's `rtu-config.js`; `decrypt` selects a key by the stored version and
refuses any other; the version travels with every ciphertext carrier (RTU config
row, channel secret row, onboarding draft blob, ingest binding SQL); both
applications refuse to boot on a dead window; a `pnpm --filter api
rotate-credentials` command re-encrypts both tables as `bms_fleet`; the
onboarding merge stops claiming a credential it did not store; and the ingest
names which credential it actually uses.

No schema change, no new npm package, no gate that depends on a deployed key.

**Out of scope, deliberately.** Retiring the `MQTT_USERNAME`/`MQTT_PASSWORD`
fallback (decision 10, blocked on data — `E8.4` stays open on it); a three-key
window; a JSON key map; pino `authorization` redaction (E8.3 deferred it here,
ADR 0062 does not take it); binding a draft credential to an endpoint rather
than an RTU code; any `AGENTS.md`, `docs/BACKLOG.md` or `docs/roadmap.md` edit
(separate `chore(agents):` PR, §9.10); exposing plan warnings on the ingest
health endpoint. API contract work is **N/A** — `credentialsSet` already exists
in the onboarding contract, `credentialSource` is ingest-internal, and the
rotation report is CLI stdout.

## 2. Facts the plan rests on

Measured 2026-09-10 in this worktree. Each one changed a design choice.

- **`apps/api` compiles with `moduleResolution: "node"` (node10), which ignores
  the `exports` map.** `packages/shared/src/index.ts:60-66` already records
  this. So the API imports the resolver from the **barrel** and the ingest
  (NodeNext) imports **`@bms/shared/credential-keys`**. One file, two routes.
- **`packages/shared` has no `@types/node` reachable.** The root
  `node_modules/@types` holds only eslint; the package's own holds `zod` and
  `typescript`. Any `Buffer` or `process` reference fails
  `tsc -p packages/shared/tsconfig.json` and `pnpm --filter @bms/shared build`.
  The resolver is therefore written over `Uint8Array`, takes an injected base64
  decoder, and takes `env` as a parameter. This also keeps the barrel safe for
  `apps/web`, which bundles it.
- **`check-dependency-adr.mjs` denies only added lines shaped like a dependency
  specifier** (`scripts/checks/dependency-spec.mjs`). An `exports` entry or a
  `scripts` entry does not match, so the Edit tool works on both manifests;
  `pnpm pkg set` is the fallback.
- **JSDoc-typed parameters on a `.js` function make arity compiler-checked for
  TypeScript callers** under `allowJs`, even with `checkJs: false` — probed:
  `TS2554: Expected 3 arguments, but got 2`. This is what turns the
  `main.ts → decryptCredentials` forwarding into a gated claim.
- **`scripts/checks/style-hygiene.mjs:39` rejects `console.log/debug/info`** on
  added lines. The CLI writes with `process.stdout.write`.
- **The API has no central env validator.** `main.ts` calls
  `NestFactory.create(AppModule)` with `abortOnError` defaulting true and
  providers instantiated eagerly, so a provider constructor that throws *is* a
  refused boot. `DatabaseModule` already uses this shape. The ingest's validator
  is `readHostConfig(env)` in `apps/ingest/src/host/config.ts`.
- **`tests/f4.108-service-parses-are-guarded.test.ts:112` allow-lists the one
  `JSON.parse` in `credential-crypto`.** Keep exactly that one; the rotation
  walk calls `decrypt` and never parses.
- **No `tests/` file needs to change**, so neither the root `typecheck:tests`
  list nor `.github/workflows/ci.yml` needs an edit. Every new spec lives under
  `apps/**` or `packages/**` and the existing vitest projects discover it.
- **Coverage thresholds `73.4 / 69.4 / 75.1 / 73.5`** against a last measurement
  of `74.14 / 70.17 / 75.89 / 74.22`. The only deliberately uncovered new lines
  are the CLI entry (~30) and its module (~10). **Never lower a threshold.**
- `withRollback` exists at `alarm-kb.integration.spec.ts:28`; services accept
  `tx: BmsTx | BmsDb` with precedent at `dashboard-point-scope.ts:49`.
- `fleet-read-wiring.spec.ts`'s `injectedToken` reads
  `SELF_DECLARED_DEPS_METADATA`, which `@Inject()` writes without
  `emitDecoratorMetadata`, so a DI token can be pinned without a Nest module.

## 3. Serial, not parallel

E8.4 is not a ⭐ enabler, but **Task 1 defines the seam every later task hangs
off**, so it is built first and hands-on. Afterwards the API chain (2–4, 6) and
the ingest chain (5) touch disjoint files, but each is about six files and the

**Task 6 Fable** (production code connecting as `bms_fleet`/BYPASSRLS),
**Tasks 2, 4, 5 Opus**, **Tasks 3 and 7 Sonnet**.

## 4. Build order and the shared-package rule

`pnpm build` runs shared → db → api → web → ingest, and both apps consume
`packages/shared/dist`. Vitest resolves `@bms/shared` to `dist` too. Therefore:

- After Task 1's implementation and **before any typecheck or test** in
  `apps/api` or `apps/ingest`, run `pnpm --filter @bms/shared build`. Re-run it
  after every later edit to `credential-keys.ts`. **A stale `dist` makes every
  dependent spec assert against the old resolver and looks like a code bug.**
- Run `pnpm typecheck:tests` after every signature change (Tasks 2, 4, 5).
  `pnpm build` excludes specs and `pnpm test` strips types; only that script
  compiles a spec against the real types (§4.6).
- Filtered runs use the root runner:
  `pnpm exec vitest run --project <api|ingest|shared> <name-filter>`.
  `pnpm --filter api test` exits 0 having run nothing.
- Integration specs need `DATABASE_URL`, e.g.
  `postgres://bms_owner:bms_owner_dev@localhost:5433/bms` — the compose override
  remaps Postgres to 5433 on this machine. They fail closed under `CI` without
  it.

**Public surface — the seam. Transcribe exactly.**

```ts
export const CREDENTIAL_KEY_ENV = {
  current: "CREDENTIAL_ENCRYPTION_KEY",
  previous: "CREDENTIAL_ENCRYPTION_KEY_PREVIOUS",
  version: "CREDENTIAL_ENCRYPTION_KEY_VERSION",
} as const;
export const CREDENTIAL_KEY_BYTES = 32;
export type CredentialKeyEnv = { readonly [name: string]: string | undefined };
export type Base64Decoder = (base64: string) => Uint8Array;
export type LoadedCredentialKeys = {
  readonly currentVersion: number;      // >= 1; defaults to 1; present even when `current` is null
  readonly current: Uint8Array | null;  // null = unconfigured
  readonly previous: Uint8Array | null; // null = no rotation window
};
export class CredentialKeyConfigError extends Error { override readonly name = "CredentialKeyConfigError"; }
export class CredentialKeyVersionError extends Error {
  override readonly name = "CredentialKeyVersionError";
  constructor(readonly storedVersion: unknown, readonly loadedVersions: readonly number[]);
}
export function resolveCredentialKeys(env: CredentialKeyEnv, decode: Base64Decoder): LoadedCredentialKeys;
export function loadedKeyVersions(keys: LoadedCredentialKeys): readonly number[];
export function keyForVersion(keys: LoadedCredentialKeys, storedVersion: unknown): Uint8Array;
```

**`resolveCredentialKeys`, in order.**

1. An empty string is unset, for all three variables — compose passes
   `${VAR:-}`.
2. `VERSION`: unset → `1`; else must match `/^\d+$/`, be a safe integer and be
   `>= 1`, else `CredentialKeyConfigError` naming the variable and the value.
3. `KEY`: unset → `current: null`; else decode; a length other than 32 →
   `CredentialKeyConfigError` ("must decode to 32 bytes") — **ruling 1**.
4. `PREVIOUS`: unset → `null`; else decode; wrong length →
   `CredentialKeyConfigError`; set while `currentVersion === 1` →
   `CredentialKeyConfigError` whose message contains `version 0` (decision 5);
   set while `KEY` is unset → `CredentialKeyConfigError` — **ruling 2**.

**`keyForVersion`.** A non-integer `storedVersion` (`null`, `NaN`, a string) →
`CredentialKeyVersionError`. `=== currentVersion` → `current`, or
`CredentialKeyConfigError("CREDENTIAL_ENCRYPTION_KEY is required")` when
`current` is null (today's message). `=== currentVersion - 1 && previous !==
null` → `previous`. Anything else → `CredentialKeyVersionError(stored,
loadedKeyVersions(keys))`, message `credential key version <stored> is not
loaded (loaded: <a, b>)`. Integers only, never bytes. **There is no path that
tries a second key.**

**Tests first.** One exported function per claim, each its own `it()`. The
decoder is a table — `decode("alpha")` → 32 bytes of `0x01`, `decode("beta")` →
32 of `0x02`, `decode("short")` → 16 — so the spec never needs `Buffer` or
`atob`.

| Assertion | Reddens when |
| --- | --- |
| unset env → `{ currentVersion: 1, current: null, previous: null }` | the default version is not 1 |
| all three `""` → same as unset | the empty-string check is dropped |
| `KEY=alpha` → `current` equals `decode("alpha")` byte-for-byte (**positive control** for the decoder wiring), `previous` null | the resolver returns a fixed key or ignores env |
| `KEY=alpha, PREVIOUS=beta, VERSION=3` → version 3, `previous` equals `decode("beta")` | the previous key is ignored or the version is not parsed |
| `VERSION` in `["0","-1","abc","1e3","1.5"]` → `CredentialKeyConfigError` naming the variable (table; the failing input is in the message — a loop of asserts reddens on its first failure only) | the digit regex or the `>= 1` bound is dropped |
| `KEY=short` → error containing `32 bytes` | the current-key length check is dropped (**ruling 1**) |
| `KEY=alpha, PREVIOUS=short, VERSION=2` → error | the previous-key length check is dropped |
| `KEY=alpha, PREVIOUS=beta`, VERSION unset → error containing `version 0` | decision 5's guard is dropped; the row above is its positive control |
| `PREVIOUS=beta` alone → error | **ruling 2** is dropped |
| `loadedKeyVersions` → `[3,2]` with a previous key, `[3]` without | the list includes `v-1` with no previous key — the error message would then lie |
| `keyForVersion(keys{3:alpha,2:beta}, 3)` is alpha; `(…, 2)` is beta (two `it()`s) | the slots are swapped |
| `(…, 1)` throws `CredentialKeyVersionError`, `storedVersion === 1`, `loadedVersions [3,2]`, message contains `"1"` and `"3, 2"` | an unknown lower version falls through to the previous key |
| `(…, 4)` throws the same class | an unknown higher version falls through to current |
| `(…, null)`, `(…, NaN)`, `(…, "3")` each throw (table, input in the message) | a loose comparison or a `Number()` coercion lets a non-integer through — **NaN makes every `===` false, so this must be asserted, not reasoned** |
| `keyForVersion({1, null, null}, 1)` throws `CredentialKeyConfigError` containing `is required` | an unconfigured current slot returns `null` |
| `keyForVersion(keys{3:alpha, previous null}, 2)` throws with `loadedVersions [3]` | `previous === null` is not checked before the `v-1` branch |

Use `err.name === "…"`, never `instanceof`, in every spec importing these
classes under vitest — F4.108: two module instances.

**Steps.** Spec and wrapper → red. Implement → green. `pnpm --filter @bms/shared
build` and confirm `dist/credential-keys.{js,d.ts}`. `pnpm typecheck:tests` (the
shared leg proves no Node global crept in). Commit.

## 10. Task 6 — `rotate-credentials` (decisions 6, 11)

**Files.** New `credential-rotation.service.ts`, `credential-rotation.module.ts`,
`rotate-credentials.cli.ts`, `credential-rotation.integration.spec.ts`/`.test.ts`;
one line in `fleet-read-wiring.spec.ts`; a `scripts` entry in
`apps/api/package.json`.

```ts
export type RotationTableCounts = { scanned: number; rotated: number; skipped: number; raced: number; failed: number };
export type RotationFailure = { table: "rtu_connection_configs" | "notification_channels"; id: string; storedVersion: number | null; error: string /* err.name only */ };
export type RotationReport = { currentVersion: number; rtuConnectionConfigs: RotationTableCounts; notificationChannels: RotationTableCounts; failures: RotationFailure[] };

@Injectable()
export class CredentialRotationService {
  constructor(@Inject(FLEET_DRIZZLE) private readonly fleetDb: BmsDb, private readonly crypto: CredentialCryptoService) {}
  run(db: BmsTx | BmsDb = this.fleetDb): Promise<RotationReport>;
}
```

The `@Inject(FLEET_DRIZZLE)` site carries the §4.3 named reason quoted from the
ADR: rotation is fleet-wide, and an RLS-bound connection would skip every other
organization's rows and still report success.

**The walk selects on ciphertext, never on version** —
`where credentials_ciphertext is not null` / `where secret_ciphertext is not
null`. Per row: `scanned++`; already at the current version → `skipped++`; else
decrypt at the stored version, re-encrypt, and update with a **compare-and-set**
clause (`where id = $id and ciphertext = $old and version = $oldVersion`,
`isNull` for a null channel version) — `rowCount === 1` → `rotated++`, else
`raced++`; any throw → `failed++` with `err.name` only, and continue.
`updated_at` is **not** touched (**ruling 3**). No `JSON.parse` here.

The CLI imports `../load-env`, creates an application context, writes the report
