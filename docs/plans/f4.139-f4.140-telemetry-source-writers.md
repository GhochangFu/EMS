## Goal

Every path that sets `assets.rtu_id` also sets `assets.meta.telemetrySource`
from the owning RTU, using the exact predicate `F4.59` shipped in
`RtusAdminService.update` (`apps/api/src/admin/rtus/rtus.service.ts:328-339`):
`ingestEnabled && (INGEST_PROTOCOLS has sourceType || a rtu_connection_configs
row exists)` → `"mqtt"`, else `"catalog"`. The predicate moves to one function;
`RtusAdminService.update`, `AssetsAdminService.create/update`
(`apps/api/src/admin/assets/assets.service.ts:138-272`) and
`OnboardingCommitService.commit` (`apps/api/src/admin/onboarding/onboarding-commit.service.ts:362-383`)
call it. The meta bag is merged, never replaced.

**Out of scope:** a view or generated column (the "larger fix" `F4.59` declined);
`F4.137`/`F4.138`; `asset_points.rtu_id` (the ingest host's edge — `F4.59`'s
comment at `rtus.service.ts:270-277` says why the invariant is over
`assets.rtu_id` only); any `apps/web` change; any API response shape (no
contract work — ADR 0030 N/A); an asset with `rtuId: null` (hand-entered or
computed per ADR 0018 — its `meta` is left exactly as sent).

## Serial or parallel

**Serial, one branch, no fan-out.** Tasks 2 and 3 both depend on Task 1's
export, the whole row is effort 1–2, and Task 1 is the seam. Tasks 2 and 3 touch
disjoint files and *could* run in two worktrees after Task 1 lands; the worktree

  the ingest host defaults it to `mqtt` (`apps/ingest/src/host/bindings.ts:422`).

- `protocolToSourceType` (`onboarding-commit.service.ts:44-52`) maps everything
  except `mqtt`/`simulator` to `catalog`, and `:323-324` forces

## Design decisions

**D1. Placement and signature.** New file `apps/api/src/admin/telemetry-source.ts`
(sibling of `master-data-audit.service.ts` — the admin-level shared modules live
there). Two exports:

```ts
export type TelemetrySource = "mqtt" | "catalog";
export async function resolveTelemetrySource(
  tx: BmsTx,
  rtu: { id: string; ingestEnabled: boolean; sourceType: string },
): Promise<TelemetrySource>;
/** Pure. Merges over the caller's bag; the derived value wins. */
export function withTelemetrySource(
  meta: Record<string, unknown> | null | undefined,
  source: TelemetrySource,
): Record<string, unknown>;
```

Row-shaped, not id-shaped: all three callers already hold the row
(`RtusAdminService.update` holds `id`, `nextIngestEnabled` (`:219`),
`declaredSource` (`:328`); onboarding holds `rtuRow` from `.returning()`;
`assertRtuLocation` will return it). The config-row read runs on the caller's
`tx`, never `fleetDb` (`assets.service.ts:335-337`). Short-circuit: the read
happens only when `ingestEnabled` is true and the first disjunct fails.
`RtusAdminService` keeps its SQL merge (`:353`) — it updates N rows it has not
read; `withTelemetrySource` serves the two single-row writers.

**D2. `create` with `body.rtuId` set:** `meta: withTelemetrySource(body.meta,
source)`. A caller-supplied `telemetrySource` is overridden — the RTU is
authoritative (the `F4.59` invariant). With `rtuId` null: `body.meta ?? null`,
untouched.

**D3. `update`:** when `nextRtuId` is set (attach, RTU change, PATCH of `meta`,
PATCH of unrelated fields), `meta: withTelemetrySource(body.meta !== undefined ?
body.meta : existing.meta, source)`. Unconditional restatement, as `F4.59`
(`rtus.service.ts:286-293`): the invariant becomes a postcondition and a split
row is repaired by the next edit. On detach (`nextRtuId === null`) the meta is
left as today (`:255`) — the invariant is over RTU-attached assets; `f1.7`
counts `a.rtu_id = r.id`; and "alive beats dead" (`:303`) argues against
forcing `catalog` on an asset whose measured points may still name that RTU
through `asset_points.rtu_id`. Audit payloads for `master.asset.create` (`:177`)
and `master.asset.update` (`:266`) become `{ ...body, telemetrySource }` where
`telemetrySource` is the derived value or `null` — a value, no ids (ADR 0021).

**D4. Onboarding:** `:378` becomes `meta: withTelemetrySource(assetDraft.meta,
await resolveTelemetrySource(tx, rtuRow))`. Every onboarded asset now carries
an explicit value (`catalog` for simulator/catalog drafts), never an absence.
Resolve once per RTU, not per asset: build a `Map<rtuId, TelemetrySource>` in
the RTU loop (`:302-356`) after the config insert, read it in the asset loop.

## Owner rulings (2026-09-16, before line one)

1. **Detach** (`rtuId: null`): leave `meta` as it is (D3 as drafted).
2. **Audit payload:** `master.asset.create/update` gain `telemetrySource`
   (derived value or `null`).
3. **Onboarded non-ingest assets** carry an explicit `catalog` (D4 as drafted).
