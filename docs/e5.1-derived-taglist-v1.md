# E5.1 derived tag list v1 — water pack, authored from industry practice

**Status: PROVISIONAL — derived, not confirmed.** Ion Exchange's real tag
list (form ref **A1**) arrives after the agreement completes. This document is
the bridge: a v1 point catalog per plant type, derived from published
practice, so the water-treatment pack (`E5.1`) can be authored as **template
version 1** and superseded by v2 when the real list lands — templates are
versioned by design (ADR 0015: a row *is* a version; published assets are
never touched by a later version).

**Derivation basis** (recorded so v1's assumptions are auditable):

1. **ISA-5.1** instrument identification — the naming discipline; our point
   codes stay in the repo's `snake_case` + unit-suffix convention
   (`chw_supply_temp_c` pattern) with the ISA letter code noted per point.
2. **Standard process designs** for conventional WTP, RO skids, ASP/MBR STP,
   ETP neutralization trains, cooling towers and ion-exchange softeners.
3. **The client's own reference dashboards** (SOW pp. 9–10, read in
   `docs/ux/ion-exchange-reference-alignment.md`, mapped in BACKLOG §7.4) —
   the parameters and units *they* chose to display: DO mg/L, MLSS mg/L,
   TSS mg/L, chlorine mg/L, pH, turbidity NTU, flow KL/hr, tank levels %.
4. **IESL's published remote-monitoring packages** — the parameters they
   already sell monitoring for, the strongest proxy for "fitted in practice".
5. **CPCB Schedule VI** — which effluent parameters carry regulatory meaning.
   Per B7/B8, alarm rows below carry the parameter and its *meaning* only —
   **no limit numbers**; values are set per site at commissioning.

**Tiers.** `C` = core: fitted in any standard design of that plant type —
low guess-risk. `X` = extended: depends on instrumentation choices — this is
the tier the client redlines. `M` = typically manual/lab entry (via `F1.8`),
not an online instrument. `D` = derived tag computed by the calc engine.

**How the client uses this document (workshop handout):** strike what is not
fitted, add what is missing, correct names and units. An hour of redlining
replaces the tag export we have been waiting for since 2026-08-09.

**Gates before this becomes template content** (owner decisions, recorded in
the E5.1 ADR): ADR 0019 Amendment 1 (`thresholdValue` optional — the B7
collision), and the E5.1 ADR itself citing this document as v1's basis.

## Cross-cutting notes

- **Per-asset electrical points** (`kw`, `kwh_today`, motor currents) reuse
  the existing electrical catalog — energy KPIs (kWh/KL) need them.
- **Every `M` row lands via `F1.8` manual entry / `F1.9` import** — the lab
  results are first-class points, which is what makes F/M ratio, BOD-based
  KPIs and CPCB reporting possible without online analysers.
- **Counts:** ~100 points across six plant types; 58 core, 27 extended,
  ~15 manual/lab — the redline burden on the client is the 27, not the 100.
- **What v2 will change** (expected, from the A1 answer): fitted-instrument
  reality per plant, their tag naming overlay, product names (C17), and any
  site-specific extras. The *shape* — units, KPIs, alarm meanings — is the
  part practice fixes and v2 is unlikely to move.
