# ADR 0040 — E5.1 water pack: provisional authoring from a derived tag list

## Status

**Proposed — drafted 2026-08-22, awaiting the owner's gate.** Four questions
for the gate are listed at the end; nothing starts until they are ruled.

**Prerequisite: ADR 0019 Amendment 2** (`thresholdValue`/`operator` paired
optional), proposed the same day. Without it, decision 4 below cannot be
implemented and the pack cannot carry honest alarm content.

`E5.1`'s two `Depends` entries (`F2.1`, `E1.7`) have been ✅ since 2026-08-05.
What has blocked it since is a client question set, not a dependency — this
ADR is the decision to stop waiting, and it records exactly what is assumed so
that stopping is auditable.

## Context

`E5.1` is the flagship P0 — the water-treatment domain pack, Ion Exchange's
core business and the Foundry demo's subject. It has been eligible-but-blocked
for 17 days on the `A1` tag list (asked 2026-08-09, restated 2026-08-17,
unanswered 2026-08-22). The client's 2026-08-22 reply states the tag lists
follow **after the agreement completes** — an open-ended wait on the one item
the whole critical path heads into.

Meanwhile three facts changed the risk calculus:

1. **`docs/e5.1-derived-taglist-v1.md` exists** — a ~100-point catalog for six
   plant types, derived from ISA-5.1, standard process designs, the client's
   own reference dashboards (BACKLOG §7.4) and IESL's published monitoring
   packages, tiered core / extended / manual so the guessable part is fenced.
2. **Templates are versioned** (ADR 0015: a row *is* a version) and the
   version lifecycle is decided (ADR 0039), so a provisional v1 superseded by
   a confirmed v2 is the designed path, not a workaround.
3. **The client's own artifacts now order the plant types** — the reference
   dashboards give STP and ETP dedicated navigation and full trains; the
   feature sheet names WTP, STP and cooling tower and omits RO and softeners.

The cost of authoring against a wrong guess (the annex's 6–8 pw figure) was
priced for *silent* guessing against no basis. This ADR replaces that with
declared, tiered, versioned assumptions the client is asked to redline.

## Decision

1. **Author the water pack as template version 1 from the derived tag list**,
   marked provisional. Six templates, in the `A3a` working order:
   **STP → ETP → cooling tower → WTP → RO → softener.** The order is a
   working assumption recorded in Part 1 of
   `docs/ion-exchange-response-form-2026-08-22.md`; one client sentence
   re-sequences it at zero cost since all six catalogs are drafted.
2. **Catalog rows, not hardcoded vocabularies.** Point keys land in
   `bms.point_keys` following the existing `snake_case` + unit-suffix
   convention (`feed_flow_klh`, `aeration_do_mgl`). The plant domains ride the
   `bms.asset_domains` lookup (ADR 0031 Amendment 1) — new sectors are an
   `INSERT`, not a migration.
3. **Tiering is carried on the data.** Core points are ordinary
   `template_points`; extended-tier points carry `meta.tier = "extended"`;
   lab/manual parameters are template points whose values arrive via the
   `F1.8`/`F1.9` manual paths. The tier marking is what makes the client's
   redline mechanical: strike extended rows, done.
4. **Alarms are authored as philosophy rows** — parameter, meaning, severity,
   enrichment (`philosophy.cause/impact/action/skill`, the ADR 0019 §3
   anchored object), **without threshold numbers**, per the `B7`/`B8` working
   position. Requires ADR 0019 Amendment 2. Discharge-consent parameters carry
   their CPCB Schedule VI meaning in the philosophy text, never a limit value.
5. **KPIs**: single-asset formulas (recovery %, salt rejection %, range,
   approach, cycles of concentration) are authored as `dialect: "bms-calc-v1"`
   and validated by the live DSL. Cross-asset formulas (kWh/KL needing pump
   energy, plant-level balances) are authored as `dialect: "unvalidated"` and
   promote when `F2.9` lands — the ADR 0019 §5 discriminator doing exactly
   what it was built for.
6. **Provenance is recorded on the template**: `meta.provenance =
   "derived-v1"` plus a pointer to the tag-list document. The `A1` redline (or
   the post-agreement tag export) produces **version 2** with
   `meta.provenance = "client-confirmed"`; ADR 0039 governs how v2 reaches
   any assets instantiated from v1. Nothing instantiated is ever rewritten.
7. **Names stay generic** (`C17` unresolved): template names are plant-class
   names; IESL product names (INDION FMR, NGPSTP, Eco MBR) swap in as display
   names when confirmed — a lookup change, not a re-author.
8. **Scope fence.** This ADR authors *content* — catalogs, templates, KPIs,
   philosophy rows. It does not wire alarms to rules (`E2.4`, own ADR per
   ADR 0019 §3), does not build dashboards (`F3.1`), does not touch the
   hierarchy (`F2.10`, own ADR), and adds no code paths — the authoring
   surface (`F2.5`) and the content contract (ADR 0019) already shipped.

## Dependencies

**None.** No npm package, no DDL beyond catalog/seed `INSERT`s through the
existing tables. AGENTS.md §9.4 is not engaged.

## Consequences

- The flagship moves after 17 days parked, with its assumptions declared,
  tiered and versioned instead of silent. The exposure is the extended tier
  (27 of ~100 points) and the plant-type order — both correctable by one
  redline session, which the workshop bring-list already requests.
- `E5.2` (mechanical pack) inherits the same pattern for free: derive, tier,
  version, redline. The wait-for-client posture is replaced by a
  review-our-draft posture across Track B.
- Two client-facing statements become commitments to honor: Part 1 of the
  2026-08-22 form (the assumptions) and the reply mail's "authoring proceeds
  in that order". If the gate re-orders or rejects, those documents must be
  corrected **before** the mail is sent.
- `E5.1`'s BACKLOG row, §1's critical-path note and §1b slot 8 all say
  "blocked on a client answer" — on acceptance, they flip to "proceeding
  provisionally under ADR 0040", which is a `docs(backlog):` follow-up.

## Open questions for the gate

1. **Accept ADR 0019 Amendment 2?** This ADR is inert without it.
2. **Confirm the `A3a` order** (STP → ETP → cooling tower → WTP → RO →
   softener) — it inverts the drafted-four order our 2026-08-09 questions
   presented to the client.
3. **Is ETP's inclusion a scope statement?** The drafted four excluded it; the
   client's artifacts promote it. Including it here quietly widens what the
   2026-08-17 handout said we would build first — better ruled than drifted.
4. **Tier encoding** — decision 3 uses `meta.tier` on `template_points`.
   Acceptable, or does the gate want a first-class column (DDL, migration)?
   Drafted as `meta` because the tier is provenance, not behaviour: nothing
   at runtime branches on it.
