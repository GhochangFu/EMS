# ADR 0086 — Administered and uploaded mimic symbol libraries (`F3.32f`)

## Status

Accepted — drafted on 2026-09-29, before any implementation code. The owner
approved this written record on 2026-09-29, and ruled draw.io in at the
v29.3.2 pin (decision 9).

The owner ruled on 2026-09-29: "Do the full row", to be built in one day. **The
release rule is per slice.** The row is built as three pull requests, each
merged on its own when it is green and verified:

1. the carried review fixes and the attributions page (decisions 5, 8, 10);
2. the QElectroTech, Commons and draw.io libraries (decision 9);
3. the organization libraries, the switch and SVG upload (decisions 1–4, 6, 7).

Each slice has its own migration: `0091` (slice 1), `0092` (slice 2), `0093` (slice 3). They merge in that order; if a slice is held, the next merged slice takes its number.

**A slice that is not merged by the end of 2026-09-30 is held**, and the v1

Slice 1 implementation notes (2026-09-29): migration `0091_mimic_lucide_licence`; gates `tests/f3.32f-carried-fixes.test.ts` and its `.integration` twin; the palette filter of decision 5 lands with decision 7's endpoint in slice 3 (plan ruling R1). The unit-symbol exemption is by symbol key, not by unit: a re-save may place a new unit with a symbol the stored layout already uses, even when that symbol or its library is retired; any other symbol must be active and in a live library (plan ruling R7, owner-accepted 2026-09-29).

Slice 2 implementation notes (2026-09-30): the shape grammar with `transform` is `packages/shared/src/contracts/mimic-shapes.ts`; the converter building blocks (`scripts/mimic-symbols/lib/`) are gated by `tests/f3.32f-mimic-symbol-converters.test.ts`, listed in the root `typecheck:tests` script.

Builds on [ADR 0084](./0084-mimic-symbol-libraries.md) and delivers its
decision 10. Amends ADR 0084 decisions 3 (the foreign key is no longer the only
symbol reference), 5 (path data can also be stored data, for an uploaded
symbol; `transform` joins the attribute list), 7 (the contract accepts
organization keys) and 8 (a layout can choose an organization library). Promotes nothing
out of `AGENTS.md` §6.

## Context

**What exists (`F3.32e`).** Four preloaded libraries — Core, Tabler Icons,
Lucide, Material Design Icons — in two global lookup tables,
`bms.mimic_symbol_libraries` and `bms.mimic_symbols` (migration `0090`, no row
security, `bms_tenant` read-only). The path data is vendored code generated by
`scripts/mimic-symbols/generate.mjs`; the web reads the symbol lists from
`packages/shared`, not from the API. A unit's `symbol` has a foreign key to
`bms.mimic_symbols(key)`. A layout chooses libraries in
`mimic_layouts.symbol_libraries`.

**What the row asks for.** Organization-owned libraries; an administrator
switch that enables a library for an organization; SVG upload with a
server-side sanitizer; an attributions page; the sources that need per-file
licence work (QElectroTech, Wikimedia Commons, draw.io); and four fixes the
`F3.32e` reviews carried.

**Two constraints from earlier records.**

- ADR 0043 Amendment 5 and ADR 0049 decision 3 reject a nullable
  `organization_id` where `NULL` means "global". So organization rows cannot
  go into the global tables of `0090`.
- A foreign key check does not apply row security. A key that names another
  organization's row passes a plain foreign key. The reference to an
  organization symbol must carry the organization in the key.

**No XML parser is a direct dependency.** `parse5`, `saxes` and `sax` are only
in the lockfile through `jsdom`, a web dev dependency. The generator parses the
vendored SVG files with regular expressions; that is safe for a pinned release
that we read, and not safe for a file that a user uploads.

## Decision

1. **Two organization tables, beside the global ones.** Migration `0093`
   creates, in the `bms.mimic_layouts` shape (`organization_id NOT NULL`,
   `ENABLE` and `FORCE ROW LEVEL SECURITY`, the strict `tenant_isolation`
   policy of `0088` in `USING` and `WITH CHECK`, no `NULL` disjunct, privileges
   from `0041`'s default grants):
   - `bms.mimic_org_symbol_libraries` — `id` (uuid), `organization_id`,
     `code`, `label`, `style` (`stroke` or `fill`), `licence`, `attribution`
     (free text, shown on the attributions page), `source_url`, `active`,
     `created_by`, timestamps. `UNIQUE (organization_id, code)` and
     `UNIQUE (organization_id, id)`.
   - `bms.mimic_org_symbols` — `id`, `organization_id`, `library_id`, `key`,
     `label`, `group_code` (the eight `F3.32d` groups), `view_box` (four
     numbers), `shapes` (`jsonb`), `source_filename`, `sha256`, `active`,
     `created_by`, timestamps. `UNIQUE (organization_id, key)`. A composite
     foreign key `(organization_id, library_id)` references the library, so a
     symbol cannot sit in another organization's library.
2. **An organization key names its organization library.** The key is
   `org.<library code>:<name>` (`org.plant:inlet-screen`). The `org.` prefix
   cannot collide with a global key: a global library code matches
   `^[a-z][a-z0-9]*$` (`0090`). The same string goes on the wire in a node's
   `symbol` and in `symbolLibraries` (`org.plant`), so the web and the
   contract keep one field. **The contract widens** (amends ADR 0084
   decision 7): a node's `symbol` accepts a static key or a key that matches
   `^org\.[a-z][a-z0-9]*:[a-z0-9][a-z0-9-]*$`; `symbolLibraries` accepts a
   static code or `org.<code>`; `libraryOfSymbol` resolves both. Whether an
   `org.` key exists in the caller's organization is the service's check, then
   the composite foreign key's (decision 3). CHECKs hold the organization
   library `code` to `^[a-z][a-z0-9]*$` with at most 27 characters, so
   `org.<code>` fits `varchar(32)`, and the whole symbol key to 64
   characters.
3. **A unit references exactly one symbol table.** `mimic_layout_nodes` gains
   `org_symbol_key varchar(64)`, with a composite foreign key
   `(organization_id, org_symbol_key)` to
   `bms.mimic_org_symbols (organization_id, key)`, no `ON DELETE`. A unit has
   either `symbol` (the `0090` foreign key to the global table) or
   `org_symbol_key`, never both and never neither; `0093` replaces
   `mimic_layout_nodes_kind_fields_check` to say so. The service maps an
   `org.` key on the wire to `org_symbol_key` and back. The composite key is
   what stops a cross-organization reference — not the policy.
4. **The administrator switch.** Migration `0093` creates
   `bms.mimic_library_settings` — `organization_id`, `library_code`
   (a foreign key to the global `bms.mimic_symbol_libraries`), `enabled`,
   `updated_by`, `updated_at`; primary key `(organization_id, library_code)`;
   the strict tenant policy. No row means enabled, so every organization keeps
   the four libraries it has today. `core` cannot be disabled. A global
   `admin` sets the switch for any organization; an `organization_admin` for
   its own. An organization library has its own `active` flag, which its
   organization's administrators set.
5. **A retired library or symbol does not break a stored layout** (the
   retired-role rule; carried from the `F3.32e` reviews). A save refuses a
   library that is disabled for the organization or inactive, and a unit whose
   symbol is inactive (carried fix 1) — **except** a library or a unit symbol
   that the stored version of the same layout already has. A new layout, a
   newly chosen library and a newly placed or changed unit must use live ones.
   The palette does not offer a retired library or symbol; the canvas still
   draws a stored one.
6. **SVG upload.** `POST /api/v1/mimic-symbol-libraries/:id/symbols`
   (multipart, one file) adds a symbol to an organization library;
   `admin` and `organization_admin` only, on the tenant pool.
   - **Limits:** 64 KiB per file, declared type `image/svg+xml`, a
     `FileInterceptor` with inline limits (the `F4.102` gate), at most 500
     symbols per organization library.
   - **Parse, do not sanitize text.** The API parses the file with `saxes`
     (a strict, non-validating XML parser, promoted from a transitive to a
     direct dependency of `apps/api`). It refuses a `DOCTYPE`, an entity
     reference other than the five XML entities, a processing instruction
     other than the XML declaration, and a CDATA section.
   - **Keep geometry only.** The root is `svg` with a `viewBox`. Kept elements
     are ADR 0084 decision 5's seven (`path`, `circle`, `ellipse`, `rect`,
     `line`, `polyline`, `polygon`), and `g`, which is flattened (its
     `transform` is pushed down, decision 9). `title`, `desc` and `metadata` are dropped. Any other element
     (`script`, `style`, `use`, `image`, `foreignObject`, `a`, `text`, a
     gradient, a filter) refuses the file with a 400 that names the element.
     Editor metadata is dropped, not refused: `sodipodi:*` and `inkscape:*`
     elements and attributes, an empty `defs`, and `metadata`. A `style`
     element or a `script` still refuses the file.
     Kept attributes are the geometry list of decision 5 only; every other
     attribute is dropped, so no event handler, `style`, `href`, `class` or
     colour survives. A numeric attribute must be a number; `d` and `points`
     must match the SVG path and points grammar. Limits: 200 shapes, 8 KiB per
     `d`.
   - **What is stored:** the parsed shape list as `jsonb` and the `view_box`.
     The raw file is not stored and never reaches a browser. The audit log
     records the upload with the file's SHA-256.
   - **How it draws:** through the same `createElement` path as the vendored
     glyphs (never `innerHTML`, never an SVG string), in the library's style
     with the role's colour class (ADR 0078).
   - **The stored shapes are checked again on the way out.** A row can reach
     the table by a path other than this upload (a `bms_fleet` write, a later
     migration). So the response contract (ADR 0030, Zod) limits `tag` to the
     seven shape elements, attribute keys to the geometry list plus
     `transform`, and each value to its grammar; the renderer copies only the
     allowlisted keys into props and never spreads a stored object. "Themeable only when
     stroke-only" becomes: no uploaded colour is kept, so every uploaded symbol
     takes the role's colour.
7. **The library API.** A new `mimic-symbol-libraries` module:
   - `GET /api/v1/mimic-symbol-libraries` — for authors: the global
     libraries with this organization's switch and the keys of inactive
     global symbols (the bundle does not know them), and this organization's
     libraries with their symbols (shapes included). The editor reads
     organization symbols from here; the global symbols stay in the static
     bundle.
   - **A layout read embeds the organization symbols it uses.** The layout
     `GET` (and so every dashboard mimic widget, which operators see) returns
     `orgSymbols`: the key, label, style, `view_box` and shapes of each `org.`
     symbol in the layout. A viewer needs no library endpoint, and a
     published dashboard never draws the fallback glyph for an uploaded
     symbol.
   - `POST`, `PATCH` for organization libraries (label, licence, attribution,
     active); `PATCH /:id/symbols/:symbolId` (label, group, active);
     `PUT /settings/:libraryCode` for the switch.
   - No hard delete for a library or a symbol that a unit uses (the foreign
     key refuses it); `active = false` retires it.
8. **The attributions page.** `/attributions`, for every signed-in user, and a
   link from the palette's licence line. It lists each global library (name,
   version, licence, source link, full notice from the bundle) and each of the
   organization's own libraries (licence and attribution as entered), and,
   for a source with per-file credits, each file's author and licence.
9. **Third-party sources** (licence research of 2026-09-29, primary sources
   quoted in the PR). Each new source is a global library in the `0090`
   shape: a row in `bms.mimic_symbol_libraries` (migration `0092`), a
   curation list, and generated modules from `generate.mjs`.
   - **`qet` — QElectroTech elements**, pinned at
     `qelectrotech/qelectrotech-elements@3b12bc579b99932e3fe307ea1e44b8c1c6d1d5c9`
     (the submodule of mirror tag `0.100`). `ELEMENTS.LICENSE` permits use in
     diagrams without condition, and requires CC BY 3.0 for redistribution
     "out of an electric diagram" — which a symbol library is. About 120
     curated elements from `energy`, `hydraulic` and `pneumatic`. The
     generator reads the `.elmt` XML itself (it does not port the GPL
     application code): `line`, `rect`, `ellipse`, `circle` and `polygon` map
     to shapes, `arc` becomes a `path`, and `text`, `dynamic_text` and
     `terminal` are dropped. Style `stroke`. Attribution: a generated notice
     with one row per symbol — author (from `<informations>`, "The
     QElectroTech team" when absent), source path, licence URI, and "converted
     to geometry". Label `CC BY 3.0`.
   - **`wmpid` — Wikimedia Commons P&ID symbols**, the public-domain and CC0
     files of `Category:P&ID symbols` (about 424 of 483; the 58 CC BY-SA files
     and the GPL file are excluded — share-alike cannot go into a closed
     bundle). The library holds the curated PD and CC0 files that pass the
     converter; the PR states the count (Commons answered HTTP 429 during the
     research, so only a few files were sampled). Commons has no release, so the curation list
     pins each file by its `sha1` and `timestamp`, and the generator refuses a
     file whose bytes differ. Each file's author and licence template are
     recorded and shown, although public domain asks for no attribution. A
     file under a threshold-of-originality template (`PD-shape`,
     `PD-textlogo`, `PD-ineligible`) is labelled as such. Label
     `Public domain / CC0`.
   - **`drawio` — draw.io stencils, pinned at v29.3.2**
     (`jgraph/drawio@48b181339578e11da7052ebf5b1fba8499418b77`, 2026-01-17).
     **Owner ruling 2026-09-29, with the risk stated:** at v31.5.3 neither the
     README nor `stencils/LICENSE` grants a licence for the stencils (they
     only forbid use in Atlassian products); the v29.3.2 README said "The
     JGraph provided icons and diagram templates are licensed under the CC BY
     4.0. Additional terms may also apply where the icons are originally
     defined by a third-party copyright holder". The owner chose to rely on
     that text at that pin, knowing that it names "icons", not stencils, and
     that third-party origin is not stated per set. Only the `pid` and
     `electrical` stencil sets at that commit are used; every vendor set
     (`aws*`, `azure`, `cisco*`, `gcp*`, `ibm*`, `atlassian`, `salesforce`,
     `office`, `kubernetes`, and the others) is excluded. The generator reads
     the mxGraph stencil XML itself: `path` (`move`, `line`, `quad`, `curve`,
     `arc`, `close`), `rect`, `roundrect` and `ellipse` map to shapes; text and
     connection points are dropped. Style `stroke`. Label `CC BY 4.0`,
     attribution "JGraph Ltd, draw.io", with the pin and the quoted README
     text on the attributions page. The Atlassian-products restriction is
     recorded; this product is not one.
   - **`transform` joins the attribute list** (amends ADR 0084 decision 5).
     Commons files are Inkscape output with nested transforms. A shape can
     carry `transform` whose value matches a strict grammar (`matrix`,
     `translate`, `scale`, `rotate`, `skewX`, `skewY` with numbers only); a
     `g`'s transform is pushed down onto its children when it is flattened.
     The same rule applies to an uploaded file (decision 6).
10. **Carried fixes from the `F3.32e` reviews.**
    - Refuse a save that names an inactive symbol (decision 5).
    - The retired-library exemption (decision 5).
    - Unknown codes in `mimic_layouts.symbol_libraries`: the read path drops a
      code that is neither a global library nor one of the organization's
      libraries and logs it, so one bad row no longer fails the whole list
      response; the write path already refuses it.
    - The Lucide label: `0091` sets the `lucide` row's `licence` to
      `ISC and MIT`, and the generator and the `F3.32e` gate change with it,
      because the gate compares the rows, the shared list and the web modules
      both ways. The label is needed: 16 of the 126 curated Lucide icons
      (`power`, `server`, `database`, `clock` and others) are on the package
      LICENSE's list of icons derived from Feather, which it puts under MIT.

## Dependencies

`saxes` (already in the lockfile at 6.0.0 through `jsdom`) becomes a direct
dependency of `apps/api`. No other package.

## Consequences

- Organization data enters the mimic vocabulary for the first time. The
  security review must prove three things: a tenant cannot read or reference
  another organization's library or symbol (policy and composite key); an
  uploaded file cannot put script, style, a link or a colour into the page;
  and a disabled library cannot be newly used.
- The editor gets its symbol list from two places — the bundle for global
  libraries and the API for organization libraries. The palette search and the
  inspector select cover both.
- A second path from a user file to the page exists. It is guarded by a parse
  that refuses, not a sanitizer that rewrites.
- `mimic_layout_nodes_kind_fields_check` and the `F3.32e` gates that pin the
  symbol foreign key change; `0088`–`0090` stay frozen.
- CC BY 3.0 §4(a) forbids terms that restrict what a recipient can do with the
  licensed work. The product's customer terms must not restrict the vendored
  QElectroTech symbols. That is a contract task for the owner, outside the
  code.
- Geometry-only conversion loses which parts of a QElectroTech or Commons
  symbol were filled; they draw in the library's one style.
- The generator fetches Commons files over the network at generation time
  only, with a pause between requests (Commons answered HTTP 429 during the
  research). The build and CI never fetch them.
- The main web chunk grows again by the vendored QElectroTech, Commons and draw.io symbols; the PR
  states the measured growth.
